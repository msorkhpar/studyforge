## The measurement — the two copies did not merely duplicate, they disagreed

**Measured 2026-09-09**, the deleted pattern against the gate that replaced it:

```text
shape                      old copy   scrub.shape_in
bare home directory        MISSED     caught
with a file beneath        caught     caught
macOS spelling, bare       MISSED     caught
inside a shell command     MISSED     caught
a leak in a dict key       MISSED     caught
```

⛔ **Four of five.** The cause of the first four is one character: the deleted
pattern was `/(?:home|Users)/[A-Za-z0-9._\-]+/` — it required a **trailing
slash**, so it matched a home path only when a file sat beneath it. The fifth is
`strings_in`, which walks `values()`; `scrub._walk` visits dict **keys**, and
its own docstring names that exact case as real.

⛔ **And the weaker copy was the one enforcing rubric §1e** — the single place
in this repository where personal-data-shaped content is *permitted*. The worst
possible location for the weaker of two gates.

⭐ **Rubric §1a had already ruled the shape** — *"do not re-derive the patterns;
`tools/quality/` owns them"*, a duplication refused five times. ⚠️ Nobody swept
for a **third** copy. There was one.

## W7 — the front door gated nothing, and `validate` was already wired for it

⛔ **`corpus/manifest/` — six modules — called `assert_clean` nowhere**, while
`archive/document.py`, `corpus/container/document.py` and `unit/content.py` all
did. So a home path in `corpus.json`'s `title` validated **green**: zero
findings, zero unchecked, in the one command an adapter author is told to trust
(R2).

⭐ **The shape is what makes it C6 rather than a plain bug: the catch was
correct and the raise never came.** `studyforge validate` forwards a leak from
this reader faithfully; there was simply never one to forward. Nothing looked
wrong from either side, which is why no review found it and no test failed.

**Measured 2026-09-09** — the two W7 tests, run against the tree with the two

⭐ **Ruling 11, end to end**: the assertion was watched failing on the real
defect, not on a synthetic one.

### ⛔ The reader set is derived, never listed

A hand-maintained list of readers is **how W7 went missing in the first place**,
so closing it with a sixth entry in one would have reproduced the defect while
closing the instance. `document_readers` asks the tree: **a module that calls
`json.loads` or `json.load` is reading a document somebody else wrote.**

⭐ **The tell is good because a reader cannot avoid it.** A module that never
decodes bytes is not reading anybody's document; one that does cannot get out of
it. Five modules match today and all five now gate.

### ⚠️ `placement/identity.py` was the second one, and its exemption did not survive reading

It decodes an identity block and did not gate. ⛔ The tempting argument — *this
framework wrote that block* — is refused by `identity.parse`'s **own contract**,
which says it reads *"files this build may not have written"* and tolerates
attribute order for exactly that reason. ⭐ A reader whose exemption rests on an
assumption its neighbour explicitly refuses is not exempt, and taking the
derivation seriously is what surfaced it. Nobody had reported this one.

⚠️ **One existing test changed, and the change is an improvement**:
`test_a_refusal_never_emits_the_address_segment_it_refuses` now sees the gate's
refusal rather than the address model's, because the gate runs first. The claim
it was written for — the value is not emitted — still holds and is still
asserted; a second test was added so the gate cannot be read as having replaced
SF-01's slug check.

## Decisions

### 1. ⛔ Deleted, not reconciled

Reconciling two lists produces a third list. `tests/fixture_checks/personal_data.py`
is now nine lines of code over a paragraph of why, and the import direction was
already sanctioned rather than assumed: `tests/fixture_checks/vocabulary.py`
imports from `studyforge` today.

### 2. ⭐ The fourth copy is made unrepresentable, and across the package

The CTO asked for a test that the fixture checker has no pattern of its own. It
is stronger than that: it walks the AST of **every** module under
`tests/fixture_checks/`, collects every literal handed to `re.compile`, and
fails on any carrying `home`, `Users`, `Bearer` or `@`.

⚠️ **Scoped by tell, not by filename**, because a fourth copy would not
necessarily be called `personal_data.py` — that is precisely how the third one
went unnoticed. The three regexes the package legitimately keeps
(`MARKUP_SHAPED`, `UNIT_DIR`, `ARCHIVE_FILE`) carry none of the tells.

⭐ **And the guard is watched failing** (Ruling 11): a temporary file with
`re.compile(r"/home/[a-z]+/")` in it is driven through the same collector, and
the collector sees it.

### 3. ⚠️ One behaviour changed with the deletion, and it is a correction

The deleted module claimed *"any address is wrong content whether or not it is
deliverable, so there is no allow-list at all"*. ⛔ But `scrub.shape_in` skips
each shape's **own placeholder** by identity, so the claim was already untrue of
the gate the fixture checker exists to predict. A fixture checker stricter than
the gate reports failures the build will not have. ⭐ No fixture is affected:
the whole-tree sweep is still empty, and
`tests/fixtures/invalid/personal-data/` still trips, both asserted.

### 4. `imports_module` — the third copy, caught before it was written

⛔ `test_version.py:imports_the_guard` and `test_blocks.py:imports_the_vocabulary`
are the same eleven lines with a different constant, and W13's own guard was
about to be the third. ⭐ `tests/support.py`'s contract already said *"if a block
is repeated between test files, extract it and import it"* — this is that rule
applied to itself. Both callers now delegate; neither changed behaviour, and
both their existing tests still pass.

## Findings

### 1. `[structural]` `tests/fixture_checks/corpus.py:strings_in` still cannot see a dict key

**Measured 2026-09-09** — the walker that the deleted gate rode on:

```text
strings_in({"<a home path>": "fine"})   ->  yields only "fine"
```

⚠️ The key is written as a placeholder here on purpose: the repository's own R7
sweep reads this document and it is right to. ⭐ The test that exercises the
real shape assembles it at run time rather than writing it down.

⛔ **Not fixed here, because W13's shape was *delete, do not reconcile*** — the
personal-data check no longer uses it. ⚠️ But `strings_in` is still the walker
for every **other** fixture check in the package, and each of those has the same
blind spot. `studyforge.archive.scrub._walk` is the correct shape and it is
already in the tree, one import away.

### 2. `[local]` The whole-tree fixture sweep reads raw file text, not decoded JSON

`test_only_the_personal_data_fixture_carries_personal_data` greps the bytes on
disk. ⚠️ `scrub.py`'s contract explains why that is the weaker vantage point —
the extraction source gated *serialised* JSON and refused three clean lessons
because `\n@router.get` is address-shaped. ⭐ It is still the right check here
(it must cover `.md` and `.svg` too, which have no decoded form), but a future
false positive on an archive fixture will have this cause and the diagnosis is
already written down.

### 3. `[structural]` Two personal-data gates remain, and their divergence is now the *documented* kind

`studyforge.archive.scrub` and `tools/quality/personal_data/` are two gates with
different subjects — one refuses content, the other sweeps this repository —
and `scrub.py` states the divergence and says ⛔ *"do not align them"*. ⭐ That
is a **third** copy retired and two deliberate ones left, each with a written
reason. ⚠️ Worth recording that the count is now two-by-decision rather than
three-by-accident, so the next sweep does not re-open a closed question.
