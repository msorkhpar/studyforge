## ⛔ EVERY PLANT IS A REAL EDIT, AND ITS EFFECT IS OBSERVED BEFORE ANY GATE IS READ

⚠️ **The brief was explicit that three no-op plants read GREEN in this session**, so this is
stated as a property and not as a habit:

- ⛔ **Nothing is stubbed.** Every reading a gate is given comes out of a real `pytest`
  process over real files in a `tmp_path` workspace — five runs per suite, and
  `tests/studyforge/exercise/gates/workspace.py` is the exercise.
  A stubbed `Attempt` would have let each plant be a value typed into a dictionary.
- ⛔ **The NEGATIVE CONTROL is a test of its own** — the same bundle with nothing planted
  clears all five — so a suite that refused everything could not pass the plants.
- ⛔ **Each plant asserts the planted STATE and prints it BEFORE reading a gate**: the main
  ask really passed on the starter, the reference's two runs really disagreed *with each
  other*, the plant really passed the edge it was planted to fail, the fold really refused,
  the ledger's digest really differs from the recorded one. ⚠️ **Every comparison is
  between two values the run produced**, never against a constant that could read the same
  on both sides.
- ⛔ **Four plants are ISOLATED and the fifth cannot be**, and that is asserted rather than
  hidden: each of `G1`, `G2`, `G3` and `G5` is refused *alone*, with the whole refusal list
  compared. ⚠️ `G4`'s plant — a test the case map does not name — is refused by
  `report.breakdown_of` on **every** run of that exercise, so `G1`–`G3` lose their evidence
  with it and answer *did not hold, no reading could be folded*. That is asserted too, with
  the sentence each of them gives.

## Decisions

⭐ **Things the task did not specify, chosen here, each with the reason:**

1. ⛔ **The gates do not run anything, and they never will.** `execute` imports
   `studyforge.exercise`, so a gate reaching back for it would make the two packages
   circular. ⭐ The runs arrive through `runs.Attempt` — a caller runs the command and hands
   the result over — which is also what lets a suite be taken **in the pinned runner image**
   with nothing in this package knowing a container exists (spec §7 §6).
   ⚠️ `test_init.py` asserts no module here imports `studyforge.execute`, `subprocess` or
   `shutil`.
2. ⭐ **A family declares its own gates and registers itself at its own import**, and
   `families` holds the RULES rather than a list of who exists. ⛔ **The only line a second
   family adds outside its own sub-package is the import in `gates/__init__.py`** — the one
   R17 already obliges it to add, because a parent contract is where a reader finds out a
   sub-package exists (`exercise/__init__.py` named `quiz` for the same reason).
   ⚠️ **Discovery by `pkgutil` + `importlib.import_module` was written first and REMOVED** —
   see the first surprise below.
3. ⛔ **A gate id belongs to exactly one family, for the life of the process.** The
   interesting attack on a gate suite is not deleting a gate, it is REDECLARING one: a
   second family answering for `G3` with a weaker rule would leave every reader of the
   record seeing a `G3` that held. Registration is additive and a collision is refused.
4. ⭐ **The record's write order is DERIVED** — family by name, then gate by its family's own
   order — and a record ordered any other way is refused, so two records of one run are the
   same bytes (R10).
5. ⭐ **`digests` leaves the ROLE open and closes the SHAPE.** `code` writes `statement`,
   `starter`, `reference`, `tests` and one `plant:<case id>` per edge; a quiz family writes
   one cited passage per question. ⛔ Closing the role set would mean every new family
   editing that module, which is the seam `families` exists to avoid.
6. ⛔ **An `Input` and a `Cited` passage are two things, not one.** An input lives in the
   bundle and `validate` re-digests the file beside the record; a cited passage lives in the
   SOURCE, which the framework may not even have, and is compared against the **ledger**.
   ⚠️ Collapsing them would make `G5` unreadable.
7. ⭐ **A case is named by its `says`, never by its `id`.** `says` is the sentence the corpus
   already ships to a reader; a case `id`'s permitted set is wider than a workspace path —
   it carries `/` and `.` — so printing one into a record is a shape nobody has bounded (R7,
   and finding 4 below).
8. ⛔ **`G2` holds for a starter that failed before any test reported.** A starter that does
   not compile writes no report, and *no test passed* is exactly what the gate claims; a
   starter that wrote no report and still **succeeded** is refused. ⚠️ A harness broken in
   general cannot hide there, because `G1` requires every case to pass on the reference over
   the same tests.
9. ⛔ **`G4`'s second arm reads the reference run.** *Every case is backed by at least one
   test* is read as *every case was named as passing in the reference run's report* — on the
   reference every backing test passes, so appearing-as-passed IS appearing. ⚠️ A case whose
   backing test FAILED on the reference is `G1`'s finding and `G4` fires too; both are
   stated in `code.py` rather than left to be discovered.
10. ⛔ **`Verdict.recorded` is a family's own evidence**, ordered text pairs with token keys.
    `Q1`–`Q3` are model judgements taken once at authoring and shipped as a record (spec §7
    §7), and what they must carry is a quiz fact `record.py` has no business enumerating.
    ⚠️ Nothing reads `recorded` to decide anything: `held` is the verdict.

## Surprises

⛔ **The framework reaches NO module by name at run time, and the gate registry was built on
doing exactly that.** ⚠️ **MEASURED**: `tests/harness/test_isolation.py`'s run-time-import
arm refused `families.py` for one `import importlib`. ⭐ **The rule is right** — its own
comment says it: a dynamic import is the door a closed set of import statements cannot see,
and it is asserted EMPTY rather than policed. ⛔ **So the seam is now a static import in the
package contract** and the cost is one line per family, in the file R17 already obliges a new
sub-package to appear in. ⚠️ **Worth knowing before designing any other plug-in-shaped seam
in this tree: there is no legal discovery mechanism in `src/`.**

⛔ **`digest_of` is a RESERVED NAME and belongs to exactly one module.** ⚠️ **MEASURED**:
`tests/studyforge/narrate/speakable/test_naming.py`'s minter arm names
`src/studyforge/narrate/speakable/naming.py` as the only definer of `clip_name` and
`digest_of`, over the whole of `src/`. ⭐ The gates' own is `digest_of_bytes`, which reads
better beside `digest_of_file` anyway. ⚠️ **It is a TREE-WIDE reservation, not a package one**
— anything later needing a hash helper meets it.

⛔ **Two refusals reproduced the value they refused, and the emission sweep caught both.**
⚠️ **MEASURED**: `tests/test_emission.py::test_no_refusal_reproduces_the_value_it_refused`
poisoned `digest_of_file(path=…)` and `require_run(role=…)` with a home path and read it
straight back out of the message. ⭐ **Both are closed and each differently**, because the two
are different mistakes: `digest_of_file` now runs `require_path` BEFORE it quotes anything, so
what it names is guaranteed workspace-relative; `require_run` **stops naming the role at all**,
because a plant role carries a case id and a case id's permitted set is wider than a path
(finding `AX-03/4`). ⚠️ **For every dependent: a `where` string and `describe()` are safe; a
raw parameter in a refusal is not, and the sweep is the only thing that would have told me.**

⛔ **`all(())` is `True`, so an empty gate record cleared everything.** ⚠️ **MEASURED, by a
test in this task that failed before the arm existed:** `record_of` accepted a document whose
`gates` array was empty, and `GateRecord().clears` answered `True` — ⛔ **so the cheapest way
to make a failed bundle read green was to DELETE the gates that refused it.** ⭐ Closed in
both places: `_require_every_gate` refuses a record naming no gate at all, and `clears` is
`bool(self.verdicts) and all(...)`. ⚠️ **It is written down because the same shape is one
`AX-06` will have** — a quiz family whose questions were all dropped would otherwise clear.

⚠️ **The context budget (~40k) was about right for the gate logic and short for the seam.**
Reading `exercise/`'s five existing modules whole, spec §7 and `E08`'s shared context is most
of it; the part that was not budgeted is `tools/quality`'s own rules — the mirror, the
surface check and the style floor shape where files go and are not in any Context field.

## For dependents

### ⛔ `AX-06` — the quiz gates, and how to share this record without editing this package

⭐ **Four properties make `gates/quiz/` work, and each is asserted rather than promised:**

1. ⭐ **Register at your own import.**

   ```python
   # src/studyforge/exercise/gates/quiz/__init__.py
   from studyforge.exercise.gates.families import Family, register

   QUIZ = register(Family("quiz", ("Q1", "Q2", "Q3", "Q4", "Q5")))
   ```

   ⛔ **`families.py`, `record.py`, `digests.py` and `runs.py` take NO edit** — every
   completeness rule, every refusal and the whole write order reach `Q1`–`Q5` from the moment
   they register. ⚠️ **The one line you add outside your sub-package is the import in
   `src/studyforge/exercise/gates/__init__.py`**, plus its table
   row — which R17 obliges you to add anyway, exactly as `AX-05` added `quiz` to
   `exercise/__init__.py`'s. ⛔ **Do NOT try to make that automatic**: there is no legal
   discovery mechanism in `src/` (first surprise above), and this row already spent a red gate
   proving it.
2. ⭐ **`record.py` requires your gates on the day you register.** A record naming `quiz`
   must carry all five, exactly once, in your declared order — and `record_document` writes
   them after `code`'s, because families are ordered by name. ⛔ A record with `Q1`–`Q4` is
   refused, with the expected order printed.
3. ⭐ **`Q1`–`Q3`'s prompt, pass and outcome go in `Verdict.recorded`** — ordered text pairs,
   token keys, free-form values, round-tripped byte for byte. ⛔ **Not `cases`/`report`**:
   those are refused on a quiz and are about a test run (`AX-00`'s handoff says so too).
   ⚠️ Nothing here reads `recorded` to decide anything, so the honesty of `Q1`–`Q3` is
   entirely in what your own code writes into it.
4. ⭐ **`Q5`'s digests go in `origins`**, one `Cited(role=f"question:{id}", path, section,
   digest)` per question — `require_role` permits a `:` and a case-id-shaped tail for exactly
   this. ⛔ Do **not** put a source passage in `inputs`: an input is re-digested against the
   file beside the record, and a page in a corpus's source is not that.
5. ⛔ **`generated`/`advisory` always**, and this package does not weaken that: nothing here
   reads or writes `provenance` or `trust`, so `unit.trust`'s rule and `quiz.require_quiz_shape`
   remain the only gate on it — ⚠️ your row still owes the assertion that no path through
   YOUR code reaches `authoritative`.
6. ⚠️ **The shape that bit this row, and it will bite yours:** `all(())` is `True`. If your
   family can produce an empty verdict list — a quiz whose questions were all dropped — it
   must refuse rather than clear. `record_of` already refuses a record naming no gate at all,
   but a `check` of yours that returned `()` would never reach it.

### ⛔ `AX-04` — the bundle, and `validate`'s gate-record arm

- ⭐ **`digests.drifted(root, record.inputs, where)` IS the arm.** It returns one sentence per
  input whose file no longer digests to what the record says, naming the file — which is your
  Acceptance's *"refused by `studyforge validate`, naming the file"* — and `()` when nothing
  has moved. ⛔ It answers sentences rather than a boolean for exactly that reason.
- ⛔ **The gate record is a FILE beside the bundle, not a key of the exercise record.**
  `record_document` / `record_of` are the two halves; the key order is `RECORD_KEYS` and
  round-tripping is byte-stable, so `AX-04` picks the filename and this row does not.
- ⛔ **`GateRecord.clears` is the *did it earn its place* question** and is derived, so a
  `generated` exercise whose record does not clear is refused without anything having to be
  recomputed. ⚠️ **A record that cleared is not a bundle that is intact**: `clears` reads the
  verdicts and `drifted` reads the files, and `validate` owes both.
- ⚠️ **`origins` are NOT re-digested by `validate`.** They name material in the corpus's
  source, which the framework may not have; `G5` resolved them against the ledger at
  authoring time and the record carries what it found.

### ⛔ `AX-08` — the authoring skill, and how a gate suite is actually run

- ⭐ **You supply the `Attempt`**: `def attempt(role: str, number: int) -> Run`. Put `role`'s
  solution in place, run the tests **in the pinned runner image**, and return
  `runs.folded(exercise, root, role, number, exit_code, where, started=started)` where
  `started` is `time.time()` read BEFORE the run. ⛔ `started` is not optional bookkeeping:
  it is what refuses a previous run's report (`AX-01`).
- ⛔ **You do not choose which runs to take.** `Evidence.taken` derives the list from the case
  map — reference twice, starter once, one plant per edge case — and `require_run` refuses a
  run answered for the wrong role or attempt. ⚠️ A caller that memoised by role would hand
  `G1` one reading twice and its flakiness arm would be unfalsifiable.
- ⭐ **A gate with nothing to read answers *did not hold*, never *held vacuously*** — so an
  exhausted attempt budget reports a refusal with a sentence, which is what spec §7 §11's
  coverage report needs.
- ⚠️ **`AX-03/1`**: the run's report is a run artifact. Do not commit it into the bundle.

### ⛔ `AX-07` — the ledger, as `G5` reads it

⭐ **`G5` asks the ledger exactly one question**: `ledger.get(origin.path)` → the digest that
source path has **now**, written `sha256:<64 hex>` (`digests.digest_of`). ⛔ It knows nothing
else about the ledger — not its file, not its entries' reasons, not its shape — so the ledger
may be anything that is a `Mapping[str, str]` at the call. ⚠️ **The key is the path as the
exercise's `origin` spells it**, and a path the ledger does not carry is refused as *material
the ledger does not account for*, which is `E14`'s first property firing.
