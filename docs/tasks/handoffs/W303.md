⛔ **So no guard was added to `prose` or `figure`**, which is what the row asked for and is

## Decisions

### ⭐ 1. The row closed as NOT REACHABLE, and a reachable sibling was fixed anyway

⚠️ **The two are not in tension and the distinction is the whole result.** The row named
`_RENDERERS[block["type"]]` in two modules; that population is unreachable and got nothing.
⛔ **The `RENDERERS` lookup in the dispatcher is the same dispatch, the same surface and the
same failure mode — refusing with an interpreter error instead of by name — and it IS
reachable**, so it got the fix. ⭐ Fixing it is not the "third place the guarantee is made" the
row warned against: it is the **first and only** place, one line from where the by-name refusal
already stood.

### ⛔ 2. `isinstance(block_type, str)`, not `isinstance(block_type, Hashable)`

⭐ **Every key of `RENDERERS` is a name from the archive's vocabulary**, so a non-`str` can
never match and the narrower test is the truer statement. ⚠️ Testing hashability would refuse
the unhashable case and let `{"type": 3}` fall through to a message reading *"nothing renders a
block of type 3"* — which invites the reader to look for a block type called `3`.

⚠️ **This moved the refusal SENTENCE for an absent, `None`, numeric or boolean type** from the
vocabulary message to the new one. ⛔ Both are `PageError` and both name the block; no test
anywhere asserted the old sentence for those inputs (checked before the edit), and the
vocabulary message is unchanged for its real subject — a type that IS a name and is unknown.

### ⛔ 3. Nothing was added to `archive` or `validate`

⭐ [`W297.md`](W297.md) met the wall — `validate` imports `archive`, so `parse` cannot ask
`validate.blocks` — and names all three places the archive's guarantee is made. ⛔ **This row
added a fourth to none of them.** The renderer refuses at its own trust boundary, which is
Ruling 50's *gate at every trust boundary*, not a re-ask.

## For dependents

- ⛔ **`render_one` now refuses a block whose `type` is not a `str`, by name, naming the
  block's position.** A consumer may rely on **no bare `TypeError` or `KeyError` escaping the
  block dispatcher** for any JSON a document can carry — every refusal from it is a `PageError`.
- ⚠️ **The refusal sentence for an absent, `None`, numeric or boolean type CHANGED.** It now
  reads `block <i> of this section declares no usable block type; a type is one of the archive's
  names [...], and this block carries <described>`. ⭐ The older *"nothing renders a block of
  type 'x'"* is unchanged and still belongs to its real subject: a type that IS a name and is
  not in the vocabulary. ⛔ **The two are deliberately distinct** — a block carrying an array
  where a name belongs must not be told the vocabulary lacks that array.
- ⛔ **Do NOT add a shape guard to `prose` or `figure`.** Their `_RENDERERS[block["type"]]` is
  **measured unreachable** with a bad key, and the property that keeps it so is asserted by name
  in the package's test. ⭐ A guard there would be a second place the same guarantee is made,
  which is what [`W303.md`](../rows/W303.md) forbade.
- ⚠️ **A third renderer module added to `MODULES` inherits the barrier test automatically**, but
  only if it exposes `_RENDERERS`; one that dispatches some other way is outside what that test
  can see, and the argument in [`W303/2`](#findings) applies to it too.
- ⛔ **Anyone taking a floor reading in a linked worktree must read [`W303/1`](#findings)
  first.** ⭐ A RED floor whose findings are **all** `personal-data-identifier` is almost
  certainly the shared git identity and not the diff in hand — check the rule breakdown before
  spending a session on it.
