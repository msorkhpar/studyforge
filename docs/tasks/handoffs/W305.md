## What landed

### ⭐ The git arm names its scopes, and reads no scope an office can write

⛔ **The defect, restated as a mechanism:** `identifiers()` resolved `user.name` and `user.email`
with a bare `git config --get`, and git's precedence puts the REPOSITORY's own config first. Every
office holding a linked worktree shares one `.git/config` while `extensions.worktreeConfig` is
unset, so the floor's verdict on an unchanged tree became a function of who was working.

- ⭐ **`IDENTITY_SCOPES = ("--global", "--system")`** — a module constant carrying the argument for
  why those two and not the other two, and the surface a test reads BY NAME.
- ⭐ **`_git_config` became `_git_identity`, which asks git SCOPE BY SCOPE** with the scope named on
  every command line. ⛔ There is no reading that can fall through to the checkout the process is
  standing in. Exit `1` from one scope means *this scope has nothing*, so the next is asked.
- ⛔ **The docstring that asserted this could not happen is corrected in place**, with the reason it
  was false recorded rather than deleted (Ruling 106's spirit): `docker/dev/check` mounts the git
  common directory into the image, so a repository-scoped identity was readable from inside the
  container off that mount.

⭐ **The argument for WHICH scopes, and it is whose datum each holds** — global and system are the
MACHINE's, which is where a real name and address actually sit, so `R7`'s git arm keeps its subject;
local and worktree are the REPOSITORY's, and a placeholder written there is indistinguishable from
a real name to a check whose `MIN_IDENTIFIER_CHARS` is `3`.

⚠️ **It is the mirror image of `tools/quality/board/dispatch.py`**, which reads `--local` and
refuses the global file for the same reason read the other way round: a branch description is the
repository's own dispatch, an identity is the machine's. ⭐ That module already ships the matching
test, `test_planted_a_description_in_the_GLOBAL_config_declares_NOTHING`.

## Decisions

⛔ **1. The remedy is a SCOPED READ, not a wider `GENERIC_IDENTIFIERS`.** The row forbids the
latter and is right to: adding `dev1` hard-codes this project's office names into a general-purpose
leak detector and fails the next office named anything else. ⭐ The scope is a property of *whose
datum it is*, so it holds for every office name that will ever exist.

⛔ **2. PER INVOCATION (`git -c`), not `git config --worktree`, and the argument is out loud.**
Three reasons, in order of weight:

- ⛔ **`--worktree` requires `extensions.worktreeConfig`, and enabling it is a WRITE to the shared
  `.git/config`** — repository-wide, under offices that are already measuring. It changes where
  every other office's config resolves from, mid-wave. That is Ruling 345's clause 3 and it is
  forbidden outright.
- ⚠️ **`--worktree` still leaves a persistent value on disk**, in `.git/worktrees/<name>/config.worktree`.
  It fixes provenance but outlives the office that set it, and it would still be read by any future
  check that asked git for a repository-scoped answer.
- ⭐ **`git -c` puts the value on ONE command and nowhere else.** It cannot rename another office's
  commits *by construction* rather than by timing, which is the only guarantee worth having here —
  the row already measured that today's clean provenance is timing.

⚠️ **The two halves are independent and both were needed:** `git -c` is the practice that protects
PROVENANCE; the scoped read is the code that protects the FLOOR. ⛔ **Neither substitutes for the
other, and only the second is a gate.**

⛔ **3. The narrowing is declared, because the brief demands it be declared rather than happen
quietly.** What this arm can no longer see: a machine whose git identity exists ONLY in a
repository-local config, and nowhere global or system, and which is also written into a tracked
file. ⭐ **Why that is sound:** (a) a repository-local identity in *this* repository is a value the
project's own working convention sets, and the convention is a placeholder (Ruling 345); (b) the
`account name`, `hostname` and `home directory` arms are untouched and still hold the user's actual
data; (c) the datum the narrowing gives up is, on this machine, `0` — the global file is where the
real identity is, and row 4 of the control shows that path still refuses it.

⭐ **4. No notice was added, and that is a surface decision.** The honest complement to this fix is
a floor notice saying whether the identity arm is armed at all (Ruling 78's family — an arm that
silently does nothing). ⛔ **`NOTICES` lives in `tools/quality/__init__.py`, outside this row's
declared surface and immediately beside the board notice `W306` is working in.** It is filed as
`W305/2` rather than taken.

⭐ **5. No convention document was edited, and none is needed** (the brief's Ruling 331 point).
[`review-rubric.md`](../../conventions/review-rubric.md#ruling-345-ruling-296-names-a-placeholder-this-names-the-mechanism-and-forbids-the-one-that-reddens-the-floor)
already carries the per-invocation clause with its measured ground, so restating it would mint a
second copy that can disagree with the first — which the standing mint freeze forbids. ⛔ **The
scoped-read contract is a property of the module and lives in the module**, where it cannot go stale
against the code it describes.
[`personal-data-shapes.md`](../../conventions/personal-data-shapes.md) is unaffected: its table
governs SHAPES, and no row of it moves.

## Surprises

⛔ **The row's sharpest claim is true, and it is sharper than it reads.** The docstring did not
merely *fail to mention* the failure mode — it asserted the mode was impossible, in the same file
that implemented it, and the assertion was checked by nothing.

⚠️ **The premise held under measurement.** This office went looking for a reason to refuse the row
and did not find one: the bare `--get` really does resolve the repository's config first, the
container really can read it off the mount, and the verdict really does move on an unchanged tree.

⛔ **SELF-CHARGE, and it belongs in the record rather than in a quiet correction.** This office's
FIRST command in the worktree was `git config --show-origin --get-all user.name` / `user.email`,
which PRINTED the machine's configured identity into this session's transcript. ⭐ Ruling 345's
clause 5 requires a NULL CHECK (`git config --local --get-regexp '^user\.' >/dev/null 2>&1`) for
exactly this reason, and names two offices that reached for the value in one wave; this is a third.
⚠️ **The datum reached no file, no commit message, no log and no outbound request, and every later
reading in this row was taken with a null check or against a fabricated value.** ⛔ **The clause is
sound and the shape it describes is easy to walk into — the instinct to *look first* is the
failure.**

⭐ **`GIT_CONFIG_GLOBAL` and `GIT_CONFIG_NOSYSTEM` are what make the mirror deterministic.** Without
them a test on this arm reads the host's real global file and would either be flaky or — far worse —
assert against the user's actual identity. ⚠️ Precedent already existed in
`tools/tests/quality/board/test_dispatch.py`; it is the idiom to copy.
