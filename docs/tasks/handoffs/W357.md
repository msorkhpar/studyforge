## What landed

⭐ **What the software does now that it did not:** a practice's `exercise` may
be `{"main_path": …, "run_command": […]}` and nothing else. The reader
(`exercise.of`, and so `archive.document.parse` and `build`) accepts it as an
`Exercise` whose `graded` is `False` and whose four grader fields are `None`.
`state_of` calls it `ungraded`, and it completes nothing. `to_document` writes it
back with those two keys only, and `unit/builder/parts.workspace_of` carries it
into the unit document's `workspace` unchanged, with no edit there.

Each of these is refused, with the missing keys named:

- a record with no `main_path` or no `run_command`, graded or not;
- any part of a grader short of the whole (`test_path`, `test_command` and
  `provenance`; `trust` alone may be omitted);
- `provenance` or `trust` beside no grader.

The ungraded record's path and command go through the same `safety` checks as a
graded one's. R5 (`unit.trust`) is asked about a grader and never about a record
with no grader.

## Decisions

### Clause 1 — one record, whose grader half is optional as a whole

⭐ **Decided: the `exercise` record may name a file with no test.** It then carries
`main_path` and `run_command` and nothing else. The grader half (`test_path`,
`test_command`, `provenance`, and `trust`, which is defaulted) is written in full or
left out in full. ⛔ **A separate declaration was considered and rejected.**

The argument, read at `b9aef83`:

1. ⭐ **Every consumer that resolves a file already reads one place.** The unit
   document's `workspace` is `exercise.to_document` of this record
   (`unit/builder/parts.py`, `workspace_of`). `SF-44`'s definition in
   [`E05`](../E05-serving-execution.md#sf-44-the-terminal-command) resolves a file
   "to its unit's exercise in the generated unit document (§7: `main_path`,
   `test_path`, `run_command`, `test_command`)". `SF-22`'s Run reads the same
   `workspace`. With one record, unit 3's file and run command reach that place with
   no new key in the archive document and no new key in the unit document.
   ⛔ A separate declaration needs a new top-level archive key
   (`archive/document.py`, which is at 393 lines, so it would also need a split), a
   new section key in the unit document (a unit-document contract change), and every
   file-resolving consumer would then search two keys for one question.
2. ⭐ **The state is still read off the structure, with no flag.** Before: graded is
   "the `exercise` key is present". After: graded is "the record names a grader"
   (its `test_path`). ⛔ The grader half is all or nothing, so a half-written grader
   is still refused. That was the old refusal's purpose ("an ungraded exercise
   wearing the graded key"), and it survives.
3. ⭐ **R5 stays on the one record that has a grader.** `provenance` and `trust` are
   facts about a grader (§7: *"`provenance` is a fact about where the grader came
   from"*). A record with no grader has neither, and writing either one on its own
   is refused.

⚠️ **The cost, stated.** *"The key's presence is the graded state"* stops being
true. Anything that tested key presence, or `workspace is not None`, to mean graded
would now be wrong. ⭐ **Measured at `b9aef83`:** in `src/`, the only thing that
decides graded is `exercise.states.state_of`, and this row changes it. `SF-22` is
in flight and reads `workspace`, so this is reported as a finding for it (`W357/1`).

### The version — `raw_api` stays `1`

⭐ **Not a `raw_api` change.** The rule for this document is in
`archive/document.py`: *"Bumped when a reader of the old shape would be wrong
rather than merely incomplete."* Every document that was valid before is still
valid and means the same thing, and an older build refuses the new shape (its
record is missing `test_path`) rather than misreading it. §7 already set the
precedent that `exercise` rides `raw_api` 1. Spec §6 applies the same test to
`list.start` and nested lists (*"Not a `raw_api` change, because every document
without … reads exactly as it did"*).

⛔ **Why this differs from `W350`.** `W350` raised `corpus_api` because an author
declares that version, and `KEY_VERSIONS` refuses a key under a version older than
the one that introduced it. `raw_api` is not declared by an author. `build` writes
it from one constant, so raising it would re-render every archive document
written so far (R10) in order to announce a relaxation.

⚠️ **The unit document's `api` is not raised either.** Its `workspace` value can
now lack the grader keys. At `b9aef83` nothing in `src/` reads that value, so no
reader of the old shape exists to be wrong. `SF-22` and `SF-44` are the first,
and both are written against this shape (`W357/1`, *For dependents*).

### Smaller decisions

- ⭐ **`run_command` is required in the ungraded shape.** A record exists so
  that a file can be resolved and run. A file with no way to run it is already
  covered by the prompt's own blocks, and writing no record is the shape for it.
- ⭐ **`state_of` answers `ungraded` for an `exercise` value that is not an
  object.** It runs on the completion path and does not validate, so the safe
  answer is the one that completes nothing. `parse` is where such a value is
  refused.
- ⭐ **`to_document` chooses its keys from `graded`, never from which values are
  `None`.** So an unvalidated `Exercise` carrying a stray `provenance` cannot
  write half a grader.
- ⭐ **The version-free wording in the spec cites §6's precedent** rather than
  restating the rule. The rule stays in `archive/document.py`.

## For dependents

- ⭐ **`SF-44` (the terminal command) — how a file resolves to a unit.** Read the
  generated unit document's section `workspace` (the `exercise` record,
  unchanged in shape by `unit/builder`). ⭐ **Every unit whose practice has a
  file names it there as `main_path`, graded or not.** A file that matches no
  unit's `main_path` is *"no unit's file"* and is refused by name.
  - **With a test:** the record carries `test_path` **and** `test_command`
    (always together). Run `test_command`. Its exit code is the verdict.
  - **With no test:** the record carries only `main_path` and `run_command`.
    Say there is no test and exit `0`. ⭐ **If you decide to run the program,
    the command is `run_command`, read from disk, never from the argument**
    (§8.3 rule 3). That choice is still yours to state before code, as `E05`
    says.
  - **The unit has no practice, or its practice names no file:** `workspace`
    is `null`. The file cannot belong to that unit.
  - ⛔ **Decide graded by the grader's presence, never by `workspace` being
    non-null.** In Python, that is `state_of` on the practice document or
    `Exercise.graded` on the record, from `studyforge.exercise`. ⛔ Only
    `completes_practice(GRADED, TEST, passed=True)` records a pass.
  - ⭐ **The fixture:** `tests/fixtures/runnable/` unit 3 is the file with no
    test (`practice/untested/hello.py`), units 1, 2 and 4 are graded, and unit
    5 names no file. `tests.studyforge.execute.runnable.unit_commands` already
    reads all four from their records.
- ⭐ **`SF-22`:** see `W357/1`.
- ⭐ **An adapter** that knows a prompt's file but has no grader for it now
  writes `{"main_path", "run_command"}` rather than no record. One that knows
  neither still writes no `exercise` key, and that stays the common case.
