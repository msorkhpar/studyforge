## Decisions

⭐ **Things the task did not specify, chosen here, each with the reason:**

1. ⛔ **A model judgement cannot be re-run, so what `validate` re-checks is its INPUTS.**
   Every `Judgement` carries `over`, the digest of the question exactly as it was judged,
   and `judged_gate` re-takes that digest from the question in hand. ⚠️ **Without it the
   Acceptance's *"recorded inputs no longer match"* has no referent**: re-author a
   question, keep the record, and a shipped verdict would read as held forever. ⭐ The
   digest is taken over the whole question document — stem, every option's text, key and
   sentence, and the passage — so any re-authoring moves it.
2. ⛔ **`Q3` is per WRONG OPTION, not per question**, for the reason `G3` is per edge
   case: *every wrong option is refuted by a named passage* is a claim about each
   distractor, and one judgement covering all of them would let the distractor nobody can
   rule out ride along with two obvious ones. ⚠️ A `Q3` judgement naming no option is
   refused.
3. ⭐ **Four modules, and the split is by what a reader can re-take.** `judged` holds the
   three that ship, `mechanical` the two that are re-run, and `family` names both sets
   (`JUDGED`, `MECHANICAL`) so the distinction R5 turns on is declared rather than
   inferred from which file a gate lives in.
4. ⛔ **`check_quiz` refuses rather than gating** an exercise that is not a quiz, one that
   asks nothing, or one claiming any pair but `generated`/`advisory`. ⚠️ **`Exercise` is
   frozen and NOT validated** — its own contract says a caller constructs one and then
   asks `from_document(to_document(...))` — so a gate suite handed a hand-built
   `Exercise` is the one path `quiz.shape` cannot close, and it is the path an authoring
   pass actually takes. ⭐ The pair is compared WHOLE and imported from `quiz.shape`
   rather than re-spelt, so a fourth provenance added to `unit.trust` is refused here on
   the day it is added (Ruling 35's shape).
5. ⭐ **`Q4` deliberately re-asks what `questions_of` already refuses**, and it is not
   duplication: `questions_of` reads a *document* and refuses the whole thing on the first
   bad question; `Q4` reads *built questions* before any document exists and answers for
   every question at once, because a gate record is what an author fixes a quiz from.
6. ⛔ **A question is named by its `stem` and an option by its `text`**, never by an id —
   the `code` family's rule and its reason: both are already shipped to the reader inside
   the practice document, so a record echoing them publishes nothing new, while an id is a
   value a sentence has no reason to carry.
7. ⭐ **`cited_for` is an authoring helper and it REFUSES a passage the ledger does not
   account for**, which is `E14`'s first property firing at authoring time. ⚠️ `Q5`
   refuses the same thing later, and that is not redundant: the ledger a bundle is
   validated against is not the one it was authored against.
8. ⛔ **The parent package takes ONE name, and the quiz names stay on the sub-package's
   own surface.** `code` is a *module* of `gates`, so its names belong on the parent's
   `__all__`; `quiz` is a *sub-package* with a contract of its own, which is exactly how
   `exercise.quiz` sits under `exercise`. ⚠️ Re-exporting twenty-three names would have
   made the parent's surface a second copy that can disagree with the first.
9. ⭐ **`Verdict.recorded` keys are `<field>:<question>` and `<field>:<question>:<option>`
   for `Q3`.** `digests.require_role` permits the `:` and the token after it, and a quiz
   id is a narrower token than a case id, so the key is bounded by construction.
10. ⛔ **Nothing in this sub-package reads `recorded` to decide anything.** `held` is the
    verdict, asserted by a test that lies in an `outcome` and reads the same answer.

### ⛔ `AX-08` — what an authoring pass owes the quiz gates

- ⭐ **One `Q1` and one `Q2` judgement per question; one `Q3` per WRONG option.** Anything
  less is refused, naming what is missing by the question's stem.
- ⛔ **Every judgement is taken over `question_digest(question)` and carries it in `over`.**
  Take the digest of the question you actually judged: a judgement whose `over` does not
  match the question as it stands is refused as *about a question this quiz no longer
  asks*, which is the whole reason a shipped verdict is checkable.
- ⛔ **Edit a question and you re-take its judgements.** There is no carry-forward, and
  that is deliberate.
- ⭐ **`prompt`, `taken_by` and `outcome` are required and must be text**, because a model
  judgement ships instead of being re-run and a reader of the record has nothing but what
  it was asked, who answered and what they said.
- ⚠️ **`held` is the verdict and nothing reads `outcome` to decide anything.** A pass that
  answered badly is recorded with `held=False`, not with an outcome sentence that says so.
- ⛔ **`cited_for(questions, ledger, where)` builds the `origins` half** and refuses a
  question whose passage the ledger does not account for.
