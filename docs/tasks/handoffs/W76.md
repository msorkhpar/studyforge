## Decisions

### ⛔ 1. Publish / move / third package — and a COUNT decided it, not a preference

⚠️ Ruling 101's producer half says *export the name from the owner's surface*.
⛔ **That is an argument for publishing, and it was the leading candidate.** Here
is why it lost.

| candidate | why not / why |
|---|---|
| ⛔ **publish all five on `page.__all__`** | ⚠️ Ruling 101 answers *"reach past, or export?"* — it does not answer *"whose name is it?"*. ⛔ **`render.page` is THE UNIT PAGE**; `render.container` is a peer and `render/index/` (`SF-14`) is a third peer. Three peers reaching into one of themselves for the escaping gate makes the unit page the base of a layer it is not the base of |
| ⛔ move to `render/container/` | impossible — `container` imports `page`; the reverse is a cycle |
| ⚠️ leave in `page`, private, and let `SF-14` reach too | ⛔ that is `SF-27/1` a third time, which is the whole reason this row sits ahead of `SF-14` |
| ⭐ **a sibling package `render/markup/`** | ⭐ **the repository already answers this question once** |

⭐ **The load-bearing measurement, taken at `6177738`:** `render.pageassets` is
already the sibling package that `page` and `container` both take shared
primitives from, **through its `__all__`, from opposite sides**:

```text
src/studyforge/render/page/assets.py:72        from studyforge.render.pageassets import SCRIPT_NAME, STYLESHEET_NAME
src/studyforge/render/container/placement.py:58 from studyforge.render.pageassets import SCRIPT_NAME, STYLESHEET_NAME
src/studyforge/render/page/blocks/prose.py:42   from studyforge.render.pageassets import SURFACE_HOOKS, class_for
```

⛔ **So the escaping gate was the one shared render primitive that was NOT shaped
that way** — and `SF-14`'s own definition makes the third peer explicit:
*"It shares the unit page's palette and type stack by importing them rather than
restating them"* (`E03-rendering.md:230`, **received**). ⭐ Palette from a
sibling, escaping from a peer's private module, is the inconsistency this row
removes.

⭐ **The second measurement — `text.py` is not a page concern by DEPENDENCY.**
Measured at `6177738`: its only import is `re`. It cannot cycle, it names no
page type, and it was in `page/` because that is where the first renderer that
needed it happened to be:

```text

src/studyforge/render/page/navigation.py imports: address, page.errors,
                                                  markup                (3)
```

⭐ **The third — consumer counts, at `6177738`:** the four primitives had **5**
in-package importers, **2** cross-package `src/` importers and **2**
cross-package test importers, spanning three packages (`page`, `container`,
`contents`); `between_units` had **1** cross-package importer.

### ⭐ 2. `between_units` is PUBLISHED, not moved, and one asymmetry decided it

⛔ **`Link` and `Links` were already on `page.__all__` and `between_units` was
not** — so the surface published the *argument* and hid the function it is an
argument to. ⭐ There is nothing else a consumer can do with a `Links`. Moving it
instead was refused on two counts: it renders **this page's** bar (it is not a
primitive), and **`SF-15` owns `render/page/navigation.py`** and `SF-27/3`'s
`aria-label` remedy is that task's (**received**, `SF-27.md` and
`E03-rendering.md:267`) — a move would have collided with an open row.

### ⛔ 3. W59's rule was applied, and it points the same way

⭐ `W59` chose a destination by *"the module that already states the rule a
function implements"*. ⛔ **`text.py` states its own rules** — R13's escaping
order, `W57`'s two permitted href forms, Ruling 56's unasserted neighbour — so
the module **is** the home and the only question was which package it sits in.
⭐ **Moving the module verbatim keeps rule and implementation together**, which
is `W59`'s criterion met; publishing would have put the framework's escaping
gate on the unit page's contract permanently, which is the failure mode Ruling
135 names.

### 4. Scope, stated rather than assumed

⚠️ **`Owns` says `src/studyforge/render/page/__init__.py` — "the contract, not
the callers".** ⛔ **A named substitute cannot be delivered inside one file**, and
the Acceptance's own second branch (*"or a named substitute is"*) and `SF-27/1`'s
own text (*"promoted onto `page.__all__`, or moved to a sibling `render/text/`"*,
**received**) both contemplate a move. ⭐ **Ruling 100's default applies: the
split stays inside the path the cell names one level up — every `src/` path in

discovered. ⚠️ The one `src/` file outside `render/` in the diff is **none**; the
one test file outside the two mirrors is `tests/studyforge/contents/test_acceptance.py`,
which the new sweep makes fail (`W76/5`) and which is fixed by re-spelling two
imports onto names **already** on `page.__all__`.

### 5. The package is `render/markup/`, not `render/text/`

⛔ **`render.pageassets.text` is already a published function.** A sibling
package called `text` would put `from studyforge.render import text` and
`from studyforge.render.pageassets import text` in the same file's namespace.
⭐ `markup` is the module's own word for what it produces — *"Turns the archive's
text into markup"*.

### 6. One module in a package, deliberately

⚠️ `render/markup/` holds `__init__.py` (contract, 83 lines) and `text.py`

shape, exactly.
