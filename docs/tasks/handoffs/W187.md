## Decisions

### ⛔ The module is `narrate/playable.py`, and it is neither neighbour's

⭐ **Named before it was written, with the reason.** It is **not**
`narrate/synth/`'s: that package is the write side — *which clips must be MADE
now* — and its seam runs `incremental → record` and stops. It is **not**
`render/page/`'s: that package's own contract says *"`narrate.speakable` is
where a speech unit is minted, and this package must not reach for it"*, so a
join living there would be the second numbering scheme the design exists to
prevent. ⭐ So it is a **third module, a sibling of both**, inside `narrate/`
because **both halves of the join are `narrate`'s records** — and it adds no
dependency edge that did not already exist. ⛔ It imports nothing from `render`.

⭐ **It is `speakable`'s mirror and is named for it**: `speakable_of(document)`
says what can be *said*; `playable_of(units, state)` says what can be *played*.

### ⛔ The corroboration, which is what makes the id join checkable

The record is keyed by id and the recorded filename carries the id **again**.
`parse_clip_name` reads the stem back to `(speech id, digest)`, the id must equal
the key the entry is filed under, and the digest is compared to what the unit
says now. ⛔ An entry that disagrees with its own key goes **silent** rather than
playing another unit's words — a valid filename over a present file is exactly
the failure shape this row names.

### ⭐ Four named states, and a fifth that still plays

`NOT_RECORDED`, `NOT_PLACED`, `MISFILED`, `NOT_ON_DISK` are sentences on
`Playable.silent` (R6) — ⛔ **never a `KeyError` and never silence.**
`Playable.reasons()` is the one thing to print at the end of a long run.
⚠️ `WORDS_MOVED` is on `Playable.stale` and **is** in `filenames`: the file is
real and made from older words, and withholding it would give the reader silence
with no reason. ⭐ Same answer, same argument, as `SF-17`'s `Synthesis.unsettled`.

### ⭐ The disk is consulted only when a directory is passed

`audio=` is optional; with it absent the pure path stays pure (R10) and a
recorded clip is taken at its word. ⛔ The directory is the placement policy's
(`synth.incremental.audio_dir`) and is never composed here (R4).

## Surprises

### ⛔ Two measured facts make the positional bug ORDINARY, not exotic — and either alone is enough

1. ⛔ **The shipped writer emits `sorted(clips)`, which is lexicographic over ids
   and NOT reading order.** `…b10` sorts before `…b2`, so a record's own sequence
   diverges from the page's the moment a section has ten speech units.
2. ⛔ **The record is never pruned** — `synthesise` merges into what it read — so
   a unit whose blocks moved leaves its old entries behind and the record carries
   MORE clips than the document has units, interleaved.

⭐ **Both are asserted as tests rather than described**, and the fixture is
eleven blocks rather than three **for the first reason**: a three-block fixture
lets a positional implementation pass every test in the file.

### ⚠️ The tests were green on their first run, which is not evidence

⛔ A green first run on new code is a reason to plant, not to stop. Eight plants,
`PYTHONDONTWRITEBYTECODE=1` and `rm -rf __pycache__` per Ruling 70 and `SF-17/1`:

| plant | killed by |

| P1 the join is positional (zip the record's entries in order) | **11 tests**, including both shift cases and the refutation control |
| P2 the filename is trusted, the id not corroborated | the three `…disagrees_with_its_key…` params |
| P3 a missing clip is silence rather than a named state | six |
| P4 the disk is never consulted | `…not_on_disk_is_named_when_the_directory_is_given` |
| P5 a clip made from other words is never reported | `…still_plays_and_is_reported` |

## Findings

### ⚠️ `W187/1` — `[structural]` — the record grows without bound and nothing prunes it

`synthesise` merges into what it read, so every id a corpus ever minted stays in
`.studyforge/narration.json` forever, and its clip stays on disk. ⛔ For this row
that is a **help** — it is why the join must be by id — but for a corpus that is
edited over a year it is dead weight in a file R8 says is committed. ⭐ Reported
rather than fixed: pruning needs a rule about which clips a build may delete, and
that is `SF-32`'s or the register's, not mine.

### ⚠️ `W187/2` — `[local]` — `SF-18/4` is closed on the library side and NOT on the build side

⭐ The `position -> filename` map now exists and `Narration.of` takes it
unchanged — a test asserts the whole seam, record → join → the href on the
element. ⛔ **What still does not exist is the caller**: nothing in `src/` reads
`.studyforge/narration.json` during a build and hands the result to the renderer.
⚠️ That is one wiring in whatever composes a page, and it is not this row's
surface. Naming it so the live run's operator meets it here rather than in a run.

### ⚠️ `W187/3` — `[local]` — the page↔DISK direction is still not asserted anywhere, and I did not stretch a test over it

`SF-17/9` and `SF-18`'s *For dependents* both say so. ⭐ This row adds the
**record↔page** leg and, with `audio=`, a **record↔disk** leg over files a test
places. ⛔ It does not add the leg that needs a really-narrated fixture corpus,
because no clip file exists in this repository's fixtures and committing binary
audio to make a check pass would be a fixture built to satisfy the check.

## For dependents

- ⭐ **`playable_of(units, state)` is the only way in**, and the caller wires it:
  `playable_of(speakable_of(document).units, read_state(state_file(root)))`, then
  `Narration.of(playing.filenames, placement)`.
- ⛔ **Never join on the position, and never zip against the record's entries.**
  The record's order is lexicographic by id and its population is not the
  document's — both are asserted, and a positional implementation fails.
- ⭐ **Print `Playable.reasons()` at the end of a long run**, and read
  `Playable.silent` for the four states. ⛔ Never `len(filenames)`.
- ⚠️ **Pass `audio=` only when you want the disk consulted** — ask
  `synth.incremental.audio_dir` for it and compose nothing (R4).
