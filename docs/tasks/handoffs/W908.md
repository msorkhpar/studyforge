## What landed

- `execute/quiet.py`: a `PYTEST` toolchain under runtime `python`, flagged `only_by_command`. `select` picks it only when the run's command names pytest (`pytest`, `py.test`, `python -m pytest`) and the corpus declares a tool with rules beside `python`. A corpus declaring `python` alone, or beside tools with no rules, is unfiltered as before. Declaring `python` beside Gradle or Maven selects what it selected before for every command that is not pytest.
- `exercise/spelling.py` (split from `report.py`): `spells` also reads a pytest node id (`tests/test_x.py::Class::name`) from the dotted `classname`, for a report with no `file` attribute. `asserted` tells a failure that an assertion caused from an error. Parametrised ids with one space (`test_collapses[inner spaces]`) were already accepted by `CASE_ID`; the character set is not widened.
- `report.py`: `Breakdown.unasserted` (default empty).
- `gates/runs.py`, `gates/code.py`, `skills/exercises/drafts.py`, `gating.py`: optional `CodeDraft.assertions_only` (default `False`). When set, `G2` and `G3` refuse a starter or a plant whose tests failed with an error that is not an assertion. No record key is added; `gates.json` is unchanged in shape.
- `gates/code.py`: the refusals of `G1` and `G4` for a run that left no report now name the declared report path.
- `bundle/emit.py`: an option naming a path (`--junitxml=<workspace>/target/report.xml`) is checked as that path, inside the workspace; it was refused whatever it named.
- Docs: `docs/authoring/exercises.md` (Python practice paragraph, `assertions_only` row).
- Fixture and tests: `tests/studyforge/skills/exercises/pytest_practice.py` (starter, reference, three plants, tests, command), `test_pytest_practice.py` (G1 to G5 over six real pytest runs, assertion-only failures read from each output, wrong report path, raising starter), `test_pytest_practice_image.py` (the same draft with every run `docker run --network none`, skipped unless told an image), `exercise/test_spelling.py`, `execute/test_quiet_pytest.py` with `transcripts_pytest.py` (real pytest output).

## Decisions

1. The variant is selected by the framework's staging (the solution put at the main file), not by an environment variable: a command is argv with no environment.
2. The row asked that a starter raising `NotImplementedError` be flagged. Existing authoring corpora use such starters, so the check is opt-in (`assertions_only`), and the worked corpus is unchanged.
3. The filter is keyed to `python` with `only_by_command` because `RUNTIMES` is closed and has no `pytest`.

## Findings

- The runner images carry no Python. The container proof ran in an untagged `python` image (3.14.7) with the host's pytest 9.0.2 put on `PYTHONPATH` read-only, `--network none`. The `claude-sdks` profile (W905) is the real runner.
- The pytest transcripts are measured on the host, not in a runner image.
