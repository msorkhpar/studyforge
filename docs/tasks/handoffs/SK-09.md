## Decisions

1. ⭐ **A separate package and a separate [`SKILL.md`](../../../src/studyforge/skills/execution/SKILL.md), not a subpackage of
   `skills.onboarding`.** The reading floor is what every corpus gets; a
   container is what a corpus with runnable code earns (§11.0), and §7's C5 says
   a corpus with no runnable unit is **complete**. ⛔ Folding this in would put a
   Docker dependency in front of somebody converting a book.
2. ⛔ **`manifest.runtimes` is the whole runnability test, and the empty answer
   is taken BEFORE the contract is read.** Not an optimisation: a book's corpus
   must not fail because a component it never needed is unpinned, unreadable or
   at a promise nobody recorded. A test asserts exactly that, by handing the
   generator text that is not a contract at all.
3. ⭐ **The prime SELECTS the corpus's own build files, source and test rather
   than authoring any.** §8.1 says the prime *copies the consuming repository's
   wrapper and build files*, and the alternative was this package carrying a
   JUnit version and a build-file template. ⛔ A version typed here disagrees
   with the corpus the day the corpus moves, and §8.1's own version guard would
   then fail a build over a disagreement this skill created. ⚠️ **Selecting
   cannot be wrong about the corpus**; the specimen is the smallest non-empty
   real file, ties broken by path so the answer is one answer.
4. ⭐ **Which runtimes owe a build file is the CONTRACT's answer**, arriving as
   `seeded` from its own prime map. A corpus of plain Python scripts is never
   asked for a build file it has no reason to own, and a corpus that declares a
   seeded tool and cannot build is refused.
5. ⭐ **The prime is selected for what the image will CARRY, not for everything
   the corpus declared.** An image without a runtime cannot compile a specimen
   in it; the withheld ones are named in the reader's document instead.
6. ⛔ **The narration component's block is CHECKED and not rendered.** See
   `SK-09/2` — its contract carries no per-project keys, so rendering it would
   mean inventing a host port, a volume name and a uid value here. ⭐ §8.1 names
   that service as publishing on all interfaces *today* and says it is to be
   fixed rather than copied, so its rulings are asserted even though its service
   is not emitted, and the reader's document points at its own compose files.
7. ⭐ **The YAML is emitted, not serialised.** Framework source takes no
   third-party package, and what is emitted is a document this framework
   composed rather than one it parsed. ⛔ `emit.py` must not grow into a YAML
   implementation: a value it cannot write is a value a generated file should
   not carry.
8. ⭐ **This skill declares its own `NOT_MATERIAL` globs rather than relying on
   `skills.onboarding`'s.** They overlap — that skill declares the whole
   bookkeeping directory — and the overlap is deliberate: each producer's globs
   carry its **own** reason, and `promote` deduplicates on the glob, so two
   different globs both stand. A path added here without a glob is a RED test in
   this branch rather than an `unclassified` finding in somebody's repository.

## Findings

### SK-09/1 `[structural]` — the contract leaves a slot for the declared set and declares nothing about how a set is written into it

`editor.image.built_by` is `[…, "--runtimes", "<the declared set>"]`: the
placeholder occupies **one** argv slot, so a set is written into one argument —
and no key in that contract says with what. ⛔ The tag's own `parts.set` says
*"sorted and joined with a hyphen"*, which is a different string for a different
purpose and is not an answer.

⭐ **`toolchain.SET_SEPARATOR` is PROVISIONAL and it is held open by a test:**
`test_the_component_still_declares_no_separator_for_its_own_build_flag` goes RED
the day `editor.runtimes.argument_separator` (or the runner's) appears, which is
when the constant is deleted and the value is read.

⛔ **It was NOT settled by reading that component's argument parser**, although
that would have answered it: `TC-05`'s own handoff says to read `consuming.json`
and nothing else, and a value taken from its code is a fork with a correct
answer in it (R18).

- *measured:* the contract at its pin carries no such key under either block.
- *received:* `TC-05`'s *For dependents*, which names the one file to read.

### SK-09/2 `[structural]` — the narration contract carries no per-project key, so a consumer cannot render its service

`narrate-service`'s `consuming.json` `service` block declares `ports[]` with a
`host_bind` and **no `host`**, `mounts[]` with a `kind` and **no `volume`**,
`runs_as` with a uid and **no `compose_key`/`compose_value`**, and
`environment[]` with defaults and **no `compose_value`**. ⛔ The editor's block
declares every one of those, and that is the difference between a contract a
consumer can render and one it can only read.

⭐ **So `E11`'s *"rendered from … the narration service's equivalent"* is met as
far as that contract permits and no further**: the block is read, its §8.1
rulings are asserted, and the reader's document points at
`profiles.<default>.compose_files` — the component's own way to bring itself up.
⛔ **Rendering it would have meant inventing a host port, a volume name and a
uid value in this package, which is the value-writing R19 forbids.**

- *measured:* both contracts at their pins, key by key.
- *received:* `E11`'s `SK-09` definition.

### SK-09/3 `[local]` — a mount that is earned by a runtime says so in English, not in a key

The editor's `/…/.gradle` and `/…/.m2` mounts are `required: false` and carry
*"omit it when gradle is not declared"* inside their `purpose` prose. ⛔ A
renderer cannot read a sentence.

⭐ **Derived from data instead**, and the join is the contract's own: its prime
block maps a runtime to the volume that runtime's cache is seeded into, and the
volume names match the mounts' exactly. ⚠️ **It is in a different block from the
mounts it decides**, so a renderer handed only the editor block earns nothing —
which a test asserts. ⭐ The remedy is one key per optional mount, beside
`required`.

- *measured:* the contract at its pin; the two volume names agree across blocks.

### SK-09/4 `[local]` — the published host port is per-project and has no key for a consumer to set it with

`editor.ports[0].per_project` is `true`, and that entry declares no `env_var`
and no `compose_value` — unlike `image` and `runs_as`, which both declare one.
⛔ **So the rendered file carries the contract's declared host port literally,
and two corpora on one host collide.** ⚠️ It was not papered over with an
invented variable name: a compose interpolation this package chose is a name no
component knows. ⭐ The remedy is the key those two other blocks already have.

- *measured:* the contract at its pin, and the rendered file.

### SK-09/5 `[structural]` — nothing in `corpus.json` names the directory an editor binds

§8.1 ruling 2 mounts **only the sources**, and the manifest has no key saying
which directory that is. ⭐ Derived from `content.include`'s own common root,
which is the corpus's own statement about where its material lives.

⛔ **A corpus whose material is at the repository root, or whose includes share
no directory, is REFUSED** — there is then no directory to bind that is not the
repository. ⚠️ That is a real limit on which corpora can be given an editor, it
is reported rather than defaulted away, and the remedy is a manifest key.

- *measured:* `MANIFEST_KEYS` carries no such field at this ref.

### SK-09/6 `[structural]` — R7's gate reads a component's declared container home as a leak

⛔ **Both instruments do**: `archive.scrub.assert_clean` raises on the pinned
contract's own workspace path, and this repository's sweep refuses the same
shape in a tracked file. ⚠️ **Neither can tell a container's account from the
host user's**, and `scrub.py`'s own contract already states that the residual
exemption class is *"manifest data read by the gate"* and that v1 builds none of
it.

⭐ **Closed inside this package only**, by masking the home of an account the
contract declares as its own — narrow, on a copy, and refusing every other home
shape. ⛔ **The general case is not closed**: any framework module reading any
component's contract meets this, and any test fixture carrying the shape does
too. ⚠️ **This row's fixtures compose the home at run time** rather than write
it, which is a workaround nobody should generalise without a ruling.

- *measured:* both instruments, at this ref, on the real contract's own value.
