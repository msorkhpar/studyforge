## ⛔ A DECISION I DID NOT TAKE, AND IT IS THE ONE THIS ROW FORCED

⛔ **Where the contents documents go.** `render.index.from_contents` takes
`Contents` and `LocalStatus` as *records*, so the index is built without either

served site presumably wants `toc.json` and `status.json`, and:

- **no plan golden carries a `create` line for either**, so writing them would
  create two paths `studyforge plan` never declared and fail the very clause

⭐ **So they are built and not written, and a test asserts both halves of that
premise** so it cannot close silently. ⛔ **Deciding it needs a placement field,
which is not mine.** The other five decisions from `W195` stand untaken.

## Decisions

⭐ **The declarations are read ONCE and passed to three passes.** Three passes
each re-parsing `corpus.json` and every container map would be three chances to
disagree about what a corpus declares, and the disagreement would surface as a
page linking a unit another page does not list.

⭐ **R3 goes through ONE call, `writing.place`.** A pass that opened a file
itself would be a second R3 policy, and the one that skipped the check would be
the one nobody noticed.

⭐ **A build refuses an output root it would have to create.** Not a style
choice: a relative root resolves against the caller's working directory, and
`SF-28/2` is what that costs when something calls a writer without meaning to.

⭐ **The index's `present` set is what THIS build wrote, never a scan of the
output directory.** A scan reads the reader's disk and says something different
the day a reader deletes a page.

⛔ **Every path is asked of `corpus.placement` and `skills.adapter.Layout`, and
one question has one spelling** — `unit_location` exists because both the page
writer and the container page's links ask where a unit's page goes, and two
call sites composing the arguments differently would put an anchor beside the
file the build wrote with nothing raised.
