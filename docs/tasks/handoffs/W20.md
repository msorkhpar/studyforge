## The check, and why it is a module rather than a seventh alternative

```text
$ git grep -nEi 'codesignal|java-senior|senior-java|iso-?8583|jpos|sparql' \
      -- 'src/**/*.py' | wc -l          # rubric §7c, on 5ebf83e

```

⭐ **The twelve it missed were all one shape: a corpus named in English rather
than by its repository slug** — `the Java corpus`, `the Java repo`, `the ISO
corpus`, `src/ISO.md`. ⛔ R1's own sentence in §7c is *"a source's name
appearing in framework source is a fail **even in a comment**"*, and English is
where a comment names things.

⚠️ **So every registry entry is anchored on a word only a corpus's name takes.**
Bare `ISO` is an **ISO 8601 date thirteen times** in this tree and a corpus
twice; a pattern that could not tell them apart would be switched off within a
day, and then R1 would be enforced by nobody. The controls are asserted:
`an ISO date`, `a Java package segment`, `the extraction source` and `the four
designed shapes` must all pass.

## The migration is citations, not deletions

⭐ **Every one of the nineteen facts already lived in a document** — spec §4's
table, `E02-content-pipeline.md`, `E06-exercise-contract.md`. So no measurement
was lost and nothing was moved: each module now uses the role word this tree
already had (`the extraction source`, 26 uses, was the precedent) and the name
stays where a document may hold it.

```text
address/__init__.py         two shapes' `levels`   → "spec §4's table is where they are named"
address/identifier.py       a module numbering     → "one of the four designed shapes"
archive/scrub.py            96 card-shaped strings → "one designed shape's material"

corpus/placement/sibling.py a reader's habits      → "a consuming corpus's reader"
exercise/states.py          the three-state table  → the table, pointing at E06
```

⛔ **Modules are never exempted, and documents are never scanned.** The check
reads `src/**/*.py` and nothing else, so the exemption is structural: a
document *may* name every corpus and a module has *nowhere* to be excused to.
⭐ That is SK-01's `SKILL.md` precedent — the far end of a pointer is exempt
for a reason rather than by name.

## Ruling 47 — one shape vocabulary, two policies

Measured, both gates, fourteen shapes. Two rows were drift and are closed:

```text
shape                        gate      scrub     quality
local hostname               pass→refuse  keep→rewrite  report      ⛔ was drift
tilde-username path          refuse    rewrite   ignore→report      ⛔ was drift
home under a longer prefix   pass      rewrite   ignore             ⭐ declared
UNC share home path          pass      rewrite   ignore             ⭐ declared
tilde-rooted path            pass      rewrite   ignore             ⭐ declared
email address                refuse    rewrite   ignore             ⭐ declared
```

⚠️ **`~/` was *not* drift and the ruling's list was one entry too long.**
`tools/quality/personal_data/shapes.py` has documented since FND-01 that `$HOME`
and `~/` are deliberately not flagged, with the reason — they are references,
not values, and `CLAUDE.md` names the environment variable as the *sanctioned*
way to carry a real one. ⛔ A check that flagged them would tell people not to
use the safe form. That is a declared divergence, and it is now a row.

⭐ **The mechanism is the `why` column, not the rows.** A row whose three
columns disagree must carry a reason of at least 80 characters; a row without
one must read `refuse`/`rewrite`/`report` or `pass`/`keep`/`ignore`. Both sides
run the real implementation against the table, so a row that stops being true
is a build failure and a row that becomes true by accident is one too.

⚠️ **The examples are stored as fragments and joined at read time.** A real
shape written whole into that document would be a finding against it, by the
sweep its own last column describes — and a test asserts every row keeps at
least two fragments so nobody tidies them into one string.

## Decisions

1. ⭐ **Nineteen, not seven.** Ruling 43's principle is that a commit adding a
   check owns its migration; the *number* was argued over the reviewer's grep.
   Building the check to find seven would have been fitting the instrument to
   the backlog. See Surprises for the Ruling 52 reading.
2. ⛔ **No allow-list, and the exemption is the scan root.** The moment a module
   can be excused, the exemption is where source knowledge accumulates.
   Asserted behaviourally: ten modules at ten depths, every one reported.
3. ⭐ **`local hostname` is a fourth environmental shape, not a fifth idea.** It
   passes the gate's own ruled criterion — *"did this build put it there?"* —
   exactly: `<host>.local` **is** the name of the machine that ran. The
   three-shapes test carried the comment *"a fourth entry needs that argument
   made for it"*, and Ruling 47 made it from the other side.
4. ⚠️ **The two gates share evidence, not code.** Ruling 31 forbids the import,
   so the table is a JSON block in a convention document and each side asserts
   only its own column. The reader is in `tests/support.py`, which both trees
   already import.
5. ⭐ **The rubric keeps its grep.** It is the hand-runnable form and a reviewer
   with a shell should still have one; it now says what it under-counts.

## Surprises

- ⛔ **Ruling 52's instance, and I am reporting it rather than stretching the
  ruling.** Ruling 43 was argued over "the 7 the rubric's grep found". The
  ruling reads as a fact about the tree and was a fact about an *instrument* —
  which is exactly the tell Ruling 52 describes: *nothing about it looks wrong;
  it looks finished*. ⚠️ **The scope Ruling 43 was argued over is "whatever the
  check finds", and it should say so** — otherwise the next author lands a
  weaker check to match a number.
- ⚠️ **One of Ruling 47's three named omissions was not an omission.** `~/` has
  been declared, with its reason, in `tools/quality` since FND-01. Two of the
  three were drift; the third was already a decision nobody had looked up.
- ⭐ **My own lexical guard failed the way lexical guards fail.** A test that
  grepped the new module for `EXEMPT`/`ALLOW`/`IGNORE` went red on
  `re.IGNORECASE`. It was measuring spelling, not the property; replaced with
  the behavioural version, and the comment says so.
- ⚠️ **Tightening `tools/quality` made five of my own R44 test tables illegal**
  — a literal tilde-username — and the floor caught them. Migrated in the same
  commit, which is the rule working on its author again.

## Findings

### 1. `[structural]` Ruling 43 states a number that was a fact about an instrument

⛔ Covered under Surprises and repeated here because it needs a ruling rather
than a reader. **"The check and its 7 pre-existing migrations"** was measured
with the rubric's grep, and any check built to R1's actual sentence finds more.
⚠️ **This will happen again to anybody automating a rubric clause**, because
every one of those clauses is a grep and every grep under-counts: §1a's
personal-data sweep, §7b's imports and §8's sections are all instruments whose
findings a ruling may end up quoting as a quantity. ⭐ The fix is one sentence
in Ruling 43 — *the migration is whatever the check finds, not what the grep
found* — and it costs nothing to add before the next clause is automated.

### 2. `[local]` `archive/scrub.py` has sixteen lines of headroom

At 384 of 400 after this commit. ⭐ **Cost named:** the next author to add a
shape must split the module first, and the seam is already visible — the
pattern set and the walker are two subjects. Filing it so that split is a
decision rather than something discovered at the ceiling by somebody who only
wanted to add a regex.

### 3. `[local]` `KNOWN_SOURCES` is an open set and says so

R1's permitted set is *"every word that is not a corpus's name"*, which nobody
can write down, so this registry is forced to be a forbidden list — the same
species as `archive.scrub`, and it inherits the same answer: it is not the only
layer. R1's *import* form is enumerated positively by §7b (`stdlib or
studyforge`), which is closed and cannot be evaded. ⭐ **Cost named:** a fifth
corpus joining the workspace needs one registry entry, and until it has one the
prose form of its name is unguarded. That is stated in the module rather than
left to be found.

## For dependents

- ⛔ **A module under `src/` may not name a corpus.** Use the role vocabulary
  this tree already has — `the extraction source`, `the four designed shapes`,
  `one designed shape`, `the depth-1 fixture`, `the first consuming corpus` —
  and cite the document that holds the measurement. ⚠️ The floor will fail you
  in the same run, not at review.
- ⭐ **`SF-10` is why this landed now.** A ~70k builder adds sites, and a check
  landing after it would inherit a backlog it did not cause. The check is in
  `CHECKS` before that work starts, so SF-10's modules meet it while they are
  being written.
- ⚠️ **Adding a personal-data shape to either gate means adding a row to
  `docs/conventions/personal-data-shapes.md`.** Both sides' tests read it, so a
  shape added to one gate and not the other fails immediately with the shape's
  name — which is the whole point of Ruling 47.
- ⭐ **A new corpus in the workspace is one entry in `KNOWN_SOURCES`**, with the
  anchors that keep a legitimate word out. Add the positive and its control to
  `tools/tests/quality/test_source_names.py` in the same commit.
