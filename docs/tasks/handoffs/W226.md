## What landed

- ⛔ **The record's format changed, and it is said first.** `narration_api` is `2`. Each entry adds `where`, the directory its clip was written into, relative to the corpus root. An entry adds `superseded` only when it has superseded clips: every clip an earlier wording or directory wrote that no prune has removed yet. ⭐ **A version-1 record still reads**: its entries have `where: null` until a run finds their clip in their unit's directory.
- New [`location.py`](../../../src/studyforge/narrate/synth/location.py): `root_of`, `where_of`, `checked_where`, `located` and `Superseded`. A directory that is absolute or climbs out of the root is refused, both when it is read and when it would be written.
- [`record.py`](../../../src/studyforge/narrate/synth/record.py): `Clip.where`, `Clip.superseded`, and `forget_superseded` (the record's one writer, as with `forget`).
- [`incremental.py`](../../../src/studyforge/narrate/synth/incremental.py): `synthesise` records `where` on every clip.
  - A clip replaced by a new wording or directory becomes `superseded`, and nothing is deleted.
  - An audio directory outside the root is refused before any request.
  - A version-1 entry gets its directory when its clip is found. An entry found nowhere keeps what it had.
- [`cli/narrate/prune.py`](../../../src/studyforge/cli/narrate/prune.py): clips are located from the record. The walk is a fallback only for an entry with no `where`, and an undeclared unit's version-1 entry is still `UNDECLARED`. Superseded clips are deleted and cleared. An entry is forgotten only once every clip it names is gone.
- Disclosure: `narrate` prints `superseded clips  N` beside `dead record  N` on every run ([`disclosure.py`](../../../src/studyforge/cli/narrate/disclosure.py), `stage.py`, `report.py`).

## Decisions

- **Read version 1, never refuse it.** A refusal would make every narrated corpus re-synthesise or hand-migrate, and the record is the one thing that cannot be rebuilt cheaply. A version-1 entry is merely unlocated. The first run that finds its clip writes version 2, which moves the record's bytes once.
- **The record names the superseded clip rather than the prune finding it on disk.** Answer 3 puts deletion on the document. `synthesise` writes `superseded` at the moment a newer clip replaces an old one, so no directory is ever scanned.
- **Located from the record, walk as fallback.** A walk is still required to be whole before any deletion, as `W218` ruled.
- **`location.py` is a new module** because `record.py` would have passed R11's ceiling. The package's seam test now names four modules.
- **Disclosure added.** Without it a kept clip is invisible until someone happens to prune. It is one line beside answer 4's count.
