## ⛔ THE SHAPE, and it is TWO directories rather than one

```
<corpus root>/
  exercises/<address>/<variant>/unit-NN/practice-M/     ← the BUNDLE, never a reader's
    bundle.json          what this exercise declares about itself
    statement.md         the statement, as Markdown
    gates.json           AX-03's gate record
    starter/<main_file>       the pristine starting file
    reference/<main_file>     the reference solution
    tests/<test_file>         the grader
    plants/edge-N/<main_file> one planted solution per edge case
  practice/<address>/<variant>/unit-NN/practice-M/      ← the WORKSPACE, the reader's
    <main_file>          a copy of the starter — this is what `main_path` names
    <test_file>          a copy of the tests
    <report path>        the run's own artifact, written by a run and by nothing else
```

## Decisions

⭐ **Things the task did not specify, chosen here, each with the reason:**

1. ⛔ **THE READER'S FILE IS NOT THE STARTER, AND THAT IS WHY THERE ARE TWO ROOTS.**
   ⚠️ **The alternative was measured rather than dismissed:** with one root, the gate
   record's digest of the starter would drift the moment anybody did the exercise, and
   `studyforge validate` would report every worked corpus as broken. ⭐ Every file a gate
   record digests is therefore one no reader touches, which is what keeps `AX-11`'s
   *"every shipped exercise's gate record verifies against the files beside it"* true
   after the corpus has been used. ⭐ Read as a property at
   `test_exercises.py::test_a_readers_own_edit_never_moves_a_digest`.
2. ⛔ **A PLANT IS FILED BY POSITION, NEVER BY CASE ID** — `plants/edge-N/`. ⚠️ That is
   `AX-03/4` taken seriously: `CASE_ID` permits `. _ - : # $ / @ + = , ( ) [ ]`, so a
   valid case id can spell an absolute path, and one used as a path segment could put a
   plant outside its bundle. ⭐ The case id reaches the gate record's **role**, where
   `gates.require_role` already bounds it, and nothing else.
3. ⭐ **THE REFERENCE SOLUTION SHIPS IN THE PAGE, AS A `disclosure` BLOCK.** The user
   ruled it always available and `AX-09` offers it at any time; the page is offline and
   `file://`-addressable (R8), so a reference the page did not carry is one the reader
   could not be offered. ⛔ `disclosure` is the archive's own *present but withheld*
   state — nothing is revealed automatically, asking is not a run, and nothing can be
   recorded as a failure. ⚠️ **`AX-09` owns how it is drawn and what its summary reads**;
   `REFERENCE_SUMMARY` is a framework constant it may replace. What it may not do is make
   the reference conditional on a pass.
4. ⛔ **THE EMISSION WRITES THE WORKSPACE AND NOT THE ARCHIVE DOCUMENT.** `emit` answers
   with the document and where it lands stays placement's decision (R2); computing an
   archive path here would be a second spelling of the arithmetic `W199` and `W298` were
   paid for. ⭐ `write` creates only the two workspace files, and refuses rather than
   skips when one exists (R3).
5. ⛔ **EVERY PATH IN `bundle.json` IS WORKSPACE-RELATIVE, AND THE TWO COMMANDS ARE THE
   EXCEPTION.** A command runs from the corpus root, so its arguments are spelled as that
   root sees them — and `emit` refuses any argument containing `/` that is not inside this
   exercise's own workspace, which buys back the containment the other values get for free.
   ⚠️ An argument with no separator is left alone: `mvn`, `test` and `-pl` are not paths.
6. ⛔ **`origin` IS REQUIRED ON A BUNDLE WHERE THE RECORD LEAVES IT OPTIONAL.** `G5`
   resolves an authored exercise's origin against the source ledger (`AX-07`), so an
   authored exercise with no origin is material the ledger cannot account for — `E14`'s
   first property firing at the earliest point it can.
7. ⛔ **R5 IS NOT RE-SPELLED.** `bundle.json` reads `provenance` and `trust` as text and
   `archive.document.build` applies the rule through `exercise.record.from_document` and
   `unit.trust`. ⭐ A bundle claiming `generated`/`authoritative` is refused by the module
   that owns that rule; read at `test_emit.py::test_r5s_forbidden_pair_is_refused_by_the_module_that_owns_it`.
8. ⛔ **CLEARED AND INTACT ARE TWO RULE IDS**, following `AX-03`'s own handoff: `clears`
   reads the verdicts and `drifted` reads the files. ⭐ `gate-record` (absent or
   unreadable), `gate-shortfall` (a gate did not hold), `bundle-digest` (a file moved),
   `bundle-contents` (a file the shape forbids), `practice-ordinals` (a numbering gap).
9. ⛔ **`generated` IS THE TRIGGER AND `bundled` IS UNTOUCHED.** A `bundled` grader's
   derivation gates are `E08`'s; nothing here widens to it, so a corpus that predates this
   milestone validates exactly as it did — asserted at
   `test_exercises.py::test_a_corpus_with_no_authored_exercise_is_untouched`.
10. ⭐ **`bundle_api` IS ITS OWN VERSION**, following the archive document's rule: bumped
    when a reader of the old shape would be *wrong* rather than merely incomplete. Nothing
    of this shape is on disk anywhere yet, so the key order is free and this is version 1.

## For dependents

### ⛔ `AX-07` — the ledger and the plan

- ⭐ **`bundle.origin` is the key `G5` hands the ledger**, and it is REQUIRED on every

### ⛔ `AX-08` — the authoring skill: what to write, and where

- ⭐ **Write the bundle, then call `emit`, then call `write`.** The skill never composes a
  path: `Places(address, variant, unit, ordinal)` answers every one of them, and
  `bundle.places` is that object derived from the document the skill just wrote.
- ⛔ **The workspace files are the EMISSION's to create, not the skill's.** `write` refuses
  an existing file rather than overwriting it (R3), so a re-run on an unchanged corpus is a
  refusal and not a silent rewrite — ⚠️ **which is a shape your R10 clause has to handle:
  *re-running with nothing changed rewrites nothing* means you check before you write, or
  you catch the refusal and treat it as "already there".**
- ⛔ **Two manifest lines are yours** (`AX-04/2`): `content.not_material` for
  `exercises/**` and `practice/**`, under `corpus_api` 2. Without them `validate` reds on
  every file in both trees, before any check of this row runs.
- ⛔ **Do not commit a run's report** (`AX-03/1`, `AX-04/3`). A bundle that holds one is
  refused by `studyforge validate`; a workspace that holds one is not, so write the ignore
  rule.
- ⭐ **The gate record's `inputs` are what `validate` re-digests**, so take them over the
  BUNDLE root: `taken_over(root / places.bundle, (("statement", "statement.md"),
  ("starter", f"starter/{main_file}"), ("reference", …), ("tests", …),
