### The three things the row said would settle it

2. ⭐ **A probe that asks Docker what is up**, `execute.EditorProbe`, modelled on
   `execute.mode.ModeProbe` line for line: one `docker inspect`, a TTL cache, and **every
   failure to ask is a negative**. ⛔ The Docker socket is never mounted into the serving
   process (§8.3, rule 2) — the host's CLI is the only thing that talks to the daemon.
3. ⭐ **`editor` on the run index**, keyed by corpus `source`, each value `{origin, folder}`.

### ⭐ What the probe reads, and what it refuses

⭐ **Up is not enough, and the discipline is `ModeProbe`'s generalised.** An answer needs
all three:

| clause | why |
|---|---|
| the container is **running** | a stopped one has no port and no folder |
| it **binds a directory of THIS source root** — the root itself or one inside it | a container by the right name over another checkout would open the reader onto files they are not being taught from |
| it publishes **exactly one host port** | the editor publishes its UI and nothing else, so one port IS the answer; two name no one UI, and guessing would frame something else |

⭐ **The folder is DISCOVERED, never composed**: it is that mount's own `Destination`, read
back out of the container. ⛔ **No path inside anybody's image is spelled in this framework**
(R1), and the fixtures use made-up container paths deliberately — the real one is a home,
which R7's gate reads as a leak (`SK-09/6`).

⚠️ **The editor binds a directory INSIDE the source root where the runner mounts the root
itself** (§8.1 ruling 2 mounts only the sources), which is why this probe accepts a
descendant and `ModeProbe` demands equality. Two matching mounts, or none, is ambiguity
rather than an answer.

## Decisions

- ⭐ **The probe lives in `execute`, not in `serve`.** `execute` is the one package that
  starts processes and the one that talks to the Docker CLI; putting it in `serve` would
  put process-spawning into the web-facing package, which is the direction
  `tests/studyforge/serve/test_init.py` exists to refuse.
- ⭐ **`editor` is a MAP keyed by corpus, not one object.** An instance serves every corpus
  it discovered and the panel knows which one it belongs to; a single object would have made
  a several-corpus instance answer about the wrong one. ⚠️ **A deviation from the row's
  literal `editor: {origin, folder}`, stated rather than slipped in** — the fields are the
  row's, the key above them is this.
- ⭐ **The probe is built ONCE per corpus and kept.** A probe's whole economy is its cache;
  a fresh one per request would fork `docker` on every page load and the TTL would buy
  nothing.
- ⭐ **A negative is cached too**, for the same reason: a page whose editor is down must not
  fork `docker` per tick.
- ⭐ **The origin is built from the binding, and an unspecified address is reported at
  loopback** — that is the address the reader's own browser has, and §8.1 ruling 3 permits
  the editor no other.
- ⭐ **The client gained the third entry point, not the panel.** `studyforge.run` is the one
  object the panel is allowed to know (`SF-24`'s own rule), so the index is fetched by the
  client and the panel asks the client. ⛔ The client builds no URL: it hands back an origin
  and a folder and the panel decides.
- ⭐ **The panel asks whether `run.editor` exists before calling it.** A site BUILT by one
  version may be SERVED by another and the client is the serving process's; a panel that
  called a function an older client does not publish would take Run and Submit down with it.
- ⭐ **The frame opens the FOLDER and not the reader's file.** Opening the file would need
  the practice's `main_path` on the panel as data — a second change to `SF-24`'s object,
  which is exactly what the row said would mean the seam was drawn wrong. ⚠️ The extraction
  source's `payload=[["openFile", …]]` is the shape to add the day the panel carries that
  path for another reason.
- ⭐ **The folder is published unscrubbed.** It is a path inside somebody else's image, read
  from the daemon; `scrub` would rewrite it and the URL would then open nothing. ⛔ The index
  is not a gated document and this value is not one this build wrote — `W416/7`.
- ⭐ **`tests/studyforge/execute/test_commands.py` imports `skills.execution`.** The claim
  being asserted is a claim ABOUT the two together — the name the framework looks up and the
  file that brings that container up — and asserting it in either module alone would assert
  half of it.
