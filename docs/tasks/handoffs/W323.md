## What landed

### The declared subdirectory, minted once

`names.STUDY_DIRNAME` is `study`, on the package surface. It is the one spelling: nothing else
in `src/` holds that literal as a path segment, and `test_names.py` now asserts that the way
the archive root and the `raw/` segment are already asserted.

⭐ **Why `study`, and why not dot-prefixed.** `GENERATED_ROOT` (`.studyforge/`) holds what a
reader does not browse — assets, the discovery cache. This directory holds **the pages a
reader opens**, so hiding it would hide the product. One word, no source in it (R1).

### Every path the `sibling` profile answers with goes through one method

`SiblingProfile.study_dir(origin, address, what)` is `origin_directory(...) / STUDY_DIRNAME`,
and `unit()` and `container()` both call it. So the segment is joined in exactly one place and
no caller, build, test or skill composes it — which is `W322`'s subject, and this row was
required not to create a new instance of it.

### What a built corpus now looks like

Under `sibling`, for a source directory `field-notes/` holding one source file:

```
<corpus root>/
  index.html                                  ⭐ the ONLY generated file at the root
  .studyforge/assets/                         shared stylesheets, scripts, player
  .studyforge/site.json                       discovery cache
  archive/                                    the adapter's, untouched by a build (R2)
  field-notes/
    topics.md                                 UNTOUCHED (R3)
    study/
      field-notes.section.html                the container's page
      field-notes.unit-01-taking-a-reading.unit.html
      field-notes.unit-02-writing-it-down.unit.html
      audio/field-notes.unit-01-taking-a-reading/
      audio/field-notes.unit-02-writing-it-down/
      images/<stem>/   video/<stem>/   practice/<stem>/   attachments/<stem>/
```

⛔ **A source directory gains exactly one name**, whatever its unit count, and `study/` itself
lists its pages plus at most five directories. ⚠️ **A media directory is created only when a
build copies a file into it** — the plan claims them, it does not create them.

### The media is one directory per KIND, with the stem below it

`study/audio/<stem>/`, not `<stem>.audio/`. Many units share one `study/`, so something has to
discriminate; putting the stem one level down means the kind is what a listing shows. ⚠️ **The
cost is stated in the module rather than hidden: a unit's artifacts no longer sort as one
contiguous run.** `UnitLocations.directories` names them, so deleting a unit is still one
question asked of placement rather than a glob.

### Two consequences that fall out, both asserted

- **The href moved and nothing composed it.** Under `sibling` a clip is now
  `audio/<stem>/<clip>.mp3` relative to the page; under `tree` it is still `audio/<clip>.mp3`.
  Every renderer asks `UnitLocations.href`, so no renderer changed — only the goldens they
  produce.
- **The ignore rules narrowed.** They were `*.audio/` and its four siblings — a bare stem
  suffix that would have had git ignore a repository's own `lecture.audio/`. They are now
  `study/audio/` and its siblings: unanchored, because a corpus cannot say in advance which
  directories hold material, but matching only inside a directory this framework writes.
  ⛔ **`ignore_home()` is still `None`, and the reason changed**: a `study/` directory *is*
  generated and *does* enclose the media, but there is one per source directory and an
  `IgnoreFile` has one home. `profile.ignore_file`'s refusal now says *no single* generated
  directory, which is the true statement; it still cites R3 and still refuses.

## Decisions

1. **The name is `study`.** It is the corpus owner's own directory name from now on, so it had
   to be a word a reader recognises without knowing this framework, carry no source fact (R1),
   and not collide with `GENERATED_ROOT`'s reason for being hidden. ⚠️ **A repository that
   already has a `study/` directory beside its material will have a build write into it.**
   That is the same class of statement the ignore rules already make, and it is stated in
   `names.py` rather than guarded against, because guarding means enumerating names that do
   not exist yet.
2. **The media is `study/<kind>/<stem>/` and not `study/<stem>/<kind>/`.** The second keeps a
   unit's artifacts contiguous but puts one directory per unit back in `study/`, interleaved
   with the pages — which is the defect one level down. The brief's clause 2 asks for audio
   *under a declared subdirectory*, not for a per-unit directory somewhere quieter.
3. **`describes` changed**, so `studyforge plan`'s `placement sibling …` line now says *in a
   study/ directory beside the source file it was generated from*. A profile whose one-line
   description said only *beside the source file* is what produced the reading this row
   corrects, and that line is what a corpus owner reads before choosing.
4. **`ignore_home()` still answers `None`, and only its reason changed.** Giving `sibling` a
   home would mean one ignore file per source directory; `IgnoreFile` has one home, and
   minting a file per directory is a build's write this profile cannot make (`W242`). The
   refusal's wording was corrected because the old sentence became false, not because the
   behaviour moved.
5. **The spec's §5 example was amended in place**, in the form §5 already uses for `W241` and
   `W254`. My change makes that worked example false, so leaving it is the *freshly wrong*
   failure [`CLAUDE.md`](../../../CLAUDE.md) names; amending a document my own change falsifies is inside the row,
   not scope beyond it.

  have gone green while asserting nothing. They now ask by path **segment**. ⛔ That is the
  same defect class as `W322`'s, sitting in tests rather than in source.

  `python3 -m` entry point that `tests/harness/goldens.py` names in its failure message; the
