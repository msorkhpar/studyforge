## Verdict — `SF-01`: ⭐ APPROVE, and it is the right exemplar

Trial merge into `release/m0-foundations`: **merge exit 0, 316 passed, 10

⭐ **What makes it the exemplar is not that it is clean — it is that every
precedent arrives with a proof and an invitation to be overruled.** That is the
behaviour to copy, more than any of the four decisions below.

### Precedent 1 — the digit prefix is `_` · ⭐ CONFIRMED, and it is a source defect

⛔ **I did not review the reasoning. I tried to break the claim.**

```
inherited('c01-a') = c01_a   inherited('01-a') = c01_a   -> COLLIDES
new      ('c01-a') = c01_a   new      ('01-a') = _01_a   -> ok

brute force: 11,300 slugs over the adversarial alphabet 'ab01-', len ≤ 6  -> 0 collisions
randomised:  283,697 slugs, full slug alphabet, len ≤ 12                  -> 0 collisions
```

⭐ **Injective, and injective by construction rather than by luck.** `slugify`
maps `_` to a separator, so no slug contains one and none starts with one —
which means the underscores in an identifier encode exactly where the hyphens
were, and a leading `_` is unambiguous. The property is structural; the tests
are the demonstration, not the reason.

⚠️ **And the inherited `c` rule collides on exactly the pair claimed.** This is a
real defect in the extraction source, found by holding its docstring to its
**stated intent** rather than its letter. ⭐ That is precisely what R20 says
extraction is *for* — knowledge flows in, gets better, and does not flow back as
a patch. Record it in the integration catalogue when that exists; ⛔ do not open
a PR against CodeSignal.

### Precedent 2 — `parse_key(key, depth)`, `depth` required · ⭐ CONFIRMED

⭐ **The argument is right and it generalises**, so I am stating it as the rule:
**when a generalisation turns a constant into data, the check that constant made
free becomes a required argument — never an optional one.** The source always
checked arity because arity was always 2. Optional `depth` converts a check that
*always ran* into one that *usually doesn't*, and the cases it stops running on
are exactly the new ones the generalisation created.

### Precedent 3 — `AddressError(ValueError)` · ⭐ CONFIRMED as a project-wide split

> **Value errors subclass `ValueError`. Document errors subclass `Exception`.**

- A **value** error means *a caller passed something this package cannot
  accept*. That is what `ValueError` means, so code that already handles bad
  input handles ours without importing from the framework.
- A **document** error — `SF-06`'s `RawDocError`, and `validate`'s — means *this
  file is not a thing I can read*. ⛔ That is not a bad argument, it is a bad
  file, and collapsing the two would have callers catching `ValueError` around a
  file read and swallowing genuine argument bugs.

⚠️ **Thirteen packages were waiting on this: it is one line each and it is
settled now.** The divergence from the source is deliberate and the docstring
says so.

### Precedent 4 — `unit_name`, not `unit_dirname` · ⭐ CONFIRMED

The string is an **identity** — progress key, served address, editor task file,
embedded identity block — and only *sometimes* also a directory. ⛔ A name
carrying `dir` invites the next reader to assume the package knows about the
filesystem, which is exactly what R4 removes and what this package is careful not
to know. ⭐ Naming follows the contract, not the most common consumer.

### The `SF-01`/`SF-02` boundary · ⭐ CONFIRMED — `SF-02` may start

**One integer wide, and that is the whole seam.** `SF-02` owns the declaration
(`levels`); `SF-01` owns the comparison (`parse_key(key, depth)`); neither
validates the other's half. ⭐ A boundary you can state in one sentence and whose
entire interface is `int` is a boundary that will not drift — and it is the
first of the fourteen, so its shape matters more than its content.

⭐ **And §4's table *being* the parametrisation is the right instinct**: six
shapes, two of them depth-1, plus synthetic depths 3 and 4, with **no test
exercising only the two-level case**. ⚠️ That last part is the one to copy. The
plan's whole risk is a framework fitted to a two-level source; a test suite that
can only fail at depth 2 would have hidden it.

### Open finding — `slugify` collisions · ⭐ ROUTED, and it gains a second half

**`SK-01`/`SK-02` is the right home, and it is not enough on its own.**

⛔ The framework cannot check the *cause*: by the time it sees an archive the
title is gone, and §6's *recorded, never derived* exists so it never tries. ⭐
**But the *effect* is visible in the archive alone** — two containers claiming one
address, or one silently overwriting the other — and that needs no title.

So `SF-25` gains **"no two containers claim the same address"**, added to its
task. Defence in depth: the adapter checks the cause, `validate` catches what
gets through, ⛔ and neither substitutes for the other. ⚠️ A collision that only
the adapter can see is a collision one careless adapter author disables.

## Verdict — `FND-06`: CHANGES REQUESTED, one item

⛔ **The sweep must respect `.gitignore`.** It gated `.idea/workspace.xml`, a file
that never enters the repository. ⭐ This is the **second** scope defect in this
check and the pattern is worth naming for the fix: *the check's patterns have
been right both times; its idea of what it is checking has been wrong both
times.* A repository-hygiene check's subject is **tracked content** — what `git
ls-files` returns — not what happens to sit in the working tree.

⭐ **Everything else about it is right, and it earned its existence before it was
even merged**: it found a real R7 violation, in a file written by the agent that
routes its own review. ⚠️ That is the strongest possible argument for the task
existing, and it is worth recording that the violation was **not** in framework
source — it was in prose, which is exactly where the ruling below says to look.

### ⭐ `docs/` swept in full, no file exempt · CONFIRMED

The reasoning is exactly right and I want it kept verbatim: **exempting `docs/`
would exempt the one place R7 has actually been violated in this repository**,
and prose *about* R7 is precisely where a real home path gets pasted as an
example. ⚠️ That the check's own handoff tripped the gate within the hour, and
that the fix was to **rewrite the example rather than add an exemption**, is the
whole argument demonstrated in miniature. ⛔ Keep that story in the task; it is
what stops the first inconvenient hit becoming the first exemption.

What makes it survivable is the placeholder convention: `/home/<name>` cannot
match, because `<` is outside the character class. ⭐ That is a convention paying
for itself in a way nobody designed.

## Ruling — rubric §1a, three measured corrections · ⭐ ACCEPTED and applied

`FND-06` measured **34 hits on the tree, every one a false positive**, ten inside
its own diff. I re-measured on this branch — **9 hits, all false: 6 × `$HOME`,
3 × `n@router.get`** — same two classes, and verified each fix against a purpose-
built table before applying it.

| Correction | Verified | Cost, stated |
|---|---|---|
| local part needs **2+ characters** | kills `n@router.get`; still catches a real address | ⚠️ `a@b.example` is missed — accepted, because **1b** matches the user's own address exactly, at any length, and a third party's one-character address is not R7's subject |
| **`.local` trailing guard** | `settings.local.json` no longer matches; a bare `<host>.local` still does | none |
| **`$HOME` / `~/` dropped** | the risk is the *expansion*, already caught by `/home/` | ⚠️ a literal `$HOME` in `src/` or a generated artifact is still a defect — just not this check's business |

⭐ **The rubric now self-tests clean**, where it previously produced two hits it
had to document as dismissals. ⛔ **A check that cries wolf is a check reviewers
learn to wave through**, which is the one failure R7 cannot afford — so these are
corrections, not loosening: each removes a class that is *provably* not a leak,
and none removes a class that could be one.

## Surprises

- ⭐ **A task found a real defect in the extraction source by taking its
  docstring's *intent* more seriously than its code.** That is the first time in
  this project that mining CodeSignal produced a correction rather than an
  inheritance, and it is what R20 predicted would happen.
- ⚠️ **`FND-06`'s two defects were both scope, never patterns.** A check that is

  looks like a false positive, which is the most expensive way to be wrong — the
  reviewer's instinct is to loosen the pattern, and that would have been exactly
  the wrong fix both times.
