### 2. The gates that keep R5's honesty

⭐ **Run by the framework (`AX-04`), in the pinned runner image, on every authored bundle. A bundle
ships only if every gate holds:**

| gate | what must hold | what it proves |
|---|---|---|
| **G1 reference** | every test passes on the reference solution, on two runs, with the same outcome each time | the exercise can be solved, and its tests are not flaky |
| **G2 starter** | **every** test fails on the starter, not just one | no test is vacuous; the reader starts with the work undone |
| **G3 edge, per case** | for each edge case *e* there is a planted solution *P_e* that solves the main ask and ignores *e*. On *P_e*, every main-ask test passes and *e*'s test fails | each edge-case test catches the one omission it names. This is E08's per-method argument, applied per case |
| **G4 map** | every test the report names maps to exactly one case, and every case is backed by at least one test | the Submit breakdown is total |
| **G5 origin** | cases (a) and (b): the `origin` resolves to a ledger entry whose digest matches the source | the exercise is built from what the source has |

- ⭐ **What is recorded.** The bundle's `exercise.json` carries `cases`: an `id` as the test report
  spells it, a `kind` (`main` \| `edge`), and `says`, one sentence the reader sees. It also carries the
  `report` (`junit-xml` and a path) and the `origin`. The **gate record** sits beside the bundle. It
  holds the sha256 of every input (statement, starter, reference, tests, each plant) and each gate's
  outcome. `studyforge validate` refuses a `generated` exercise whose gate record is absent or whose
  digests no longer match (`AX-05`).
- ⭐ **So Submit can report "main ask ✓, edge cases n/m".** The test command writes a JUnit XML
  report. Surefire writes it with no configuration, and pytest writes one with `--junitxml`. The stdlib
  `xml.etree` reads it, and the `cases` map folds it into *main* plus *edge n/m*, naming each failed
  edge case by its `says`. ⛔ **The pass rule does not change.** `is_pass` stays
  `mode == "test" and exit == 0`, so a practice completes only when every case passes. The breakdown
  is a report, never a second definition of a pass.
- ⛔ **When a gate fails, the exercise is not shipped.** The skill may re-author that bundle within a
  fixed attempt budget, and ⛔ **never by loosening a gate or dropping a case**. After the budget runs
  out, the coverage report names the page, the exercise, the gate, the case and the run's last output
  lines. A page left with nothing shipped is named as such (R6). That is E08's *"a low yield is never
  fixed by loosening a gate"*, applied to authored exercises.

### 5. Open questions for the user

⛔ **Each blocks `M10` until ruled.**

1. **What is an exercise for a corpus whose subject is not code?** A history book has no checkable
   coding task. ⭐ **Recommendation:** `M10` is code exercises, and it covers every corpus with a code
   subject. A non-code corpus stays complete at the reading floor. A quiz shape for it goes to the v2
   backlog.
2. **Is the reference solution ever shown?** ⭐ **Recommendation:** yes, but only after the reader's
   first passing Submit, as LeetCode does. It is never shown before.
3. **May an authored exercise carry the `advisory` label?** R5 requires one for a `generated` grader.
   ⭐ **Recommendation:** keep R5 as it is, and word the label for a learner rather than as a warning:
   *"written for this site; its tests are proven against a reference solution"*.
4. **Is the pilot a checkpoint?** ⭐ **Recommendation:** yes. The three pilot pages' exercises go to you
   once, you approve the shape and the per-page counts, and the other 35 then run on gates alone,
   with no further review.

## Decisions

- ⭐ **Authored graders stay `generated`/`advisory`.** Minting a third trust level would change R5's
  vocabulary, and the gates already make the claim precise. Reversible by question 3.
- ⭐ **The breakdown channel is JUnit XML.** Maven, Gradle and pytest all write it, and the stdlib
  reads it. Parsing console output was rejected: `quiet` rewrites that stream by design.
- ⭐ **Edge-case tests are not hidden.** An offline workspace cannot hide a test file. The case titles
  appear after a Submit, and the test file is the reader's to open.
- ⭐ **No `raw_api` or `progress_api` bump**, by `W357`'s test: every older document stays valid, and an
  older build refuses the new keys. That is for the register to confirm.
- ⭐ **The bundle is source-side material and the adapter emits it**, so R2's seam and R3's additivity
  both hold. ISO has no root `pom.xml`, so its practice module needs no `permitted_edits`.
