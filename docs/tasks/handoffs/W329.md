## Decisions

- ⭐ **Two instruments, both pre-existing, and the seam between them is *who wrote the file*.**
  Onboarding's record answers for onboarding's footprint; `source_files` answers for what a build
  writes. ⛔ Neither is a name, a suffix or a directory. Reversible.
- ⭐ **`capability` gave up its own walk.** It now iterates `inventory.enumerated` under
  `inventory.enters`. ⚠️ **This is a widening beyond the row's readings**: it also stops counting
  `node_modules/**`, `build/**` and `dist/**` as graders and source files, which is the behaviour
  `inventory` has always had. It is asserted both ways.
- ⭐ **The refusal is in `write`, not in `onboard`.** `onboard()` stays pure, as `W270` and `W283`
  kept it, and the guard holds for a caller who reaches `write` by any route.
- ⚠️ **`recorded.py` is a split, not a trim** (Ruling 261). `onboard.py` measured near R11's bound
  before this row; the seam is *what a manifest already records*, which is pure and has nothing to
  do with writing files.
- ⚠️ **`tests/**` overlaps the adapter's `tests/ingest/**`.** The manifest refuses a *repeated*
  glob, not an overlapping one, and `promote`'s collision check compares glob strings. Dropping the
  adapter's would be an edit outside this surface.

## Surprises

- ⛔ **`placement` was a fourth flipped answer, and nothing in the brief named it.** It was found
  by the refusal this row added, on the first end-to-end run: `_placement` reads
  `capability.source_files`, and the archive a build writes is full of `.json`. ⭐ That is the case
  for making the guard derived rather than a list of fields somebody thought of.
- ⛔ **Clause 4's control was vacuous in the pinned image, and the image is what caught it.** The
  image both forbids bytecode and redirects its cache out of the bind mount (`W30`), so the
  onboarding [skill](../../../src/studyforge/skills/onboarding/SKILL.md)'s step 4 writes no
  `.pyc` beside the modules there and both clause-4 checks went RED on an empty inhabitation. ⭐ The
  step-4 subprocess now unsets both variables, the idiom
  [`tests/docker/test_dev_image.py`](../../../tests/docker/test_dev_image.py) already uses, so the
  two environments read the same and the clause measures the interpreter an integrator actually
  runs, and `W30`'s hazard is not reintroduced because the corpus lives under pytest's `tmp_path`
  and never the bind-mounted checkout. ⚠️ **The defect this row fixes is therefore invisible to a
  gate run only in the image** — which is why it survived a green suite.
- ⚠️ **The install record names the hand-written module too** (`ingest/read.py`, marked
  `hand_written`). It is set aside with the rest, which is right — it is the adapter's reading
  step, not the corpus's material — but it means `generated` is *"what onboarding wrote"* rather
  than *"what is regenerable"*.

## For dependents

- ⛔ **A second run of the onboarding procedure passes `existing=` the manifest's text** (`W283`)
  **and now also gets a refusal if any recorded answer would move.** The remedy the refusal names
  is to settle it in the draft, or to uninstall and onboard afresh.
- ⭐ **A corpus onboarded before this row carries `tests/*.py` in its manifest.** Regenerating it
  through onboarding rewrites the glob to `tests/**`, so `recorded.moved` will not object — the
  field it changes is `content.not_material`, which `W283`'s rule owns. ⚠️ Until that regenerate,
  `python3 -m pytest tests` in such a corpus still leaves bytecode `unclassified`.
- ⚠️ **`buildserve`'s partial-state vocabulary is untouched.** Clause 3 needed the `exercises`
  answer to stop moving, not a new state.
