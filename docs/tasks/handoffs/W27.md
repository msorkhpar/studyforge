### 2. The propagation vector, removed

`corpus/manifest/document.py`'s `_gate` docstring said it was *"Converted to
`ManifestError`, following `unit.content._gate` **exactly**"*. ⛔ That sentence
is the defect's transmission mechanism — a module citing a neighbour as its
justification is how one translating site became three — and it is gone. What
replaces it says the opposite, names the ruling, and records the dead arm the
translation caused, so the next reader of that function meets the argument
rather than the precedent.

⚠️ **The counter-argument it carried was not deleted, it was moved.** *"A
promise with one exception is not a promise"* is answered where the promise is
made — in `errors.py` — not where it is broken.

### 3. The contract sentences — the second half of the task

Each of the three packages' `errors.py` now names what crosses it, in the shape

⭐ **This is why the ruling asked for the sentences and not just the raises.**
`manifest/errors.py` would have contradicted its own module within one commit,

## Decisions

**D1. `_gate` kept as a named function where it existed; not inlined.** It is
now a one-line wrapper, which is arguably indirection — but `unit/served.py`
keeps exactly that shape for exactly this reason: the docstring explaining why
the leak is not translated needs somewhere to live, and a comment at a call
site is not where a future author looks. ⭐ `identity.py` had no `_gate`, so it
got the same explanation as a comment rather than a new function invented to
hold it. **Copy the shape, do not invent one.**

**D2. Assertions moved from a phrase to a type.** Every migrated test asserted
`"personal data" in str(error)`. ⛔ **That phrase only ever existed in the
wrapper text the translation added** — `PersonalDataLeak`'s own message names
the *shape* (`"carries a home path (R7)"`). So the assertions became
`pytest.raises(PersonalDataLeak)` plus `not isinstance(..., <PackageError>)`,
which is both what the ruling is actually about and strictly stronger: a phrase
match cannot distinguish a translated leak from an untranslated one, and a type
check is the only thing that can.

**D3. `test_no_refusal_reproduces_a_value_from_the_authored_file` widened to
`pytest.raises((ContentError, PersonalDataLeak))`, deliberately not to
`Exception`.** Its claim is about *emission* — no refusal reproduces the value
— and holds for both types; one of its five cases (`{"title": 4}`) is still a
genuine `ContentError`. ⚠️ **This is the one migrated test that passes on both
trees, and I am not counting it as a negative control.** A bare `Exception`
would have covered both and said nothing about which.

**D4. `docs/tasks/BOARD.md` not touched.** The W27 row is the PO's to close.
⛔ Staying inside the task is what turned this defect into a ruling in the first
place (`SF-10` found it in `unit/content.py`, did not fix it, filed it).

## Surprises

⚠️ **S1. The migration was measured at zero and is actually ten.** The ruling
and the board both cite `grep -rn 'carries personal data and is refused' tests/`
→ 0, concluding *"the three sites move without rewriting a single assertion"*.
⭐ **The grep is correct and the conclusion does not follow.** Re-run on this
tree it is still 0 — but ten tests broke, because they never asserted the
message: they asserted the **type** (`pytest.raises(ContentError)`,
`pytest.raises(PlacementError)`, `pytest.raises(ManifestError)`) and the phrase
`"personal data"`, which lived only in the wrapper. ⛔ **An instrument pointed
at the message could not see a test pointed at the type.** Ruling 55, exactly
as written — and the second consecutive wave in which a ruling's own number was
wrong when checked (W20's said 7, found 19).

⭐ **S2. `manifest/errors.py` had already ruled the leak out by name.** Not an
omission — an explicit sentence, *"One deliberate exception, **and it is not a
leak**"*. ⚠️ The contract had been reasoned about and had reached the wrong
answer, which is a different and more durable failure than one nobody thought
about, and it is the strongest argument for the ruling's second half: fixing
the raise without fixing that sentence would have left the module's own written
rules justifying its reversal.

⚠️ **S3. `src/studyforge/unit/content.py:134` reads
`except TypeError, json.JSONDecodeError:` — no parentheses.** ⭐ **Not a
defect**: PEP 758 landed in Python 3.14 and the pinned image is
`python:3.14-slim`. Noting it because it reads as a Python-2 syntax error at a
glance and cost me a verification round trip.

⚠️ **S4. `ruff format` formats python code fences inside markdown**, so a
handoff can fail `test_ruff_format_is_clean_where_ruff_exists`. ⭐ Mine did,
for column-aligned trailing comments in the *"For dependents"* example. **A
handoff is a checked file**: run the pinned suite *after* writing it, not
before.

## Findings

**W27/1 `[structural]` — a ruling that quotes a grep should say what the grep
cannot see.**
Ruling 58 measured its migration with a message grep, got 0, and stated *"the
three sites can be corrected without rewriting a single assertion"*. The real
migration was ten tests, none of which the grep could match, because a test that
catches a type contains none of the message's words. ⛔ **The generalisation:
when a change alters an exception's TYPE, the migration surface is
`pytest.raises` and `except`, not the message text** — and a message grep
returning 0 is the expected reading in that case, not a reassuring one. ⭐ **The
counterpart command, which finds all ten:**
`git grep -n 'pytest.raises' -- tests/ | grep -iE 'contenterror|placementerror|manifesterror'`
against the modules being changed. Would recur for any future error-type
migration; costs one line in the rubric's §8a-i blast-radius clause.
**Measured:** `grep -rn 'carries personal data and is refused' tests/` → `0`;
`docker/dev/check python3 -m pytest -q` with `src/` changed and `tests/`
unchanged → `10 failed, 2558 passed, 8 skipped`. 2026-09-10.

**W27/2 `[local]` — `validate/corpus.py`'s three arms had one live test between
them.**
Of the three `except PersonalDataLeak` arms, `:196` had a driving test, `:157`
was dead, and `:177` was live but untested — so *"is this arm reachable?"* could
not be answered from the suite for two of three. ⛔ **A catch arm with no test
is indistinguishable from a dead one**, which is the whole shape of the W7 and
W27 defects one layer up. W27 adds a test for `:157` and `:177`; all three are
now driven. Filed rather than generalised because it is three arms in one
function, not a mechanism.
**Measured:** `git grep -n "f.rule for f in result.findings] == \[\"personal-data\"\]" --
tests/studyforge/validate/test_corpus.py` → **1** before (the `:196` document
arm), **3** after (one per arm). 2026-09-10.

**W27/3 `[local]` — `unit/errors.py` serves two readers and its contract named
neither.**
Unlike the other two packages, `unit/` has two gated readers behind one error
family (`content.py` and `served.py`), and `served.py` already did the right
thing while `content.py` did not. ⚠️ **The package contract was silent, so the
two modules disagreed and neither was wrong by its own file.** The sentence
added names both. Worth knowing for E06/SF-14, which will add further readers
to this package: **the contract sentence is per-family, not per-module**, so a
third reader inherits it and does not restate it.
**Measured:** `git grep -n 'assert_clean' -- 'src/studyforge/unit/'` → 2 readers,
1 shared `ContentError`. 2026-09-10.

## For dependents

⛔ **Anyone holding a branch that touches `unit/`, `corpus/manifest/` or
`corpus/placement/` needs this before they merge** — the CTO flagged W27 as a
*collision*, not a chore, and this is the broadcast half.

**What changed for a caller.** Reading any of these documents can now raise
`PersonalDataLeak`, which is **not** a `ValueError` and **not** in the package's
family:

```python
try:
    manifest = parse_manifest(text, "corpus.json")
except ManifestError:
    # ⛔ No longer sees an R7 refusal at all: the leak propagates past this
    # arm and stops the run, by design.
    report_and_continue()
except PersonalDataLeak:
    # ⭐ Add this arm only if you MUST keep walking, and file it as R7.
    file_under_personal_data()
```

⚠️ **`studyforge validate` is the one caller that legitimately continues past
one**, because reporting every problem in one run is its contract (R6); it files
`RULE_PERSONAL_DATA` and its walk still stops at an unreadable manifest.

**If you are writing a new reader.** Call `assert_clean(document, where)` bare.
⛔ Do not wrap it. Then add the *"one exception travels through, deliberately"*
sentence to your package's `errors.py` — **five** packages carry it now
(`archive`, `corpus/container`, `corpus/manifest`, `corpus/placement`, `unit`),
and the rubric check is `git grep -n 'except PersonalDataLeak' -- 'src/*.py'`,
which must return only arms that file R7 and never a
`raise <PackageError>(...) from None`.
