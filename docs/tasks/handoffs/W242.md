## The design, argued before the code

The contract is ISO's §11.3: *for `sibling`, where the generated ignore lines live when the root
ignore file is R3-forbidden, and how committed media is classified.*

**1. A build's output is committed. Generated ignore rules are the media policy's and nothing
else's.**
- §5: *regenerable is not the same as available*. That argument is made for narration, and it
  holds for the page that plays it, the root index and the two-file bundle the page links. A clone
  that ignores its pages has no reading floor. A clone that ignores only the bundle has pages that
  are unstyled, with no error, which is the failure §5 refuses for media.
- `sibling` pages have no directory of their own, so R3 leaves them no ignore home anyway.
- ISO-05 forbids any generated rule matching `*.html` or `*.json`. The page suffixes,
  `/index.html` and `/.studyforge/site.json` all do. The discovery cache is deterministic and a
  stale one is detected (§5), so committing it costs a diff line and nothing else.
- So `SHARED_IGNORE_LINES` goes. With media committed (`auto`, `always`) a build needs **zero**
  ignore lines, and ISO-05's two ignore clauses hold by construction.

**2. The ignore home is a `.gitignore` inside the generated directory the rules are about, and
never the root.** A profile answers `ignore_file(media=…)`, which returns a home and its lines.
- Under `tree` with `media.commit: never`, every clip is below `.studyforge/`. The home is
  `.studyforge/.gitignore`, and SK-07 writes it from the manifest (R19).
- Under `sibling` with `never`, no generated directory encloses the media. The only homes are the
  root ignore file (R3) and a file inside each unit's media directory, which the build would have
  to mint. The profile raises, `plan` refuses, and onboarding refuses. None of this is silent.
  Nothing in scope declares that combination.

**3. Classification is manifest data that SK-07 generates.** A profile answers `output_globs()`:
every path its build writes outside the generated root. Both profiles write `index.html`;
`sibling` also writes the two page suffixes and the four media kinds, spelled from `names`.
Onboarding declares them in `content.not_material` with a reason. `validate` is unchanged: it
already classifies by the manifest, and it already skips `.studyforge/` and `archive/`.
`.studyforge/**` is deliberately absent, because the pin directory is onboarding's own glob.

**4. Rider `INT06-1/4`: two generators declaring one glob are refused, naming both.** This is
W239's rule applied to generators. Keeping the first reason is choosing one audit over another.
Adding a third generator makes a collision reachable, and `.studyforge/**` above is the one that
nearly was.
