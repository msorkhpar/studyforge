## The design, argued before the code

The contract is ISO's §11.3: *for `sibling`, where the generated ignore lines live when the root
ignore file is R3-forbidden, and how committed media is classified.*

**1. A build's output is committed. Generated ignore rules are the media policy's and nothing
else's.**
- §5: *regenerable is not the same as available*. That argument is made for narration, and it
  holds for the page that plays it, the root index and the two-file bundle the page links. A clone
  that ignores its pages has no reading floor. A clone that ignores only the bundle has pages that
  are unstyled, with no error, which is the failure §5 refuses for media.
- `sibling` pages have no directory of their own, so R3 leaves them no ignore home anyway.
- ISO-05 forbids any generated rule matching `*.html` or `*.json`. The page suffixes,
  `/index.html` and `/.studyforge/site.json` all do. The discovery cache is deterministic and a
  stale one is detected (§5), so committing it costs a diff line and nothing else.
- So `SHARED_IGNORE_LINES` goes. With media committed (`auto`, `always`) a build needs **zero**
  ignore lines, and ISO-05's two ignore clauses hold by construction.

**2. The ignore home is a `.gitignore` inside the generated directory the rules are about, and
never the root.** A profile answers `ignore_file(media=…)`, which returns a home and its lines.
- Under `tree` with `media.commit: never`, every clip is below `.studyforge/`. The home is
  `.studyforge/.gitignore`, and SK-07 writes it from the manifest (R19).
- Under `sibling` with `never`, no generated directory encloses the media. The only homes are the
  root ignore file (R3) and a file inside each unit's media directory, which the build would have
  to mint. The profile raises, `plan` refuses, and onboarding refuses. None of this is silent.
  Nothing in scope declares that combination.

**3. Classification comes from the corpus's declarations, asked of the plan.** `validate`'s
source scan asks `studyforge plan` which paths a build writes. A planned file is recognised by
its exact path, and everything under a planned directory is recognised with it. Those files are
the build's output, not material.
- ⚠️ **Revised during the work, and measured.** The first form had SK-07 declare the profile's
  globs (`**/*.unit.html`, `**/*.audio/**`) in `content.not_material`. The manifest parser refuses
  them: *"a pattern whose correctness depends on which files happen not to exist silences the
  unclassified check"*. Interleaved output cannot be declared by directory, and at onboarding
  there is no archive to enumerate it from. So the brief's "declared as manifest data" is met by
  the placement field and the container maps, read through the plan. No consumer writes
  anything, and nothing new is declared.
- The plan is already the one enumeration of a build's output (Ruling 99), and
  `generate.footprint` reads it the same way.
- ⛔ A planned path the manifest includes is `contested`. A plan that refused recognises nothing,
  and `validate` says so.

**4. Rider `INT06-1/4`: two generators declaring one glob are refused, naming both.** This is
W239's rule applied to generators: keeping the first reason is choosing one audit over another.
The merge test grounded dedup in *"the ordinary case of the adapter and this skill both writing
under `tests/`"*. Measured: every onboarding in the suite passes with the refusal. The two globs
are `tests/ingest/**` and `tests/*.py`, not one glob.

## Decisions

All of these are reversible, and ruled here because the user is asleep.
- **Committed, not ignored:** pages, the root index, the bundle and the cache (design 1).
- **`sibling` + `never` is refused**, not given a per-directory home that the build would have to
  mint (design 2).
- **A plan refusal inside `validate`** is an `Unchecked` under the existing `unclassified` rule
  id. No new rule id is minted, so [`validate.md`](../../authoring/validate.md)'s count stands.
- **"The population is printed"** is met by the acceptance test's printed count and by the
  re-read. `validate`'s report gains no line kind (`W242/4`).
- **The rider's refusal names producers and positions, never the glob.** A caller's flat
  sequence may carry anything (R7).

## Surprises

- The manifest parser refuses leading-wildcard `not_material` globs, which reshaped design 3.
- The tests this row replaced wrote plan lines into a root `.gitignore`. That is the edit R3
  forbids, and it sat inside green tests.
- The origin-sites guard (`W109`) caught a raw `origin` read in this row's own first test.
