## What landed

⭐ **`tests/build_inputs.py`, and it is what a test module now imports:**

- `declared()` — every input the two plans declare: `plan.INPUT_ROOTS`, then
  `editor_plan.OWN_INPUTS`. ⛔ **Not a list of its own** — it reads the two tuples.
- `entries(inputs=None)` — the TOP-LEVEL names a copy carries, de-duplicated in declaration
  order, plus `.dockerignore`. ⚠️ `docker/minimal` and `docker/editor` both resolve to `docker`,
  copied once. `inputs` narrows it to one plan's declaration.
- `copy_inputs(target, source=ROOT, inputs=None)` — replaces `target`, copies each entry
  (`copytree` for a directory, ignoring `__pycache__`), returns `target`.

⭐ **Every planted copy in the sibling's `tests/` is now one call.** Measured on the diff: eight
call sites across seven modules held 27 `shutil.copy`/`copytree` statements and three
`rmtree`+`mkdir` pairs, and 52 removed lines become 22. The editor's six sites pass no `inputs`;
`test_image.py` and `test_plan.py` pass `plan.INPUT_ROOTS`, the runner's smaller set they
already used.

## Decisions

- ⭐ **The entries are derived, not configured.** The row's second clause — *a new input
  directory is ONE edit* — is only true if the tests never hold a second list. So
  `build_inputs` reads `editor_plan.OWN_INPUTS` and `plan.INPUT_ROOTS` at CALL time, and
  `tests/test_build_inputs.py` asserts it by declaring a fabricated `extra/` in `OWN_INPUTS` and
  reading it out of the copy — with the undeclared half asserted first.
- ⭐ **Top-level names, not the declared paths.** A copy of `docker/editor` alone is not a build
  context: the real copies always took the whole `docker/`. The helper keeps that, and the
  de-duplication is asserted.
- ⭐ **`.dockerignore` is in the copy, though it is in no inputs digest.** Two of the three image
  modules already copied it and one did not; the build context is read through it, so every copy
  carries it now. ⚠️ **It moves no digest and no tag** — measured below.
- ⭐ **`test_image.py` and `test_plan.py` were brought in too**, though the row names the editor's
  four. They are the same duplication over the runner's declaration, they are inside the declared
  surface, and leaving them out would have left the helper living once *and a half*.
  `test_image.py`'s copy carries the same three entries it carried before; `test_plan.py`'s
  gains `.dockerignore` and the `__pycache__` exclusion, and the runner's inputs digest reads
  neither — asserted, since that test compares the copy's digest with the tree's.
- ⭐ **`copy_inputs` replaces its target** rather than requiring an empty one, so a caller hands
  over either a temporary directory or a name under `.work/` and the two shapes stop differing.
- ⭐ **The *lives once* clause is read off the modules themselves**, by `own_copies()`, which
  looks for the three shapes that are a second LIST: a whole input directory copied from `ROOT`,
  a non-literal name (a loop), and more than one named input file in one module. ⚠️ **One named
  file is a restore, not a list** — `test_editor_plan.py` legitimately puts the real
  `editor-pins.json` back over a planted one — and a deeper path is a fixture inside an input,
  not the input. Both exclusions are asserted with fixtures.

## For dependents

- ⭐ **Adding a top-level input directory is now one edit**: name it in `plan.INPUT_ROOTS` or
  `editor_plan.OWN_INPUTS` and every planted copy carries it. ⛔ **Do not add it to a test
  module** — `tests/test_build_inputs.py::TheHelperLivesOnce` refuses a second list.
- ⭐ **A new test module that needs a build context** imports the helper:
  `sys.path.insert(0, str(Path(__file__).resolve().parent))`, then `import build_inputs`, then
  `build_inputs.copy_inputs(<target>)`. The `sys.path` line is what makes it work under
  `unittest discover`, under `python3 -m unittest tests.<module>` and under `pytest` alike.
- ⛔ **No image input changed, so no image tag moves and no rebuild is owed by this row.** The
  three image modules' `planted_copy` functions were called directly on the host and the
  contexts they produce were read: the editor's two produce the same six entries as before, the
  runner's the same three, and both plans' `inputs_digest` over each copy equals the tree's.
