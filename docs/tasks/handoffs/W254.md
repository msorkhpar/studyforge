**Findings:**

### W254/1 `[structural]` — against W254 clause 1: the case for qualifying only on collision

This is for the register and is not implemented. Prefixing only units whose
paths collide leaves every collision-free corpus byte-identical, and it keeps
names short. Measured on the three committed fixtures at `973fc67`: pages and
plans were identical. Its cost is the one clause 1 names. A unit's name then
depends on the corpus, so declaring a mirrored unit later renames an existing
page, and anything keyed by page path moves.

### W254/2 `[structural]` — library build callers are not preflighted

`generate.write_site`, `write_pages` and `narrate` do not ask the plan before
writing. Only `studyforge build` does. A caller of the library is stopped by the
same-run guard, which fires after the first colliding unit's pages are written.

### W254/3 `[local]` — consuming corpora's committed pages move on their next build

Every `sibling` corpus's committed pages get new names on its next build: ISO,
and the Java consumer. Any document or link that spells a page name must follow.

**For dependents:** `ISO-09` can re-take its archive. On ISO `8afdd5b`:
`validate` reports no `duplicate-path`, `plan` has 0 refusals, and the build
writes one page per unit. A new caller that places a unit asks the profile and
never composes a name.
