## What landed

### ⛔ The defect

`QA-04/4`: no skill obliged a conversion to write a findings log, so `M8`'s deliverable was rebuilt
by hand from commit bodies, and two of the conversion's seven numbered findings survived only in a
message ([round 109](../BOARD-ARCHIVE.md#po-round-109)).

### ⭐ The shape

- ⛔ **The log lives at `.studyforge/findings.md`** (`LOG`). `.studyforge/` is already in
  `studyforge.validate.source.SKIP_DIRS`, so writing the log can never make the corpus it describes
  invalid, and the generated R3 check already accepts additions inside it.
- ⭐ **A log is a rendering of `Finding` values** — the delivery skill's existing record — each
  followed by one slot line asking *could a skill have generated this?*, answered `yes` (a hole, and
  which skill), `no` (a candidate entry, and why) or `open`. A `none` finding writes zero and carries
  no slot.
- ⛔ **`closing(text | None)` is the end of a run.** It refuses, naming every gap at once, an absent
  log, text that is not a log, a log with no finding, a `none` beside a real finding, and any finding
  whose slot is missing, doubled, outside the three answers or mismatched with its reason. ⭐ A log it
  accepts is reported finding by finding with the count still `open`, so an unsorted log reads as
  unsorted.

## Decisions

- ⛔ **The surface is wider than the `SKILL.md` documents, and it had to be.** Clause 3 asks for a
  run without a log to be *refused*; a document cannot refuse anything. ⭐ The refusal lives in the
  delivery package, beside `Finding`, because the log is a list of findings and the delivery skill is
  where they are defined.
- ⛔ **Nothing is generated into the corpus, and `artifacts.py` was not needed.** A generated empty
  log would satisfy "a log exists" on the first run and defeat the check. ⭐ The corpus already
  receives the procedure as a GENERATED stub pointing at the onboarding `SKILL.md` at its pin, and
  that is the generated procedure clause 3 names.
- ⚠️ **`open` is accepted, and counted aloud.** The row asks for the sort to *start* half done; a
  conversion office is not always the office that sorts.
- ⭐ **Step 7 was added after the uninstall step rather than renumbering.** Step numbers are cited
  from code (`onboard.STEP`) and from other documents.

## Surprises

- ⚠️ **The catalogue does not carry the question in those words.** Its admission test is *would the
  next source have to learn this again?*, and its table refuses *anything a skill could generate*;
  *could a skill have generated this?* is the `QA-04` sort's phrasing (`W346/1`).
- ⚠️ **The fence regex the delivery walkthrough uses pairs fences wrongly once an info-string fence
  appears** — the first draft of this row's test used it and read the wrong block (`W346/4`).
