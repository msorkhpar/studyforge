## Decisions

**1. The duplicate-path check places the corpus; it does not compare origins.**
E10 asks for the whole path set — pages, media directories and container pages
together — and that is what `paths.check_placement` builds. The predecessor's
`check_sibling_collisions` compared *origin directories* instead, which is both
narrower and wider than the requirement (finding 18). ⛔ Do not narrow this back
to addresses: the set is what catches a cause nobody predicted, and it already
has (finding 13).

**2. A unit is placed from its own `origin`, and there is no fallback to its
container's.** Placement rules an absent origin a refusal rather than something
to guess around, and inventing one would put generated output where the corpus
owner never agreed (R3). ⚠️ **`SF-04` (`studyforge plan`) must compose the same
way** — `profile.unit(container.address, unit.n, unit.title, origin=unit.origin,
label=unit.label)` and `profile.container(address, titles, origin=container.origin)`.
`validate` is the first caller to compose container and unit into placement at
all; if `plan` composes differently, this check measures a build that will not
happen.

**3. `validate` does not scrub, per Ruling 17.** `report.Finding`'s docstring now
says what is true — a message *originated* here names the field and never the
value; a message *forwarded* from an upstream refusal is that module's guarantee —
and `test_run::test_no_identifier_reaches_a_report_line` enforces the composition
end to end so the trust is not merely stated (Ruling 13).

## Findings

### 13 `[structural]` — E10's `slugify` collision example is wrong, and the ruling built on it is right anyway

E10 and `address/slug.py` both say `slugify` **deletes** accented characters, so
`café` and `cafe` produce one slug. It does not: an accent is a
non-alphanumeric, so it collapses to a **separator**.

**Measured:** `docker/dev/check python3 -c "...; slugify(...)"`, 2026-09-09:

```text
'Café'            -> 'caf'             'Cafe'            -> 'cafe'
'Streams: an API' -> 'streams-an-api'  'Streams, an API' -> 'streams-an-api'  COLLIDE
'C# Basics'       -> 'c-basics'        'C Basics'        -> 'c-basics'        COLLIDE
'A/B testing'     -> 'a-b-testing'     'A B testing'     -> 'a-b-testing'     COLLIDE
```

⭐ **The conclusion survives and gets stronger.** The collision class is *wider*
than accents — any two titles whose non-alphanumerics collapse to the same
separator run are one name — and punctuation is far likelier in real material
than an accent. ⛔ Which is exactly why the check is the path set and not any one
cause. Both tests are committed: the punctuation pair collides, and `Café`/`Cafe`
is pinned as **clean** so nobody "fixes" the check to match the example.
**Owner:** PO to correct E10's paragraph and `address/slug.py`'s docstring.

### 20 `[structural]` — ⛔ an archive document carrying an unknown `exercise` object validates **green**, with nothing unchecked

The PO's SF-23 concern, measured rather than anticipated. This is the exact
shape of *"a corpus validates green with its graders invisible"*.

**Measured:** a valid one-unit corpus, one edit — a top-level `"exercise":
{"grader": "pytest", "files": [...], "timeout_s": 30}` added to the archive
document — driven through `validate()` in the pinned image, 2026-09-09:

```text
with an unknown 'exercise' object -> valid: 0 finding(s), 0 unchecked claim(s)
```

⚠️ **Zero findings and zero unchecked claims.** The digest still matches, because
`content_sha256` is taken over `blocks` and an unknown sibling key is not a
block. Nothing in the pipeline asks whether a top-level key is one the archive
contract knows.

⛔ **Not fixed here, and the owner is not `validate`.** "Which top-level keys does
an archive document have" belongs to `archive.document.parse` (SF-02), which
accepts unknown keys silently today; `validate` would only be re-asking a
question the reader already answered — the same "two readings from one parser"
mistake this task exists to refuse.

⭐ **What SF-23 needs from this, concretely:** adding `exercise` to the document
must be a change to the **known-key set** in `archive.document`, not an addition
that happens to be tolerated. If it is merely tolerated, then a *typo* in the key
(`exercies`) is also tolerated, the grader is invisible, and the corpus is green.
**Owner:** SF-23 — with SF-02's contract as the place the change lands. Worth
raising before SF-23 starts, since it is the same document the two tasks share.
