## Decisions — what the task did not specify

### ⛔ The speech id carries the unit's logical address, flattened with a DOUBLE hyphen

`Q23` rules that *"the speech id comes from the unit's LOGICAL ADDRESS"*. A unit
key is `<slug>/…/unit-NN` and a filename component may carry no `/`, so the
separator has to become something.

⛔ **A single hyphen would NOT be injective:** `a-b/c` and `a/b-c` both flatten
to `a-b-c` — the exact ASCII collision `unit.sections` refuses to create by
*removing* slugification rather than by checking for it. ⭐ **A doubled hyphen
cannot appear inside a slug** — `address.slug_fault` names *"whose hyphens are
doubled somewhere inside it"* as one of the three ways to fail `is_slug` — so
`--` is a separator the segments provably cannot contain, and `unit_key_of` is a
**true inverse**, round-tripped in a test at depths 1 to 3.

⚠️ **Why the id and not only the filename carries the unit.** Spec §8.2's
synthesis API *"takes a list of `{id, text}` and returns one artifact per id"*,
and a batch spans units. ⛔ **Unit-relative ids collide in that batch.** The
cardinality is therefore asserted corpus-wide as well as per document.

### ⛔ The gate REFUSES and never scrubs — and it runs at BOTH ends

`archive.scrub`'s own contract rules it: ⭐ ***scrub our words, refuse the
source's.*** A spoken string is derived from the **source's** words, so
rewriting one into a placeholder would put an mp3 on disk quietly saying
something the material does not, with nobody knowing personal data had been
there. ⛔ `PersonalDataLeak` travels out as itself (Ruling 58).

⛔ **It runs on the source string as well as the derived one, and that is
MEASURED rather than cautious** — see finding SF-16/1.

### ⛔ No table of language display names, and none is portable

The extraction source keeps `LANGUAGE_NAMES` (`java` → `Java`, `bash` →
`shell`). ⛔ **It cannot be ported under that name or any like it:**
`tests/studyforge/corpus/manifest/test_document.py::test_no_module_maps_a_variant_to_a_capability`
refuses a module-level collection whose name contains any of `CAPABILITY_WORDS`,
and ⭐ **`"LANGUAGE"` is the first entry in that tuple.** ⚠️ Measured, not
inferred — the test reads names, not values, so the refusal is on the spelling,
and a renamed table would still be a vocabulary this framework has no business
holding (R1).

⭐ **So the caption speaks the archive's own recorded `lang`, as recorded**, when
it is one legible token (`LANG_PERMITTED`, `LANG_MAX`), and the plain caption
otherwise. The framework learns no language name at all.

### ⛔ The disposition table is CLOSED, so a twelfth block type fails the build

The source's rule was *"a block type with no branch here is spoken as a
paragraph"* — ⛔ an **open set** that fails toward *acceptance*, so a new
container type would have had its children read aloud out of a collapsed
section. ⭐ `SPEECH_OF` names all eleven and an unknown type **raises**;
`test_script.py` asserts it is exactly `BLOCK_TYPES`.

### ⭐ Nesting is addressed positionally, one `b<n>` per level

A `quote` is walked into (`b3.b2`), a `disclosure` is not. ⛔ **The two container
rules are derived from `CONTAINER_TYPES`** rather than named, because
`archive/blocks.py` says in as many words that *"a consumer that names `quote`
itself is the next `disclosure` waiting to be forgotten"*.

### ⚠️ No `identifier_speech` knob

The source carries a `SPLIT`/`VERBATIM` switch. ⛔ Nothing in this framework's
manifest declares one (measured: no `narrat`/`speech`/`voice` field in
`corpus/manifest/`), nobody has asked for one, and a knob with no constituency
is what §4's YAGNI refuses. Identifiers are always split.

### ⚠️ A section's `heading` field gets no speech id

It is a label the renderer shows; the section's own blocks already carry the
document's heading as a `heading` block. Speaking both would say it twice.
