## ⭐ The two-directional reading, and how it was taken

⛔ **The Acceptance clause with teeth is a claim about a reader that is no longer in the
tree**, so it was not asserted from today's constants — ⚠️ **an assertion ABOUT the previous
reader cannot take the half that matters.** ⭐ **The previous reader is RUN:**
`tests/studyforge/exercise/test_previous_reader.py` reads `src/studyforge/exercise/record.py`
out of git at `9806710e`, imports it as its own module beside today's, and asks both the same
questions in one run.

⛔ **The instrument is checked before it is believed** — a module that had silently resolved
to today's would pass every refusal for the wrong reason, which is a no-op plant wearing a
green tick. So one check asserts the loaded module's key set is the **strict subset** that
predates this task, and its negative control asserts the same module still READS a record
written before it.

| direction | reading |
|---|---|
| a document carrying `kind`, `cases`, `report` or `origin` | ⛔ **refused** by the previous reader, naming the key — each of the four, and all four together, and through `of` on a practice document |
| the same documents | ⭐ **read** by today's reader, in the same test module, so the two claims cannot drift apart |
| every record this repository committed before `AX-00` | ⭐ **read identically** by both readers, field for field, and **written back byte for byte** — key order included — by both |

⚠️ **`kind` is carried as its DEFAULT token in that population deliberately.** A document
saying the one thing the previous reader already assumed is still a document it must refuse,
because what it cannot do is read the key at all.

## Decisions

- ⭐ **`cases.py` owns the VOCABULARY and `record.py` keeps the DOCUMENT**, and that is the
  named seam. The record decides which keys exist, which are written and in what order; this
  module decides what they may say. ⛔ Both modules are inside R11's bound with the seam and
  neither would have been without it.
- ⛔ **`code` is the default and is NOT written out** — ⚠️ **the one place this record departs
  from `trust`'s ruling**, which writes a defaulted field so it cannot be told from one nobody
  wrote. ⭐ **The difference is the installed base.** `trust` is defaulted inside a half that
  is already written whole; **every** `exercise` record that exists is `code`, so writing the
  token would re-render every archive document ever written — the cost `W357` refused to pay
  for a version bump, under R10, for exactly this reason. ⭐ An absent `kind` is unambiguous
  *because* `code` is the only kind that has ever existed, which is the claim a defaulted
  `trust` could not make. ⚠️ **The cost, stated:** a document that writes `"kind": "code"`
  explicitly round-trips to one without it. The value round trip holds; the bytes are
  canonicalised. An adapter writing that token gets a build whose output does not carry it.
- ⛔ **`cases` and `report` are ONE claim, written whole or not at all, and only beside a
  grader.** `cases` with no `report` names tests nothing can be read from; a `report` with no
  `cases` is a file nothing folds through. ⭐ The precedent is the grader half itself, and the
  refusal names the key, which is the Acceptance clause.
- ⭐ **`origin` is NOT a grader fact**, so it is the one new key an **ungraded** record may
  carry. An exercise authored from a page was authored from that page whether or not anything
  checks the reader's answer, and the source ledger (spec §7 §3) has to resolve its entry
  either way.
- ⛔ **`origin`'s rule is imported, never re-spelled.** `fields.optional_origin` is the tree's
  one reader of that key (`W109`, a standing property and not a reading at one ref), so
  `cases.origin_in` hands the value to it and re-raises its sentence under `ExerciseError` —
  ⭐ character for character the shape `record._trust` already uses for R5. ⚠️ **The dependency
  direction is stated rather than inferred:** `exercise` imports `corpus.container`, and
  nothing in `corpus` imports `exercise`. ⭐ The better home is a leaf both packages ask, the
  shape `sourcepath` and `describe` already have — **filed as `AX-00/2`, not built here.**
- ⭐ **`origin_in` takes the RECORD, not the value.** That is not a convenience: the key is
  read only where it is handed to its one reader, so no second site in the tree reads an
  `origin` and decides something.
- ⭐ **`cases` is an ARRAY, not an object keyed by id.** The reader is shown them in order, and
  a repeated id must be refusable rather than silently one entry. ⛔ Three refusals beyond the
  Acceptance, each argued: an **empty** array (absent and empty are different mistakes), a
  **repeated** id (a map that is not a map folds one result into two cases), and a map naming
  **no `main` case** (the breakdown a reader is shown is *main ask* plus *edge cases n/m*, so a
  map of edges alone describes a run whose ask nothing reports).
- ⭐ **A case `id` is permitted a wider set than a path or an argv token**, because it is
  compared byte for byte with what a report spells: a Java `Class#method`, a pytest
  `file::test[param]`, a parameterised `name(int,int)`. ⛔ It carries no whitespace, and the
  pattern is anchored `\A…\Z` rather than `^…$` — see `AX-00/1`.
- ⭐ **`REPORT_FORMATS` is `("junit",)`, a closed set of one.** Console output is deliberately
  not a format: the quiet run modes rewrite that stream by design, which is `AX-01`'s own
  argument, stated once where the token lives.
- ⛔ **A `quiz` record round-trips today, and the quiz SHAPE is `AX-05`'s.** What lands here is
  the token and the refusal of any other. ⚠️ **A `kind: "quiz"` record must still satisfy
  `REQUIRED_KEYS` on this branch** — see *For dependents*.
- ⛔ **No fixture was added and none was modified.** Every new-key document lives in the test
  modules, where a shape being *refused* cannot be mistaken for material, and the pinned counts
  in `test_record.py`'s fixture sweeps are untouched.
- ⭐ **Two existing tests in `test_record.py` were RESTATED, not deleted**, and both restatements
  are strictly stronger: the key partition is now three-way with the new group asserted
  disjoint, and the graded round trip names the six keys a record with no authored material
  writes (derived from `AUTHORED_KEYS`, so a fifth key cannot narrow it silently).

- ⚠️ **`record.py` was 245 lines, not "near R11's bound".** The brief and the epic both give
  that as the reason for a new module. ⭐ **The seam is right anyway and was kept** — the
  vocabulary and the document are different subjects, and `record.py` is 367 lines now, so the
  premise would have become true by the end of this task and `AX-01`'s and `AX-05`'s additions
  land on top of it.
- ⛔ **`W109`'s sweep caught the second spelling of `origin` that this task's first draft
  wrote**, and refused it in the suite rather than in review. ⚠️ It is worth saying that the
  instrument is not scoped to the container map: its subject is the KEY, anywhere in `src/` and
  `tests/`, which is what made it reach a brand-new package on its first commit.
- ⚠️ **That sweep resolves a subscript's key through every module-level binding of the
  variable's NAME**, not only the enclosing comprehension's. A new module-level
  `for key in EXERCISE_KEYS` in `test_record.py` therefore made an unrelated `RECORD[key]`
  three lines away read as an access to `origin`. ⭐ Repaired by naming the loop variable
  something else, with the reason written beside it; filed as `AX-00/3`.
- ⚠️ **A `slots=True` dataclass cannot be defined by a module executed outside `sys.modules`** —
  it rebuilds its class and resolves `cls.__module__` through that table. The previous reader
  is therefore registered under a name carrying its ref while it runs, and removed after.
- ⛔ **The adapter author's reference is BOUND to this constant by a test.**
  `tests/test_authoring_reference.py::test_the_exercise_keys_the_reference_shows_are_the_shipped_keys`
  asserts the first JSON fence in [`docs/authoring/exercises.md`](../../authoring/exercises.md)
  carries `EXERCISE_KEYS` **whole, in order** — so appending four keys made the suite RED on a
  document, and updating that document is part of landing the contract rather than scope this
  office chose. ⭐ **That is the convention working** ("a tightening owns its migration"), and
  it is why `W357/3`'s first half cannot recur. ⚠️ **One consequence, stated:** that fence must
  therefore show `"kind": "code"`, which is a key the build writes back only for a `quiz`. The
  page says so in the sentence beside it.
- ⛔ **`^…$` with `.match` accepts a trailing newline**, which is how the first draft of the
  case-id pattern let `Test#x\n` through. ⚠️ **The same spelling is live in `safety.py` today**
  — `AX-00/1`, and it is not a test-only curiosity.

### ⭐ What you get from a record

```python
from studyforge.exercise import of, Case, Report, Origin, MAIN, EDGE, JUNIT

exercise = of(practice_document, where)  # an Exercise, or None
exercise.kind  # "code" (the default) or "quiz"
exercise.cases  # tuple[Case, …] | None — in the order the corpus wrote them
exercise.report  # Report(format, path) | None
exercise.origin  # Origin(path, section) | None — section is None for a whole file
exercise.breaks_down  # graded AND both breakdown keys present
case.id, case.kind, case.says, case.ask  # `ask` is `kind == MAIN`
```

### ⛔ `AX-01` — the case report

- ⭐ **`cases` is ORDERED and its ids are DISTINCT**, both guaranteed by the reader, so a fold
  may key a map on `case.id` without checking for a collision. ⛔ **At least one case is
  `MAIN`**, also guaranteed — so *main ask* always has something to report, and
  `edge cases n/m` counts `EDGE` cases only.
- ⭐ **`exercise.breaks_down` is the ONE question to ask before folding anything.** It is
  `graded AND cases AND report`, and it is false for every record shipped before `M10`. ⛔ Do
  not test `exercise.cases is not None` — the dataclass is frozen, not validated, and an
  unvalidated one can carry anything.
- ⭐ **`report.format` is `JUNIT` and the set is closed at one.** Widening it is a line in
  `cases.REPORT_FORMATS` plus whatever reads it; ⚠️ if you find a report id your fold cannot
  express, the value to widen is `cases.CASE_ID`, whose permitted set is written down in
  `CASE_ID_PERMITTED` and measured against four real spellings in `test_cases.py`.
- ⚠️ **`report.path` is a WORKSPACE path** — `safety.require_path`'s rule, relative, inside the
  reader's workspace — and it may name a **file or a directory**: surefire writes a directory
  of XML, pytest writes one file. ⛔ **Deciding which, per format, is `AX-01`'s** and is not
  decided here. Nothing in this task touches the filesystem.
- ⛔ **A run that wrote no report is not a refusal at this layer.** The record says where the
  report *should* land; whether it is there, and whether it is stale, is `AX-01`'s Acceptance.
- ⭐ **`says` is the reader-facing sentence and it is never reproduced in a refusal here** (R7).
  It is guaranteed non-blank text and nothing else — no length bound, no punctuation rule.

### ⛔ `AX-05` — the quiz shape

- ⭐ **The token is yours already**: `kind_of` reads `"quiz"`, `Exercise.kind` carries it, and
  `to_document` writes it (it is not the default, so it is always written out). An unknown kind
  is refused naming both permitted tokens.
- ⛔ **A `quiz` record must still satisfy `REQUIRED_KEYS` — `main_path` and `run_command` — on
  this branch, and that is the thing you will change.** ⚠️ It is stated rather than
  pre-built: §7 says a quiz carries **questions** in place of a workspace, and writing a
  required-key set per kind before the quiz record existed would have been this office
  designing your contract from the outside. ⭐ **The seam for it is `record._require_present`,
  which is the one function that decides what a record must carry**, and the kind is already
  read before any of it (`_authored` runs first), so the dispatch costs a parameter.
- ⭐ **`origin` is already yours and needs nothing from you.** A question's passage is an
  `Origin(path, section)` — `SF-36`'s region, Ruling 92's heading bound — and it is the one new
  key an ungraded record may carry, so a quiz that grades without a run still records what it
  was written from.
- ⛔ **`cases` and `report` are refused on anything ungraded, naming the key.** A quiz produces
  no run, so if a quiz ever needs a per-question breakdown it is **not** these two keys; say so
  in your row rather than relaxing this refusal, because the refusal is `AX-00`'s Acceptance.
- ⚠️ **R5 is untouched and is asked only of a grader.** A quiz record that names no grader is
  never put to `unit.trust`; one that does is, and `generated` + `authoritative` is refused
  exactly as before.

### ⛔ `AX-03`, `AX-04` and anything that WRITES a record

- ⭐ **Write the keys you carry and no others.** `to_document` chooses keys by the record's
  SHAPE, never by which values are `None`, so an `Exercise` built by hand cannot write half a
  grader or half a breakdown — and `kind` is written only when it is not `code`.
- ⛔ **A document written before `AX-00` round-trips to the same bytes**, which is what lets
  this land with no version bump. ⚠️ **If a later task makes any of these four keys
  unconditional, that property dies and every archive document in existence is re-rendered** —
  `tests/studyforge/exercise/test_previous_reader.py` is where it fails, on every committed
  record at once, and that is deliberate.
- ⭐ **`raw_api` is unchanged at `1`, by `archive/document.py`'s own rule**: every document
  valid before is valid now and means the same thing, and an older build refuses the new shape
  rather than misreading it. ⛔ **That second half is RUN, not asserted** — see *The
  two-directional reading* above, and copy its shape rather than re-deriving it.
