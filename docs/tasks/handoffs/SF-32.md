## Decisions

⭐ **The measured population is placement's population, not a list retyped
here.** `measure` takes the `UnitLocations` placement already answered with and
walks `UnitLocations.directories`, which derives from `UNIT_MEDIA_DIRNAMES` —
the same tuple `Profile.media_ignore_lines` covers. ⛔ A footprint that weighed
less than the ignore rules covered would clear a limit by not looking, so the
two populations being one population is asserted rather than assumed.

⛔ **One place inverts the policy.** `ignore_lines(profile, verdict)` exists so
a second caller does not write `media=not manifest.media.commits` for itself;
two spellings of one inversion are right until one of them is edited. See
`SF-32/4`.

⭐ **An absent media directory is an honest zero, and a root that is not a
directory is a refusal.** Refusing on the first would fail the first build of
every corpus on the absence of the thing it was about to create.

⛔ **The two frozen field names are CONFIRMED, not renamed.** SF-02's routed
finding offered the rename; Ruling 104 closed that window at CTO round 28, and
this row re-reads them off `MediaPolicy` rather than retyping them
(`LIMIT_TOTAL`, `LIMIT_FILE`).

### ⛔ The scheduled cell — *a `provides` bump invalidates every recorded address*

⭐ **ACKNOWLEDGED, which is the act the trigger names** (`NS-05/8`, `NS-04/4`,
carried in `PO-2026-09-12-round58.md`). ⛔ **This row does NOT apply, and the
reason is measured rather than asserted.**

⚠️ **Measured at this branch's tip, population `src/studyforge/corpus/media/**`,
instrument `git grep`:** imports of `studyforge.narrate` — **0**. Occurrences of
the `Address` type — **0**. Reads or writes of the narration record — **0**.
The package's whole import surface is `corpus.manifest` (for `MediaPolicy`),
`corpus.placement` (for `UnitLocations` and `Profile`), `studyforge.describe`
and the standard library.

⭐ **And it records nothing of its own.** Every reading is taken fresh from the
disk in the call that needs it; there is no cache, no state file and no
persisted value — so there is no recorded address here for a bump to
invalidate, and nothing this package holds can go stale between runs.

⚠️ **The one consequence worth stating, so the next reader does not re-derive
it.** A bump invalidates the record's addresses but leaves the **files** on
disk, and `SF-16`'s filename is `<speech-id>-<digest of spoken text>` — which a
`provides` bump does not move. So re-synthesis overwrites in place: the file
**count** in a footprint is unchanged and the **total** moves only by whatever
the new conditions cost per clip. ⛔ **A bump is therefore not a footprint
event.** The footprint event in this family is `W187/1`, and it is `SF-32/5`.

## Surprises

⚠️ **The row's own JSON example declares a third limit the shipped manifest
refuses.** `"max_files": 20000` appears in the row; `parse_media`'s `known` set
is `{commit, max_total_bytes, max_file_bytes}` and an unknown key is a
`ManifestError`. That is `SF-32/1`, and it is the reason the acceptance's *"the
file **or count** responsible"* is only half-served.

⚠️ **The refusal is the product here, not a side effect.** `MediaError` carries
the whole report — the number, the limit, the files responsible and the two
ways forward — because a refusal with no way forward is a wall, and this is the
moment the extraction source never had.
