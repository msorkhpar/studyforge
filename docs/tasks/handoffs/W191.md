## What landed

⭐ **1. The measurement the row demanded FIRST — and it changes the remedy.** ⛔ **The
two populations do not merely differ; one CONTAINS the other**, measured at `883dae6`
by reading the code rather than by argument:

| direction | the answer, and where it is read |
|---|---|
| ⛔ everything the floor fails on, the suite also fails on | [`tests/test_quality_floor.py`](../../../tests/test_quality_floor.py)`::test_the_quality_floor_is_clean` calls `run_all(repository_root())` and asserts it empty — the floor's whole failing population, inside the suite. Its own docstring says why: *"With it, `pytest` is sufficient."* |
| ⭐ the suite fails on much the floor cannot | `ruff check` and `ruff format` ([`tests/test_repository.py`](../../../tests/test_repository.py), Ruling 78 — the floor is standard-library-only by Ruling 77 and may only report the linter's absence), every behavioural test, every in-image assertion, and the sibling/workspace assertions the image cannot reach |

⛔ **So this was never a MERGE of two populations — it is a DISCLOSURE that the floor
is the WEAKER gate, wholly inside the stronger one.** ⚠️ **An office that read the
floor's `0` and inferred the suite's inferred the wrong way round**, and no amount of
adding checks to the floor would have fixed it (Ruling 78 is not overturned here, and
nothing was moved into the floor).

⭐ **2. `python3 -m tools.quality.certify` — one command, one exit code.** It reads
`tools.mergegate.GATES`, runs every gate, and prints one block:

    certification: ref <sha> · role <main checkout|linked worktree>
    floor [pinned image]: GREEN exit 0
    suite [pinned image]: GREEN exit 0
    suite [host]: GREEN exit 0
    ⭐ CERTIFIED: every declared gate is GREEN at this ref … (exit 0)

⛔ **Exit `0` certified, `1` not certified, `2` UNREAD** — no gate declared, no ref, or
a dirty tracked tree, and an UNREAD run is never a pass (Ruling 191).

⭐ **3. `--check FILE` reads a PASTED block** and refuses a claim that is not whole:
every declared gate present, each green, with a ref. ⛔ **It cannot read that a command
was RUN, and the module says so in its own contract** — see *Decisions*.

⭐ **4. The convention now names the requirement in a form an office cannot meet by
halves.** The merge-condition table's two rows — *the floor green*, *the suite green* —
are ONE row: **every declared gate, read by one command**. ⛔ **Which gates those are is
no longer enumerated in prose in any of the three documents that carried it**, because a
list in prose is exactly what an office satisfies half of.

## Decisions

⛔ **1. It is a COMMAND, in neither `CHECKS` nor `NOTICES`, and it runs no suite inside
the floor.** ⭐ Rulings 77/78 keep the two gates separate and this row does not touch
that: `python3 -m tools.quality`'s population, exit code and output are byte-for-byte
unchanged. ⚠️ It lives under `tools/quality/` because the row's dispatch put its surface
there; the mirror asserts it is registered in neither list, so the floor's exit code
cannot depend on it (`mergegate.py`'s own argument, cited rather than re-derived).

⛔ **2. It declares NO gate — that is what keeps it from being the third instrument the
row forbids.** ⭐ Two gates that disagree are not fixed by a third that agrees with
neither, so the population is `tools.mergegate.GATES`, READ. ⚠️ **The consequence is the
point:** the office's certification and the coordinator's re-reading on the merged tree
cannot name different populations, and a gate added to that list is one the office is
already running. ⛔ `tools/mergegate.py` is UNTOUCHED — no behaviour, no entry, no line.

⛔ **3. One behavioural difference from the merge gate, deliberately.** `mergegate`
stops at its first red; this does not. ⚠️ **There the merge is already refused and a
later gate cannot change the outcome; here a partial reading IS the defect** — an office
that stopped would hold exactly the half reading this row exists to refuse, and would
meet the other gate on the next round.

⛔ **4. What `--check` can and cannot do, stated rather than implied — this is the row's
checkability clause, answered honestly.** ⭐ **No instrument can read a claim about a
command somebody ran.** What is readable is whether a claim is WHOLE, so a record that
ran one gate and claimed both is caught: the block it must paste is one it cannot
produce. ⛔ **A record that FABRICATES the missing line is not caught by any reader** —
**the instrument that catches it is `tools.mergegate`**, which re-runs this same
declaration on the merged tree and refuses the merge. ⚠️ **The cost is named because it
is real: that catch lands at merge time, on the coordinator's clock, rather than at the
claim.**

⛔ **5. `--check` is a COMMAND and deliberately NOT a floor check over
`docs/tasks/handoffs/`.** ⚠️ **Measured at `883dae6`: of `255` task handoffs, `2` carry
both `FLOOR_EXIT` and `SUITE_EXIT`, `27` carry `FLOOR_EXIT` alone and `226` carry
neither** — and reading the `27` shows most are PROSE ABOUT the block (`W295/6`,
`W297`'s findings), not certification claims. ⭐ **The readings are not in the tree at
all: they live in the hand-back message**, which [`W220`](W220.md) states in its own
words — *"their readings and exit codes are in the hand-back, not here"* — because a
handoff cannot quote the sha of the commit that contains it. ⛔ **A floor check there
would have an empty real population**, which Ruling 191 makes a defect rather than a
pass, so the reader is a command the coordinator or the office points at a file.

⛔ **6. R7: the ROLE is a KIND of checkout, never a path.** ⚠️ **The block this rubric
told every office to paste ran `git rev-parse --git-common-dir` and called its output
THE ROLE** — an absolute path carrying a home directory, which R7 forbids in any record
or message. ⭐ It is gone from the obliged block, `certify` prints `main checkout` or
`linked worktree` instead, and a test asserts the header carries no path separator.
⛔ **Frozen records that already pasted one are NOT chased** (the remedy is
forward-looking, `W301`'s own form), and no such instruction survives in
`docs/conventions/` — measured: `git grep -n git-common-dir docs/conventions/` prints
nothing at this tip.

⛔ **7. The out-of-surface test edit, disclosed under
[Ruling 143](../../conventions/review-rubric.md#ruling-143-cto-round-39-an-out-of-owns-test-edit-under-three-bounded-conditions).**
[`tests/docker/test_dev_check_rubric_form.py`](../../../tests/docker/test_dev_check_rubric_form.py)
is `W301`'s module and it reads the obliged block, so changing that block RED-ENS it.
⭐ **All three conditions hold: (1) it pins a defect and says so in its own body; (2)
every assertion is RE-POINTED at the population that now carries the answer —
`tools.mergegate.GATES` — and the ONE control that INVERTS says so in its own comment
(the block used to owe the wrapper two invocations and now owes it NONE); (3) it is
disclosed here, by path.** ⛔ **Nothing was deleted.** ⚠️ `W301`'s property is
strictly stronger afterwards: it is now asserted against the argv that RUNS, not
against text an office retypes.

⛔ **8. The clause was edited in all three documents that carry it.** ⭐ The dispatch
said *keep any convention edit to the clause you are changing*, and this IS one clause
with three homes — [`review-rubric.md`](../../conventions/review-rubric.md) (the
runnable form), [`delivery-flow.md`](../../conventions/delivery-flow.md) and
[`agent-protocol.md`](../../conventions/agent-protocol.md) (both of which enumerated
the two gates in their own words). ⚠️ **A
half-edit would have left two copies saying the thing this row exists to remove.**

## Surprises

⛔ **1. The floor is INSIDE the suite, and has been since `tests/test_quality_floor.py`
was written.** ⚠️ The row is framed as *two gates that can disagree*, which invites
*merge the populations*; the measurement says the containment is one-directional and
already complete in the direction that matters. ⭐ **The defect was never the
populations — it was that the OFFICE-FACING ARTEFACT was a phrase.**

⛔ **2. The commands were only misspellable because they were TYPED INTO A DOCUMENT.**
⚠️ `W301` corrected one instance — a bare `docker/dev/check` redirected into
`floor.txt`, which runs the image's own `CMD` (the suite) and still exits `0`. ⭐ **The
class is gone rather than the instance: no gate command is typed into the rubric at all
now**, so there is nothing left there to respell.

⛔ **3. The dispatch's four gates and `GATES`' three are not the same list.** See
`W191/1`.

## For dependents

⭐ **What an office does from now on**, at the ref that will merge, from its own
checkout, on the host (the command starts the pinned image itself, per gate):

    python3 -m tools.quality.certify > "$CAP/certification.txt" 2>&1
    CERTIFY_EXIT=$?
    cat "$CAP/certification.txt"
    python3 -m tools.quality.certify --check "$CAP/certification.txt"

⛔ **Paste the block UNEDITED.** ⚠️ `--check` reads the grammar `render` writes, so an
edited block is refused for the same reason a half one is. ⭐ **`CERTIFY_EXIT` is the
whole certification: there is no second reading to remember.**

⛔ **A red gate still stops the merge and there is no office to appeal to.** ⚠️ **An
`⛔ UNREAD` line — exit `2` — is not a pass**: it means the tree is dirty, the ref is
unreadable, or no gate is declared, and the fix is to commit and re-run rather than to
report anything.

⭐ **For the coordinator:** `--check` also reads a merge body or a hand-back pasted into
a file, and refuses a claim missing a declared gate BY NAME. ⛔ **It cannot tell you a
command ran** — `tools.mergegate` is what reads that, on the merged tree.
