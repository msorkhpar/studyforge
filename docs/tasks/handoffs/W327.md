### ⛔ THE DESIGN DECISION, stated first: `buildserve` was EXTENDED, not joined by a new skill

⭐ **The brief offered either a narration skill of its own or a declared,
argued extension of [`buildserve`](../../../src/studyforge/skills/buildserve/SKILL.md). The extension was taken, for four reasons:**

1. ⛔ **Spec §9 divides the skills by what they *are*, and a narration skill
   would be on the wrong side of its own rule.** *"A skill precedes the artifact
   it produces"*; `studyforge narrate`, the narration record and the clip naming
   all already exist, so a skill minted over them now would be a
   **retrospective** — §9's word — validated against exactly one source.
   `buildserve` is already declared there as one of the *"wrappers over entry
   points that already work"*, which is precisely what this is.
2. ⛔ **`buildserve` already owns the narration step.** It runs the verb, it
   reads the record, and it prints the partial state. The defect is a sentence
   **in this skill** — *"Optionally, a running narration service"* — and a second
   skill would leave that sentence standing.
3. ⛔ **Two skills owning narration is the gap, restated.** The row exists
   because an operator is not told narration is available; making them first
   work out *which skill to read* to find that out is the same defect one layer
   up.
4. ⭐ **The seam is real and was cut, so the extension is not a bulge**:
   `narration.py` is the component's facts, `states.py` is the partial states,
   and each has its own mirror.

⛔ **What that costs, and it is a real cost (§9).** Everything this row documents
was validated against **one** deployment of one component. The first honest test
of it is a second operator on a second machine — which is exactly where §9 says
a retrospective fails. ⭐ **What bounds it:** nothing here restates the
component's API, so what can be wrong is the *pointer* and not a copy of the
contract, and the promise the framework built against is now **read from that
component's own `consuming.json` by a test** rather than believed.

## Decisions

1. **The distinction is read from what HAPPENED, never from a declaration.** No
   manifest declares narration, and the plan places a unit's audio directory for
   every declared unit whether or not anything is speakable — so neither could
   answer *could this corpus speak*. ⭐ The narration run's own exit code can: a
   run that finished against a service and placed no clip **is** the answer that
   there was nothing to say. ⛔ And a run that never happened is reported as
   unfinished rather than guessed at, which is the half the row is about.
2. ⚠️ **The bound on that reading, stated rather than left to be found.**
   `code == OK` with no record also covers a run every one of whose segments the
   service reported `skipped`. Both are *"it asked and got nothing"*, which is
   what the state's sentence says; it does not say *the corpus declares no
   speakable block*, because this skill does not read one.
3. **`NO_NARRATION` was renamed `NOT_NARRATED`.** With a second silent state
   beside it the old name answers neither question. The printed state **name**
   is unchanged (`narration`), so nothing a person or a grep reads moved.
4. **`cli.narrate.cli` was admitted to the thin skill's allowed imports, for
   `DEFAULT_SERVICE` alone.** The argument is `NO_SERVICE`'s, which that test
   already accepts: a skill that told an operator to start a service on a port
   the verb never calls would be worse than saying nothing. ⛔ It buys the
   constant — no client, no transport, no socket; the module-level import of the
   HTTP client that `W223` moved is still deferred inside `main`.
5. **Narration itself is not fenced**, following [`W313`](W313.md)'s decision 6: it needs a
   running service, which a document cannot promise. `narrate --help` is fenced
   instead and is executed like the rest, and it is what binds the section's
   stated address to the verb's actual default.
6. **The first-start fetch is a plain sentence, not a command.** It cannot be
   read out of the component's `consuming.json` (see the findings), and §8.3
   forbids this skill starting anything — so the section states what will happen
   and sends the reader to that component's own README for the doing.
7. **Only the narration section's fences are executed.** Step 1's invocation
   serves until interrupted and step 2's verbs need a corpus root; making those
   executable is a harness this row did not need. Recorded as a finding.

## Surprises

- ⚠️ **The remedy an operator reads was already *"start the narration service"* —
  and named nothing.** The gap was never a missing sentence; it was a sentence
  that pointed at something the reader had no way to identify, start or find.
  ⭐ That is why this row is mostly *facts and pointers* and only a little logic.
- ⚠️ **`studyforge narrate`'s own refusal has the same shape**, and is outside
  this surface: see the findings.
- ⭐ **The pinned image is the honest half of the promise check.** Two tests skip
  in there, each saying why — the image mounts exactly one directory, which is
  the same reason `tools.workspace` refuses to answer in there rather than
  reporting every sibling absent. On the host both ran.
- ⚠️ **A wrapped line defeated a first draft of the document checks.** The
  section's prose is read with its whitespace collapsed, so a re-wrap cannot turn
  a check green or red; the fences are read unwrapped, because a command's line
  breaks are the command.
