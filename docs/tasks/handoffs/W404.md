## What landed

⭐ **[`tools/workspace/pinned.py`](../../../tools/workspace/pinned.py) — one
reader, and it answers with a state rather than with bytes.** `read_sibling`
resolves a component through the pin file and reads one file out of it at the
commit that file records. `read_directory` reads a directory a caller named.
Both return a frozen `Reading` carrying `state`, `text` and `source`.

⭐ **The three outcomes are a closed set and each carries its own sentence:**

| state | predicate | what it means |
|---|---|---|
| `PINNED` | `reading.pinned` | read at the commit the pin file names — ⭐ the only reading another host reproduces |
| `WORKING_TREE` | `reading.working_tree` | read off disk — ⚠️ **labelled LOCAL**, and the sentence says why the pin was not usable |
| `ABSENT` | `reading.absent` | nothing to read — ⭐ **an answer**, which is the pinned image's case |

⭐ **The working-tree reading is kept and labelled rather than refused, and that
is the design.** Refusing one would turn *"the sibling moved off its pin"* into
a crash; a caller that needs reproducibility asks `reading.pinned` instead of
asking for `reading.text`. ⛔ **The policy lives with the CALLER**, once:
`container.reason_for(reading, must_be_pinned=…)`.

⭐ **`ABSENT` is why nothing crashes inside the pinned image.** Only the checkout
is mounted in there, so no sibling resolves at all — **measured** in the image
suite above, where the runner cases skip saying *"no checkout of
code-server-toolchain sits beside this repository"*. ⛔ That was a first-class
requirement of the dispatch and it is asserted, not hoped for.

⭐ **`tests/studyforge/execute/container.py` now reads the contract at the

## Decisions

1. ⛔ **`git cat-file blob <commit>:<path>`, never `git show`.** `show` prints a
   **tree listing** for a directory and exits `0`, so a reader built on it hands
   that listing back as if it were file content. ⭐ Asserted:
   `test_a_path_that_is_a_directory_at_the_pin_is_never_read_as_content`, with
   the file inside that directory reading fine in the same case, so the refusal
   is about the **shape** and not about the path.
2. ⛔ **A working-tree reading is labelled, not refused, inside the reader.** The
   refusal belongs to the caller, because *"the sibling moved"* is a sentence a
   person needs and a crash is not. ⭐ The policy is one parameter,
   `must_be_pinned`, stated once and asserted in both positions.
3. ⛔ **A directory a caller names is NOT one of the three states' business.** It
   is `WORKING_TREE` by construction and `must_be_pinned=False` — this is what
   keeps every existing synthetic fixture in `test_container.py` meaning what it
   meant while the real sibling is held to its pin.
4. ⚠️ **The predicate is `reading.working_tree`, and the name it is NOT is the
   shorter one everybody reaches for first.** ⛔ **It cannot be written here
   either** — that word is the mDNS suffix, so an attribute access ending in it
   is host-name shaped and the personal-data floor reports every consumer under
   R7. ⭐ **Measured twice: 8 findings and a RED floor across five source files
   before the rename, and once more in THIS handoff**, which tripped the same
   check by naming the rejected spelling in prose. ⭐ Ruling 179 already records
   it as a known false positive; this row **avoided** it rather than asking for
   an exemption, and `W404/3` carries the remedy.
5. ⭐ **The reader lives in `tools/workspace/`, not in `tests/`**, because two of
   its four callers are already outside `tests/studyforge/execute/` and the two
   it did not take (`W404/1`) are elsewhere again. ⛔ A new module in the package
   rather than growth in `__init__.py` (339/400 lines), as the dispatch required.
6. ⛔ **`read_sibling` requires the component to be `present` in the pin file.**
   A `not-yet-created` row is a first-class register entry (Ruling 54), so it is
   a first-class *reading* too — `ABSENT` with a sentence — never a lookup that
   falls through to whatever happens to sit on disk under that name.

## For dependents

- ⭐ **Read a sibling's file with
  [`tools.workspace.pinned`](../../../tools/workspace/pinned.py) and nothing
  else.** `read_sibling(name, path, repository_root=…)` gives you the three
  states; take `reading.pinned` when your result has to reproduce on another
  host, and **report `reading.source`** whenever you report `reading.text`. ⛔ Do
  not join a path onto `workspace_root()` — that is `W404/2`'s defect and it
  skips the pin file entirely.
- ⛔ **`absent` is not an error and your check must not treat it as one.** Inside
  the pinned image every sibling is absent; a reader that raised there would turn
  the authoritative environment red for a fact that is true of it. Skip, and
  quote the sentence.
- ⚠️ **Do not name a predicate, attribute or variable for the word this row
  avoided** (decision 4, `W404/3`) — the floor reports it under R7 and the
  finding lands on the consumer's file, not on the definition.
- ⭐ **For whoever takes `W404/1`:** the missing piece is one predicate on
  `Reading` separating *the pin could not be consulted* from *the pin carries no
  such file*. Both branches already exist inside `read_checkout` and each already
  has its own sentence; what they do not have is a name a caller can switch on.
- ⭐ **For `W402`, on the same package:** this row adds
  `tools/workspace/pinned.py` and its mirror only, and changes **nothing** in
