## Decisions

**1. How much was ported, and what stayed behind.** The instruction was not to
port whole and then split, so the boundaries were drawn from what the
*vocabulary* needs. What came across: the line classifier and every measured
width in it, the fence rules, lists, tables, images, the media embed. What
stayed behind: everything whose stated reason is *"to agree with the DOM
reader"*. That reason is the extraction source's, and studyforge has no DOM
reader, so it does not carry — it is the load-bearing half of three of the four
divergences below.

**2. The four divergences, and all four are intended.** Three are the ones the
task named; the fourth is new and is *agreement*, not divergence.

| | extraction source | here | why |
|---|---|---|---|
| thematic break | **no block at all** | `rule` block | `<hr>` is not a block tag for its DOM reader. 10 of 166 Java lessons use one; dropping it loses structure the author wrote |
| blockquote | inner blocks, **transparent** | `quote` wrapper holding blocks | same reason, same non-carry |
| `<details>` | tags dropped, **summary kept as a paragraph** | `disclosure` container | ⛔ not merely different: **every** surveyed use hides an exercise answer, and flattening shows it outright |
| unknown tag alone on a line | prose | **prose** | see Decision 4 — the same answer, reached from CommonMark rather than from a DOM |

**3. `disclosure` is read as a container, and the body is recursed into.** The
rejected opaque-`html` reading would keep the hiding and make the body
invisible: a fenced query inside an answer would not be a `code` block —
uncounted, unhighlighted, invisible to SF-25's gate. ⚠️ A test asserting only
that a disclosure is *present* passes against a parser that stores and never
looks inside, so `test_the_body_is_recursed_into_rather_than_stored` asserts
the inner block types instead.

**4. ⭐ `html` uses CommonMark's own block-tag list, and this resolved an
ambiguity in the task text rather than re-ruling anything.** SF-07 says both
*"`html` survives for genuinely unstructured markup"* and *"an unknown tag on
its own line stays prose"*, which read as contradictory until CommonMark
separates them: its **type 6** HTML block requires a **named block-level tag**
(`div`, `figure`, `table`, …); its **type 7** would open a block for any tag
alone on a line. This reader takes type 6 and deliberately **not** type 7. Both
sentences are then literally true, `<div class="callout">` is an `html` block
and `<marquee>hello</marquee>` is prose — ⭐ which is also what the extraction
source does, so it is one fewer divergence rather than one more.

⚠️ It matters beyond tidiness: a paragraph that merely *opens* with something
tag-shaped keeps its inline emphasis, which an `html` block would render
verbatim and lose.

**5. The container readers receive `parse` as an argument.** They are the only
readers that recurse. Passing the dispatcher in keeps the dependency one-way —
nothing else in the package can loop back into `document` — and it makes both
testable against a stub, which two tests use.

**6. Fence awareness is architectural, not a special case.** `scan.block_kind`
tests for a fence **first**, so nothing inside one is ever classified; and
`container.find_close` skips a fence using **the code reader itself**, so
"where does this fence end" has one definition and cannot drift. ⚠️ The second
half is the one a reader gets wrong: a disclosure whose body quotes a
`</details>` inside a fence closes early, ends the withheld section, and spills
the answer onto the page.

**7. A disclosure with no `<summary>` is not a refusal.** It is legal markup
and nothing is lost — the label is simply empty. Only material that cannot be
represented without loss raises, and there are exactly three such constructs:
an unclosed fence, an unclosed `<details>`, an `<img>` with no `src`.

**8. `BLOCK_TYPES` is eleven and `CONTAINER_TYPES` is two.** Both are exported
because a walker needs to recurse on containers without knowing which they are
— ⭐ FND-04's own lesson: `disclosure` was forgotten by every walker precisely
because the set of containers was implicit.

## Surprises

**⚠️ The context field is wrong about the shape of the work, and the epic says
so in a warning that turns out to be exact.** Reading is ~35k; the acceptance
is a computation. What it does not say is that the *port* is the small half:
the source's parsing rules transferred almost unchanged, and the time went into
the four divergences and into building an acceptance that could tell a real
disagreement from a deliberate one.

**⭐ Running the extraction source's own test file against the port is the
cheapest acceptance in the task, and nothing suggested it.** One `sed` on the
import line; every assertion stays theirs. **85 of 102 pass unchanged, 17 fail,
and all 17 are the three ruled inversions** (9 thematic-break, 5 quote, 3
disclosure). ⚠️ That number is the acceptance: "their tests pass unchanged"
cannot be literally true when three behaviours are deliberately inverted, and
*which* ones fail is the only evidence that nothing else drifted. Two failures
were mine and real — they are what produced Decision 4.

**The recount matched the task's numbers exactly, on the right denominator.**
`rule` in **10** of the 166 lesson files and `quote` in **1**, which is what
SF-07 predicted. ⚠️ Over *all* 218 markdown files in that repository it is 15
and 2 — same corpus, different denominator, and a number quoted without its
denominator is how the "18 ISO files carry raw HTML" claim survived.

**ISO's raw-HTML count is confirmed at 0, from the parser rather than from a
grep.** 49 files, 46 of them carrying fenced code, **zero `html` blocks**.
Every tag-shaped thing in that corpus landed in a `code` block, which is the
fence-awareness claim proved on the material that motivated it.

## Findings

**1. `[local]` — the fixture prose is load-bearing for the strongest test, and
nothing says so.** `test_authored_markdown_reproduces_the_committed_document`
holds two Markdown documents that must produce `depth1` unit 3's two archive
documents exactly, so the **prose is duplicated** between the test and the
fixture. Editing the fixture's wording breaks the test with a diff that looks
like a parser regression. ⚠️ Left as it is deliberately — the alternative is
generating the fixture from the Markdown, which would make the test agree with
itself. But the fixture README should say the text is quoted elsewhere.

**2. `[structural]` — `counts` and the container types are one contract with
two owners.** `document.BLOCK_TYPES` (this task) and FND-04's `COUNT_KEYS`
(`tests/test_fixture_consistency.py`) are the same eleven types written twice,
and `CONTAINER_TYPES` duplicates FND-04's `CONTAINER_BLOCKS`. They agree today
and a test asserts the fixtures' types are a subset of the vocabulary — but
nothing asserts the *reverse*, and nothing ties `counts`' key names to the type
names. **SF-06 owns the archive document and should own one list**, with this
package and the fixture checker both reading it.

**3. `[structural]` — the archive has no `math` block and one corpus may need
one.** Not hit by any of the three real corpora and not invented here (R6's
answer is a vocabulary that covers what real material *contains*). Recording it
because display maths is named in the epic's list of upstream fixes and there
is no block for it: if a fourth corpus arrives with `$$…$$`, it becomes prose,
which is a silent loss of exactly the kind this reader exists to refuse.

**4. `[local]` — the media-embed wrapper is the one place a line produces no
block**, and it is not a silent drop: the `src` is the content and the opening
tag already emitted a `video` block for it. ⚠️ But a stray `</video>` with no
opener also produces nothing, and that *would* be a silent drop. Not fixed —
no corpus has one, and inventing the case would mean guessing what it means.
Worth a check in SF-25's completeness gate rather than a guess here.

**5. `[structural]` ⛔ **`release/m0-foundations` is RED in the container
today, and it is not this branch.** Found by trial-merging before reporting,
which is what the gate now asks for. `ruff format --check` refuses
`docs/tasks/handoffs/SF-01.md`, and the suite fails with it:

```
=== release/m0-foundations ALONE (no SF-07), HEAD=7a82249 ===
1 file would be reformatted, 108 files already formatted
FAILED tests/test_repository.py::test_ruff_format_is_clean_where_ruff_exists
1 failed, 358 passed, 8 skipped
```

⭐ **The cause is a thing nobody knew: ruff formats Python code blocks inside
Markdown.** SF-01's handoff aligns the trailing comments in its usage example
into a column, and the formatter reflows them to single-space. Every handoff
with a ` ```python ` block is therefore formatter-checked, and no branch
authored before FND-03's image existed could have seen it.

⚠️ Not fixed here — it is another task's file and my own branch is green in the
container (327 passed, 8 skipped, 0 failed). The fix is to unalign four
comments, or to accept the reflow; either is one commit. **Reported rather than
patched, but reported first**, because it blocks everyone and the longer it
sits the more likely somebody learns to read a red suite as normal.

**6. `[structural]` — `docs/tasks/README.md:288` and `CLAUDE.md:33` still say
"R1–R19" while the spec has R20.** Reported in FND-01, FND-03 and FND-06.
Still open.

## For dependents

**1. What you get.**

```python
from studyforge.archive.markdown import parse, MarkdownError, BLOCK_TYPES, CONTAINER_TYPES
```

`parse(text, lang_default="")` returns a list of blocks in document order.
⛔ It raises rather than returning a partial result. Catch `MarkdownError` to
**report**, never to continue: a caller that swallows it has reintroduced the
loss the reader exists to remove (R6).

**2. ⛔ Recurse on `CONTAINER_TYPES`.** `quote` and `disclosure` hold blocks.
A walker that does not recurse sees a disclosure's body as nothing at all —
which is how `disclosure` came to be missed by every walker in the first place.
`counts` counts **top-level** blocks; anything wanting the total recurses
deliberately.

**3. For SF-06 (archive document).** `BLOCK_TYPES` is the eleven names your
`counts` needs one key each for, and Finding 2 asks you to own the single list
both this package and the fixture checker read.

**4. For SF-08 (personal-data gate), which is next and mine.** Every `text`,
`summary`, `alt`, `title`, `src`, `lang`, header and cell is a string entering
the archive and must pass the gate. ⛔ `summary` in particular: it is content,
not a widget label. And the gate walks `CONTAINER_TYPES` or it will not see a
withheld answer at all.

**5. For SF-16 / E04 (narration).** ⛔ Speak a disclosure's `summary` and
**stop**. The body gets no speech ids, so a clip for it cannot be minted or
addressed, and the withheld count belongs in the coverage report. ⛔ Do not
invent a spoken sentence announcing the hidden section.

**6. For SF-12 (render).** The archive gives you `summary`, `open` and
`blocks`. The `<details><summary>` markup is **yours** (R13) — the vocabulary
deliberately does not prescribe it. `open` is the author's default and is
honoured, not overridden. An `html` block is stored verbatim and rendered
as-is, never parsed.

**7. For E07 (the Java adapter).** ⭐ **166/166 lesson files parse with zero
errors, producing 8,083 blocks.** Ingestion there is wiring, not parser work,
which is what this task exists to make true. The types those files actually
use: `heading` (166 files), `list` (166), `para` (166), `code` (165), `table`
(31), `rule` (10), `quote` (1). No `html`, no `disclosure`, no `image`, no
`video` — so if your ingest produces one, look at the ingest.

**8. ⚠️ If a document refuses, the answer is the vocabulary, not the parser.**
The reader raising is correct behaviour — it is what stops a silent loss. A
construct it does not recognise is a gap in the vocabulary and a decision for
whoever owns the block model, and the refusal names the line so the triage is
cheap.
