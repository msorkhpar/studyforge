# W225 — handoff

**Kind:** task handoff — W225

**Status:** done

**What landed:**

- ⭐ **`docker/dev/check` names the image by its build inputs' CONTENT.** It hashes, inside
  the Dockerfile's own pinned base (read-only mount, no network), every file of the build
  context `docker/dev/` plus the files the Dockerfile mounts from `project` (`INPUTS`),
  exports the digest as `STUDYFORGE_DEV_IDENTITY`, and prints
  `docker/dev/check: image studyforge/dev:inputs-<64 hex>` on stderr before Compose runs.
- ⛔ **`compose.yaml`'s `image:` REQUIRES the identity** (`${…:?}`): unset, Compose exits 1
  rather than fall back to a shared name. `studyforge/dev:local` is named by no instruction.
- ⭐ **`W211/3`:** the Dockerfile's first sentence is the hand build,
  `docker build --build-context project=. docker/dev`.
- ⭐ `tests/docker/test_dev_image_identity.py` — seven static checks, six with a doctored-copy
  control (the shared-tag absence check's red is shown by plant instead), and
  one opt-in plant run for two differing inputs (`Dockerfile`, `pyproject.toml`). A racing
  docker client runs the second checkout's whole `check` between the first's build and its
  container start; each must read its own input. The throwaway repository is removed after.
- `test_dev_image.py`'s `dev_image` fixture builds through `check` and returns the printed name.

**Decisions:**

- ⭐ **An INPUT digest, not the built image's id.** Rulings 238 and 290 disqualify an image id;
  an input digest is reproducible across hosts and caches, so two offices with identical inputs
  print one identity. ⚠️ It names inputs, not bytes: unpinned apt layers can still differ.
- ⭐ **The whole `docker/dev/` directory is hashed**, `check` and `compose.yaml` included —
  nothing to parse, and a new `COPY` is covered. The cost: editing `check` alone names a new tag
  (every layer cached).
- ⭐ **One Compose line kept.** A split `build` + `run` would break `W123`'s one-invocation
  checks. The plant opens the window inside `run --build` from outside, with a docker client.
- W152's decision stands; its documented direct form still carries the attestation variable.

**Surprises:**

⚠️ The first plant run failed on its own harness: the raced run's stderr also carries the second
checkout's printed name. Now asserted — it proves the window opened, so the readings are not
vacuous.

**For dependents:**

⭐ **Quote the printed line, not a guard.** `docker/dev/check …` prints the image on stderr, so a
capture taken `2>&1` carries it. `docker image inspect studyforge/dev:inputs-<hex>` resolves it.
⛔ Do not build under a hand-picked tag: `compose.yaml` refuses without the derived identity.
⭐ **No hold at merge:** a pre-merge `check` names only `studyforge/dev:local` and a post-merge one
never reads or writes it, so neither side can run the other's image. Pre-merge checkouts still
race each other, as today, until they carry this commit.
