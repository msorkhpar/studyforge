## Decisions

### 1. ⛔ `where=` / `what=` are excluded **by construction**, and the construction is now tested

Ruling 13 condition 3 refused to let these be nineteen allow-list entries and
asked for the property to be asserted once. **It is a stronger property than
"callers pass a relative path".**

⭐ **`where` is the filename, not the path.** Every entry point in the framework
that turns a `Path` into a `where` passes `path.name` — `archive.document.load`,
`corpus.container.document.load`, `corpus.manifest.document.load`,
`unit.content.load`. A single filename component **cannot be an absolute path**,
so the exclusion is a property of the value, not an exemption for a name.

⚠️ **Four docstrings said so and nothing tested it.** The second half of the
check does: every public callable with a `Path` parameter is handed a real
absolute path to a file that does not exist, and its refusal must reproduce no
directory from it. 46 path parameters probed; 6 echoes on the base, 0 here.

⛔ **So `LABEL_PARAMETERS` is a category with one reason, named once — not a
list of sites.** The distinction is the one the CTO drew: a list of *instances*
of a defect is the thing that rots; a category whose defining property is tested
is not.

### 2. ⛔ There is **no** allow-list and **no** recorded floor. The claim is the empty one

The task offered both and warned that a list needs justifying. ⭐ **Neither was
needed, because the class turned out to be fixable inside the task.** Ruling 13
condition 2 is binding — *the task that lands the check lands the fixes* — and
the harness-reachable sites were 23, not 45, once the denominator above is
right. All 23 are fixed.

⛔ **What is asserted instead of a floor is coverage.** `Census.report` prints
what the probe reached, `test_the_check_reaches_the_tree_it_claims_to_check`
pins a lower bound on it, and `Unreached` is a named, printed category rather
than a silent skip. A check with an empty result says *how much it looked at*
(`agent-protocol.md`, *a new check reports its coverage*).

### 3. `describe` is extracted to its ruled home, but **Ruling 10 is not finished**, and that is deliberate

Ruling 10 named three copies. One is retired (`unit.errors` re-exports). Two
remain, and **they disagree in ways that are decisions rather than drift**:

| | `str` | `int` | `bool` | empty `str` |
|---|---|---|---|---|
| `studyforge.describe` | `a str` | `3` | `True` | `a str` |
| `version._said` | `a str` | `3` | ⚠️ `a bool` | `a str` |
| `container.fields.said` | ⚠️ `text` | ⚠️ `an int` | ⚠️ `a bool` | ⭐ `an empty string` |

- ⛔ `version._said` says **`a bool`** on purpose, and the reason is in its
  docstring and pinned by a test: an integrator who wrote JSON `true` where `1`
  was wanted learns from *"as a bool"* and learns nothing from `True`.
- ⭐ `container.said` distinguishing **empty from non-empty text** is not drift
  either — it is strictly more information than `describe` has, and its
  refusals read better for it.

⚠️ **So the remaining consolidation is a design decision about two behaviours,
not a rename**, and doing it in passing inside W1 would have been exactly the
"slipped into a diff" the CTO refused. Both differences are tabled above so the
Ruling 10 task starts from the analysis instead of re-deriving it.

### 4. ⛔ `version.check` now refuses a `contract` outside `CONTRACT_FIELDS`

The last echoing site was `contract`, interpolated into the refusal twice. ⭐ It
is closed by **making the illegal value unrepresentable rather than exempting
the parameter**: `version.py` already documented that a task registers a new
contract in `CONTRACT_FIELDS` *in the same commit*, and the only thing holding
that convention was a tree test a caller outside `src/` never runs. Five in-tree
callers and every test already pass a registered name.

### 5. Where the check lives — ⛔ **and this one needs a ruling**

`handoffs/SF-03.md` proposed it beside the R7 sweep in `tools/quality`, and
**Ruling 19 says W2 and W6 are one `CHECKS` entry.** ⚠️ **I did not put it
there, and I am flagging that rather than absorbing it**, per the coordinator's
own instruction to say so:

1. ⛔ `tools/quality`'s contract says it depends on *"the standard library, and
   nothing else, ever"*, and its docstring gives the reason: it must lint a tree
   whose framework does not import. This check **must** import and call
   `studyforge`, so registering it in `CHECKS` makes the linter fail on any
   import error in the tree it is linting — including one it was about to
   report.
2. `tests/emission/` is under `pytest`, which `tests/test_quality_floor.py`
   already establishes as the gate; no contributor gains a second command.

⭐ **It also satisfies the ruling's actual concern by construction: this adds
zero entries to `CHECKS`, so it cannot be two overlapping ones.** ⚠️ If the CTO
wants it in `CHECKS` anyway, that is a change to FND-01's stated contract and
should be ruled as such — it is a two-line move once ruled.

### 6. Disclosed edits outside the literal wording of W1

Each is here because a commit that tightens a rule brings the tree into
compliance in the same commit, and each is one line or one sentence.

- ⛔ **`AddressError`'s docstring** (coordinator's finding 9) said the message
  *"names the offending value with `!r`"* — the sentence that authorised the
  defect. ⚠️ **Two more had it**: `PlacementError` (*"names the value"*) and
  `ManifestError` (*"names the offending field and value"*), and I was changing
  messages in both those packages. All three now state the opposite and say why
  they used to say it.
- **`corpus.container.fields.FILENAME_PERMITTED`** is now `SLUG_PERMITTED | {"."}`.
  W1 needed the same derivation to describe a slug fault; two copies of one
  *computation* is the same defect as two copies of one constant, one step
  earlier. `test_fields.py`'s literal pin is untouched and still passes.
- **`describe()` applied at 13 further reachable sites** in `archive.document`,
  `corpus.manifest.{content,edits,media}`, `corpus.placement.{identity,locations,profile}`
  and `render.pageassets.{source,vendored}`. Ruling 13 condition 2.

## Findings

### 1. `[structural]` 39 `{value!r}` sites this check cannot reach

**Measured 2026-09-09**, on this branch — code lines only, prose excluded:

```text
$ grep -rn "!r}" src/studyforge/ | grep -v /validate \
    | grep -vE ':\s*#|⛔|⭐|⚠️|`\{' | wc -l
39
```

⚠️ **Not all 39 are defects, and I have not triaged them.** Several are the
framework's own vocabulary — `address.key` after its segments are proved slugs,
`unit_name(ordinal)`, a registered profile's `name`. What follows is the subset
whose shape makes them defects on sight.

⛔ They are the same class W1 fixed — a refusal quoting a value read out of a
hand-written file — but they are raised **inside** document readers, reached only
by a whole valid document with one bad field, so the per-callable probe never
gets to them. The worst-shaped are the ones whose branch *is* the path check:

- `corpus/manifest/content.py:181` — `"must be relative to the source root and
  stay inside it, got {pattern!r}"`
- `corpus/manifest/edits.py:167,172,176` — the same shape for `edit.path`

⭐ **These are the exact tell §1f names**: a branch that fires *because* a value
is an absolute path, formatting that value. `studyforge.describe` is now
available to every one of them. ⚠️ Not fixed here: they are SF-02's and SF-05's
modules and outside a task scoped to two lines and their enforcer.

**Route:** the owners, or a follow-up pass; the fix is one call each.

### 2. `[structural]` The check goes red the moment `feat/SF-25-validate` merges — this is C5

⛔ **`validate` forwards `str(error)` from SF-01's exceptions into a `Finding`.**
Every new public callable in `src/studyforge/validate/` is probed by
`tests/test_emission.py` **from the moment both branches are in one tree**, and
neither branch has ever seen the other's rule.

⭐ **Run the trial merge with both, not with either alone** — that is precisely
what rubric §0a exists for. ⚠️ My branch merges before SF-25 by ruling, so the
red, if any, lands on theirs; Developer 1 has been told the address messages
change under them and to assert on type and rule rather than on sentences.

⭐ **And their end-to-end poison test is not a duplicate of this one.** Mine is
per-function and sees every public callable; theirs is per-pipeline and sees a
file on disk becoming a report line. §10b's vantage-point argument: neither can
see the other's cases.

### 3. `[local]` Three markdown readers raise `AttributeError` on input they will not accept

**Measured 2026-09-09**, the four probes the census reports as unreached:

```text
archive.markdown.leaf.read_heading(line=…)        AttributeError: 'NoneType' object has no attribute 'group'
archive.markdown.leaf.read_video(line=…)          AttributeError: 'NoneType' object has no attribute 'group'
archive.markdown.container.read_disclosure(lines=…)  AttributeError: 'NoneType' object has no attribute 'group'
```

⛔ Not an R7 leak — the message carries nothing — but it is R6: a public reader
that will not accept an input owes it a named refusal, not an
`AttributeError` from a `re.match` that returned `None`. ⚠️ They may be intended
as internal to `scan`, in which case the finding is that they are public.

### 4. `[structural]` A `Protocol` implementation that annotates nothing is invisible to any signature-driven tool

`SiblingProfile.container`, `SiblingProfile.unit`, `TreeProfile.container` and
`TreeProfile.unit` carry no parameter annotations. ⚠️ This probe recovered by
reading `Profile`'s, but **the same hole is in front of every future tool that
reads signatures** — a plan printer, a CLI generator, a doc builder.

### 5. `[local]` `slugify` still misattributes its own limitation to the corpus

CTO round 16, finding 8, is still open on this tree: the refusal for a title with
no ASCII alphanumerics says *"titles are the corpus's, so this is a corpus
defect."* ⚠️ A Russian title is not a defect (R1). ⛔ **Deliberately not fixed
here** — it is SF-01's routed one-line change and putting it in this diff would
make two unrelated rulings share a commit.

### 6. `[structural]` W6 cannot be done on this branch: the file is not here

Ruling 19 asks W6 to ride with W1+W2, and names `validate/corpus.py`'s `_text`
and its six sibling `except` clauses. ⛔ **`src/studyforge/validate/` contains
only `__init__.py` at `9ad45a2`** — `corpus.py` exists on `feat/SF-25-validate`,
which is Developer 1's surface and which I was explicitly forbidden to touch.

⭐ **Reported rather than guessed at, and part of it is already covered:** a
callable that forwards `str(error)` reproduces the poison, so
`tests/test_emission.py` **already fails on the W6 shape** the moment the two
branches are in one tree — which is finding 2, and the reason the trial merge
must be run with both.
