## What landed

### The two trees are asked for, not typed

`tests/test_authoring_geography.py` computes each profile's tree from
`profile.corpus()`, `profile.container()` and `profile.unit()`, walks each returned record with
`dataclasses.fields`, and replaces the values it drew at with the placeholders a page shows.
The page carries one fence per profile, labelled with the profile's own name as the fence's
info string, and the path column of each fence is compared to the drawing line for line.

⛔ **Nothing in the module types a generated path.** The substitution table's keys are read off
the profiles' own answers — the page name a profile returned, the media directory it named — so
no name that `names.py` mints is re-derived here.

⭐ **Three properties fall out of asking rather than typing, and each is asserted:**

- **A profile with no fence is RED.** The fences are matched to profiles by their info string
  and the set of them must equal `registered()`, so a third profile joins the page's obligations
  by being registered.
- **A location added to `CorpusLocations` or a sixth kind added to `UnitLocations` is RED**
  until the page draws it, because the records are walked and not enumerated.
- **A drawing that leaked a value it was computed at is RED**, so the page cannot acquire a
  fabricated address or title from the instrument that is supposed to keep it honest.

## Decisions

1. **The drawing lives in the test module, not in `src/`.** ⚠️ `skills.adapter.archive_tree()`
   is in `src/` because the page that draws it is **shipped** — [`skills/adapter/SKILL.md`](../../../src/studyforge/skills/adapter/SKILL.md) goes
   out with the framework, so its drawing has to go with it. ⭐ `docs/authoring/` is a document
   in this repository, read by an instrument in this repository, so putting a public
   `site_tree()` on `corpus.placement`'s surface would add an export nothing but a test imports.
   ⛔ **The property the brief asks for is that the fence is COMPUTED from the owning types, and
   that is satisfied wherever the computation sits.** See `W330/1` for the one case that would
   change this answer.
2. **A new module, `tests/test_authoring_geography.py`, rather than four more tests next door.**
   `tests/test_authoring_reference.py` is close to its 600-line ceiling and could not hold it —
   the same reason and the same precedent as `W117/2`, and Ruling 261's split rather than a trim.
   ⭐ **The seam is named:** that module reads the reference's **vocabularies** and imports no
   profile; this one reads its **geography** and imports nothing else. ⛔ Nothing was moved out
   of the existing module, so no frozen citation of a test name is re-addressed.
3. **The coverage sentence is NARROWED, and the alternative was rejected on a measurement.**
   ⛔ Making it true was considered first and is not reachable: **12 of the reference's 47
   `##`/`###` sections are opened by an instrument by heading** on this branch's tip, and 10
   were at `7027ee6`, counted by walking every `section`, `rows_under` and `vocabulary_under`
   call in the three suite modules that read these pages.
   ⚠️ The remainder is reasons, advice, and figures quoted inside sentences — *the bill was 116
   archives*, *one in eight are served at a slug their title does not produce* — and a check that
   read those would be a check on prose that a machine cannot evaluate. ⭐ **So the sentence now
   claims exactly the classes an instrument reads, says plainly that the prose is not checked,
   and says that it used to claim otherwise.** ⛔ **Hiding the narrowing was the one thing the
   brief forbade**, so the page names the defect that caused it: the trees were wrong and
   nothing read them.
4. **The fences carry a comment column and are compared on the path column only.** ⚠️ Byte-for-
   byte equality, as `test_ingestion_contract` uses for the archive tree, would cost the reader
   the labels beside four of the eleven lines. ⭐ The comment column is stripped by the same
   two-or-more-spaces rule that module already uses, and the comments are prose — covered by the
   sentence that now says prose is not checked.
5. **The `plan:` summary line is described rather than quoted.** The page quoted a four-count
   format; the real line carries nine counts. ⛔ Replacing one stale literal with a fresh one is
   what this row exists to stop, and the line's shape is `cli.plan.report`'s and not placement's,
   so it is outside what this instrument may ask for. The sentence now says what the line does
   and stops.

## Surprises

- ⚠️ **The `tree` fence was not merely correct — it was four lines short.** The brief records it
  as correct, and it was, of what it drew: it omitted the container page entirely and three of
  the five media kinds. ⭐ **That is the argument for walking the dataclass rather than listing
  the paths**: an omission looks exactly like a correct fence, where a wrong line at least reads
  as wrong once somebody runs a build.
- ⚠️ **The four-line shared head is identical under both profiles and is drawn twice.** The root
  index, the assets bundle, the archive and the discovery cache do not move between profiles, so
  each fence repeats them. ⭐ Kept, because each fence is then *everything* a build of that
  profile writes, which is what a reader at step 3 needs; a shared fence plus two deltas is a
  composition the reader has to perform.
- ⚠️ **[`examples.md`](../../authoring/examples.md) quotes a `plan` summary line that is false today**, and no instrument reads
  it — `W330/2`. It was found by deriving which sections any instrument opens, not by reading the
  page.
