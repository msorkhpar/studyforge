## What landed

- ⭐ **`build.py --runtimes a,b,…`.** It defaults to `DEFAULT_SET` (renamed from `EDITOR_SET`), which
  is `TC-01`'s five. `editor_plan.selection(pins, names)` checks the set before the runner is planned.
  The runner is then planned and built for THAT set, so no second version is chosen.
- ⭐ **Extensions are data selected by runtime.** Each pin in `editor-pins.json` names its runtime in
  `for`, as TypeScript and readline already did. `extensions_for` installs those whose runtime is
  declared. It refuses a `for` that names no pinned runtime. It refuses a missing required extension
  (`REQUIRED_EXTENSIONS` is now per runtime). It refuses a dependency or pack member outside the
  selection, even one that is pinned.
- ⭐ **The environment comes from the plan.** `environment(declared)` supplies `EDITOR_PATH` (the
  declared bin dirs, then the base's `PATH`) and `PROFILE_D`. It also supplies `WITH_JAVA`, which
  picks between two stages on the same base: `home-java-yes` sets `JAVA_HOME` and `home-java-no` does
  not. `ENV` cannot be conditional, and a stage template is the pattern the runner already uses.
- ⭐ **The build refuses a wrong environment.** The check step now also requires `JAVA_HOME` to be set
  exactly when java is declared. It requires every `/opt` entry on `PATH` to exist, and `/opt` holds
  only the declared trees. Both checks run under `sh -c` and `bash -lc`.
- ⭐ **The seed drops a runtime's block when that runtime is not declared.** The seed has
  `// @runtime java` and `// @runtime python` blocks, and the build deletes each undeclared one with
  `sed`. The file stays valid JSON(C) either way, because the last member sits outside every block.
- An empty extension selection builds: the install loop skips an unmatched glob.

## Decisions

- ⭐ **Extensions tied to an unselected runtime are NOT installed.** `redhat.java` embeds no JRE, so
  without the JDK it cannot start its language server, and it would fail on every activation.
  `fwcd.kotlin`, the Gradle and Python extensions likewise point at a runtime the image does not hold.
  Installing them anyway would ship a broken feature, and would undo most of the size saving that
  the Acceptance measures. The build's exact-set check compares against the selection, so a
  selection mismatch still fails the build naming the id.
- ⭐ **With no `--runtimes`, the build makes the default five.** The Acceptance's *full build* is
  `TC-01`'s image, and an unchanged command line should keep producing it. An explicit `--runtimes`
  is what a consumer passes.
- ⭐ **The refusal names an unpinned toolchain, but only one shaped like a runtime id**
  (`^[a-z][a-z0-9-]{0,31}$`). The Acceptance asks for a clear message and the brief asks for the
  name. The runner's rule is to echo nothing that arrived. A malformed name therefore gets the
  runner's answer: what is pinned, and nothing echoed. See `TC-02/2`.
- ⭐ **`sqlite` is refused for the editor, naming why** (`NOT_CARRIED`). The editor copies `/opt` and
  `/usr/local` from the runner, and the runner installs sqlite from Debian's packages into `/usr/bin`.
  Its version check would fail late, inside Docker. See `TC-02/1`.
- ⭐ **Maven gets no required extension.** `redhat.java` imports Maven projects itself, and no Maven
  extension is pinned. Adding one would be a new pin, and a new pin is not selection. See `TC-02/3`.
- ⭐ **The `PATH` order is `TC-01`'s**, filtered to the declared set: java, maven, gradle, kotlinc,
  node, then the base's `PATH`.

## Surprises

- ⚠️ **`TC-01`'s image already put `/opt/maven/bin` on `PATH` without holding Maven.** This is
  `TC-01/16`'s second half. It is the one visible difference between the default build and today's
  image, and that difference is intended.
- ⭐ **The editor's build-time report was lost once a step was cached.** A cached check step prints
  `CACHED` and no versions, so a test could not read the build log. That is why the reported
  versions are now kept in the image at `/opt/code-server/toolchain-versions`.
- ⭐ The editor's inputs digest also covers the runner's, so every editor tag moved with this change.
  The runner's tags did not, because `docker/minimal/` was not touched.
