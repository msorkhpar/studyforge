## Decisions

**1. ⛔ THE ADAPTER CALLS THE SERVICE'S FUNCTIONS, NOT ITS HTTP API.** `NS-02`'s
handoff pointed at this — *"`run_job` is a plain function returning a plain
dict and needs no HTTP"* — and the consequence is the one worth having:
⭐ **nothing has to be running.** An agent narrating one paragraph does not
first deploy a web service. ⚠️ **The price is Decision 5 and it is real.**

**2. ⛔ THE STDOUT REBINDING IS THE FIRST THING `run_adapter` DOES, AND IT
HAPPENS BEFORE THE ADAPTER IS BUILT.** Building it constructs an engine and a
store, and either could print. ⭐ **The real handle is kept locally and handed to
`serve_stdio` privately, which is what makes the property ASSERTABLE**:
`serve_stdio` writes to the handle it is given and never to `sys.stdout`, so a
test can drive it with a synthesis path that prints and read what a client
would actually have received. ⛔ **Carried from CodeSignal's tool server
unchanged in substance**, and `p18` plants its removal.

**3. ⛔ THE DISPATCH TABLE IS CLOSED, not a `getattr`.** `engine/registry.py`'s
rule, one level up: a tool name arrives from a client, and dispatching by
attribute would turn it into an instruction to call an arbitrary method on the
adapter. ⭐ **Two tests drive it** — `synthesize_chunk` and `__init__`, both real
attributes, both refused.

**4. ⛔ A FAILED SYNTHESIS IS `isError` CONTENT; AN UNKNOWN TOOL IS A JSON-RPC
ERROR.** The line is *was the call well formed*. ⚠️ **A client shows `isError`
content to the model and treats a JSON-RPC error as a fault**, so putting a
refused voice in the second bucket would hide the reason from the only party
that can fix it. ⭐ Carried from CodeSignal's server, which drew the same line.

**5. ⚠️ THE ADAPTER IS A SECOND WRITING PROCESS, AND I DECLARED THE CONDITION
RATHER THAN CHANGING THE STORE.** `narrate/artifacts.py` says the publish lock
is in-process and that *"one serving process per deployment is the shape this
service is run in"*. ⛔ **This row creates a second process, so pointing it at a
live deployment's artifact directory removes that premise.**

⭐ **What made this a declaration rather than a defect is a measurement:** the
container sets `NARRATE_ARTIFACT_DIR=/var/lib/narrate/artifacts` onto a named
volume, and the adapter run on a host takes `config`'s default — a relative
`artifacts` directory. ⛔ **So by default they do NOT share a store, and sharing
is something an operator does deliberately.** It is `agent.shares_the_store:
false` in `consuming.json` with the reason, a section in `docs/agent.md`, and a
test.

⚠️ **The alternative — a cross-process file lock — was considered and rejected
as SCOPE, not as wrong.** It is a change to `NS-02`'s storage layer, made from a
row that owns an adapter, and it would have arrived with no reviewer of the
thing it changed. See `NS-06/1`.

**6. ⛔ NO PATH OUTSIDE THE STORE IS RETURNED, AND NO ABSOLUTE ONE.** CodeSignal's
tool server returned a repository-relative path because it **wrote into the
repository**; ⭐ **that is precisely the behaviour E13's seam removes** (R4), so
it is the one thing not carried over. The adapter answers with the content
address, the service-relative URL, and the file's name *within* the store —
never the directory, which is either a container path or somebody's home
directory (R7).

**7. ⛔ NO PERSONAL-DATA GATE IS IMPLEMENTED HERE, AND THE OBLIGATION IS PUT
WHERE THE CALLER READS IT.** `E13` rules the gate client-side and pre-request
(R7, `NS-05`) and this package is inside the service. ⚠️ **But the caller here
is an agent, with no `narrate.client` between it and the engine** — so the
obligation is repeated in **every speaking tool's `description`**, which is the
text a model actually reads, and a test asserts it is there. ⭐ **A rule that
lives only in a docstring is a rule the caller never sees.** See `NS-06/3`.

**8. ⭐ `python3 -m narrate agent` IMPORTS THE PACKAGE INSIDE ITS OWN BRANCH.**
One line, and it is what turns *"the adapter is optional"* from a sentence into
a property: start the serve path in a fresh interpreter and `narrate.agent` is
absent from `sys.modules`. ⛔ **Move that import to the top of `__main__.py` and
a test fails.**

**9. ⚠️ `provides` moved 2 → 3 ONCE for both rows, not twice.** The adapter is
part of what this deployment promises, and so are `NS-04`'s route and address
change; they land in one commit history and there is no ref at which only one
of them is true. ⭐ **The reasoning is in `NS-04`'s Decision 10 and in
`narrate/__init__.py`**, and `TestTheProvidesGateActuallyGates` fired the
question rather than letting it be skipped.

## Surprises

- ⛔ **The transport clause cannot be tested in-process and I did not expect
  that to be so absolute.** My first instinct was a `StringIO` sink and a
  printing fake — ⚠️ **which tests nothing at all**: the print would go to the
  suite's captured stdout and the sink would be a buffer the test itself
  supplied, so the assertion would hold with the rebinding removed. ⭐ **Only a
  real process has one file descriptor that both the print and the client are
  looking at**, and `p18` is what proved the difference rather than my reading
  of it.
- ⭐ **The same argument applied to "the adapter is optional" and I nearly
  missed it.** An in-process `"narrate.agent" not in sys.modules` is answered by
  whatever the rest of the suite has already imported — and `tests/test_agent.py`
  imports it at the top. ⚠️ **The test would have been vacuous in the most
  literal way: it imports the thing it asserts is not imported.** A fresh
  interpreter is the only honest instrument.
- ⚠️ **CodeSignal's tool server DOES have a personal-data gate and mine does
  not**, which I did not expect from a row described as *"carried over"*. Its
  `call_synthesize` catches `PersonalDataLeak` because the `synth.py` beneath it
  gates. ⛔ **`E13` forbids that here** — the gate is client-side, never in the
  service — so the carry-over is deliberately partial and the gap is `NS-06/3`.
- ⭐ **Reading the source of the thing being carried over was worth far more
  than the row's summary of it.** The stdout rebinding, the notification rule,
  the `isError` boundary and the `Content-Length`-framing warning are all in
  that file's own docstring, and three of the four are not in the epic.

## Findings

### ⛔ `NS-06/1` — `[structural]` — this row is the SECOND PROCESS that `NS-02/10` and Ruling 341 both said would be the moment to re-read them, and I am not the office that can rule on it

⭐ **`NS-02`'s *For dependents* is explicit and it named this exact trigger:**

> A second writing PROCESS, or a cleanup job, is the point at which both the
> lock's residual and Ruling 341's §R9 trigger need re-reading — see `NS-02/10`,
> which the reviewer upheld: the trigger is a second *party*, never a second
> writer.

⛔ **This row creates one.** Two readings, kept apart because they have different
answers:

**(a) Ruling 341's §R9 trigger — my reading is NOT tripped, and I did not mint a
row.** The per-artifact record's trigger is *"anything outside that component
opens the file, or a second writer appears in that store"*, and `NS-02/10`'s
sharpening — upheld — is that the clause means a second **party**. ⭐ **The
adapter is the same component, the same repository and the same code**; a second
process of one party is not a second party. ⛔ **§R9 is the reviewer's register
and minting from a task branch is not mine to do**, so this is a reading offered,
not a decision taken.

**(b) The publish lock's residual IS widened, and that one is not a matter of
reading.** `NS-02` measured the remaining window as *"two serving processes
sharing one store"* and mitigated it by observing that one serving process is
the shape the service is run in. ⛔ **That premise is now conditional rather than
structural**, and the condition is whether an operator points the adapter at a
deployment's artifact directory.

⭐ **What I did instead of changing the store:** measured that the default
configurations do **not** share a directory, declared
`agent.shares_the_store: false` with the reason, wrote the condition into
`docs/agent.md` and `README.md`, and tested the declaration. ⚠️ **What I did NOT
do, deliberately: make the lock cross-process.** A `flock`-based publish lock is
maybe twenty lines and is probably the right end state — ⛔ **but it is a change
to `NS-02`'s storage layer arriving from a row that owns an adapter, and it
would land with no reviewer of the thing it changed.** Routed rather than taken.

### ⭐ `NS-06/2` — `[local]` — a NEGATIVE result: the epic's context path resolves, and I checked rather than reporting a missing file

⛔ **`E13`'s `NS-06` row gives the context as `CS/tools/tts/server.py`, and no
such path exists on disk.** ⚠️ **My first reading was that this was a stale
citation**, which would have been a finding against the epic.

⭐ **It is not.** `docs/tasks/README.md` defines the shorthand — measured at
`4b48e6d`, role `wt/dev1`, HOST, `grep -n "CS/"`:

```text
`SF/` = `studyforge/` (this repo) · `CS/` = `CodeSignal/.pipeline/` · `CSD/` =
```

⛔ **So `CS/tools/tts/server.py` is `CodeSignal/.pipeline/tools/tts/server.py`,
which exists, is 192 lines, and is the file the row means.** ⭐ **Recorded as a
closure**: the same shorthand appears on roughly twenty context lines across
seven epics, so an office that reported it as broken would have reported twenty
defects that are not there. ⚠️ **Worth one line in `E13`'s preamble or nowhere —
I am not editing an epic from a task branch.**

### ⚠️ `NS-06/3` — `[structural]` — the agent-facing surface has NO personal-data gate by construction, and the obligation currently lands on nothing

⛔ **`E13`'s preamble rules it: the gate stays client-side and pre-request (R7),
`NS-05` owns it, and it is never in the service.** ⭐ **I followed that and I am
not disputing it** — a second copy inside the service is something a caller can
believe in while sending the request that defeats it.

⚠️ **But `NS-05` is the FRAMEWORK's client, and the caller of this adapter is an
agent.** ⛔ **There is no `narrate.client` on that path.** So for one-off
narration through the adapter the gate has no owner in the code — and E13's own
argument for why it matters is at its sharpest here:

> An mp3 that speaks an account identifier is personal data on disk that
> **cannot be grepped for afterwards** — unlike text, it is unrecoverable once
> written and unfindable once shipped.

⭐ **What this branch does about it, which is the most a service-side row may
do:** every speaking tool's `description` states the obligation in the text the
model reads, a test asserts it is there, `consuming.json` declares it, and
`docs/agent.md` opens with it. ⛔ **What it cannot do is enforce it.**

⚠️ **Routed to `E11`'s skills, which the row itself names as a consumer** (*"and
for the skills of E11"*). ⭐ **The concrete ask is one sentence in whichever skill
wires this adapter into an agent: the skill runs `scrub` then `assert_clean`
before the tool call, in the same order the archive writer uses.** ⛔ **Recorded
rather than fixed because a gate in the service is exactly what the epic
forbids, and a gate in a skill is not this row's to write.**

## For dependents

**`E11`'s skills — you are the caller with no client, and `NS-06/3` is yours.**

- ⛔ **Gate before the tool call.** `scrub` then `assert_clean`, in the archive
  writer's order. The adapter will not do it and the epic forbids it doing it.
- ⭐ **`python3 -m narrate agent`, stdio, newline-delimited JSON-RPC 2.0.**
  ⚠️ **Not `Content-Length:` framing** — a client built from an LSP example
  hangs at the handshake with no useful error.
- ⭐ **Prefer `narrate_batch` over repeated `synthesize`.** Same manifest as
  `POST /v1/jobs`; per-request overhead is the difference the batch row names.
- ⛔ **Read `isError` on a tool result, not just the JSON-RPC envelope.** A
  refused voice, an unsynthesisable text and an engine failure are all
  `isError: true` with a message; only an unknown tool or method is an envelope
  error.
- ⚠️ **`file` is a name inside the store, not a path you can open.** Fetch by
  `url` from a running service, or read the store you configured. The adapter
  never writes into your tree (R4).
