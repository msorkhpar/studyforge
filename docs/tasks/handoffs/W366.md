## What landed

- ⭐ **Clause 1.** `changed_paths` is `git diff --name-only --no-renames $(git merge-base HEAD
  <branch>) <branch>`: only the branch's own changes, never what the target did since. The
  import map is built on the MERGED tree. It covers `import`, `from … import` (relative
  imports included), every parent package, dotted strings that name a module
  (`-m tools.quality`), and f-strings under a package. A name whose module was deleted is kept.
  Tests that read the tree get `reads_tree` and are taken **test by test** (`file::name`).
- ⭐ **Clause 2.** `SHARED` (conftests anywhere, `pyproject.toml`, `docker/dev/`,
  `tools/quality/`, `tools/gates.py`, `tests/fixtures/`, plus the selector's own three modules)
  selects everything. So does a path of a kind the selector cannot scope, and so does an
  empty selection (Ruling 191).
- ⭐ **Clause 3.** Before any gate line, the reading prints `scope: ⚠️ SELECTED … — this is NOT a
  full-suite reading`, or `scope: FULL`, or `scope: FULL, AUDITING the selection (<why>)`,
  followed by `why:` lines. Each suite gate line carries its scope. A green run that took a
  selection ends `PASSED … — ⚠️ the suite read a SELECTION, not the full suite`.
- ⭐ **Clause 4.** Merge number `N` (from counting first-parent merges on `HEAD`) audits when
  `N % AUDIT_EVERY == 0` (`AUDIT_EVERY = 5`), and `--full "<reason>"` audits on demand. An
  auditing gate's stdout is teed, and every `FAILED`/`ERROR` id outside the selection prints
  as `⛔ AUDIT RED [env]: the selection would have MISSED <id>`.
- ⭐ **Clause 5.** Every clause is asserted both ways, including the plant (below).

## Decisions

- ⭐ **What a conftest imports is NOT shared machinery.** The root conftest reaches the visual
  harness, and through it most of `studyforge`. Treating that as shared would have made every
  framework change a full run. A conftest loads in EVERY run, targeted or full, so a defect it
  reaches breaks the targeted run itself and cannot hide outside it. The conftest files
  themselves stay shared, as the row requires.
- ⭐ **Tree readers are taken per top-level test, not per file.** Per file, the marker covered
  about half the suite's tests, because one tree-reading test marks its whole file. Taint is
  followed by name inside a file (helpers, constants, fixtures taken as arguments), from
  `tests.` helpers by imported name, and from conftest fixtures. Only `test*` functions and
  `Test*` classes are named: `file::x` for anything else is a pytest error, not a selection.
- ⭐ **A root finder pointed into `tests/fixtures/` does not count as reading the tree**, because
  that directory is shared and a change there selects everything anyway.
- ⭐ **The merge counter lives in `tools/selection.py`.** `tools/mergegate.py` may not contain a
  history verb (its mirror asserts that). A counter judges no landed commit.
- ⭐ **The default runner tees only a gate that audits.** Every other gate runs through the
  same `subprocess.run` as before, so `certify` and every non-audit reading are unchanged.

## Surprises

- ⚠️ **One module can reach a large share of the files.** A change to
  `src/studyforge/render/page/rail.py` reaches more than half of the test files through
  imports alone, because the import graph is dense. That is what those tests actually import,
  not a defect in the selector.

## Findings

- `[structural]` **`W366/1`: the board convention does not name `--full`.** It spells out the
  merge invocation ([`docs/conventions/board.md`](../../conventions/board.md), `W302`), and a milestone close now needs
  `--full "<milestone> closes"`. That file is outside this row's surface.
- `[structural]` **`W366/2`: the tree-reader rule is deliberately conservative.** `__file__` used
  only to sweep `src/`, and a token that appears inside a test's string literal, both count.
  The document-only figure below could fall further with a sharper rule. The audit is the
  safety net for whatever the rule misses. A miss is fixed with `pytest.mark.reads_tree`,
  which the rule reads.
- `[structural]` **`W366/3`: `tools/quality/certify.py` depends on `mergegate.run_gate` returning
  an `int`.** It still does. A future change to the runner has to keep that, or change
  `certify` in the same row.

## For dependents

- ⭐ `stage_and_read(root, branch, runner, gates, full="")` scopes every gate named `suite`.
  Pass gates that contain no `suite` to take no scope at all.
- ⭐ A runner may return `int` or `(int, failed_ids)`. Only the second form feeds the audit.
- ⭐ A test that reads the tree by a route the tokens cannot see should carry
  `@pytest.mark.reads_tree` (or `pytestmark = pytest.mark.reads_tree` for the whole file).
- ⭐ `python3 -m pytest -m reads_tree` runs what a document-only change selects.
