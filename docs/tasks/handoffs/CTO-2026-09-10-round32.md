## ⛔ Ruling 111 — a version-checked document KEEPS its declared version, and the class has a third member

⭐ **Both developers independently found and fixed the same bug in their own
package this round**, and both wrote down the same insight: while the accepted
set held **one** number, a document that always reported the build's default
reported the truth **by coincidence**, and the bump is what made the defect
visible.

> ⛔ **`from_document` returns what the document DECLARED.** A version field
> records which contract the corpus was written to; replacing it with the
> build's own default rewrites the one field that says which reader the
> document was written for, and it silently breaks `render`'s byte-exact round
> trip for every document at any version but the newest.

⚠️ **The population is not two. I swept every register rather than accepting
the two instances handed to me** — the widening discipline, run because two
independent discoveries in one round is the signature of a class:

| register | stores the version? | passes it through? |
|---|---|---|
| `corpus/manifest/document.py` — `corpus_api` | yes | ⭐ **FIXED by `SF-35`** |
| `corpus/container/document.py` — `container_api` | yes | ⭐ **FIXED by `SF-36`** |
| ⛔ **`unit/content.py` — `content_api`** | ⛔ **yes (`content_api: int = CONTENT_API`)** | ⛔ **NO — `grep -n 'content_api=' src/studyforge/unit/content.py` returns nothing** |
| `unit/served.py` — `api` | no api field on the object | n/a |
| `archive/document.py` — `RAW_API` | no api field on the object | n/a |

⛔ **`unit/content.py` is the third instance and it is unfixed.** ⭐ **Exposure
today is `0`, and that is precisely the trap**: `KNOWN_CONTENT_API` holds one
member, so the default is right by coincidence — **the exact condition under
which the other two were invisible until the day somebody bumped them.**

⭐ **The remedy is one line at the call site, but the RULE is what stops the
fourth instance:** a register that stores its version on the object is checked
by a test that reads a document declaring an **older** version back and asserts
the field survives. ⛔ **A test that round-trips only the current version cannot
fail.** ⚠️ **That is `W37`'s class exactly** — a check that cannot fail by
construction — so it is routed there, with the one-line fix separable and not
waiting for the sweep.

## ⛔ Ruling 112 — when two legal branches make an illegal merge, the ceiling is the SECOND LANDER's, and a split TASK discharges it — never a size exception

### The measurement

```

```

⚠️ **Both developers declined the split, each for the same stated reason — the
seam a split would use is the one the other developer was working across — and
BOTH WERE RIGHT.** ⛔ **Two agents splitting one module blind, in one wave, is a
worse outcome than the breach.** The call is recorded as correct, not excused.

### ⛔ The coordinator's C5 claim is FALSE, and the correction matters

⚠️ **I was told *"neither branch's gate can see it."*** ⛔ **Measured: the gate
saw it.** `review-rubric.md` §0a — *review the merge, not the branch* — is
exactly the clause that catches this, and it caught it **on the first attempt**,
in the run recorded in §0a-i above: the second lander's trial merge fails the
floor at 419. ⭐ **There is no missing gate and nothing to mint for it.**

⚠️ **What IS true is narrower and worth keeping**: the gate fires at *review*,
not at *build*, so it spends a developer's whole task before saying so. ⛔ **That
is a cost, not a hole**, and it is the same cost §0a was written to accept when
it chose the merge over the branch as the subject of a verdict.

### ⛔ The size exception is unavailable BY CONSTRUCTION, and this is the ruling

⭐ **`review-rubric.md` §3c condition 3 requires the opt-out to say *why
splitting would be WORSE*.** ⛔ **Here splitting is plainly BETTER** — the module
holds two independent checks with two disjoint constant sets, and this round's
two tasks touched one half each without meeting except at a shared header.
⚠️ **"A task is queued to split it" is a reason splitting is better**, so it
fails condition 3 as written, and §3c condition 4's isolation question answers
against the file too.

> ⛔ **A ceiling breach created by a MERGE is discharged by splitting the module,
> never by a size exception.** ⭐ A size exception is a permanent design claim;
> a merge breach is a scheduling fact, and putting a scheduling fact in a
> permanent mechanism is how the exception becomes the norm.
