## What landed

### The containers navigation is a bar down the left, and one set of bytes says so at both widths

⛔ **`W324` built the navigation and left it in the column; this row is the placement and nothing
else.** The whole change is three CSS rules under one width threshold, over the markup `W324`
already emits:

```css
@media (min-width: 72rem) {
  body:has(nav[aria-label="Containers"]) { display: grid; grid-template-columns: … }
  body:has(nav[aria-label="Containers"]) > * { grid-column: 2; }
  body > nav[aria-label="Containers"] { grid-column: 1; grid-row: 1; align-self: start; margin: 0; }
}
```

- ⭐ **At the wide width the rail runs down the left of the reading column**, starting level with
  the masthead, with the column indented past it. ⛔ **Asserted as three facts and not one** —
  the rail ends before the column begins, it starts no lower than the masthead, and the column's
  left edge is past the rail's width — because each of those alone has a passing shape that is
  not a rail.
- ⭐ **At the narrow width it is the card `W324` shipped**: the region back in the one column,
  above the reading surface, at the column's own width. ⛔ **That is the degradation, and it is
  named rather than left to a reader's judgement of a screenshot** — the clause is the same width
  equality `test_site.py` runs over every other region, with the rail put back into the population.
- ⛔ **THE READING COLUMN IS NOT TOUCHED.** The content track is written as the measure plus the two
  gutters that `box-sizing: border-box` had already put inside `body`'s bound, and the rail plus one
  gutter is added OUTSIDE it — so `main` resolves the same width in the two-column page as in the
  one-column page. ⭐ That is what keeps
  `test_every_chrome_region_resolves_the_same_column_as_the_reading_surface` a true statement about
  every region but the rail itself, rather than a clause this row had to weaken.
- ⛔ **No script, no second markup and no template change.** The page bytes are identical at both
  widths and identical to `W324`'s; `<details>` is still the disclosure, the tab order is still
  document order, and the wide arm is opened with **scripts disabled** so R8's floor is part of the
  layout clause rather than a separate one.

### The two-column page is asked for by the page that carries the region

⛔ **`:has()` is the condition and it is not a convenience.** The root index carries no rail at all
— `render.index.document` lists it in its table of absences — so a grid declared unconditionally
would give that page an empty `17rem` column down its left and shift its own contents off centre.
⭐ The negative control asserts exactly that: a tree with the rail cut out is **not** laid out as a
grid, which is the half of this clause a check over the good tree cannot see.

⚠️ **A browser with no `:has()` gets the card**, which is the shape this stylesheet already ships at
a narrow viewport — so the degradation is one shape reached two ways, not two fallbacks to keep in
step.

### The harness can state a width, and the two widths are joined to the stylesheet

⛔ **Nothing in `tests/visual/` could set a viewport before this row**; every reading was taken at
whatever the launch window happened to be. ⭐ `OpenPage.resize` sets it on the session before
navigation, for the reason the colour scheme is an argument to `open`, and `page.py` names the two
widths — `WIDE` is the launch viewport, so every check that sets none still runs at the wide one and
the harness's default population is now the two-column page.

⚠️ **The two widths are STATED in the harness and JOINED to the stylesheet, which are different
acts.** `page.py` reads no stylesheet — that module's docstring forbids it, and rightly. The join is
one check in `test_rail.py`: it reads `chrome.css`'s single `min-width` back and asserts the stated
pair straddles it. ⛔ **So a breakpoint moved in the stylesheet is a red check rather than two
readings of one layout**, which is the failure a hard-coded width fails silently at.

## Decisions

### ⚠️ An existing clause was narrowed and its other half added — flag this first

⛔ **`test_chrome.py::test_the_column_is_bounded_exactly_once_and_on_the_element_that_owns_the_measure`
asserted the bounding selectors were EXACTLY `["body"]`**, which said two things at once: *the bound
lives on `body`* — the measured defect, three columns from one correct declaration — and *there is
exactly one of them*, which was only ever true while the page had one shape.

⭐ **The rail beside the column is a second bound on the SAME element under a media query**, and the
defect the clause exists for is a bound on a DIFFERENT element. ⛔ **What landed asserts the subject
instead, in both directions**: every bounding selector's subject is `body`, and there is at least
one — so a file that bounded nothing cannot pass, and a file that bounded a region cannot either.
The test is renamed to `…_only_ever_on_the_element_that_owns_the_measure` so its name states the
claim it now makes.

### ⛔ The rail is not sticky, and that is grid's property rather than a preference

⚠️ A grid item's containing block is its grid AREA, so `position: sticky` on a one-row item sticks
within that row and does nothing at all; an item spanning every row would have to know how many rows
a page has, which nothing does. ⭐ **A rail that scrolls with the page is still a rail**, and the
brief's *must not become a redesign* is the other reason. Recorded as `W325/3`.

### ⛔ `--rail` and `--page-max` were the brief's two tokens, and they are not equally load-bearing

⭐ **`--rail` is the rail track's width and carries the layout.** ⛔ **`--page-max` is painted as the
ceiling on the two-column page and DOES NOT BITE under the face this image pins** — said in
`chrome.css` beside the declaration rather than left for a reader to discover. ⚠️ It is a real
ceiling rather than decoration only because `--measure` is `80ch` and `ch` resolves against the prose
face, so the sum is not a constant; whether a ceiling no shipped face reaches earns its declaration
is the palette owner's question and is `W325/2`. ⭐ **Neither token needed anything the palette
cannot express, and no third token was minted.**

### ⭐ The column note this file carried is DATED rather than wrong, and says so

⚠️ `chrome.css` said `--page-max` *"is an outer edge for a rail-and-content layout; against a bounded
single column it would never bite at any viewport"*. ⛔ **That reading was right and there is a
rail-and-content layout in this file now**, so the paragraph records what it was and what dated it,
rather than being silently replaced — the same move `W324`'s office made with the keyboard clause.

  coincidence**: the content track was written so the single-column and two-column pages resolve the
  same reading column. It is asserted by the wide column-equality check, which compares every other
  chrome region against `main` and would go red the moment the track disagreed with the regions
  inside it.

  corpus with `generate.write_site`, where container pages DO carry the region; its geometry checks
