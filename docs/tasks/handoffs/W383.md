## What landed

- ⭐ One template holds the words a read row speaks. The rail, the container listing and the
  index tree each fill it, so the three regions cannot drift apart.
- ⭐ The words are emitted `hidden` on every row, so a built page is still byte-identical
  whoever opens it (R10). `progress-view.js` removes `hidden` only on a row the store holds,
  and puts it back on an unmark. With no working store nothing is said, just as nothing is
  drawn.
- ⭐ `chrome.css` keeps the shown words off the screen: absolutely positioned, one pixel, and
  clipped. The tick and the box are still the only visual mark.
- ⭐ The index filter matches a row's text without its read words. Otherwise a filter for
  *"read"* would match every row the reader had finished.

## Decisions

- **The string is `, marked read`.** It follows the title inside the link, so a screen reader
  hears *"Fields, marked read"*. The comma gives a pause and is not spoken. *"marked read"*
  matches the page's own control (*"Mark as read"*); a bare *"read"* could be heard as an
  instruction.
- **Shown by the script, not by CSS on `data-marked`.** With the stylesheet missing, a
  CSS-only switch would print the words on every row. `hidden` keeps them off when unread
  whatever loads.
- **Toggled in `progress-view.js`, not in `read-mark.js`.** The row names `progress-view.js`,
  and it already reads the store for both regions. `read-mark.js` still sets `data-marked` on
  the lists, and nothing about that changed.
- **A keyless rail row carries no words**, because it can never be marked (`W368`).

## Surprises

- The Up next slip copies the next row's anchor and strips every `span` from the copy. So the
  new words never reach the slip, and no change was needed there.

## Findings

- `[local]` **W383/1** (surface): the row named markup, `progress-view.js` and `chrome.css`.
  But `chrome.css` may only reach a `data-kind` value that `pageassets` publishes
  (`test_chrome.py` and `test_surface.py` check this both ways). So I added one kind hook,
  `read_state`, to `surface.py` and made no other change there. No other row in this wave
  names that file. The register may rule otherwise.
- `[local]` **W383/2** (a reading's limit): no screen reader ran. The browser checks read the
  proxy for one: the words are present, not `hidden`, not `display: none`, and at most one
  pixel in each direction. Checking the spoken result would need assistive technology on the
  host, which the visual harness does not have.

## For dependents

- ⭐ A new region that lists units and wants to say a unit is read should fill
  `read-state.html` with `kind=SURFACE_HOOKS["read_state"]`, and not write its own words.
- ⭐ Any script that searches a row's text should leave out `span[data-kind="read-state"]`,
  as the index filter now does.
