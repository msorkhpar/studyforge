## Decisions

### ⛔ 1. `HEADER_CHARS` 600 → 900 — ATTACK THIS FIRST

⚠️ **This is the one change outside the four files the row implies, and it is a
change to a CONTRACT rather than to data.** ⭐ **The reading that forced it, taken
on this branch:**

| | chars |
|---|---|
| the `Languages:` line alone, at 26 names | **170** |
| both declaration lines together | **262** |
| the old header, before this row | **586 of 600** |
| the best header I could write inside 600, keeping the reproduce recipe | **598** — a margin of **2** |
| the header as shipped, inside 900 | **786** — a margin of **114** |

⛔ **Inside a 600-character window the header can no longer carry both its
declaration and the recipe that reproduces it**, which is the whole of what a
vendoring header is for. ⚠️ Fitting it would have cost the upstream URL and the
reason the order matters, and would have stranded the next grammar entirely — the
failure mode being an `AssetError` saying the header carries **zero** `Languages:`
lines.

⭐ **The widening is safe because the invariant was never the window.** It is
`grammars.declared_languages`, which REFUSES a header carrying two `Languages:`
lines — and **no Prism 1.30.0 component carries that marker at all**, measured over
all eleven vendored here. ⛔ The two magic `600`s in `test_vendored.py` now read the
constant instead, so the window cannot move again while a test quietly keeps the
old one.

### ⭐ 2. The order, and the measurement that chose it

`core`, `clike`, `markup`, then the rest alphabetically. Two constraints and one
rule:

- `clike` is required by `java`, `javascript` and `kotlin` — Prism's own
  `components.json` says so, and it is why `clike` came second already.
- ⛔ **`markup` MUST precede `javascript`.** `javascript` attaches inlined
  `<script>` support behind `Prism.languages.markup &&`. **Measured both ways, same
  eleven components, same sample** (`<p>` wrapping a `<script>var a = 1;</script>`):
  markup first, the script body tokenises as keyword / operator / number inside
  `script` and `language-javascript`; markup last, the same input emits only `tag`
  and `punctuation` and the script body is left bare. ⚠️ **No error, no warning —
  which is why it is now a test and not a sentence.**
- Everything else is alphabetical, so the rule is checkable by eye rather than
  being an order a reader has to take on trust.

### ⭐ 3. Where the new token classes were filed

⛔ **`prolog`, `doctype` and `cdata` are filed under PUNCTUATION and deliberately
NOT under comment.** Prism's own themes colour them as comments; this stylesheet's
standing rule is that nothing takes the comment colour and its italics unless it IS
a comment — the rule earned by Kotlin's string literals, which only a screenshot
caught. The names a document declares (`tag`, `attr-name`, `property`, `key`,
`doctype-tag`, `name`, `variable`) read as types; their values (`attr-value`,
`value`, `entity`) read as strings; Gherkin's step keyword (`atrule`) is a keyword;
its `feature`, `scenario`, `important` and two table halves paint nothing, as
containers, alongside `script` and `language-javascript`.

### ⚠️ 4. `markup` and `xml` are TWO grammars, and both owe a sample

`Prism.languages.xml = Prism.languages.extend("markup", {})` is a deep clone, so the
bundle carries two markup-shaped grammar objects. Both are sampled, because the
suite's own rule is that a vendored grammar with no sample fails rather than going
quietly untested.

### ⭐ 5. R8, answered by construction rather than by disarming

The whole re-vendored bundle contains **no** `fetch(`, **no** `XMLHttpRequest` and
**no** URL of any kind. The single grep hit is prism-java's `import(?:\s+static`,
which is a Java KEYWORD regex and not a dynamic import. ⛔ Unlike `plyr.js`, this
bundle needs no disarming clause at all.

### 6. The samples carry no corpus knowledge

They are XML- and Gherkin-flavoured because that is what the grammars are for, not
because any corpus was consulted (R1). They are test fixtures; no module under
`src/` gained a list of languages.
