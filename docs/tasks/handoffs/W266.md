## Decisions

- ⛔ **Only a UNIT's origin reads a file.** A container's `origin` places its page
  (`plan/derive.py`, `generate/containers.py`, `validate/paths.py`) and reads nothing. ISO names
  each whole-series aggregate as a container origin, so counting container origins would let
  the row's own plant survive. Reversible.
- **The population is the classification scan**, so these are never judged: `not_material`
  files (the hand-written ingest module included), files the repository declares as output,
  generated pages the plan recognises, and nested stores.
- **Judged only while a unit origin is on disk, and every container map parsed.** With every
  origin absent, `origin-missing` (`W255`, `W261`) is the answer, and a second rule on every
  file would bury it.
- **The shared-origin fixture excludes its README** rather than declaring it `not_material`:
  the fixture is `corpus_api` 1, and `not_material` needs 2.
- **No FND-04 invalid fixture changed.** Each names origins under an absent `solo/`, so no unit
  origin is on disk and the rule does not judge; each still fails on its own rule alone.

## Surprises
