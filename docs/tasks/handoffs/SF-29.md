## What landed

- ⭐ **`select(runtimes)`**: pass it a corpus's declared `runtimes` (`Manifest.runtimes`, `W350`).
  It returns the rules of the ONE declared runtime that has any. It returns `None` when none
  does and when two do. `None` filters nothing.
- ⭐ **`filter_lines(lines, toolchain)`** is a generator over `RunHandle.lines()`, and each line is
  decided as it arrives. **`Quiet(toolchain).keeps(line)`** makes the same decision for one line.
- ⭐ **`Toolchain` is data**: three tuples of regexes, `always_noise`, `signal` and `noise`.
  `TOOLCHAINS` maps runtime names to rule sets, and a third build tool is one entry.
- ⭐ **The order of the checks is the design.** The exit line and any stack-trace line are kept
  first, then `always_noise` is dropped, then `signal` is kept, then `noise` is dropped. Anything
  else is kept. So no toolchain rule can reach a frame or the exit line, and a line nobody named
  survives.
- ⭐ **Maven (3.9)**: every `[INFO]` rule, banner, build phase header, timing and `BUILD …` line is
  dropped. The help footer's `[ERROR]` lines (`-> [Help 1]`, *re-run with -e/-X*, the wiki
  link, `-rf :` resume hints, *Please refer to …* report and dump notices) are dropped. Every
  other `[ERROR]`, every `Tests run:` tally at any level, every `[WARNING]` and every unprefixed
  line is kept.
  On the pinned passing run, what remains is `Running smoke.AdderTest`, two tallies and the exit
  line.
- ⭐ **Gradle**: the extraction source's rules, ported. The exceptions are in *Decisions*.

## Decisions

- ⭐ **Only drops, never edits.** The extraction source rewrote paths here. `SF-20`'s `LineGate`
  now does that for every line before this module sees it, so a rewrite here would be a second
  place that spells a path.
- ⭐ **Selection reads the declaration, never the command or the output.** Two build tools
  declared means no filter. Guessing wrong would drop output, and not guessing costs noise.
- ⭐ **Every frame of a stack trace is kept.** The extraction source kept only frames naming its
  own package. That is a source's name (R1), and the epic says *intact*. A trimmed trace is
  wrong exactly when the bug is somewhere unexpected.
- ⭐ **Not ported:** the output-marker block (a source's harness names, R1); the `STANDARD_OUT`
  rule (it relied on that harness relabelling the output; here the header is the only label);
  blank-line collapsing (a program's blank line is its output); and the *nothing to show*
  sentence. Maven prints a failure's cause at `[ERROR]` or `[WARNING]`, both are kept, and the
  exit line always survives. A sentence the filter made up would break *only drops*.
- ⭐ **Maven's `BUILD SUCCESS` / `BUILD FAILURE` is dropped.** The verdict is the `Tests run:`
  tally plus the exit line the page already reads. **`[WARNING]` is kept**: a real failure's
  cause arrived as one (`The POM for … is missing`), so it is not noise.
- ⚠️ **Maven's repeated compile error is NOT de-duplicated.** Maven prints the error lines again
  after `BUILD FAILURE`. Dropping the repeat would split them unevenly: the `[ERROR]` path line
  repeats exactly, but its continuation lines come back with a new prefix. That would leave
  orphaned `symbol:` lines. Duplicate is honest, orphaned is not.
- ⭐ **The image test runs `smoke.json`'s own command with only `-q` removed.** Quiet mode is
  Maven filtering its own output, so it cannot be the input to a test of this filter.

## Surprises

- ⚠️ **The pinned toolchain's real output was on this host all along, for a passing run only.**
  `code-server-toolchain`'s recording build (`build.py --record-maven`) had run `mvn -B -C -ntp
  test` on its Maven smoke project, on the pinned Java, Maven and plugins, and its log was in
  that component's untracked work directory. `MAVEN_PASS` is that log's run. The only edits are
  the ones `transcripts.py` names.
- ⚠️ **This host has a Maven 3.9.16 distribution (the pinned version), but no cache to feed it.**
  Offline, on an empty repository, it fails before any plugin runs. That failure is real and is
  committed (`MAVEN_OFFLINE`, and `MAVEN_OFFLINE_TRACE` with `-e`). With the host's own Maven
  cache as a read-only fallback, it still failed: the cache holds the plugins' POMs but lacks
  jars the plugins need (surefire's JUnit provider, the compiler's plexus jars). ⛔ Nothing was
  downloaded (`-o` throughout), nothing was written into that cache, and nothing left this host.
- ⚠️ **Maven's own `-e` trace contains a blank line and a tab-indented continuation** in the middle
  of the trace. A filter that dropped blank lines, or that decided each line by its prefix alone,
  would break it. It survives whole (asserted).
- ⚠️ **Maven 3.9.16 printed no JVM warnings on Java 26**, and the pinned log shows none on Java 25,
  so no unprefixed launcher line needed a rule.
