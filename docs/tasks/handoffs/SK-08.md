## Decisions

- ⭐ **The procedure is the branch's first commit and the modules the second.**
  §9, and it changed the design once (see *How §9's ordering is evidenced*).
- ⭐ **The parse rule is ADJACENCY, never a list of headings to skip.** A task
  is a `###` heading whose next non-blank line declares a milestone. ⛔ A skip
  list would need an entry every time somebody wrote a new kind of subsection,
  and **the entry nobody adds is the row that vanishes** — silently, from a
  document a planner is trusting to be complete. Measured: the rule separates
  92 task rows from 14 headings that are carried rulings, revisions and prose,
  with no exceptions and no allow-list.
- ⭐ **A cancelled row is counted, never dropped.** `FND-05b` declares no
  milestone; it is not a capability and it appears in the derivation line as
  *1 cancelled row carried and not counted*. ⛔ A generator that quietly
  discards input is one nobody can check.
- ⭐ **`Terminal.checked` is coverage, and the choice is the whole finding.** A
  subset check over the never-used table passes on a table with one row in it.
  ⛔ The claim a terminal statement makes is about the capabilities that were
  **not** named, and only an enumeration can see those.
- ⭐ **A refusal names the field, never the value** (R7) — see Surprises. The
  one exception is `read_epic`'s `name`, which is refused unless it is a **bare
  filename** *before* anything quotes it, which is `where=path.name`'s
  construction arriving at a plain string parameter.
- ⚠️ **`Terminal.checked`'s refusal quotes the `missed` ids and withholds the
  `stray` ones, and that asymmetry is deliberate.** `missed` comes out of the
  **index**, whose ids were matched by `_HEADING`'s closed pattern and cannot
  carry a path; `stray` comes out of `Unused.capability`, which is caller text.
  ⛔ The refusal says so in its own message rather than leaving the difference
  to be inferred.
- ⭐ **A profile is data and the seam is asserted, not described.** The test
  that matters builds a profile this package has never seen and exports through
  it — because *"adding a tracker is one value"* is a claim about code that
  does not exist yet, and only a third profile tests it.
- ⚠️ **`FIELDS` maps a field to a lambda, and every one reads a stored
  attribute.** `test_no_field_in_the_registry_computes_anything_about_the_plan`
  pins that: a field that computed something would be a second opinion about
  the plan, disagreeing with the document under exactly the conditions nobody
  tests.
