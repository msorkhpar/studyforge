## What landed

### The shape — `container.json`, unit `origin`

```json
{
  "n": 3,
  "title": "Card issuance",
  "origin": { "path": "TestCases.md", "section": "3. Card issuance" }
}
```

- ⛔ **A string is still a whole file** and every v1 map parses byte for byte as
  it did.
- ⭐ **The reader hands the two halves back SEPARATELY.** `Unit.origin` stays a
  plain path in both shapes and `Unit.origin_section` is the region, `None` for
  a whole file. ⛔ **`section` is not a unit key** and `UNIT_KEYS` is unchanged:
  the object is the *value* of `origin`.
- ⚠️ **That choice is what makes the blast radius zero.** `origin_directory`
  takes `.parent` of a path, `validate/paths.py` passes `declared.origin` to a
  placement profile, and `placement.profile` type-checks it with
  `is_source_path` — ⛔ **all three would have broken on a value object**, and
  none of the three is in this task's `Owns`. Media placement is unaffected
  (Ruling 92's second consequence), and it is unaffected *without editing
  anything that would have had to change.*
- ⛔ **A container's own `origin` is unchanged and stays a string.** It is
  `folder` — the directory a container came from — and a region of a directory
  is not a thing. An object there is refused by `optional_path`.

## Decisions

1. ⛔ **The parsed form is `(path, section)`, not an `Origin` value object.**
   ⭐ **Measured rather than argued:** `walk.root / declared.origin` in
   `validate/source.py`, `profile.unit(origin=…)` and
   `walk.root / _relative(declared.origin)` in `validate/paths.py`, and
   `origin_directory`'s `is_source_path` type check in
   `corpus/placement/profile.py` are the four consumers, and ⛔ **three of them
   are outside this task's `Owns`.** A value object would have required editing
   `paths.py` and `placement/` to keep them working — unrequested scope, in the
   round where a second developer is live. ⚠️ **A string keeps every one of them
   correct by construction**, and it is what Ruling 92's own second consequence
   asks for.
2. ⛔ **Uniqueness is enforced in `validate`, not in the container reader.**
   The ruling says *"or the manifest is refused"*; ⚠️ **the container reader
   cannot see the source file** — `parse` is given text and `load` reads
   `container.json`, never the material. ⭐ **So "refused" is `studyforge
   validate` exiting 1 with a named rule**, which is the same place
   `check_completeness` already refuses a short read. The reader refuses the
   *shape* (a fragment, a missing key, a non-text section); the checker refuses
   the *fact*.
3. ⛔ **Two rule ids, not one.** Precedent taken from `RULE_IGNORE_DECLARATION`'s
   own docstring in the same module: *"a different fact, and one a script
   filters on separately"*.
4. ⭐ **The section is matched as written, with only surrounding whitespace
   removed.** A closing-hash heading (`## Card issuance ##`) keeps its trailing
   hashes in its text, so a corpus writing the section the other way gets
   `occurrences == 0` — ⛔ **a named finding rather than a region that quietly
   starts somewhere else.** Stripping them would be this module holding an
   opinion about a *rendering* convention, which is the coupling a heading was
   chosen to avoid.
5. ⛔ **The `#` rule went into `sourcepath`, not into `container.fields`.** It is
   the module that states what a source path may be; a copy in the container
   reader is the exact defect Ruling 44 removed. ⚠️ **The consequence is
   deliberate: `placement.origin_directory` refuses a fragment too**, and it
   should — a fragment was never a location on disk anywhere.
6. ⛔ **`docs/specs/…` was not edited.** See `SF-36/1`: the spec's example is not
   wrong, it is incomplete, and the spec is not in this task's `Owns`.
