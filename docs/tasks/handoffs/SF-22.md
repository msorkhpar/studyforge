## What landed

- ⭐ **`/api/v1/run/`**: `GET` → `run-index` (the modes, the start and stop templates, the
  client's path, the live run); `GET client.js` → the execution client; `POST
  <corpus>/<mode>/<key>` → a streamed `text/plain` run; `POST stop` → `{"stopped": bool}`.
- ⭐ **Two modes, the data's own words**: `run` (Run) reads the workspace's `run_command` and is
  recorded `run`; `test` (Submit) reads `test_command` and is recorded `test`. `exercise.COMMANDS`
  IS `progress.MODES`, so a Run cannot be recorded as a Submit.
- ⭐ **The command is read, never received.** `workspace_of` builds the unit's document through
  the same `ContentSource` the content namespace serves, parses it with `unit.served.parse`, and
  takes the practice section's `workspace`; `Runner.start([argv])` gets that argv as the document
  holds it. A `Request` has no body and no query field, and `app` DISCARDS a `POST` body.
- ⭐ **One run at a time** (`409` for a second), and **every run ends recorded** — by its last
  line, by `stop`, by a timeout, or by a page that hung up.
- ⭐ **`studyforge.run`**, the client: `available()`, `start(corpus, practice, mode, onLine)` →
  the verdict, `stop()`. It draws nothing.

## Decisions

- ⭐ **Starting a run is a `POST`.** A `GET` that acted would run a grader on a prefetch. `app`
  gained `writers=` for exactly this, and refuses a writer that is not a registered namespace, so
  content, assets and the static mount can never answer `POST`. `Origin: null` is refused on
  a start and on a stop (a page from `file://`, or a sandboxed frame).
- ⭐ **The URL's mode words are `run` and `test`, not `run` and `submit`**: one vocabulary from
  the data (`exercise.COMMANDS`) through the URL to the record (`progress.MODES`). "Submit" is the
  panel's label, `SF-24`'s.
- ⭐ **The "generated unit document" is the one the content namespace serves**, built from the
  archive on disk on request (`CorpusContent.unit`) — no `unit.json` is written by a build, and a
  second reader of the archive would be a second document.
- ⭐ **The exit line is recognised by the HANDLE**: a run is one command, whose `returncode`
  exists only once its output ended, so a program printing `--- exit 0 ---` cannot pass itself.
- ⭐ **The verdict is recorded BEFORE the exit line is written**, so the exit line stays last even
  when the store refuses the outcome (a fixed line says so, before it).
- ⭐ **A status from a signal (negative) is recorded as `128 + n`**: the record takes `0` or more.
- ⭐ **A mode whose command the workspace does not name is `409` and starts nothing**
  (`workspace.get`, never an unguarded index). `W357` lets a record carry `main_path` and
  `run_command` alone, so a non-null `workspace` no longer means graded: Run is offered for both
  shapes, Submit only where `test_command` is named.
- ⭐ **The body is a class, not a generator**: `app` closing a generator that never started runs
  none of its body, which would leave the run alive and the slot held.
- ⭐ **A hang-up is found by WATCHING the socket.** A run waiting on output writes nothing, so no
  write would ever fail; `app` polls the socket for end-of-file and calls the stream's `cancel()`,
  which is `RunHandle.stop()` — thread-safe by `SF-20`'s contract.
- ⭐ **Every line is scrubbed again as it is written** — the response is where it leaves the
  process, and `scrub` is idempotent by its own contract.
- ⭐ **The client is served by the run namespace, not bundled into `page.js`** — see *Surprises*.
- ⛔ **`serve`'s no-spawn property is NARROWED, and says so**: importing `serve` now loads
  `subprocess` through `execute`. The fresh-interpreter arm imports `execute` first and asserts
  `serve` adds nothing on top; the bare reading asserts the instrument does see it; a third pins
  the two importers. The source arm (`spawns`) is unchanged: no `serve` module names a process
  library.
- ⭐ **`skills.buildserve.states` imports the MODULE** (`import studyforge.serve.routes.run as
  run`): the quality floor's surface check refuses the name taken from a package with no
  `__all__`; the skill's thinness test now admits that module, its comment stating it is for
  `NAMESPACE` alone — the precedent is `cli.narrate.cli`, admitted for `DEFAULT_SERVICE`. ⚠️ The
  test admits the MODULE; nothing asserts which name is taken from it.

## Surprises

- ⚠️ **A bundled client broke R8's floor**, measured: the first host suite put the client in
  `render/assets/` and `pageassets.SCRIPT_PARTS`, and every floor reading of a built site went RED
  on `page.js names the serving origin: /api` (`tests/studyforge/cli/serving.py`). ⭐ Moved to
  `serve/assets/run-client.js`, served at `/api/v1/run/client.js`: it now exists exactly where an
  origin can answer it. That bundle edit was reverted by restoring the one file this office had
  changed; no plant was involved.
- ⚠️ **`http.client` keeps the socket open while a response object lives**: the hang-up test was
  RED until it closed the response as well as the connection. A browser that navigates away
  closes both.
- ⚠️ **The raises convention's floor needed an entry** although its note says a new caller needs
  no edit (`SF-22/5`).
- ⚠️ **`run.py` reached the size ceiling exactly** once the client's route landed; split at the
  seam between the namespace and a started run (`runs.py`), rather than trimmed.
- ⭐ **One host reading outside the suite**: the client, loaded into Node 24 on this host with a
  stand-in `location`, ran a Submit of unit 1 against a live instance (the grader's lines, then
  verdict `0`), refused a `..` key before any request, and stopped nothing. ⛔ No JavaScript runs
  in the suite (`QA-03/1`); this is disclosed, not asserted.
