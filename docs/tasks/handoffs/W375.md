## Decisions

- **The name is `tests/spawning.py`.** `tests/process_starts.py` would sit beside
  `tests/test_process_starts.py` and read as its mirror.
- **The plants moved to the sweep's file.** The sweep is the detector's main reader. If the
  plants stayed in `serve`'s mirror, the dependency would still run the wrong way.
- **"Every way" means the modules that exist to start a process.** A general module that
  starts one inside a single routine is not counted: `http.server`'s CGI handler,
  `platform`, `uuid`, `ctypes.util`, `imaplib`'s stream transport. The detector reads
  imports, so counting those would refuse `http.server`, which `serve` is built on. The
  helper's docstring states this limit, and `import http.server` is a pinned passing plant.

## Findings

### W375/1 `[local]` — the detector reads `os.<name>` only through the bare name `os`

`import os as o; o.system(...)` is not seen. `from os import system as s` is seen, because
the import is read. Nothing in `src/` aliases `os` today. The row does not ask for this, so
it is recorded here and not fixed.

### W375/2 `[local]` — an event loop's `subprocess_exec` / `subprocess_shell` are not seen

These are methods on a loop object, so an import scan cannot see them unless the source
also imports `asyncio.subprocess` or a `SPAWNING_FROM` name. Nothing in `src/` uses them
today.
