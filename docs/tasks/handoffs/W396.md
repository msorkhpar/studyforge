## What landed

⭐ **What the rules say now that they did not:** an office's `git merge` carries the office's
identity, with the command written out —
`git -c user.name=<office> -c user.email=<office>@example.invalid merge --no-ff -m '…' <branch>`
— and the section says why the harm is not disclosure (nothing is pushed) but that the branch
answers *who made this* in two voices.

⭐ **What the gate does now that it did not:** `read_authorship` counts the introduced commits
whose author line is NOT an office's, and `render_authorship` prints ONE line immediately under
the population when a branch carries both kinds: the counts, that a plain `git merge` authors its
merge commit with whatever identity ran it, that this is a disclosure and never a refusal, and the
per-invocation form. ⛔ **The exit code is untouched**: what the gate refuses is still exactly two
distinct OFFICE identities among the commits one merge introduces.

## Decisions

- ⭐ **A disclosure, never a refusal — and the reason is in the module's own table.** *An office's
  carrier with a coordinator fix-up on it* is the same shape and passes deliberately, so a gate
  that refused the mix would refuse legitimate branches. ⚠️ It would also refuse every branch that
  already carries a plain merge commit, for a defect no office could clear from its own tree —
  the merge is landed history, and re-authoring it is a rewrite the register never asked for.
- ⭐ **It is a COUNT, like everything else this module answers.** No author line is stored,
  returned or printed (R7, Ruling 345's clause 5), and the disclosure names a command shape rather
  than any identity. Asserted: no office name from the fixtures appears in the line.
- ⭐ **Silent when there is nothing to say.** A register round's commits are all one kind and so
  are an office's when the office merged as the rules say, so the line prints only for the mix —
  and the tests assert both of those silences, not only the noisy case.
- ⭐ **It prints under the POPULATION and above the verdict**, because it qualifies the population
  (Ruling 191(a)'s shape), and the existing order assertion for the clean verdict still holds.
- ⭐ **The rule lands in [`agent-protocol.md`](../../conventions/agent-protocol.md), and Ruling 345 is CITED rather than rewritten**
  (Ruling 106): the rubric's record is where the mechanism and its measurement live, and this is
  the office-facing clause that names the case the short form let through.

## Surprises

- ⚠️ **The existing gate was already correct and was never going to fire here.** A non-placeholder
  line is never refused — deliberately, since a register round's commits carry one — so the
  measured merge commit passed for exactly the reason the module documents. ⛔ The gap was not a
  wrong verdict; it was that nothing in the reading said the branch had two voices in it.

## Findings

- `[local]` **`W396/1`: a branch already carrying a plain merge commit will print this line at its
  next merge.** That is intended and is not a defect in the branch: the line names the count and
  the remedy for the NEXT merge, and the register decides whether it cares.
- `[structural]` **`W396/2`: the COMMITTER line is not read anywhere.** `read_authorship` reads
  `%an <%ae>` only. A commit made with `-c user.name=…` sets both, so nothing is missed today, but
  an office using `GIT_AUTHOR_*` alone — which Ruling 345 also permits — would leave a committer
  line this gate never looks at. ⛔ Outside this row (it widens the gate's subject); recorded for
  whoever wants the whole shape.

## Measured

On this host, the host's `python3`, at this branch's tip; every plant is a throwaway git
repository with fabricated identities (`example.invalid`, and a machine stand-in whose domain
carries no dot).

⭐ **Both ways, planted:** a carrier that takes the release tip with a plain `git merge` reads
`mixed == 1` beside one office identity, prints the line under the population, and is NOT refused;
the same merge taken with the office's `-c` form reads `mixed == 0` and prints nothing at all. A
register round branch — every commit one kind — is silent, which is the case that would fire
loudest if the reading counted a person's line on its own.
