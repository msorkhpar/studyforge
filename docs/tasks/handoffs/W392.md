## Decisions

- ⭐ **The document is the data; the module is only its reader.** A seventh rejected identity is a
  row somebody adds to the table, with no code change. ⛔ That is also the whole exemption
  mechanism: an identity stops being refused when its row leaves the table, which is the same edit
  as changing the rule, so the instrument and the convention cannot come apart.
- ⭐ **Bands are written in CHROMA (`max − min` over 255), never HSL saturation.** Measured: the
  near-white paper the user accepted reports a saturation above 35% and a chroma below 5%, so a
  saturated-ground row written in saturation would refuse the accepted paper on its first run.
  `test_a_near_white_reads_LOW_chroma_where_HSL_saturation_reads_high` holds that reason.
- ⭐ **A row is a CONJUNCTION, per theme, per group.** Cool slate is what the user ACCEPTED and the
  rejected row is slate WITH teal-green AND amber; light and dark are read apart; a gradient row's
  stops must meet inside ONE gradient. Each of those three is asserted clean in the direction that
  would otherwise be a false refusal.
- ⭐ **The green bound the user gave is RECORDED here and read by nothing here**, deliberately, and
  the document says so: it is a per-token rule over the shipped palette, it belongs to the row that
  repaints the site, and on this base the shipped palette still carries the green — a floor finding
  would have reddened every office's merge gate for a defect none of them could clear.
- ⭐ **The module is a PACKAGE at a named seam** (R11, Ruling 261): the document's side
  (`rejected`), the tree's side (`shipped`), the measures they share (`colours`), and the verdict
  (`__init__`). The flat form measured 464 lines against the 400 ceiling.
- ⭐ **One LOOK is read once.** A block that resolves to the same tokens as another — a dark block
  declared twice, once under `@media` and once under `[data-theme="dark"]`, which is exactly what
  `palette.css` does — is one theme, or one identity would be reported as two.
