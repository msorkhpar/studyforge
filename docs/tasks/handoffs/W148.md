## Surprises

### ⛔ A latent crash the ignore batch walked straight into

⚠️ **`resolve_target` answers in two frames.** For a link with a path part it returns a
`.resolve()`d path; for a same-document `#anchor` it returns the document EXACTLY as it was
handed in. ⛔ `python3 -m tools.quality` hands the walk `Path(".")`, so a caller that
collects both kinds and asks `config.relative` about them raises
`ValueError: … is not in the subpath of '.'`. ⭐ **`collisions.py` already works around it**
— it calls `.resolve()` on every result — **and nothing on the function says so.**
⚠️ I normalised at my own call sites and did not change the contract; see `W148/5`.

exclusion applied. ⛔ **But that is a READING, not a property**, and the control says so:
