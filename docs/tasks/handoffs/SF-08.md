# SF-08 — handoff

**Status:** done. `src/studyforge/archive/scrub.py` (278 lines) and
`tests/studyforge/archive/test_scrub.py` (474 lines, 54 tests). Suite green in
the FND-03 container: **647 passed, 8 skipped**, `ruff check` and
`ruff format --check` clean, quality floor clean.

⚠️ **The pattern set is three shapes, but not the same three the epic
counted.** The extraction source's profile-URL rule is **not** ported — it
names a source (R1) — and the home path takes its place. Counted rather than
inherited, as `CLAUDE.md` asks. See *Decisions* 2.

## What landed

`archive/scrub.py`, one module, no package needed. Public surface:

| name | what it is for |
|---|---|
| `assert_clean(value, where)` | **the gate.** A decoded string *or* a whole decoded document. Raises `PersonalDataLeak` |
| `scrub(text)` | rewrite one string this framework wrote — a log line, a subprocess's output |
| `scrub_document(value, where="document")` | the same, over a decoded document, structure preserved |
| `leaks(value, where)` | every `(location, shape)`, non-raising, for callers that report instead of refusing |
| `shape_in(text)` | the name of the first shape in one string, or `None` |
| `SHAPES` | `(name, pattern, placeholder)` — **where a new rule would go, if one could be justified** |
| `HOME_PATH_PLACEHOLDER`, `EMAIL_PLACEHOLDER`, `TOKEN_PLACEHOLDER` | what `scrub` writes |
| `PersonalDataLeak` | the refusal |

Everything rides one walker. `scrub_document` uses its rebuilt result and
`leaks` throws that result away, so the two layers cannot come to disagree
about which strings a document has — which is what *"both layers ride the same
walker"* has to mean if it is to mean anything checkable.

## Decisions

### 1. Scrub our words; refuse the source's

The task says *"`scrub` on the way in, `assert_clean` as the refusing gate"*
and the epic says *"the gate **refuses**, it never rewrites."* Those read as a
contradiction and are not one. The line is **whose words they are**:

- A log line, a compiler diagnostic, a path in a progress report — this
  framework's own process wrote them. Rewriting one loses nothing, so `scrub`.
- An archive document is the verbatim record of what a source said (§6).
  Rewriting it corrupts the record, breaks the `content_sha256` that covers
  it, and leaves nobody knowing personal data was ever there. So `assert_clean`.

Both live in this module, and the belt-and-braces order survives the port:
scrub upstream, assert at the boundary. ⭐ A match at the inner gate is not
redundancy — it is the news that an upstream stage failed, and that is worth
surfacing (R6).

### 2. Three shapes, and they are not the extraction source's three

Counted, not inherited. `CS/tools/study/scrub.py` has exactly three rules —
profile URL, email address, bearer token — and E02 is right that none of them
is a content shape. But **one of the three names a source**:

| extraction source | studyforge | why |
|---|---|---|
| profile URL (`/learn/profile/<id>`) | ⛔ **not ported** | It is one site's URL scheme. A framework pattern for it is the framework knowing about a source (R1). It belongs to the adapter that captures those pages, upstream of the archive |
| email address | ✅ ported | |
| bearer token | ✅ ported | |
| — | ✅ **home path**, added | Spec §6 requires `assert_clean` to refuse an absolute home path, and the inherited gate — which only ever saw web pages — has no pattern for one. FND-04 had already noted this in `tests/test_fixture_consistency.py` |

⭐ **The test that keeps this honest is the definition, not the count:** every
shape must reach a document *because of whose machine and whose account ran
the build*. A fourth entry needs that argument made for it, in writing.

⛔ **No payment-card pattern**, and ⛔ **no username pattern, ever** — both
rulings are quoted in the module contract and pinned by tests
(`test_no_pattern_matches_a_card_shaped_string`,
`test_a_package_name_carrying_an_account_name_passes`), so a later reader meets
the reason and not just the absence.

### 3. Shape only — never a value derived at run time

FND-06's repository gate has a §1b check that derives *this machine's* account
name, hostname and git identity at run time and compares. That technique is
available here and is **refused**, for a reason that is not the one you would
expect:

⭐ **`assert_clean` is half of what `studyforge validate` promises an adapter
(R2), and a gate whose verdict differs by machine is not a contract.** If the
material legitimately contains a word that happens to be some reader's account
name, the corpus would validate on one machine and be refused on the next, and
the adapter author has no way to act on that. FND-06's gate is a *local
development check* — a machine-specific verdict is exactly what it wants,
because the question it asks is "did **I** leak **my** data into this repo?"

A test scans this module's own imports with `ast` and asserts they are exactly
`__future__`, `re`, `collections` — so `os`, `pwd`, `socket`, `getpass` and
`subprocess` cannot arrive later without the test saying why not.

### 4. No allow-list, and exactly one hole

⛔ FND-06 exempts unreachable addresses (`example.com`, RFC 2606's reserved
TLDs) because `CLAUDE.md` positively instructs authors to write them, and a
check that fired on the sanctioned placeholder would be telling people not to
use the safe form. **This gate has no allow-list at all**: in an archive an
address is wrong content whether or not it is deliverable.

The one exemption is each shape's own placeholder, skipped by identity so that
`assert_clean(scrub(text))` can pass at all. ⭐ **After a deliberate choice of
placeholders, only one of the three is reachable:**

| placeholder | matches its own shape? |
|---|---|
| `/path/to/project` | no |
| `contact@example.com` | **yes** — every well-formed placeholder address is address-shaped |
| `Bearer` + `<redacted>` | no — the angle bracket is outside the pattern's character class |

⚠️ That last one diverges from the extraction source, which writes `Bearer`
followed by the bare word `REDACTED` — **eight characters of `[A-Za-z0-9]`,
which is the shape**, so the source's own placeholder trips the source's own
pattern. See *Surprises* 2.

The remaining hole is real and is stated rather than hidden. It is also why
FND-04's negative fixture deliberately uses a *different* address: a fixture
written with the scrubber's own replacement value would not be refused at all,
and the negative fixture would be protecting an empty box.

### 5. One walker, over decoded values, keys included

⛔ Neither layer ever sees a serialised form. The measured defect is in the
module contract: a rendered JSON newline is a backslash and an `n`, so a
decorator on its own line serialises with `n` immediately before an `@`, and
three clean lessons were refused. The fixture is
`ESCAPING_ARTEFACT` — and it has a companion test,
`test_and_the_serialised_form_would_have_matched`, without which the first
test would pass just as well on material that was never address-shaped at all.

Two smaller calls inside the walker:

- **Dict keys are visited.** An asset map keyed by a filesystem path is as
  much a leak as one valued by it, and a walker over `.values()` never sees it.
  ⚠️ FND-04's test-local walker takes the other choice — *Findings* 2.
- **A type the walker does not understand is refused, not skipped** (R6), and
  the `TypeError` names `type(value).__name__` and never `repr(value)`. A
  test builds an object whose `__repr__` leaks and asserts the message does
  not.

### 6. `where` is required, and the refusal scrubs it

⛔ The refusal is forbidden to carry the matched text, so its **location is
the only actionable thing it is allowed to say**. A default for `where` would
let a call site drop it and leave a refusal nobody can act on, so there is no
default and a test asserts there is none.

⭐ And `where` is itself passed through `scrub` before it is formatted into the
message. This is the general form of the rule now in `module-structure.md`:
never format an exception object into a message, name the field you mean. The
same failure arrives one step earlier if the *caller's* string is a home path —
the gate would emit exactly the leak it exists to prevent. Refusing to echo the
matched value is not enough on its own.

### 7. The residual class is recorded, not built

The three conditions are in the module contract verbatim — a floor the manifest
can never lift, scoped and reported rather than globally silent, and the gate
still refuses but refuses less. ⛔ v1 builds none of it. The point of writing
them into the source rather than only into the epic is that the module is where
somebody will be standing when a real second source forces the question.

## Surprises

1. ⚠️ **This handoff's subject matter turned the quality floor red — twice.**
   A comment in `scrub.py` and another in `test_scrub.py` spelled the
   extraction source's token placeholder, which *is* the shape, so FND-06's
   sweep reported my own two new files. Fixed by rewriting the sentences to
   name the word without spelling the token, which is the same fix FND-06's own
   handoff needed. **This is the answer to my open question** — see
   *Findings* 3.
2. ⚠️ **The extraction source's token placeholder is a hole in the extraction
   source's own gate.** `Bearer` + `REDACTED` matches `\bBearer\s+[A-Za-z0-9._\-]{8,}`,
   so `assert_clean` there relies on the identity skip to avoid refusing its
   own output. Measured, and it is why two of the three placeholders here are
   chosen not to match at all — a placeholder that needs an exemption is a hole
   with a friendlier name.
3. ⭐ **The escaping-artefact acceptance is vacuous without a second test.** A
   test asserting "this document is not refused" passes on any clean document.
   The proof that the hazard is real is the assertion that `json.dumps` of the
   *same* document **is** address-shaped. Two tests, and the pair is the
   acceptance.
4. `scrub` on a home path replaces only the `/home/<name>` prefix, so
   a path becomes `/path/to/project/rest/of/it`. That reads correctly and is
   the right semantics, but it is worth knowing before someone asserts on a
   whole scrubbed path.

## Findings

1. `[structural]` **The two gates' email patterns differ by one character of
   local part, and the difference is load-bearing.** FND-06 requires two or
   more characters before the `@` because it reads whole files and the only
   email-shaped text on this tree was the escaped-newline artefact. **This gate
   requires one or more**, because it reads decoded strings and therefore has
   the structural fix available. ⛔ Do not "align" them; a comment in `SHAPES`
   says so. The cost of FND-06's choice — an address like `a@b.example` slips
   its sweep — does not transfer here.
2. `[local]` **`tests/test_fixture_consistency.py` (FND-04) has a weaker
   home-path pattern than this gate**: it requires a trailing slash, so a
   document ending a sentence with `/home/<name>` and nothing after it passes
   that check and is refused by this one. Its `strings_in` walker also skips
   dict keys. ⭐ Now that the real gate exists, that file could import it and
   the divergence would be gone — but it is FND-04's file, so this is a finding
   and not a patch.
3. `[structural]` **Prose *about* the patterns is swept, and for the archive
   gate the right answer is the opposite of FND-06's.** FND-06 ruled: sweep
   `docs/` and every other tracked file, no exemptions, and it is survivable
   only because the placeholder convention is something **we control** — we
   write our own documents, so we can be told to write `/home/<name>` with
   angle brackets. ⛔ **The archive gate cannot make that bargain**, because
   its subject is material *somebody else wrote*, and telling a source to
   phrase its lessons around our regexes is not available. So:
   - the archive gate sweeps **content**, never documentation, and it has no
     tree sweep and no file list — it is called at boundaries;
   - a corpus whose material legitimately carries a shape this gate owns is the
     **residual class**, answered by a manifest declaration (§*Decisions* 7),
     not by an exemption and not by a softened pattern;
   - and the two gates therefore *must* disagree, because one can demand a
     convention of its authors and the other cannot.
   ⚠️ The live proof is *Surprises* 1: writing about this gate is the thing
   most likely to trip the other one.
4. `[local]` **`tools/quality/personal_data/shapes.py` carries a `#:`
   doc-comment with nothing under it** (around lines 107–111, describing
   `GENERIC_IDENTIFIERS`). The constant moved to `identity.py` when I split the
   module at FND-06 and the comment stayed behind, so it now documents the
   function below it. Cosmetic, misleading, mine, and outside this task's diff.
5. `[structural]` **One acceptance clause cannot be closed in M1.** *"No
   generated file, log or report in the entire v1 output contains personal
   data — asserted by a repository-wide check, not by inspection."* There is no
   generated output yet. What exists: FND-06's tree sweep covers the
   *repository*, and `test_every_other_fixture_document_passes_the_gate` covers
   every committed corpus document. ⭐ The output half wants a check that runs
   over a built site, and the natural owner is E10 — it should be an explicit
   clause on whichever task first produces a site directory, not left to be
   noticed.
6. `[structural]` **The gate has no callers yet, and that is the risk.** A gate
   nobody calls is green forever. The call sites are listed below; each one
   should assert the gate *is* called, not merely that it works.

**Q1b, for E04.** ⭐ **Narration speaks a disclosure's summary and stops.** The
body gets **no** speech ids, so a clip for it cannot be minted or addressed;
the unit's speakable record states how many blocks it withheld and the
narration coverage report names units with unspoken content, so the omission
reads as a decision rather than as a bug in the walker (R6). ⛔ No invented
sentence announcing the hidden section — that is narration writing prose the
author did not. ⛔ No manifest knob: the rule is uniform, so R1 holds with no
per-corpus data at all. ⭐ **SF-07's parser is what makes the body
identifiable** — `disclosure` is a block type and it is in
`archive.markdown.CONTAINER_TYPES`, so the walker needs no heuristic.

**If you are about to unify the two gates: don't.** They differ in three ways
and each one is a ruling, not an accident.

```text
                        archive gate                repository hygiene gate
subject                 material a source wrote     files we wrote
allow-list              none                        unreachable addresses
value derived at run    never (R2: one verdict      yes (§1b: "did I leak my
time                    on every machine)           own data into this repo?")
```

⛔ And neither imports the other's pattern list. A test asserts this module
contains no `import tools`, with the reason attached, so the duplication is not
mistaken for drift and "fixed".
