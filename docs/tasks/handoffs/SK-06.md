## Decisions

- **The merge rule** is `SKILL.md` § The merge rule. It is a join:
  - a pass is never lost;
  - this machine's `first_passed_at` never moves;
  - `last` is the later run by instant, and an unorderable pair leaves this machine's;
  - `runs` is the larger count, never the sum, so a re-import or a round trip changes nothing.

  ⚠️ `runs` also rises by at most two, for the runs `record_run` must record to carry a pass or a later `last` (`SK-06/1`).
- **The belief rule:** an imported pass is believed as recorded. The record keeps no history (`SF-19b/5`), and progress enters only from an `owner` archive. The import refuses only an entry the store could never have written, and names it by key.
- **Material** is every regular file under the root except `.git`, `__pycache__` and the progress store. ⛔ Both kinds are R7-gated, and a symbolic link is refused.
- **Import checks everything before it writes anything.** A differing file is kept, never overwritten. A refused practice exits `1` after the rest is applied.

## Findings

| id | marker | against | what |

| `SK-06/1` | `[structural]` | `studyforge.progress` (`SF-21/3`) | `record_run` is the only public write, so a merge is runs appended. That costs up to two runs over the larger count, and it is many locked writes, not one.
