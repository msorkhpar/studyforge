### What the panel is

- **The statement is the SECTION** — a practice's prose, hint and starting code are ordinary
  blocks and `render.page.section` renders them (R1). This module never touches `blocks`.
- **The panel follows its section**, outside `<section>`, the shape the attachments region
  and the narrated deck already have — so it is not in the outline, and a unit with several
  practices gets a panel after each statement rather than two statements and two toolbars.
- **The file** the reader works in, named in text, always.
- **The editor slot** carrying the sentence that says the editor is not running and how to
  start it — ⛔ never a blank frame, which is what an `<iframe>` pointed at a container that
  is down gives you.
- **Run always; Submit only where the workspace names a test command** (`W357`), and
  **Stop** ships `hidden` and is shown only while a run is live. ⛔ **No disabled control is
  ever emitted for an act the page cannot perform.**
- **The grader label**: two sentences, two template files, chosen by `Exercise.authoritative`.
  ⛔ **Neither `provenance` nor `trust`, nor any of their values, reaches the page** — asserted
  over all three record shapes.
- **A section with no `workspace` gets NO panel at all** — not a disabled one. A lesson, a
  quiz (`AX-09`), and a corpus that ships no graders each render with no practice affordance.
- **Over `file://` the controls stay hidden** and the panel says Run and Submit need the local
  study server. ⛔ Nothing is disabled there either.

### How a served page gets the client — one way, and the pair is the property

⭐ The serving process inserts exactly one `<script … defer></script>` before the first
`</head>` of an HTML page **as it answers it**; the file on disk is untouched, and the built
page names no API, no origin and no client file (R8, and the floor in
`tests/studyforge/cli/serving.py` reads a built text that names it as a defect). ⛔ The panel
reads `window.studyforge.run` and nothing else.

## Decisions

- ⭐ **The panel is joined in `page.document`, not given a page-skeleton slot.** A slot is one
  region per page and a unit may carry several practices; a panel that did not follow its own
  statement would leave a reader with two statements and then two sets of controls.
- ⭐ **`data-practice`, never `data-section`.** `templates/section.html` carries a CORPUS's own
  key in `data-section` (R1), so a corpus with a section called `practice` would otherwise be
  styled and scripted as the framework's panel.
- ⭐ **`practice.css` targets no class at all**, like the four chrome parts, so nothing is added
  to `pageassets.SURFACE_HOOKS` and the both-directions class contract is untouched. The
  `data-*` the script reads are script hooks with one emitter and one reader, which is
  `render/page/mark.py`'s `data-unit` precedent stated at length.
- ⭐ **The practice key is minted by `progress.practice_key`** from `page.mark.key` taken apart
  by `address.parse_unit_key` at the document's own depth. ⛔ No separator is typed in the
  renderer and there is no second key format on the page (`SF-21/4`).
- ⭐ **The insertion is decided by a `client=` ARGUMENT, never by `serve.app` importing the run
  route.** Importing it there would put `execute` — and a process library — into every import
  of `serve.app`, which `tests/studyforge/serve/test_init.py` asserts against.
- ⭐ **`client_for(namespaces)` gates it**, so the `--site` form's named seam (`W386`) can still
  serve a site with NO execution and that page is told to fetch nothing.
- ⭐ **A served page carries a DIFFERENT validator from its file** (`client_etag`, a mark inside
  the opaque tag). The weak ETag is size and mtime, which do not move when the client is
  inserted, so without a mark a page cached from a served origin and one cached from a plain
  file mount collide under one tag.
- ⭐ **The insertion happens BEFORE the personal-data gate**, so what leaves the process is what
  was gated. A page gated and then edited is a page whose served bytes nothing checked.
- ⭐ **The client path is CHECKED, not escaped.** The only caller passes `run.CLIENT_PATH`; a
  value that needed escaping there is a value this route should not have been given.
- ⛔ **No browser storage.** A run's outcome is the SERVER's record (`SF-21`), written where it
  was established; a page that also remembered would be a second answer to *did this pass?* —
  and there is therefore nothing for `W397`'s one-storage-origin problem to reach.
- ⭐ **Focus follows the control that goes away**, and it is asked BEFORE the control is
  disabled: a disabled element drops focus to the document immediately, so a check taken
  afterwards always answers no and a keyboard reader is returned to the top of the page.
