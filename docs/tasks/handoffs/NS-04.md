## Decisions

**1. ⛔ THE CATALOGUE IS DECLARED BY THE ADAPTER, NOT FETCHED FROM THE ENGINE.**
⭐ **The engine has a `GET /v1/audio/voices` and I deliberately do not call it at
request time.** A live fetch puts a network call inside validation, so an engine
that is down turns *"this voice does not exist"* into *"try again later"* — and
a job in a misspelled voice is then **attempted** rather than refused, which is
the exact outcome this row exists to remove. ⚠️ **Two more things follow and both
were needed**: `consuming.json` can carry the catalogue, which is a *file* a
consumer reads without running anything (R19, `SK-07`); and the suite needs no
engine and no GPU. ⛔ **The cost is real: a declaration can drift.** It is named
in three places and made *measurable* by `tools/reconcile_voices.py`, and the
measurement is taken below rather than deferred.

**2. ⛔ THE IDS ARE MEASURED; THE NAME, LANGUAGE AND GENDER ARE DERIVED BY A
PUBLISHED RULE.** ⚠️ **Mixing the two would give a hand-written table that is
partly a reading and partly an assertion, with no way for a reader to tell which
half is which.** ⭐ So `VOICE_IDS` is a reading with its image digest beside it,
and `LANGUAGE_BY_PREFIX` / `GENDER_BY_PREFIX` are Kokoro's naming convention
written down so a consumer can check the derivation. ⛔ **The decoder is TOTAL**:
a prefix outside the tables gives `unknown`, never a guess and never a drop — a
voice the engine really serves must stay selectable, and a decoder that refused
one would turn a naming convention into an outage.

**3. ⛔ THE ADAPTER CONTRACT WIDENED FROM FOUR MEMBERS TO FIVE, and that is a
POPULATION change, not only a file change.** `check_engine` is a gate over
*every object offered as an engine*, so an object that satisfied the old
contract is refused today. ⭐ **The alternative was worse**: *which voices exist*
is a fact about an engine family, so a catalogue held anywhere above
`narrate.engine` would make the server branch on which engine was deployed —
which is precisely what `registry.py` exists to prevent. ⚠️ **`tests/support.py`'s
`FakeEngine` gained `voices()` and deliberately carries TWO voices, not a copy
of Kokoro's 68**: a double mirroring the real list becomes a second declaration
of it, and the two drift.

**4. ⛔ THE ENGINE MODEL IS NOW IN THE CONTENT ADDRESS. This is `CTO-69/19` and
`NS-02/14`, routed to this row, and I took the FIRST of the two remedies they
offered.** ⚠️ **The defect was silent and it mis-served audio**: a deployment
that swapped the model kept every address, so a corpus stayed *"cached"*, every
clip spoke in the new model's voice, no count moved and no test failed.

⭐ **The split I used is `engine/base.py`'s OWN three-field split, used for the
thing it was written for.** `EngineIdentity`'s docstring already says the model
is *"the one that changes what the audio sounds like without either of the other
two moving"*. So:

| | in the address? | |
|---|---|---|
| engine **family** | ⛔ no | a different family is a different adapter, and its audio differs — but the family never changes under a running deployment without the model changing too |
| hardware **profile** | ⛔ no | ⭐ **the property `NS-03` built**: a CPU↔GPU move of one model must not re-synthesise a corpus |
| engine **model** | ⭐ **yes** | it decides how a voice sounds |

⛔ **The rejected remedy was *"declare the exclusion and make a model change a
deliberate store reset"*, and it is rejected for `CTO-69/18`'s own reason**: it
puts a correctness property in an operator's memory. ⚠️ **The cost of the remedy
I took is that every address moves once** — a store filled under `provides: 2`
is a complete cache miss under `3`. ⭐ **Stated in `narrate/__init__.py`, in
`consuming.json`, in `docs/api.md` as an upgrade note, and in a test whose name
is the question.** Nothing is deleted, so the cost is disk and one run.

**5. ⛔ `parse_job`'s `catalogue` IS REQUIRED AND HAS NO DEFAULT.** ⚠️ **An
optional validator is a validator that is off wherever somebody forgot it.**
⭐ **A test asserts the `TypeError`**, so a future call site has to decide which
catalogue it means rather than inheriting `None`.

**6. ⛔ THE REFUSAL IS THE WHOLE JOB, NOT THE SEGMENT.** A voice applies to every
segment, so an unknown one is a property of the **request**. ⭐ **A `400` before
anything runs, rather than a `200` carrying three thousand `failed` entries
after three thousand round trips** — and the assertion is on the engine's own
call list, not on a status string.

**7. ⚠️ A REFUSAL NAMES WHAT IS PERMITTED AND NEVER ECHOES WHAT ARRIVED.**
`config._one_of`'s rule. ⭐ **It is also the more useful message** — the caller
already knows what it sent — and it keeps a caller's string out of whatever log
an operator pastes somewhere. ⚠️ **With 68 voices the message is long**, and
that was weighed: a truncated list is a message a caller has to go elsewhere to
finish reading, and `GET /v1/voices` is named beside it either way.

**8. ⭐ `default_voice` IS PUBLISHED ON `/healthz`, and it is the same argument
`chunk_chars` won.** It is part of the content address of every segment
submitted **without** a `voice`, and a caller recomputing an address cannot read
a deployment setting from a constant. ⛔ **`engine_model` is published for
exactly the same reason** and is now in `addressing` on every manifest.

**9. ⛔ ONE SOURCE FOR THE DEFAULT.** `VoiceCatalogue.listing()` deliberately
does **not** carry a default; `build_server` resolves `config.voice` against the
catalogue once, at startup, and both `/healthz` and `/v1/voices` report that.
⚠️ **Two sources for one answer is how they come to disagree**, and a test
asserts the two routes agree.

**10. ⛔ `provides` 2 → 3, and I CHECKED `NS-02`'s ARGUMENT RATHER THAN
INHERITING IT.** `NS-02/13` kept `2` on the ground that *"version 2 has never
left this repository"*. ⭐ **Measured, role pinned checkout `../narrate-service`,
environment HOST, ref `58622a5` (`main`):** `git show main:narrate/__init__.py`
prints `PROVIDES = 2` and `git show main:consuming.json` prints
`"provides": 2,`. ⛔ **So version 2 HAS merged, the argument is dated, and `3`
is the next number rather than more churn inside an unpublished one.** The gate
test now records that reasoning in the tree with the old wording quoted beneath.

**11. ⚠️ `python3 -m tools.workspace record` was NOT run**, for the reason all
three predecessors measured: it rewrites the commit of every `present` row and
would advance the `ISO-8583-jPOS-tutorial` pin the board holds `pending`.
One row was edited by hand.

**12. ⭐ `tools/reconcile_voices.py` IS A TOOL AND NOT A TEST, deliberately.** A
test that reached an engine would be a test that does not run — the suite needs
no engine, no GPU and no network, and turning that into a `skip` hides a red as
a dot.

- ⛔ **The engine serves 68 voices and 15 of them are legacy `v0` variants**,
  which I had no expectation of at all. ⚠️ **They forced the decoder to be
  total rather than clever**: `af_v0` has no speaker part after the marker, so
  a rule that assumed one produced an empty name. It is a real id the engine
  really serves, and the decoder now names it `Legacy (v0)` rather than
  refusing it.
- ⚠️ **The engine's own catalogue carries a quality grade and a training
  duration per voice, and I deliberately did not carry them.** ⭐ They are the
  engine's editorial opinion of itself; committed into a declaration they would
  go stale with nothing noticing, which is the drift this file's own tests
