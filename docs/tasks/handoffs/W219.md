### ⛔ THE FLOOR IS REBUILT, AND ITS KEY HOLDS NOTHING A SPLIT MAY CHANGE

The replaced floor was a set of `path:function` strings. ⭐ **A declared split may change the
module a reader lives in and the name it is called by, and change neither what it catches nor
how many callers catch it** — so both halves of that key are exactly the part that moves, and a
floor built on them cannot tell a move from a loss.

⭐ **What is left once they are stripped is the SUBJECT: which package's tuple is being caught.**
The floor is now `REACH`, a map from subject package to the number of catch sites that name its
tuple. A caller may move, be renamed, be split; the count does not notice. A caller that stops
being found lowers its subject's count below the floor and the assertion fails, ⛔ **naming the
subject AND printing the whole population** — `population_report` lists every site the sweep
found with what it caught, so the count never hides which site went.

### ⛔ THE PREDICATE READS A WIDENED ALIAS, WHICH IS WHAT TODAY'S TREE USES

`skills/onboarding/standing.py` binds `REFUSED = (*RAISES, ContentError, ArchiveError)` at
module level and then writes `except REFUSED`. ⚠️ **That names the tuple WHOLE** — widening adds
arms and removes none — **but the first office's predicate read the handler expression only, so
on today's tip it read that site as retyping `generate`'s tuple.** ⭐ `tuple_names_bound_in` now
resolves module-level aliases with the SAME predicate, so `(*RAISES, X)` carries the tuple and
`(*RAISES[:1], X)` carries nothing: ⛔ **a slice cannot be laundered through a module constant.**

## Decisions

⛔ **1. THE FLOOR IS A PER-SUBJECT COUNT, AND THE ALTERNATIVES WERE REJECTED FOR A REASON EACH.**

- ⛔ *A pinned set keyed on `path:function`* — what was refused. It cannot survive the move.
- ⛔ *A pinned set keyed on the function name alone* — survives a move between modules, dies on
  the rename half of a split, and `W313`'s seam is precisely where names change.
- ⛔ *A pinned set keyed on `(caller package, subject)`* — survives a move WITHIN a package,
  which is the case in hand, but reads a move BETWEEN packages as a loss and cannot see a
  second site in the same package disappearing.
- ⛔ *A set the sweep repairs by derivation* — a floor that rewrites itself from what it finds
  is not a floor; it agrees with every shrink it is supposed to catch.
- ⭐ **The per-subject count is what remains once every part a split may legitimately change is
  removed from the key**, and it is the row's own reasoning one level up: the first office
  derived the population instead of typing it, and this derives the site's identity instead of
  typing it.

⚠️ **Its one blind spot, stated so it is not mistaken for coverage (Ruling 208): one caller
deleted and another added for the same subject in the same commit reads as no change.** ⛔ A
name-keyed floor sees that and this does not; ⭐ a name-keyed floor also cannot be kept, which
is why the trade goes this way. The `retyped` arm still reads every site individually.

⛔ **2. THE MOVE PLANT IS RUN OVER EVERY SITE, NOT OVER THE ONE THAT MOVED.** `W313`'s split is
the case in the row, but writing `skills/onboarding/removal.py:_stubs` into the test would put
the very brittleness the row is about back into the fixture. ⭐ **So the plant derives its
subject: each site the sweep finds in turn is moved into a new module beside its own and
renamed, carrying the imports and module-level constants the moved function reads.** ⚠️ **The
assertion that the site's NAME changed is what makes the green a reading** — without it a copy
that moved nothing would pass.

⛔ **3. THE DELETE PLANT IS RUN OVER EVERY SITE TOO**, so no single subject's floor is carrying
the reading, and each red is checked to name the subject AND to print the population.

⛔ **4. THE ALIAS ARM READS MODULE LEVEL ONLY.** A tuple aliased inside a function body is not
resolved. ⚠️ Stated as `W219/5` rather than built: resolving local bindings means following
assignment flow, and nothing in the tree writes that shape today.

⛔ **5. `archive` IS EXEMPT, on the first office's argument, unchanged.** The convention covers
*a package whose reader lets ANOTHER package's exception through*; both of `archive`'s
pass-throughs are `archive`'s own, so a caller has no second package's paragraph to retype.
⭐ The exemption is checked rather than asserted, and expires the day a caller catches a foreign
exception around an archive reader.

⛔ **6. `skills/onboarding/` WAS NOT EDITED.** The one site there the sweep read as
non-conforming was the predicate's gap, not the package's defect — `standing.py` already names
the tuple whole. ⭐ **The repair went into the instrument, where it belonged.**

## Surprises

⛔ **1. THE REFUSED FLOOR HAD A SECOND WAY TO GO WRONG, AND TODAY'S TIP WAS ALREADY IN IT.**
Carrying the first office's instrument onto today's tip turned the sweep RED — not on the moved
site, which it found, but on `skills/onboarding/standing.py:standing_of`, whose conformant
widened alias the predicate could not read. ⚠️ **So the branch could not have been merged by
repointing one string either**; the tree had moved under it in two independent ways.

⛔ **2. THE MOVE PLANT WENT RED ON ITS FIRST RUN, AND IT WAS THE FIXTURE THAT WAS WRONG.**
Splitting a function into a new module carried its imports but not the module-level alias it
catches with, so the moved `standing_of` read as retyping. ⭐ **A real declared split carries
the constants the moved code reads**, which is what `removal.py` did; the fixture now does the
same, and the failure was the fixture being a worse split than `W313` was.

⛔ **3. THE FIRST OFFICE'S OWN READING OF THE OLD FLOOR IS CORROBORATED HERE FROM THE OTHER
SIDE.** It measured that the floor it replaced named fewer sites than the sweep reached. ⚠️ **A
floor that is a strict subset of what the instrument finds cannot catch the instrument
narrowing** — and the refusal that produced this branch is the same defect seen from above: a
floor whose key is unstable is repaired by hand, and a floor repaired by hand drifts.

## For dependents

- ⛔ **A new package that exports `RAISES` is INSIDE the sweep the moment it lands** — there is
  nothing to add to [`tests/raises_sweep.py`](../../../tests/raises_sweep.py). ⚠️ What it owes is
  a handler that names the tuple at every caller, and the sweep will name the site if it does not.
- ⛔ **A handler names the tuple only by naming it WHOLE.** `except RAISES`,
  `except (OSError, *RAISES)` and `except ALIAS` where `ALIAS = (*RAISES, MyError)` all pass;
  `except RAISES[:1]`, `except RAISES[0]`, a retyped member list and an alias built from a slice
  do not.
- ⛔ **A site that handles one member differently keeps its own arm FIRST and still names the
  tuple** — `except PersonalDataLeak: raise`, then `except RAISES`. That is the form
  `generate/declarations.py` already used and the form `serve/discovery.py` now uses.
- ⭐ **MOVE A CALLER FREELY.** Split it into a new module, rename it, both at once — the floor
  in [`tests/test_raises_convention.py`](../../../tests/test_raises_convention.py) holds, and
  there is nothing to repoint by hand. ⛔ **What you may not do silently is REMOVE a catch site**:
  that lowers its subject's count, and raising `REACH` is a deliberate edit you say out loud.
- ⭐ **`archive` owes no tuple**, and the reason is one clause in the convention with a test
  behind it. ⛔ If you make `archive` let another package's exception out, that test goes red and
  the exemption is spent — the remedy is the tuple, not an edit to the test.
