## Decisions

- **`SKIP_DIRS`, not `.git` alone.** The copy leaves out the root's `.studyforge` as well. `validate` never reads it as material, so the copy cannot differ from what `validate` accepts, and one imported rule is kept instead of a filtered copy.
- **The nested store is copied, not refused by the template.** The verdict and its name then come from `validate`, and the template only decides what reaches it.
- **The stores are asked of `validate` only in a working tree.** Outside one, nothing is asked of git at all, so nothing needs excluding.

## Surprises

- ⚠️ **Plant P4 SURVIVED, and it is measured as equivalent.** It asks git about a nested store's own path. In a scratch repository outside every checkout, `git check-ignore` answers "not ignored" (exit `1`, no error) for a nested `.git` directory, a gitfile, and a path inside a store. So on those shapes asking changes nothing. The filter is kept as a guard: `W259/2` measured git failing (exit `128`) inside a registered submodule, a shape not reproduced here.
