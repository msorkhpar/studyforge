### ⛔ THE DESIGN DECISION, stated first (settling clause 1)

⭐ **The reader's document states what the BUILD read, and `reader_document` is still pure.**
A new module, `skills/onboarding/standing.py`, does the reading and returns a `Standing`;
`artifacts.reader_document(manifest, hand_written, *, commit, standing=None)` renders it. With
no `standing` the document says the state was not read, and prints no figure.

⛔ **No second reader of the archive or of the narration record.** `standing_of` calls, in this
order, the framework's own readers:

| what is read | asked of |
|---|---|
| the manifest, the container maps, which declared units have material | `generate.read_corpus` |
| where one unit's page and audio go | `generate.unit_location`, `narrate.synth.audio_dir` |
| the narration record | `narrate.synth.read_state` at `narrate.synth.state_file` |
| the served document a page renders | `unit.builder.build_unit` |
| whether a page plays a clip | `narrate.playable.playable_of`, asked with that page's audio directory |

⚠️ **Those are the calls `generate.narration.recorded` and `heard` make**, reached through the
surfaces of `narrate.synth` and `narrate.playable` rather than through `generate.narration`,
which exports neither (Ruling 101; the floor reported it and the import was moved, not declared).

⭐ **What each figure means, so nobody has to re-derive it:** *units* is the declared count and
the count with material; *narrated* is the units whose page plays at least one clip; *reading-only*
is the units whose declared practice count is zero as `generate.declared_practices` reads it;
*container* is needed exactly when some unit declares a graded practice. An unreadable record or
container map is a **refusal carried as data** and quoted, never an exception and never a figure.

## Decisions

1. **The split is at the removal seam, declared before it was cut.** `onboard.py` stood at
   398/400 and this row adds a parameter and a call to it. `uninstall` and its five private
   helpers moved to `removal.py` unchanged: `onboard` composes and writes, `removal` takes back
   out, and the two share only the install record. `onboard.py` is now 325 lines and
   `removal.py` 113. The package re-exports `uninstall` as before, so `__all__` and every
   caller outside the package are unchanged.
2. **`root` is a parameter of `onboard`, not of `write`.** The file set — and the install
   record's digest of every file in it — is fixed when `onboard` returns, so a document whose
   text depended on `write`'s argument would make the record a claim about bytes that had not
   been decided yet.
3. **`reader_document` stays pure and takes the reading as data.** `artifacts.py`'s contract
   says it does no I/O; the reading lives in its own module, which is also what makes every
   *"what would it say for a corpus shaped like this"* question answerable without a corpus.
4. **A unit is narrated when its PAGE PLAYS a clip**, which is `playable_of` asked with that
   page's own audio directory — not "the record names an entry". A record that names a clip no
   page can play is exactly the state `W288` and `narrate.playable` exist to distinguish, and a
   document that counted it would tell a reader a unit is narrated while the page is silent.
5. **The commands carry `PYTHONPATH=../studyforge/src` and `python3 -m studyforge.cli`.**
   `studyforge validate` is the installed command and is not on a fresh clone's path; the
   module form reaches the same code with nothing installed, which is `docs/authoring/`'s own
   rule. ⛔ The test executes them rather than matching strings, so a typo is RED.
6. **Narration is named but not fenced as a run.** It needs a running narration service, which
   a document cannot promise; `narrate --help` is fenced instead, and it is executed like the rest.
7. **Two sentences of [`SKILL.md`](../../../src/studyforge/skills/onboarding/SKILL.md) changed, and no more.** Step 3's fence passes `root='.'` and
   step 5 says to run step 3 again after ingest — without those the procedure produces a document
   that never states a state, which is the defect this row is about. The table's reader-document
   row says what the file now carries.

## Surprises

- ⚠️ **`generate.narration` exports neither `recorded` nor `heard`.** The first draft imported
  them and the quality floor reported `surface-reached-past` twice (Ruling 101). Declaring them
  in `deviations` would have been declaring a defect, and exporting them is `generate`'s surface,
  not this row's — so this module asks `narrate.synth` and `narrate.playable` directly, which is
  what those two functions do anyway.
- ⚠️ **`build . --out .` writes `index.html` at the corpus root**, so the fenced build is a real
  build into the repository the reader is standing in. That is the placement design (media and
  pages are committed by default, `SF-32`, `W242`) rather than a choice made here; a corpus that
  wants its site elsewhere changes `--out`, which is why the plan command precedes it.
- ⚠️ **`validate` on a corpus that is not a git working tree reports an unchecked claim** and
  still exits 0. The executed-command test asserts the exit codes, not the prose.

## For dependents

- **Anybody onboarding or regenerating a corpus:** pass `root=` to `onboard`. Without it nothing
  breaks and nothing is invented — the document simply says the state was not read.
- **A corpus that wants its reader document current:** regenerate after ingest and after
  narration. `write(..., regenerate=True)` rewrites it and leaves the one hand-written file alone.
- ⭐ **`standing.standing_of(root)` is available to any skill that needs the same reading.** It
  never raises and never prints a path (R7); the refusal it carries is the build's own sentence.
- ⛔ **`uninstall` now lives in `skills.onboarding.removal`.** Import it from the package
  (`from studyforge.skills.onboarding import uninstall`), which is unchanged; only a module-level
  import of `skills.onboarding.onboard.uninstall` had to move, and the two tests that did it now
  import from `removal`.
