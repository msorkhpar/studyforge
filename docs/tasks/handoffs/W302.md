## What landed

### ⭐ `tools/mergegate.py` — the merge path, as a tree artifact rather than one office's habit

⛔ **It IS the merge, so there is no way to take the merge without it.** It stages with
`git merge --no-ff --no-commit`, runs every gate in `GATES` against the tree that merge
produced, and commits only when each exits `0`.

```bash
python3 -m tools.mergegate <branch> --body <body-file>
# ⛔ exit 0 merged · 1 a gate refused and NOTHING was committed · 2 nothing was read
```

- ⛔ **It reads the MERGED tree, never `HEAD`** — most of `PO-92/1`'s population ARRIVED
  WITH CARRIERS, so a `HEAD`-side reading would have passed every one of them. ⭐ Asserted
  directly: a gate that refuses only what the branch adds fires, and the mirror states in
  its own name that a `HEAD` reading would have passed it.
- ⛔ **A red reading ends in `git merge --abort`, and the restore is VERIFIED BY READING
  THE TREE** — `HEAD` back at the tip and the tracked tree clean — never by the abort's own
  exit code
  ([Ruling 287](../../conventions/review-rubric.md#ruling-287-the-container-cannot-restore-and-a-restore-whose-exit-code-is-unread-is-not-a-restore)).
  ⭐ **A refusal whose restore cannot be verified is `UNREAD`, not a tidy `REFUSED`.**
- ⭐ **`GATES` is the DECLARED PAIR and every entry is required**, each naming what the
  OTHER environment cannot answer — so removing one is visibly removing a READING rather
  than tightening a command.
- ⛔ **It stops at the FIRST red**, and the gates it therefore did not take are NAMED with
  their environment: two gates share the name `suite`, so a bare name cannot say which
  reading went unread
  ([Ruling 326](../../conventions/review-rubric.md#ruling-326-a-reading-is-quoted-with-its-environment-or-it-is-not-a-measurement-and-green-names-the-environment-that-produced-it)).
- ⛔ **`UNREAD` is a real third state** — no gate declared, a tree git cannot read, a dirty
  tracked tree, a merge that does not stage, or an unverifiable restore. ⭐ An empty gate
  list returns it and never the pass code
  ([Ruling 191](../../conventions/review-rubric.md#ruling-191-cto-round-49-a-control-owes-inhabitation-and-an-empty-population-returns-the-pass-reading-rather-than-no-reading)).
- ⛔ **It asks git for a COMMITTER IDENTITY before it stages anything**, and names its
  absence. ⚠️ MEASURED: the pinned image configures NONE, so without this the merge simply
  fails and the office is told *"did not stage cleanly"* — which names the wrong thing.
  ⭐ Asked of git itself rather than of one config key, so an identity from the
  environment, a system file or a repository config all answer, and the message says to
  pass one PER INVOCATION and set none (`W305`'s rule, taught at the point of failure).

## Decisions

### ⛔ RULED: a COMMAND, and the placement is FORCED rather than chosen

⚠️ **The naive remedy — *add it to `tools.quality.CHECKS`* — is refused by an existing
ruling, which is the wall [`W296`](../rows/W296.md) met.** ⭐ The argument is
`board/corroborate.py`'s and is CITED rather than re-derived:
[Ruling 80](../../conventions/review-rubric.md#2e-ruling-80-a-floor-checks-verdict-may-not-depend-on-untracked-state)
(a branch position is the purest untracked state there is), R10 (the floor runs over
arbitrary roots with no release branch and no daemon), and Ruling 191 (a floor check that
shelled into git and found nothing would return THE PASS READING FROM AN EMPTY
POPULATION). ⛔ **The mirror asserts it is in neither `CHECKS` nor `NOTICES`.**

### ⛔ RULED: it lives at `tools/`, beside `treestate.py`, and NOT under `tools/quality/`

⚠️ `subject.py`, `gated.py` and `trial.py` are merge-path instruments that DO live under
`tools/quality/`, so the precedent cut both ways. ⭐ **That package's own contract says it
is the FLOOR — standard-library-only, runnable on a clean checkout with no network, over
arbitrary roots.** ⛔ **This shells to a docker daemon and to `git merge`**, so filing it
there would falsify the package's opening sentence. ⭐ `treestate.py` is the standing
precedent for a `tools/` module that is not floor machinery.

### ⛔ RULED: the PAIR is RUN and BRANCHED ON; the SKIP CENSUS is a DISCLOSURE

⚠️ **Clause 1b meets a ruling wall of its own, and this is how it is resolved.**
[Ruling 328](../../conventions/review-rubric.md#ruling-328-a-gates-predicate-ranges-over-state-the-branch-controls-a-property-over-host-state-is-a-disclosure-and-never-a-gate)
says a gate's predicate ranges over state THE BRANCH CONTROLS. ⛔ **Which tests an
environment can REACH is host state** — a sibling checkout appearing flips it with no file
the branch owns being touched — ⭐ **so what is GATED is each environment's EXIT CODE,
which the branch's own diff can move, and what is DISCLOSED is the census, which the suite
already prints and nothing here reads.**

### ⛔ RULED: the gate PERFORMS the merge rather than advising about it

⭐ **An instrument whose exit nothing reads is indistinguishable from one nobody ran** —
[`W296`](../rows/W296.md)'s sentence, and this row's own origin. ⛔ **So the command does
the merge**: there is no ordering in which an office gets the merge and skips the gate.

### ⭐ DECIDED: it stops at the first red

⛔ **A refusal is complete the moment one gate refuses**, so a later gate cannot change the
outcome — and a refusal that costs a whole second environment is one that eventually gets
worked around. ⚠️ **The gates NOT taken are named, because a shorter list must never read
like a list that all passed** (`FND-07`'s rule, and
[Ruling 78](../../conventions/review-rubric.md#ruling-78-the-floor-prints-the-lint-state-including-its-absence)'s
shape).

## Surprises

- ⛔ **THIS ROW'S OWN SUBJECT CAUGHT THIS ROW'S OWN DIFF, and that is the sharpest thing
  measured here.** The first commit on this branch was **format-RED in the pinned image**
  while the HOST floor read `quality floor: clean` and the host suite SKIPPED both ruff
  gates. ⭐ It was found only because the plant's image reading quoted a line from
  `tools/mergegate.py` rather than from the planted file. ⚠️ **An office following the
  host-only practice this row exists to end would have merged it** — settled by `ruff
  format` applying its OWN output in the image.
- ⛔ **AND IT CAUGHT IT A SECOND TIME, in the owed SUITE gate, which came back RED.** The
  mirror passed on the HOST and **12 of it failed in the pinned image**, because
  `tools.mergegate` runs `git merge` and `git commit` ITSELF and the image configures NO
  git identity — so every staged merge failed in there. ⭐ The host passed only because the
  shared config happens to carry one. ⚠️ **Both times the divergence was invisible to every
  host reading, and both times only the image gate found it** — which is the row's own
  thesis, measured twice on the branch that argues it.
- ⛔ **`tests/docker` is unreachable in BOTH routine environments**, not host-only: unset,
  the host skips it because the image cache was not probed, and the image skips it because
  building inside itself would recurse (Ruling 332's measurement, re-taken here).
- ⛔ **`tests/visual` RUNS in both**, and in the image it is the PINNED browser. The skip
  reason clause 1b attributes to it — *"inside the dev image, which has no docker client"* —
  belongs to a docker test, not to the visual harness.
- ⚠️ **The genuine host-only half is the SIBLING and WORKSPACE assertions**, which the
  image cannot reach because it mounts only the checkout.
- ⚠️ **The full pair is not cheap**: a green merge pays both environments' suites. ⭐ A
  REFUSED merge is now much cheaper than before, which is the direction that matters.

## For dependents

- ⭐ **Merging to a release branch: run the command, and let it do the merge.**
  `python3 -m tools.mergegate <branch> --body <file>`. ⛔ **A host-only certification cannot
  answer the `ruff` enforcement** — the host reports those gates as SKIPPED rather than
  passed, and `quality floor: clean` has never meant lint-clean.
- ⛔ **Adding a gate is adding an entry to `GATES` with the environment it is taken in and
  what only it can answer.** ⚠️ A gate with no `answers` text fails the mirror: the list is
  the unit, and an entry that cannot say what it uniquely reads is one somebody will delete.
- ⭐ **Whoever takes [`W296`](../rows/W296.md):** the subject gate belongs in this command,
  BEFORE the merge is staged — a refused subject should never reach a staged tree. The
  mirror's fixtures already build a release checkout with an unmerged branch.
- ⭐ **Reproducing the plant** (the trial branches were throwaway and are deleted): cut a
  branch, change one docstring's first word from `Return` to `Returns`, commit it there,
  and run the command against it. ⛔ The host floor and the host suite both stay GREEN on
  the merged tree; the image refuses it. ⚠️ Plant on a COMMITTED tree and restore by
  `git merge --abort`, which is the gate's own mechanism.
- ⛔ **Run the command where git HAS an identity — which means the HOST, not the image.**
  ⚠️ It invokes `docker/dev/check`, whose recursion guard refuses to run inside the image
  anyway, and the image configures no committer at all (`W302/6`). ⭐ It now says so itself
  rather than failing obscurely.
- ⚠️ **Read `W302/4` before your first commit.** Pass the identity per invocation with
  `git -c`; ⛔ setting it writes the SHARED `.git/config` and renames other offices' commits.
