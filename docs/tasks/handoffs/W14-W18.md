## ⛔ W18 — R5 was failing open on the release branch

**Measured before:** `FORBIDDEN = (("generated", "authoritative"),)` named one
of the two pairs that break R5. ⛔ **So `user` + `authoritative` was accepted,
and a grader the reader wrote could declare itself the source's own.** Nothing
raised, and the suite was green about it.

⚠️ **The test that should have caught it is the tell.**
`test_a_user_written_test_may_be_advisory_and_not_authoritative` was *named*
for `user` and *asserted* `generated`. So the hole was refused by nobody and
asserted by nobody — an open set and a test that agreed with it.

**Landed, in Ruling 35's form:**

```python
#: ⛔ The provenances that may claim `authoritative` … ⭐ **The legal set, not
#: the illegal one**: a fourth provenance added to PROVENANCE is refused
#: `authoritative` on the day it is added, without anybody deciding.
MAY_BE_AUTHORITATIVE = ("bundled",)
```

⭐ `FORBIDDEN` is gone rather than extended — a second row would have been the
same open set with one more entry. `unit.__init__` exports the new name.

## W14 — two invalid fixtures, one surface

`tests/fixtures/invalid/` now holds **seven**.

**`count-mismatch/`** — E10's acceptance clause, unexercised until now. The
document says `"paras": 2` and carries one. ⛔ Its `content_sha256` is correct,
so the digest check passes and only the count check fires. ⭐ That is the
fixture's whole point: **a corpus can be byte-exact and still lie about
itself**, and `counts` is the field a consumer reads *instead of* walking the
blocks — a table of contents, a progress estimate, a narration length.

**`user-authoritative/`** — finding 29, and W18's negative control. A practice
document recording `provenance: user` with `trust: authoritative`. ⛔ **It was
a valid corpus until W18 landed**, which is exactly why it is this pair and not
`generated` + `authoritative`: a fixture pinning the pair that was *already*
refused would have been refused before the fix and after it, and would have
proved nothing.

⭐ **The check that fires is the framework's own.** `tests/fixture_checks/exercise.py`
calls `studyforge.exercise.of`, which calls `unit.trust.check_test_record`.
There is no second spelling of R5 in the fixture machinery; `unit.trust` is
asked one further question and only one — *which rule id names this refusal* —
which is a classification made after the framework has already refused.
