## What landed

### `W287`: the footprint is measured, and no closed task is named as future

- `derive._measured` weighs the declared units' media directories with `corpus.media.measure`.
  That is the one existing measurement, and it stats files without opening them. It runs only
  for a policy that weighs its media. `always` and `never` walk no disk.
- `MediaProjection` gained `measured` (a `MediaFootprint`) and `unmeasured` (why a reading was
  refused). The verdict comes from `corpus.media.verdict_for`, not from a comparison written
  here.
- The `media footprint` line now takes one of these forms:
  - `fits — measured N byte(s) in M file(s) on disk under the declared units' media directories, …`
  - `EXCEEDS — measured …: <each crossing's own sentence>`
  - `measured — 0 byte(s) in 0 file(s) …; nothing is there yet — studyforge narrate writes the clips there, …`
  - `not measured — <reason>`
  - with a rate, the projection line comes **first**, and the measured line still follows it.
- `UNPROJECTED` names no task. `derive` measures every corpus whose policy prints a footprint,
  and the no-media test asserts that a fixture plan does not print it. It remains the
  sentence for a projection built with neither a reading nor a rate.

### `W288`: a copy is located from the record, and a superseded clip is named as superseded

- `recorded.read_record(root) -> Recorded`. It holds `entries` (token to the paths
  `synth.located` gives), `superseded`, `read` and `refusals`.
  `Recorded.copies(token, audio)` gives the filenames the record locates **in that unit's audio
  directory**.
- A copy line is named only when the entry's own `where` locates its clip in the declared unit's
  audio directory. That directory is compared with the record's answer and never used to guess
  where a clip is.
  - A **dead** entry, whose `where` is a directory no declared unit reads, is named as nothing.
  - An unlocated entry (`where` null) is named as nothing.
- `report.SupersededClip(path, speech_id)` renders as `superseded <path>  <id>'s earlier clip —
  no build copies it; studyforge narrate --prune deletes it`. `Plan.superseded` holds them.
  They are **not** creations and **not** in `Plan.paths`, which a build's footprint is taken
  from. The summary counts them, zero included.
- A superseded clip is named only when the record locates it (its name is one file, and its
  `where` is present. A `where` that climbs out of the root is already refused by the record's
  reader, `narrate.synth`, before a plan sees it) and something is at that path, checked with
  `os.path.lexists`.

## Decisions

1. **A split at a named seam** (Ruling 261): the question *what does the narration record let a
   plan say* moved to `recorded.py`, and the record tests moved to its mirror.
   `test_derive.py` was the tight file, and it shrank.
2. **The measurement is asked of `corpus.media`, never written a second time.** That package
   is where a commit decision's number comes from. A plan that weighed files its own way would
   be a second measurement that could disagree with the first.
3. **"The copies a build makes" does not mean "on disk".** A clip whose entry locates it in its
   unit's directory but which is absent from disk is still named. `W267`'s line for it is
   `expect`, written by `studyforge narrate`, and
   `generate/test_clips.py::test_plan_enumerates_every_copy_and_the_build_agrees_path_for_path`
   asserts that. Only *where* decides whether a line is a copy.
4. **An unlocated (version-1) entry is declined, not guessed.** A build could still find its
   clip in its unit's directory. Naming it would mean deriving where the clip is from
   placement, which `W288` clause 1 forbids. The next `studyforge narrate` records the
   directory, and the line comes back. The cost is under **For dependents**.
5. **A rate adds a line and never replaces the reading.** A projection that fits beside a disk
   that does not fit would be the one line in the report that overclaims.

## Surprises

- ⚠️ My first design also required a copy's clip to be on disk. Reading `generate/test_clips.py`
  before writing it showed that `W267` deliberately plans an absent clip as `expect`. Decision 3
  is the corrected reading.
- ⚠️ A measurement authority already existed. `corpus.media.measure` and `verdict_for` were
  built for this question, and `W287`'s *"measures what is there"* needed no new code to
  weigh anything. Its docstrings still describe `plan` as projection-only (`W287/2`).
- ⚠️ A plant copy of `src` and `tests` alone does not run: the root `conftest.py` imports
  `tools.treestate` and reads git. The plant tree carries `tools/` and a throwaway `git init`.

## For dependents

- ⭐ **The M6 media-footprint row** reads `media footprint  …measured N byte(s) in M file(s)…`.
  That figure comes from `corpus.media.measure` over the declared units' media directories
  (see `W287/3` for what that excludes). With `--bytes-per-unit` there are **two** footprint
  lines, projection first.
- ⛔ **`Plan.paths` never contains a superseded clip**, so `generate.footprint` never owns one.
  A consumer that wants them reads `Plan.superseded`, not the text.
- ⚠️ **The summary line gained a count** (`N superseded clip(s) no build copies`). A consumer
  that matched the summary by position must re-read it. None in this repository does.
- ⚠️ **A version-1 record's entries are not planned as copies** until `studyforge narrate` runs
  once and records their directories. A build still copies their clips. A rebuild into the same
  `--out` would then refuse to replace them, because `Footprint.owns` does not name them. That
  was read from the code, not run. The refusal is safe, and it clears after one `narrate`.
- ⭐ `SupersededClip` is on the package's public surface (`studyforge.cli.plan`).
