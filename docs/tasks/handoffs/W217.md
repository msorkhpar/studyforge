## Decisions

1. ⛔ **Refuse, don't observe.** A write outside the minted directory raises the
   `EACCES` an unprivileged process gets. If the OS would fail first (`ENOENT`
   for a missing parent, `EEXIST` for an existing `mkdir` target), the event is
   let through so the OS raises its own error. ⭐ Measured, and the reason it is
   done this way: the census reads the same figures at the default uid before
   and after this change. Every uid now behaves like the unprivileged run.
2. ⭐ **Three outcomes, no writer list.** A write inside the minted dir *lands*.
   A write into `POISON_ROOT` (a path the harness invented and handed out) is
   *refused and counted*. A write anywhere else is an **`Escape`**: refused,
   and it fails the build. A process start is refused outright.
3. ⚠️ **In-process, unlike `tests/harness/probes/audit.py`.** The hook is inert
   when disarmed, and the census has to probe callables a test defines inside
   itself.

**The population:** every audited write event (`WRITE_EVENTS`, the
interpreter's own vocabulary), to **any path on any filesystem**. Relative
paths and `dir_fd` are resolved and symlinks are followed. ⛔ **It still cannot
see:**

- a write through a descriptor opened before the call;
- a write that makes no audited call (C extension, `ctypes`);
- a `dir_fd` on a system without `/proc/self/fd` (refused as an escape rather
  than guessed);
- **calls made by `tests/emission/documents.py`'s `document_census`, which is
  not wrapped** (see `W217/5`).
