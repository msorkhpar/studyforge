## What landed

### ⛔ The defect, in one line

`W313` made the reader's document state the corpus's real state, read through the build's own
readers. ⛔ **Nothing refreshed it.** `studyforge narrate` writes the narration record and no verb
rewrites a generated document, so the first corpus shipped a document saying
*narrated: 0 of 38 (there is no narration record yet)* while every unit page carried audio. ⭐ The
integration office left it wrong rather than hand-correcting it, and that was right (R19).

### ⭐ The shape chosen, and why

⚠️ **The brief left two open:** the verb that changes the state refreshes the document, or the
document stops carrying the count and derives it at read time. ⭐ **Chosen: the second.** Four
reasons, in order of weight:

1. ⛔ **The set of verbs that move these figures is OPEN, and part of it is outside the framework.**
   Narrating moves `narrated`; **ingesting moves `units`, and ingesting is an ADAPTER's** — R2 puts
   that seam on disk, and an adapter writes an archive and nothing else. ⭐ A framework cannot make
   every adapter refresh a document it has never heard of, so the first shape could never be total
   — and a document refreshed by some of its producers is not fixed, it is **freshly wrong less
   often**, which is harder to notice.
2. ⛔ **Refreshing it would make `narrate` rewrite a file at the corpus root.** The reader's document is a
   committed artifact that no build plan names, and `W331`'s generated R3 check reads exactly that:
   an `M` on a path the plan does not declare. ⭐ A fix that makes the corpus's own R3 check go RED
   on an ordinary narration is not a fix.
3. ⭐ **A POINTER resolves at read time; a fact in a snapshot cannot.** This is the property this
   repository's own [`CLAUDE.md`](../../../CLAUDE.md) was rewritten over (Ruling 161), one level up, and the argument
   transfers exactly — ⚠️ **except that it is WORSE in a corpus**, because the corpus's reader is
   not an agent who can be told to check a board. They have one document.
4. ⭐ **It removes a step rather than adding one.** The onboarding
   [`SKILL.md`](../../../src/studyforge/skills/onboarding/SKILL.md) step 5 told the operator to re-run
   step 3 after ingest. That instruction was the old shape's maintenance cost, and it is now gone:
   ⛔ an instruction that must be remembered after every narration is the defect, not the remedy.

### ⭐ Nothing of `W313`'s reading was discarded

⚠️ **`W313`'s figures were MOVED, not deleted.** `standing.lines` is the same prose, rendered from
the same `Standing`, produced by the same `standing_of` reading through the build's own readers. ⭐
**What changed is where it resolves**: in a command that runs when a person types it, instead of in
a file written once. ⛔ **`standing_of` is not weakened — it is promoted from a generation-time
detail to the instrument the product points at.**

### ⭐ One producer (Ruling 330), asserted rather than asserted-to

⛔ **There is exactly one place where a figure becomes prose**, and the document holds no second
copy. The test that holds this reads `FIGURES` against both sides: every figure must appear in
`standing.lines`'s output (so the tuple is not a set of spellings nobody produces) and none of them
may appear in the document. ⚠️ **That control matters**: without it, renaming a figure would make
every *"it is not in the document"* clause pass over nothing.

## Decisions

- ⭐ **`cli.py` + `__main__.py`, not a `standing/` package.** The command had to be runnable the way
  this repository defines runnable — `tests/test_authoring_reference.py` asks a commanded module
  for `<name>.__main__` — and `skills/buildserve` and `skills/personalarchive` already answer that
  with a `cli.main` and a four-line `__main__`. ⚠️ Splitting `standing.py` into a sub-package would
  have moved its mirror into a directory and bought nothing: both modules are well inside R11.
- ⚠️ **`python3 -m studyforge.skills.onboarding <root>` reports a standing rather than onboarding.**
  ⭐ Onboarding is not a one-shot command — it takes a draft a person settled, which is why the
  [`SKILL.md`](../../../src/studyforge/skills/onboarding/SKILL.md) beside it is the procedure — so the package's module entry point is free for the one question an
  **onboarded** corpus keeps asking, which is asked after the skill has finished running.
- ⭐ **A generated document reaching `studyforge.skills.*` is not a new dependency.** `W331` already
  has the generated corpus suite importing `studyforge.skills.reconnaissance.installed`, and the
  generated skill stubs already address skill documents inside the framework checkout.
- ⛔ **Two exit codes, split on whether there was a READING and not on whether there were figures.**
  *Nothing has been ingested* exits `0`: it is an answer, and the document prints this fence before
  ingest as well as after. `UNUSABLE` is for a root that is not a corpus, or a corpus the build
  refuses — ⚠️ and the refusal is still PRINTED, because an exit code with no sentence leaves a
  reader nowhere.
- ⭐ **`reader_document` lost its `standing` parameter rather than keeping it unused.** A parameter
  that is accepted and ignored is an invitation to put a figure back.
- ⚠️ **The section moved BELOW the fresh-clone section.** Its fence is the only place a `PYTHONPATH`
  appeared before the paragraph that explains the framework's address; ⭐ and a reader working down
  the page now runs it against the corpus they have just ingested.
- ⛔ **The alternative that was costed and NOT taken: keep the figures and have the corpus's own
  generated suite refuse them when stale.** It keeps `W313`'s numbers and makes staleness
  detectable — but the corpus still ships a wrong document between the narration and the
  regeneration, the reader still reads the wrong number, and the corpus's own suite goes RED on
  ordinary operation until somebody re-runs a skill. ⚠️ That is the class of defect `W331` had just
  finished removing.

## Surprises

- ⛔ **The obvious "it states no figure" clause PASSED against the unfixed generator.** Before
  ingest the old document printed no figures either — it printed *Nothing has been ingested* — so a
  clause written over `reader_document(manifest)` alone was green on the defect. ⭐ **The clause had
  to be measured on an INGESTED corpus to bite**, and it was rewritten until it did. ⚠️ A cheap
  version of it would have been a check that could not fail.
- ⚠️ **Moving the section changed what the execution test measures, for the better.** With the
  standing fence last, running the document top to bottom ingests first, so the fence reports the
  corpus the reader has just built rather than an empty one — ⭐ which is why that test now reads
  the standing three times off one document instead of comparing two documents.
- ⛔ **`tests/test_authoring_reference.py` cannot command a plain module.** It asks for
  `<name>.__main__`, which only a package has, although `python3 -m package.module` runs perfectly
  well. That decided this row's placement rather than a preference (`W332/1`).

## For dependents

- ⛔ **A corpus onboarded before this row keeps the old document.** Regenerating it through the
  onboarding skill replaces that document with one that states no figure; `W332/3`.
- ⭐ **`reader_document` no longer takes `standing=`.** A caller that passed one now fails at the
  call, which is the intended reading: there is nothing for it to state.
- ⭐ **`standing.lines(standing_of(root))` is the one way to turn a corpus into those figures.**
  ⛔ Anything that needs them calls it — a second rendering is the defect this row removed.
- ⚠️ **`onboard(...)` no longer reads the corpus at `root`** to write the reader's document, so
  onboarding is that much cheaper and its output is a pure function of the draft and the pin.
  `root=` still decides how every generated document addresses the framework (`W321`).
- ⛔ **`W331/1` is still open and is still on this surface**: `test_walkthrough._first_run` discards
  step 4's exit code. This row did not widen it — its own clauses execute what they assert.
