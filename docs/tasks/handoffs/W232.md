## The form taken, named

⭐ **The form is `W148`'s and Ruling 153's: READ THE TRACKED FILES**, not `W28`/`W35`'s *honour the
ignore declaration*. ⚠️ The two forms answer different questions and the difference is the reason:

- ⛔ `git check-ignore` (the `W28`/`W35` form, and `tools.quality`'s) answers *"does my WORKING
  TREE pass right now"*, so a file written and not yet added is caught. That is right for a floor
  gate and wrong here — it would still read an **untracked, un-ignored** copy as this repository's,
  which is the half `W142` was paid for.
- ⭐ `git ls-files` (the `W148`/Ruling 153 form) answers *"what does this REPOSITORY contain"*.
  This census asks exactly that: *is there a second copy of the store in this repository.* ⚠️ Its
  blindness — a copy written and not yet `git add`ed is invisible — is stated in the helper's
  docstring rather than left to be discovered, and it is the correct blindness for the question.
  ⚠️ `CTO-66/5` is the recorded COST of this form: taken at the natural place, it silently narrowed
  the R7 personal-data sweep. ⭐ That cost does not land here — this census is not a personal-data
  gate, and `tools.quality`'s sweep is the other instrument and is untouched.

⛔ **The census and its helper name no directory at all.** The previous form excluded `.git` by
name; an exemption for `.scratch` by name would have been the same defect waiting for the next
ignored directory. The tracked set has no names in it. ⚠️ `.scratch` IS spelled in the first
plant — that is the plant's subject, not the remedy's mechanism, and the census would read the
same over any other ignored directory.

## Decisions

All reversible, and ruled here because the user is asleep.

- **`tracked_copies` stays LOCAL to the module, and `tests/support.py` is untouched.** The shared
  query is the reusable half and it already exists; a basename filter is one expression with one
  caller, and `W314` and the two merging branches are live beside this one.
- **The module's OTHER disk walk is left alone** — the test that asserts no Python module can read
  the reader's store walks `(repository_root() / "src").rglob("*.py")`. It is inside the declared
  surface and it was not changed: it is second-tier by the reading above, an ignored `.py` does not
  legitimately live under `src/`, and narrowing it to the index would make a brand-new unadded
  module that names a storage key invisible — a real loss for no gain against this defect. Stated
  as a decision rather than left as silence.
- **The population pattern is `*.js` filtered by basename**, not a path glob. A glob such as
  `*study-progress.js` would also match `vendor-study-progress.js`, which is a different file.
- **`ASSET_PATH` is derived from the published `ASSET_DIR`**, never typed, so moving the asset
  directory moves the census with it.

## Surprises

- ⚠️ **The planted run found ONE test, not a family.** The row's prose and both riders describe
  the symptom as *"a copy under `.scratch/` turns the suite RED"*, which reads as a class; measured
  at `b92798b` it is one assertion. ⭐ Worth recording, because the next office to see the symptom
  will be tempted to look for more.
- ⚠️ `tests/support.tracked_files` **refuses** a tracked file missing from the working tree rather
  than skipping it, so the census now fails loudly on an unstaged deletion of the store. That is a
  behaviour this row inherits rather than chose, and it is the right one.
