## What landed

⭐ **What the software does now that it did not:** `corpus.json` may carry
`"runtimes": ["java", "maven"]` under `corpus_api: 4`, and `Manifest.runtimes`
holds it sorted. When the key is absent, the value is `()`, meaning no runner.
Each of these is refused by name:

- a name outside `gradle`, `java`, `kotlin`, `maven`, `node`, `python`,
  `shell`, `sqlite`, with the vocabulary quoted in the refusal. This covers
  versioned spellings like `java21` and `maven:3.9`;
- a repeated name;
- `maven`, `gradle` or `kotlin` without `java`, with every missing one named
  at once;
- the key at all beside `exercises: false`;
- a value that is not a list, including an explicit `null`;
- the key under `corpus_api` `1`, `2` or `3`, with both numbers named.

## Decisions

- ⭐ **The top-level version entry is `(None, "runtimes"): 4`** in the one
  `KEY_VERSIONS` map. `_check_key_versions` reads the document itself when the
  block is `None`. This is `TC-00/2`'s trap closed without a second map beside
  the first, which is what that constant's own note warns against.
- ⭐ **The split is at two seams.** First, `runtimes.py` holds the key, as the
  row requires. That still left `document.py` over R11's 400 lines, because
  the version gate and the field both grew. So the second seam is **the
  document versus its fields**: `fields.py` takes the plain per-field rules,
  which read one value and know nothing of the version, the keys or the gate.
  ⚠️ **Those rules became one function per key** (`exercises_of`, `levels_of`,
  `variants_of`), with the key spelled inside each function. Moved as they
  were, they became public callables taking a caller-supplied `key`, and
  `tests/test_emission.py` caught every one of them echoing it (rubric §1f).
  Their messages are unchanged.
- ⭐ **`runtimes: []` beside `exercises: true` is the same as absent.** A
  declaration beside `exercises: false` is refused **whatever it holds**,
  `[]` included, because the proposal refuses the *key* there.
- ⭐ **An explicit `null` is refused, not read as absent**, following
  `media.max_files`: a corpus that wrote the key tried to declare something.
- ⭐ **`MANIFEST_KEYS` places `runtimes` right after `exercises`**, which is
  the key it depends on. The spec's §4 table and the authoring table follow
  the same order.

## Findings

- `[structural]` **`W350/1`: onboarding's `promote` does not raise the version for this
  key.** `src/studyforge/skills/onboarding/manifest.py` works out the version
  it needs from `content.not_material` alone. A draft that carries `runtimes`
  under a lower `corpus_api` is refused by its own read-back
  (`_refuse_unreadable`) rather than written wrong. So nothing is silently
  wrong, but a draft `W351` writes cannot be promoted until `_api_for` knows
  about `runtimes`. `OPTIONAL_KEYS` also leaves out `runtimes`, so an empty
  list survives promotion. ⭐ This belongs to `W353` or `W351`, not this row.
  `media.max_files` has the same version gap, which is why this will recur for every key a version adds.
- `[local]` **`W350/2`: the authoring reference joined the surface.** The row's surface
  was `corpus/manifest/` and spec §4. The contract's own test
  requires [the authoring reference](../../authoring/corpus.md#every-key) to name the new key and version, so
  landing the key without editing it would have left the suite red.
- `[local]` **`W350/3`: spec §4's key table is still not checked in both directions**
  (`W16`, still `todo`). `test_runtimes.py` asserts only that the key list
  carries `runtimes` and the version that added it, with a synthetic red
  case. It is narrow on purpose and does not replace `W16`'s subset and
  coverage checks. ⚠️ A dated blockquote in §4 (CTO, 2026-09-10) still quotes
  the key count from that day. It is a record and was left alone
  (Ruling 106).
