## ⛔ The node ruling — three states, not two

**Measured on `SF-11`'s merge:** host 1089 passed / 10 skipped with node
v24.16.0; the node-gated half is **38 passed** when run explicitly. The image has
no JS runtime.

⭐ **My round-7 wording said the container is authoritative *always*, and that if
it cannot run a check the verdict is `Blocked`. That was written for the SF-01
case — a check that did not execute at all — and read literally it discards a
real, passing, evidence-producing run.** The purpose was always *a check that did
not run is not evidence*. It was never *the container is more capable*: it is
authoritative because it is **pinned** (R15), not because it is better.

| State | Meaning | Counts? |
|---|---|---|
| **pinned green** | ran in the image at a pinned toolchain | ⭐ this is the verdict |
| **unpinned green** | ran and passed, in an environment nobody pinned | ⚠️ **real evidence, named in the review** — and the image gap is a finding with an owner |
| **did not run** | skipped, tool absent, unreachable | ⛔ not evidence at all |

⛔ **`Blocked` is for a condition that could not be executed.** `SF-11`'s
executed and passed. The correct record is **unpinned green**, named.

⭐ **And the repair for unpinned evidence is to pin it, not to argue about it.**

**Ruling: `FND-03` follow-up — a pinned JS runtime in the dev image.** ⚠️ Not
optional and not "when convenient": E03 and E04 add more browser-side behaviour,
so the gap widens from here. ⛔ **Pin the version exactly**, in
`docker/dev/requirements.txt`'s spirit — an unpinned node would make the same
result unreproducible in the other direction.

⭐ **The developer was right not to edit the Dockerfile.** It is `FND-03`'s
surface, and its own comment warns against an image that quietly grows a
toolchain. Reporting it as blocked rather than claiming green was the rule
working — the rule was just wrong.

### ⭐ The mitigation is what makes the ruling safe

**42 tests run everywhere**, including *no combination takes the comment colour
unless it is a comment* over 26 combinations. ⛔ **And the two halves are
chained**: the node half fails if a grammar emits a combination the in-gate table
does not record.

⭐ **That chaining is the load-bearing part and it is why this is APPROVE rather
than a conditional one.** The half that always runs cannot fall behind the half
that sometimes does — so the container-runnable portion genuinely covers the
contract, and the unpinned half is a *stronger* check on top rather than the only
check. ⚠️ Its enforcement is still only as good as somebody running node, which
is exactly why the image gap is a finding and not a note.

⚠️ **And the blocked half is the one that caught the original defect** — a
string-literal variant filed under `comment` italicised every string in one
language *while the tests passed*. ⛔ A defect no in-gate assertion found is the
strongest possible argument for pinning the environment that finds it.

### `surface.py` — ⭐ CONFIRMED, and the asymmetry is the point

**The failure it prevents is silent and total**: a stylesheet and a template
disagreeing about one class name give a page that renders, carries every word,
and is unstyled with no error anywhere. In the source they were one codebase and
*could not* disagree; `SF-11` lands before `SF-12`, so the agreement has to be
written down.

⭐ **`SURFACE_CLASSES["list"] == "items"` deliberately, and that is the clause I
would defend hardest.** If every entry were an identity mapping, somebody would
eventually delete the lookup and use the block type directly — and the contract
would evaporate with every test still green. One entry that *cannot* be inverted
makes the indirection load-bearing. ⭐ **R4's argument about paths, applied to
markup**, and it is the same move as `unit_name`-not-`unit_dirname`.

### R8 and vendoring — ⭐ CONFIRMED, first explicit drawing of the boundary

The naive check — *no `https://` in any asset* — can only be passed by **editing
vendored code**, which this project forbids. So the decomposition is right:

- ⛔ no **authored** asset fetches anything;
- every network path the player has is **disarmed by configuration**;
- the sprite is **substituted**, not fetched;
- ⭐ **a URL inside a vendored bundle is not a defect, pinned by a test** so
  nobody later "fixes" it.

⚠️ That last test is the one that matters in five years. Without it, the next
reader sees a remote URL in the tree, believes R8 is violated, and edits a
vendored file to fix a defect that was never there.

### ⛔ The tree check — tested, not read, and the honest framing is confirmed

I probed the scanner against six shapes:

```text
  doc["raw_api"]              -> FLAGGED        doc.get("raw_api")   -> FLAGGED
  doc.pop("raw_api")          -> FLAGGED        F="raw_api"; doc[F]  -> not flagged
  for k in ("raw_api",)       -> not flagged    docstring prose      -> not flagged
```

⭐ **So *a floor, not a proof, aimed at the likely shape of the mistake* is
exactly accurate, and I do not want it stronger.** Both ways of strengthening it
are worse: tracking a value through assignments is a static-analysis project
living inside a test, and a grep for the field name fires on the four manifest
docstrings that **correctly** explain the rule — ⛔ *a check that fires on correct
code gets switched off*, which this project has already paid for once.

⭐ **And the target is the accidental second implementation, not an adversary.**
Nobody routes a field name through a variable to evade a check they have not
heard of. Written into `module-structure.md` as a rule, because the next author
of a syntactic check will feel the same pull toward false strength.

⚠️ The scanner correctly ignoring prose is the part I would call out as the
design win — it is `FND-06`'s lesson applied *before* the defect rather than
after.

### The three decisions

1. ⭐ **The caller supplies the exception type — CONFIRMED, and the extension of
   the SF-01 precedent is right.** SF-01 settled *value errors subclass
   `ValueError`, document errors subclass `Exception`*. This adds the clause that
   was missing: ⛔ **one implementation of a check does not get to change what a
   package promises to raise.** `VersionError` and `ManifestError` are
   **siblings**, both `ValueError` — so `except ValueError` catches both, and
   `except VersionError` catches only version failures. Making one inherit from
   the other would tie two packages together to save a line and would make
   `except VersionError` catch things that are not about versions.

2. ⭐ **Different sentences for a wrong type and a wrong value — CONFIRMED, and
   it lands somewhere I did not predict.** Round 8's rule was *never format an
   exception object into a message; name the field you mean*. This is the same
   argument one level up: **name the type rather than echo the payload**. Two
   independent reasons and both hold — an integrator who typed JSON `true` and is
   shown Python's `True` has to translate, and ⛔ a dict payload can carry a home
   path, so echoing it makes a **version check** leak personal data. R7 turning
   up inside a version guard is the sort of thing this rule exists to catch
   before anyone thinks of it.

3. `where` keyword-only with no default — consistent with `SF-08`. Fine.

### The two findings

- ⚠️ **`CONTRACT_FIELDS` is five of six**, and the TOC schema version has no field
  name until E03 mints one. ⛔ **A promise with no enforcer is the shape I ruled
  on for `SF-12`'s clause, and it gets the same answer: make it a tripwire.**
  Pin the tuple's exact contents in a test, so **E03 adding the sixth field fails
  that test** and forces whoever adds it to read why. ⭐ The blind spot is
  acceptable; a blind spot nothing announces is not.
- **Direct reads only** — confirmed above, framing confirmed, no change wanted.

⚠️ **`False` where `0` is supported is the same bug**, and flagging it as *the
half a reader leaves open after being told "true is the problem"* is right. No
contract accepts `0` today, so a test is the correct weight.

## ⭐ Naming the pattern, as asked: tests are becoming arguments

`assert True in ONE` **before** `assert not is_supported(True, ONE)` answers a
doubting reader with an execution rather than a comment. ⭐ **Yes, this is a
pattern, and it has now arrived three times independently:**

- a negative fixture asserted to **really be refused**, so it cannot be quietly
  repaired into an input that passes (`FND-04`);
- an acceptance clause found **vacuous** and replaced by a pair — this document
  is not refused, **and** a differently-serialised form of it **is** (`SF-08`);
- the porous membership test asserted **before** the guard that closes it
  (`SF-33`).

⚠️ **The shared property is that each of these tests would still pass if the
guard were deleted**, and the paired assertion is what gives the pair meaning.
⛔ **A test that only checks the fix stops meaning anything the moment somebody
decides the fix looks unnecessary.** In `module-structure.md` now.

## Surprises

- ⭐ **The node case is the exact inverse of the one my rule was written for, and
  the rule survived only by being re-derived from its purpose.** A rule stated as
  a conclusion (*the container is authoritative*) failed; the same rule stated as
  its reason (*evidence must have run, and pinned evidence is reproducible*)
  handles both directions. ⚠️ That is worth remembering the next time I write one
  as a conclusion.
- ⭐ **Three tasks in a row have improved on the instruction they were given** —
  `FND-04`'s split asserting *absence* rather than a short list, `SF-08` replacing
  a vacuous clause with a pair, `SF-33` asserting the bug before the guard. That
  is not compliance; it is the review loop paying back.
