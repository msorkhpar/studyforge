## Decisions

### ⛔ How a stale cache is made detectable — and it is not `site_api`

⭐ **The signal is a content digest recorded in the file.** `scan_sha256` is a
`sha256` over `Site.document` — every artifact's path and identity, and every
page that could not be identified — serialised with the same canonical form the
cache itself holds. A cache carries the digest of the scan it was written from;
`freshness(site, recorded)` compares it against a fresh scan's.

⛔ **No `mtime`, and that is Ruling 18 rather than taste.** Measured
2026-09-09: an mtime verdict and a content verdict disagreed **in opposite
directions at once**; the mtime verdict flipped FAIL→PASS 33 minutes later with
nothing moved; and `git worktree add` resets every mtime — which is where this
project's own merges are measured. ⭐ *"And the right signal was already in the
file."* So the right signal is **put** in the file.
`test_this_module_names_no_filesystem_timestamp` parses `freshness.py`, drops
its docstring and unparses it — ⚠️ **`ast.unparse` drops comments outright, so a
grep would have measured the contract and been red from the day it was written.**

⭐ **Three verdicts, not two**, for the same reason `tools/knowledge/index.py`
has three: an absent cache, an unreadable one and one at a `site_api` this build
does not speak are states where the question **could not be put**, and calling
any of them `stale` is a verdict the evidence does not support.

### ⭐ "The scan wins" is structural, not a rule anybody follows

⛔ **`assemble` scans on every call and returns that result on every branch.**
There is no argument that would make the cache authoritative and no code path
on which a cached `Site` is handed back. ⚠️ **That is what makes the staleness
question answerable at all**: a design where the cache *could* be used has to
decide whether to trust it, and every such decision is a chance to be silently
wrong. Here the only things riding on the verdict are whether the file is
rewritten and what the report says.

⚠️ **So `site.json` is the written RECORD of a scan rather than a shortcut past
one**, which is exactly what §5 says — the server scans at startup, and the
cache is *"a cache of that scan, never the authority"*.

### ⛔ Ruling 95's two traps, both carried

1. **An unsupported or absent `site_api` does not raise.** `cache.Cached.supported`
   uses `version.is_supported`, never `check`; `assemble` reports `Cached.says`
   — the path, what was declared, what this build speaks — and rewrites the file
   at the current version. ⭐ Nothing is carried forward, which is what makes it
   R9's refusal rather than a migration.
2. **`site_api` is not the staleness mechanism.** `Site.document` deliberately
   excludes it, so the digest cannot move when the version does.
   `test_the_version_key_is_a_constant_and_not_bumped_per_scan` asserts two
   different sites render the same `site_api`.

### The scan takes a `{corpus: depth}` mapping, not a depth

⚠️ **The depth is per corpus and only the block knows which corpus.** A root may
hold two corpora of different depths — the acceptance asks for exactly that —
so the scan cannot know which depth applies until it has read `corpus` out of
the very block it is about to validate. ⛔ A page naming a corpus the scan holds
no depth for is **reported by name**, never guessed at from the number of
segments it happens to carry: guessing would defeat the arity check entirely.

### There is no skip list in the walk, deliberately

⚠️ `validate/source.py` records that two of its five original `SKIP_DIRS` were
*"the framework knowing about two ecosystems, which is R1 with the sign
flipped"*. ⭐ **This walk needs none**: it globs two suffixes this framework
minted, so a `.git` object or a `node_modules` is not *skipped*, it simply does
not match. ⛔ Adding a skip list would import that problem into a walk that does
not have it.

### The report is a return value, never a logger

⭐ Findings come back as `Discovery.report`, exactly as `validate` returns
`Finding`s. A caller that throws it away has made a visible decision; a package
that logged somewhere the caller never looks would have made an invisible one.

## Surprises

⚠️ **`Path.rglob` matching inside dot-directories is load-bearing and was
verified rather than assumed.** Under the `tree` profile *every* generated page
lives below `.studyforge/`. ⛔ A walk that skipped dot-directories would report a
perfectly empty site for an entire placement profile — a green run with no
pages. Measured on the pinned image's Python 3.14.7: `rglob` matches inside
dot-directories **and** matches dot-prefixed filenames.
`test_the_walk_reaches_inside_the_generated_dot_directory` pins it.

⚠️ **`identity.parse` could not be the reader here, and that is not a defect in
SF-03.** It takes the declared depth up front, which is right for its caller and
impossible for a multi-corpus scan. ⭐ `scan.py` therefore borrows
`identity.IDENTITY_PATTERN` and hands the decoded block to
`identity.from_document`, so every piece of *validation* still has one home and
this module grows no second opinion about what a valid identity is.

⚠️ **`placement`'s arity refusal echoes the address key**, and it turns out to
be safe: `_address_of` has already established every segment is a slug before
`require_depth` can fail, so the echoed key cannot carry a path. ⭐ Recorded
because it looks like an R7 defect on a first read and is not.

## Findings

SF-04/1 `[local]` — **`is_unit_page` and `is_container_page` have no
caller in `src/`.** SF-03 minted them *"for a discovery scan"*, and this
discovery scan does not want them: it globs `*{UNIT_SUFFIX}` and
`*{CONTAINER_SUFFIX}` directly, because a glob on the constant lets the OS
filter and needs no whole-tree walk. ⭐ **And the deeper reason is R4** — the
suffix says which files to *open*, never what one *is*; `kind` comes out of the
block. So the predicates are dead for the caller they were minted for. ⚠️ Not
deleted here: they are SF-03's surface and `test_names.py` asserts them. The
decision belongs to whoever next touches `placement/names.py`.

SF-04/2 `[structural]` — **`version._said` is private and now has a second
implementation.** `cache._said` composes the same sentence — *"declares
`site_api` 99"* versus *"declares `site_api` as a bool"* — because this caller
**reports** rather than refuses and so cannot go through `check`, where the only
copy lives. ⛔ Two spellings of one rule is the defect `placement/names.py`
already paid for once (`label_of`'s forbidden list). ⭐ The fix is one line in
`version.py` — promote `_said` to `said` — and it is a change to another task's
module, so it is a finding rather than a line in this diff.

SF-04/3 `[local]` — **nothing yet calls `assemble`.** `cache_path(root,
profile)` exists so a caller need not compose the path, and `SF-19b`'s
*"discovery wiring"* is the named consumer. ⚠️ Recorded because SF-25's rule
cuts the other way here: this API was designed against a caller that does not
exist yet, and the mitigation is that `cache` and `freshness` are usable without
it — `studyforge validate` can call `assemble(root, depths)` with no cache at
all and get the scan plus an honest *"not judged"*.

## For dependents

**`SF-19b` (serving: discovery wiring), `SF-28` (delivery), and anything that
renders a contents page:**

```python
from studyforge.corpus.discovery import assemble, cache_path
from studyforge.corpus.placement import profile_for

profile = profile_for(manifest.placement)
found = assemble(root, {manifest.source: manifest.depth}, cache=cache_path(root, profile))

found.site.units  # every unit page, sorted by path
found.site.unit(corpus, address, 7)  # by identity — never by path
found.site.corpora  # sorted; two corpora, one scan
found.report  # R6: print it, do not discard it
found.verdict  # fresh | stale | unverifiable
```

⛔ **Do not read `site.json` to answer a question about the site.** Call
`assemble`. The file is the written record and a reader that believed it would
be the one silently-wrong path this whole contract removes.

⛔ **`SF-04` is the one writer of `site.json`.** A second producer is now a
change to R21's register, not a discovery.

⚠️ **`depths` is a mapping and the scan reports a corpus it was not given.** A
server holding two corpora passes both entries; passing one and scanning a root
that holds the other produces a *report*, not a crash and not a silent drop.

⭐ **The identity block is `placement`'s, not this package's.** A writer embeds
`identity.render(...)`; this package only ever reads it. Nothing downstream
should re-spell `IDENTITY_PATTERN`.
