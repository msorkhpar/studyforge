# Rulings

## ⛔ Ruling 1 — `tree` keeps the directories, not the filenames

**The contradiction was never between two documents. It is inside one task
entry, three paragraphs apart:** `E01-core-contracts.md`'s SF-03 asked for the
extraction source's shape "reproduced byte-identically" and, in the same
Definition, for "every generated page gets a real name … never `index.html`".

Measured 2026-09-09 in the extraction source's `study/` tree: **1,290 unit pages
named `index.html`, 0 named `*.unit.html`**, and `layout.py` sets
`UNIT_PAGE_FILENAME = "index.html"`. Discovery globs the suffix.

**⭐ §5's naming rule holds; the byte-identical clause is amended.** Four
reasons, and the first is decisive:

1. ⛔ **A `tree` page named `index.html` is found by nothing.** Discovery is not
   a feature of placement — it is the mechanism that makes R4 possible at all.
   "Location is data" is only true because a scan can find the artifact
   wherever it went. A profile that opts out of being discoverable has opted
   out of the ruling it exists to serve.
2. ⛔ **It would make `sibling` impossible, not merely different.** Twenty units
   share one directory there; `index.html` cannot be written twice.
3. ⛔ **The root index is `index.html`.** A unit page with the same name is
   indistinguishable from it without opening the file, which defeats "a scan
   reads names" for the one filename it most needs to tell apart.
4. ⚠️ **The clause's value is fully preserved.** What "byte-identical" was
   protecting is that a later migration *moves* a tree rather than re-deriving
   one. SF-03 keeps `units/unit-NN/` with `audio/`, `images/` and `video/`
   inside it, segment for segment, and every media href a page holds is
   unchanged. **One file per unit is renamed. Nothing else moves.**

⭐ **The general lesson, which is larger than this clause:** an acceptance
pinned to another repository's exact bytes decays the moment either repository
moves, and it decays *silently*, because nothing re-measures it. ⛔ Pin the
**property** — "the directory shape is preserved so a migration is a move" —
and let a test measure it. R20 says the extraction is one-way for the same
reason; this is that rule showing up as an acceptance criterion.

**Applied:** `E01-core-contracts.md` SF-03's `tree` bullet and Acceptance are
edited, and cite this ruling.

## ⛔ Ruling 2 — `label` goes into the container map now, optional

**Add to each unit entry: `label`, optional `str`, the corpus's own display
numbering, spelled the way the corpus spells it.**

⚠️ **The cost is asymmetric and that is the whole argument.** R9 versions this
contract and never migrates it at read time. Adding the field at freeze costs
one optional key and invalidates nothing. Adding it after costs a `container_api`
bump, dual-reading, and every archive already written.

⛔ **It is not a speculative field.** Three things are already true:

- **Spec §5 commits to an output that cannot be produced without it** — the
  worked example `4.4.1-introduction-to-the-streams-api.unit.html`. A design
  document already promised this.
- **The consumer is written and tested.** `label_of` enforces the constraints;
  `test_names.py:47` asserts that supplying `4.4.1` reproduces §5's example
  character for character.
- **Nothing else can supply it.** SF-03 proved, across the four designed shapes,
  that deriving it from the source filename means a parser per corpus (R1). It
  is corpus data or it does not exist.

⭐ **This is R21 working as intended.** The contract is *located* — one optional
key on the unit entry in `container.json` — before anyone describes it further.
An optional field nobody has ruled on is exactly the shape R21 exists to remove,
and it was three weeks from being one.

**Constraints, matching what `label_of` already enforces:** non-empty, no path
separator, no whitespace, because it becomes part of a filename. ⚠️ **Not a
slug** — `4.4.1` is not one and must not have to be. Absent, a unit is named by
its ordinal, which is what ships today.

**Applied:** `E01-core-contracts.md` SF-05.

## ⛔ Ruling 3 — the R7 sweep folds before it matches, and never judges intent

⚠️ **The hole, as posed:** two of SF-03's tests need the shape they refuse and
spell it as two concatenated literals so the sweep does not read it as a leak.
`test_version.py` did it first; it is now the established technique. The sweep
reads source text, sees the operator between the halves, and finds nothing —
**and it cannot tell a legitimate split from an evasive one.**

⭐ **It never needs to. That framing is the trap.** Trying to infer intent from
a source line is unwinnable and would produce a gate nobody trusts. ⛔ **Evaluate
the expression instead of reading the line:** walk the Python AST and
constant-fold adjacent literal concatenation before matching. A split then folds
to the same string an unsplit one produces, and **the distinction the sweep
cannot make stops existing.** ⚠️ Python only, and the check says so — a Markdown
file has no AST and keeps the text sweep.

⛔ **Then the shapes get one sanctioned home, not a technique.** One named
module, each shape carrying the reason it is there, listed in
`SANCTIONED_PERSONAL_DATA_DIRS`, imported by every test that refuses one. ⭐ The
config already says the design is "the ONE directory allowed to hold the shape";
the split is a second, unlisted one that arrived because it was easier. Fixing
the class rather than exempting the instance is the precedent FND-06 itself set
when it refused an allow-list.

⚠️ **State the reach.** Folding stops the accident and the easy workaround.
`chr(47)`, a `join`, an f-string built at runtime — those still pass, and no
source-text gate will ever catch them. ⛔ **The gate for those is a different
gate**, which is ruling 4.

⛔ **And name what is not being defended against:** this repository has no
adversary. It has agents who need a shape for a test and take whichever route is
open. The fix is to leave exactly one route open and make it the easy one.

**Applied:** `E00-foundations.md` FND-06 follow-up.

## ⛔ Ruling 4 — the rubric gains an emission clause, because a sweep reads files and a leak is a runtime value

**Finding R1 above is not a coincidence; it is the shape of the hole.** SF-03
learned "do not write the shape" because that is what the gate could teach it —
and then wrote code that *emits* the shape from a value that never appears in
the file. ⛔ **Every R7 check this project has answers "did an identifier reach a
file?". Nothing answered "would this code write one into a log?"** — which is
the question the incident R7 was written from actually turned on. Nothing
reached a file there either.

⭐ **Rubric §1f (new):** the reviewer reads every raise, log and report line the
diff adds and asks of each — *could the value being formatted be a path, a URL,
a hostname, or a header the framework did not compose?* ⛔ **The tell is a
refusal whose own subject is the shape:** a branch that exists *because* a value
is an absolute path, formatting that value into its message.

⚠️ **And check which branch an existing assertion covers.** SF-03 has a test
named `test_a_refusal_carries_no_absolute_path`. It passes. It is on the wrong
function. ⭐ An assertion's existence is not coverage of the thing it is named
after.

⚠️ **It is CHANGES REQUESTED, never REJECT.** REJECT's R7 cause is an identifier
that *reached a commit* — it survives deletion, so the branch is rewritten. An
emission that has not happened is fixed by amending one line. ⛔ But it is never
a nit either, and §1f says so.

**Applied:** `review-rubric.md` §1f. ⚠️ I ran its command against this very
branch before committing it, found the leak at hit 9 of 14, and corrected a
no-op `sed` in it that I had written from habit.

## ⛔ Ruling 5 — a task reports an acceptance it cannot meet; it does not rewrite one

SF-03 implemented §5's naming rule, wrote down why the byte-identical clause
cannot hold, measured it, and **left `E01` alone**. ⭐ That is the standard, and
it is now written into `agent-protocol.md`.

⛔ **A task that quietly edits its own acceptance to match what it built has
destroyed the only record that a decision was made.** The next reader finds a
clause agreeing with the code for no stated reason, and cannot tell an
argued-through ruling from a convenience.

⚠️ **The obligation is symmetric.** A reported contradiction nobody corrects is
a trap re-sprung on the next task that reads the clause and believes it. The
task reports; the CTO rules; the document is edited and cites the ruling. ⛔ All
three, or the report was just a complaint.

⚠️ **It is not licence to reinterpret an inconvenient acceptance.** The test is
whether the halves are *jointly unsatisfiable* and you can show it — a
measurement, a counter-example, a contract that would need two versions. "I
would have designed it differently" is a finding.

## ⛔ Ruling 7 — the exception-formatting rule is right, and the instance is harmless

**Routed to me:** `corpus/manifest/document.py:144` is
`f"{where} is not valid JSON: {exc}"`, written before `module-structure.md`
forbade it. ⭐ Correctly not patched — *no branch is expected to fix a rule it
never saw* — so it needs an owner, and here it is.

⚠️ **Measured, because the rule deserves better than obedience:**

| formatted | yields |
|---|---|
| `JSONDecodeError` as `{exc}` | `line 1 column 2 (char 1)` — ⭐ no path, no payload |
| `OSError` as `{exc}` | ⛔ `[Errno 2] … '/path/to/nowhere/x.json'` — **the whole path** |
| `OSError` as `{exc.strerror}` | `No such file or directory` |

⛔ **So the concrete danger is `OSError`, and this instance is not one.** It is a
convention violation with no leak behind it. ⭐ **The blanket rule still stands**,
and the measurement is the reason it should: you cannot ask every author to audit
each exception type at each call site, and the one they get wrong is the one that
carries a filename.

⚠️ **Correction, mid-ruling, before I shipped it.** I wrote that the convention
needed its mechanism added. ⛔ **I then read it, and the mechanism is already
there** — `module-structure.md` already explains that `OSError` formats itself
with the filename it was given, with the `strerror` fix beside it. I was about
to add, as a finding, something the document has said all along, which is the
same failure as inheriting a claim: **asserting the state of a document from
memory instead of reading it.** Twice in one round.

⭐ **What is genuinely missing is the step after the measurement.** The rule
says never do it and explains why. It does not say what to do about an instance
that is *provably* harmless — and I have just proved one is. ⛔ Without that, the
next author measures their `{exc}`, finds no leak, and concludes the rule does
not reach their case. ⭐ **It does, and the reason is that auditing each exception
type at each call site is the work nobody does twice** — a rule that holds by
inspection has been traded for one that holds by argument, re-made by every
reader. That paragraph is the edit.

**Owner:** FND-06's follow-up batch, at the bottom of it — one line, no
behaviour change, and ⚠️ **the convention edit matters more than the instance.**
⭐ SF-05 already writes the correct shape (`{exc.strerror}`, and `path.name` not
`path`), so the pattern to copy is in the tree.

**Applied:** `module-structure.md` gains the mechanism.
