## ⛔ The record's fields, which Ruling 351 deliberately left to this office

`.studyforge/narration.json`, `narration_api` 1, three keys:
`{narration_api, conditions, clips}`. `conditions` is
`{voice, format, provides, chunk_chars}`; each entry of `clips` is
`{filename, conditions, engine, engine_model}`, keyed by speech id.

⭐ **Compared, per unit:** the filename (the wording address), the conditions
fingerprint, and **whether the file is on disk**. ⛔ **Not compared: `engine` and
`engine_model`.** On a cache hit they are the *first* synthesis's, not the
deployment's (`NS-05`), so comparing them would re-synthesise a corpus against a
fact no probe reports. They are provenance.

⛔ **`check`, not `is_supported`** — the opposite answer from `site_api`'s, from
the same argument. The discovery cache is discarded because the tree rebuilds it;
this record is rebuildable only by re-synthesising every clip, so R9's refusal is
spent by stopping.

⛔ **`probe()` is the CALLER's**, per `NS-05`'s *For dependents*. That is what
makes an unchanged re-run cost **zero** requests rather than one per corpus:
`synthesise` takes `Conditions` and opens nothing to obtain them.

## ⭐ For the renderer — agreed with `SF-18` directly, this wave

`SF-18` asked which field carries the clip's file extension, because rendering is
pure (R10) and the extension is only knowable from the wire. **What I answered:**

- **`conditions.format`** — one bare suffix, no dot, one value per corpus build.
  Their word, kept, because it echoes the wire rather than renaming it in
  transit. ⛔ Nested inside `conditions` rather than at the document root, because
  `conditions` is hashed as a unit into the per-clip fingerprint; hoisting it
  would either drop a format change out of the hash or duplicate it.
- **`clips.<speech id>.filename`** — the whole filename, and what I recommended:
  it is what was actually placed, so it cannot disagree with the disk, and its
  stem parses back through `parse_clip_name`, which is the round-trip they build.
- ⚠️ **I could not promise one format per corpus.** The format is the service's
  answer, not the request; a deployment answering something else places a good
  clip under another suffix, which I surface as `Synthesis.unsettled`. So
  `conditions.format` is the REQUESTED format and `filename` is the truth.
- ⛔ **No second validator.** `client.py` already checks `FORMAT_NAME` before it
  builds a filename, so a second copy in the record would be the second authority
  we were both avoiding.

Neither of us read the other's branch.

## Findings

### ⛔ `SF-17/1` — `[structural]` — AGAINST MYSELF: my own plant sweep was falsified by a stale `__pycache__`, in the direction of agreement

P1 and P2 replace two different anchors with the same text, and both anchors are
the same length, so both mutations produced a source file of **identical size**;
written inside the same mtime second, CPython accepted the cached bytecode and
P2's run executed **P1's module**. It reported P2 as killed by the conditions
tests — a plausible, wrong answer a reader would have accepted. ⭐ Ruling 70 names
exactly this and I did not obey it until the numbers looked odd. ⛔ **`-p
no:cacheprovider` disables pytest's cache and does nothing about CPython's**;
every sweep in this repository wants the environment variable and the `rm`. ⚠️
Structural rather than local: nothing about this was specific to my row, and the
next office to plant same-length mutations will hit it.

## For dependents

- **`SF-18`, `SK-03`, the renderer.** Read `conditions.format` for the corpus's
  suffix, or `clips.<speech id>.filename` for the exact file — see the section
  above. A unit with no audio is still a stated state: `Synthesis.failed`,
  `.retryable` and `.reasons` say which and why (R6). ⛔ Never `len(written)`.
- **Whoever wires the pass into a build.** `probe()` once for the corpus, build
  one `Conditions` from it, pass the same one to every unit's `synthesise`. ⛔
  `Conditions` refuses an unstated voice or format on purpose: a build that lets
  the service choose cannot record what its clips were made under.
- **`SF-32`.** The record is one entry per speech unit and carries no clock — it
  does not move when nothing else does (R10).
- **Anyone editing this package.** ⛔ The seam runs one way: `incremental` imports
  `record`, never the reverse, and a test asserts it. The two source-shape checks
  run over **every** module in the package, one syntactic and one textual, each
  with a positive control beside it: adding prose that names a media directory is
  fine, adding a **string constant** is not.
