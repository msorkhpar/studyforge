# W914 — handoff

**Kind:** task handoff — W914

**Status:** done on `feat/W914-mock-exam` (from `release/claude-cert-support`). Nothing was pushed or merged.

## What landed

- **The record.** A quiz record may carry an optional `mock` key (`exercise/quiz/mock.py`): a `pass_mark` (a whole percent from 1 to 100) and `domains` (each an `id` token and a `title`). A question may carry an optional `domain`, written last and only where set. A mock exam is a quiz (`kind` stays `quiz`), so every quiz rule holds for it. A `domain` on a quiz with no `mock`, and `mock` on a record that is not a quiz, are refused. `mock` sits after `questions` in `EXERCISE_KEYS`. `QUIZ_KEYS` is unchanged: a quiz may also carry `mock`.
- **The rule.** `exercise.quiz.scores` and `passed`: a percent is rounded down (2 of 3 is 66), built on `grade`, total like it.
- **The gates.** `Q1` to `Q5` run over every question unchanged. A new family `mock` declares one gate, `P1` (`exercise/gates/quiz/mock.py`): every question names a domain, every named domain is declared, every declared domain has a question; it answers for all of them at once and names a question by its stem. `gate_quiz` adds it for a draft with `QuizDraft.mock`, and puts it first in the record (families are written by name, `mock` before `quiz`). `validate` refuses a mock exam whose gate record carries no `P1` (a record names a family only by carrying one of its verdicts).
- **The page.** `render/page/mock.py` with two templates and two files, `mock-exam.css` and `mock-exam.js`, linked from the exam's own section and written beside the shared bundle only for a corpus that has a mock exam (`generate/mockexam.py`). The shared `page.css`, `page.js` and `practice-quiz.js` are untouched. The section is a quiz section but carries no `practice` part named `key`, `check` or `controls`, so the shared quiz script does nothing to it. The page shows a progress line (a `<progress>` and "n of N answered"), keeps the answers in the browser under `studyforge.mock.v1`, names every unanswered question by number at submit and grades nothing, then shows each verdict and sentence, a score per domain and the overall score against the pass mark, locks the answers until "Start again", records a pass in the quiz pass store, and works at phone width (a sticky progress line, full-width controls, a table that does not scroll sideways).
- **Docs.** `docs/authoring/exercises.md`: the key fence and a *A mock exam* section.
- **Tests.** `exercise/quiz/test_mock.py`, `exercise/gates/quiz/test_mock.py`, `render/page/test_mock.py`, `generate/test_mockexam.py`, `validate/test_mock_exercises.py`, `tests/visual/test_mock_exam.py` (27 readings in a real headless Chrome, `file://` and served), fixtures `exercise/quiz/mock_exam.py` and `mock_corpus.py`.

## Decisions

1. A mock exam is a quiz with a `mock` key and not a third `kind`: the kind set stays closed at two and no consumer of `is_quiz` needed a branch.
2. The gate is `P1`, not a name like `M1`: the roadmap sweep refuses a milestone-shaped token anywhere in the tree.
3. The page's script is a separate file linked from the section, never added to the shared bundle, so every existing site is byte-identical.
4. The pass mark is the corpus's (a number it declares); the page says only whether the score reached it.

## Existing tests changed

Every edit is an addition to a list that pins the record's closed vocabulary or a package's surface; no assertion about behaviour moved. `tests/studyforge/exercise/test_cases.py` (the authored keys now end `questions`, `mock`, `concepts`), `test_previous_reader.py` (a value for the new key, so the previous reader is shown refusing it), `quiz/test_init.py` and `gates/quiz/test_init.py` (the new names on each surface), `quiz/test_grading.py` (the new module in the import allow-list), `render/pageassets/test_bundle.py` (the two new files are parts on disk), `render/templates/test_init.py` (the two templates are many-line), `tests/visual/__init__.py` (one acceptance row). `tests/test_compatibility_baseline.py` and `tests/baseline/` are unmodified. `tests/studyforge/exercise/quiz/test_shape.py` and every other quiz test are unmodified.

## Findings

### W914/1 `[local]` The key block of a mock exam is in the page

As for every quiz, the key and the per-option sentences are in the page they grade (`data-mock-part="key"`). Nothing here changes that ruling.

### W914/2 `[local]` `validate` does not re-run `Q1` to `Q5`

It reads the record and re-digests the bundle; it now also owes a mock exam its `P1`. A quiz's record with a whole family deleted is a gap that predates this row and is not widened by it.
