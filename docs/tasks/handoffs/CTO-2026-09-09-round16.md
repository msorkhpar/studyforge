# ⛔ Ruling 12 — the label class is correct, and it costs nothing new

**Three shapes SF-05's tests accepted are now refused: `A`/`VII`, `unit_07`,
`§4`. Ruled: correct, and keep them refused.**

⭐ **The uppercase argument is the strongest of the three and it is the
author's:** `A` and `a` are one filename on a case-insensitive filesystem, and
`sibling` puts twenty units in one directory. ⛔ **An uppercase label is a
collision this framework would generate and never detect on the machine that
generated it** — green on the author's laptop, broken for the reader. That is
R10's failure mode, not a style preference.

⛔ **And the cost is not new, which is the part worth measuring.** `slugify`
already imposes the same class on every **title**, one field over:

```text
'Introduction to Streams'  -> unit-01-introduction-to-streams.unit.html
'Einführung in Ströme'     -> unit-01-einf-hrung-in-str-me.unit.html
'Введение в потоки'        -> REFUSED
'ストリーム入門'                 -> REFUSED
```

⚠️ **So a corpus outside the class could not be named before this branch
either.** The label restriction adds no limitation; it applies the existing one
consistently. ⭐ The escape the author names is right and needs no ruling: a
corpus records a label inside the class and keeps its own numbering in the
**title**, which carries no filename constraint.

# ⛔ Finding 8 — `slugify` deletes rather than transliterates, and calls the corpus defective for it

**Mine, found while ruling 12, and larger than the thing I was ruling.**

| title | slug | outcome |
|---|---|---|
| `Einführung in Ströme` | `einf-hrung-in-str-me` | ⚠️ **mangled, silently** |
| `Café Décor` | `caf-d-cor` | ⚠️ **mangled, silently** |
| Cyrillic, CJK, Greek | `` | ⛔ **refused** |

⛔ **`ü` becomes a dash, not a `u`.** Nobody decided that; it is what "replace
every non-ASCII-alphanumeric with a separator" does to a language with accents.
A German, French, Spanish, Polish or Turkish corpus gets filenames that are
neither the title nor a transliteration of it — ⚠️ **and it never fails, so
nothing surfaces it.**

⛔ **Two consequences, and the second is worse than the first.**

1. **A corpus whose titles carry no ASCII letters cannot be named at all**, and
   the refusal says the title *"slugifies to nothing, so it can be given no
   name; titles are the corpus's, so this is a corpus defect."* ⚠️ **A Russian
   title is not a defect.** R6 licenses failing loudly; it does not license
   misattributing the fault, and R1 says the framework knows nothing about any
   source — including which alphabet it is written in. ⭐ **Cheap fix, and it is
   the one I am requiring: change the message.** Name the framework's own
   limitation, not the corpus's supposed error.
2. **Two titles differing only in accented characters can collide**, and the
   collision is invisible in the source. ⭐ This is SF-25's duplicate-path check
   earning itself a third time, and it is the reason it must run over *names*
   and not only over addresses.

⚠️ **Nothing has ever exercised this.** All four designed corpora are English,
so v1 has never met a non-Latin title, and the behaviour above is what the code
does rather than what anyone chose.

⛔ **Ruled as a declared limitation, not a v1 feature, and not escalated.**
Transliteration is a real decision with a real cost — ⚠️ **taking it later
renames every generated page**, so it is exactly the shape that should be
*recorded* now even though it is not *done* now. ⭐ **v1 states honestly that
titles must slugify to something, in the spec and in the refusal**, and the
transliteration question is a named open row with an owner rather than a
surprise the first non-English corpus discovers.

**Routed:** SF-01 owns `slugify` — the message, today. The spec gains the
limitation and an open row. ⚠️ Neither is this round's branches' work.

# ⛔ Ruling 13 — Finding 6: adopt the behavioural check; the tightening owns the migration

⭐ **It is the right shape and it retires the syntactic one.** Poison a path
into each string parameter and assert the refusal does not contain it: no AST,
no heuristic, and **no false positives by construction** — it fails only when a
refusal really does reproduce what it refused. ⛔ §1f as I wrote it is a
reviewer reading raise-lines, which has now missed a site twice. **A rule a
machine can check should not be a rule a person checks.**

⭐ **The honest delta is what makes it adoptable.** 46 pairs before, 45 after —
the author reported one and named why the count is not yet precise (a filler for
`title` raised first, so `unit_stem(label=…)` was never reached). ⚠️ **A check
that overstates its own coverage is the failure `agent-protocol.md` already
names**; this one understates it and says so.

**Three conditions, and the second is the one that matters:**

1. ⭐ **Per-annotation fillers first**, so the count is a measurement rather than
   a lower bound. A check reports its coverage.
2. ⛔ **The task that lands the check lands the fixes.** *When a convention
   tightens, the tightening owns the migration* — and 26 red sites is precisely
   the blast radius that rule exists for. ⚠️ **Not a gate switched on over a red
   tree with a promise to clean up.**
3. ⛔ **The 19 `where=`/`what=` pairs are not allowlist entries.** Nineteen
   exemptions sharing one reason is a **category**, and a category-sized
   exemption is how an allowlist rots into a config file. ⭐ They are safe only
   because callers pass a relative path — which is *enforced nowhere*, and which
   I had to tell SF-04 by hand in round 14. **Assert it once**: one test that
   every caller passes a relative `where`. Better still, make it unrepresentable.

⭐ **The allowlist shape for the genuine remainder is right** — `(module,
callable, parameter)` with a reason each, following the formatter exclusion where
**the empty claim was the strong one.** ⛔ It should be empty, and each entry an
admission with a name on it.

## ⭐ The pattern this project keeps arriving at, now named

Three independent times in two rounds:

- Ruling 8 — **derive the permitted class** instead of listing forbidden characters.
- SF-09 — **require a slug** instead of slugifying, so a colliding key cannot be represented.
- Ruling 13 — **type `where`** instead of exempting nineteen parameters.

⛔ **Make the illegal value unrepresentable; do not enumerate it.** Every time
this project has written a list of things that are wrong, the list has been
incomplete and stayed incomplete silently. ⭐ Every time it has instead made the
wrong thing impossible to express, the question stopped recurring. **That is the
default, and a list is now the thing that needs justifying.**

# ⛔ Ruling 14 — Finding 7: `require_slug` and `require_ordinal` are the fix to make first

**Verified through a caller, not just at the source:**

```text
identity 'corpus' must already be a slug, got '/path/to/home/jane/corpus'
   (did you pass a title? slugify() it first, and record the result)
```

⛔ **It is R7's exact shape: the branch fires *because* the value is not a slug,
which is precisely when it may be a path.** Two lines, and 7 of the 26 sites are
those two lines seen through their callers — ⭐ **the single change that removes
the most emission in the tree.**

⚠️ **And the parenthetical is why it must not simply be deleted.** *"did you
pass a title?"* is the most useful sentence in that module: it names the actual
mistake, and a corpus author debugging a bad address needs it. ⛔ **Removing the
echo must not remove the diagnosis.**

⭐ **`describe` is the answer, and this is why it is queued with it** (Ruling
10): name the **type** when it is not a `str`; when it is a `str` that is not a
slug, say **which character class failed and at what position**. Actionable,
specific, and it reproduces nothing.

**Owner:** the `describe` extraction task, after step 1.3, with this pair done
first because it is the highest-leverage two lines in the tree. ⚠️ ⛔ **Not a
hotfix on a release branch** — `studyforge.address` is SF-01's module and the
last hotfix that reached across a package boundary is what produced the seam we
spent two rounds closing. The author was right to leave it.
