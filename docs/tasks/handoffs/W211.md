# W211 — handoff

**Kind:** task handoff — W211

**Status:** done

**What landed:**

- ⭐ **`studyforge` is ON THE PATH inside `docker/dev/check`**, by an EDITABLE install
  in `docker/dev/Dockerfile`: pip writes a `.pth` naming `/workspace/src`, a
  `dist-info` and the console script. ⛔ **No module of this project is in the image**
  — it is built against an EMPTY `/workspace/src`, so the command runs the MOUNT, and
  without a mount it fails on `ModuleNotFoundError` rather than running a stale copy.
- ⭐ **The build backend is an image input**: `setuptools` pinned by version AND
  sha256 (`ARG SETUPTOOLS_VERSION`, `ARG SETUPTOOLS_SHA256`, resolved in the pinned
  base image), installed `--require-hashes`, used `--no-index --no-build-isolation`,
  and UNINSTALLED in the same step.
- ⭐ Only `pyproject.toml` and `README.md` cross from the checkout, BIND-MOUNTED
  (never a layer) from the named build context `project: ../..` in `compose.yaml`.
- ⭐ `tests/docker/test_dev_image_command.py` — five static checks and four in-image
  checks (skip on a host, fail in the image). It REPLACES
  `test_studyforge_is_not_installed_into_the_image`, whose decision this row reverses.

**Decisions:**

- ⭐ **Editable, at image-build time, over a launcher script.** A hand-written launcher
  needs no backend but retypes what pip generates; the editable install exercises the
  real `[build-system]` and `[project.scripts]`. ⚠️ **The cost: the entry-point table
  and version are BAKED at build.** `check` rebuilds on every run and the COPY-free
  bind mount is content-keyed, so the step re-runs when `pyproject.toml` moves;
  `test_the_installed_entry_point_is_the_mounted_declaration` turns a stale image red.
- ⭐ **Hash-pinned although `requirements.txt` pins by version only** — stronger than
  its neighbours, and the Dockerfile's other fetched inputs all carry a checksum.
