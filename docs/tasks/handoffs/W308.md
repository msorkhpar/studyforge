## What landed

### ⭐ `tools/authorship.py` — WHO WROTE IT, as a verdict

- `author_is_placeholder(line) -> bool` — the predicate, and **the only function on the merge
  path that ever sees an author line.** ⛔ It returns a BOOLEAN; nothing it reads reaches a
  caller, a message or a log.
- `read_authorship(root, branch) -> Authorship` — reads `HEAD..<branch>` and reports a
  `population`, the `foreign` SHORT SHAS, or an `unread` reason.
- `render_authorship(authorship) -> list[str]` — the printed lines, **population first**.

### ⭐ `tools/mergegate.py` — the gate, wired BEFORE the merge is staged

`stage_and_read` calls `read_authorship` after the committer-identity check and **before
`git merge --no-commit`**. `Outcome` gained an `authorship` field; `Outcome.verdict` answers
it FIRST and never consults `restored`, because nothing was staged and there is no tree to
restore. `render` prints the authorship reading above the gate readings on every path.

## Decisions

⛔ **1. A SPLIT at a named seam, not a trim** (Ruling 261). `tools/mergegate.py` stood at
`356` of R11's `400` before this row, and the floor already flagged it *near and moving*.
⭐ **The seam is the QUESTION ASKED:** `tools/authorship.py` answers *who wrote the commits
this merge introduces*, `tools/mergegate.py` answers *what the tree that merge produces
reads*. ⚠️ The argument lives in the new module and is POINTED AT from the old one, never
copied into both.

⛔ **2. The population is `HEAD..<branch>`, and that one choice settles two clauses at once.**
The commits a merge INTRODUCES are the proposal; everything reachable from `HEAD` has landed.
⭐ So the gate is not a backlog over frozen tips — **and the user's own identity, which the
standing ruling permits on a LOCAL commit because nothing is ever pushed, sits on the release
line and is therefore never read.** ⚠️ One plant asserts both.

⛔ **3. The predicate is a property of the ADDRESS, never a roster of offices.** `W305`
refused *"add `dev1` to the allow-list"* because it fails the next office called anything
else. ⭐ `author_is_placeholder` asks only whether the address is unreachable BY CONSTRUCTION
(RFC 6761's reserved TLDs, RFC 2606's documentation domains), so it holds for every office
name that will ever exist and needs no maintenance when one is added.

⛔ **4. The reserved-domain knowledge is DUPLICATED rather than imported, deliberately.**
`tools/quality/personal_data/shapes.py`'s
`ALLOWED_ADDRESS` is the same knowledge, and importing it was refused twice over: that is a
FLOOR package, and `tools/mergegate.py`'s contract says it imports neither `studyforge` nor
`tools.quality` so that *a tree too broken to import is still one whose merge is REFUSED
rather than one that crashes the gate*. ⚠️ **The cost is drift, and it is a FINDING below
rather than a silence.**

⛔ **5. The AUTHOR line only, not the committer.** The row says *author line*; reading the
committer too would be a silent widening. ⚠️ Recorded so the next office knows it was a
choice and not an oversight.

⛔ **6. A UNIFORMITY arm was considered and REJECTED.** *"Every introduced commit has the
same author"* would catch a mid-carrier identity leak, but it refuses a legitimate
coordinator fixup on an office's branch — ⚠️ **and this file IS the merge path, so a false
refusal there refuses every future merge.** ⭐ The residual it would have covered is named
under Findings instead.

⛔ **7. The gate runs BEFORE staging**, so a refusal costs no gate and leaves no tree to
restore. ⭐ That ordering is what lets the gate be strict without ever being the reason an
office loses work.

## Surprises

⚠️ **1. The floor's own email SHAPE nearly made this row's fixtures illegal.** A realistic
fabricated stand-in for a machine identity — anything of the form `<name>@<host>.<tld>` — is
matched by the personal-data shape and is NOT in `ALLOWED_ADDRESS`, whose exemption covers
only reserved domains. ⭐ **The stand-in is therefore DOTLESS by design**
(`jane.doe@workstation`): the shape regex requires a dot in the domain, so the value cannot
match it, while the predicate under test still correctly refuses to call it a placeholder.
⚠️ **Any office writing an identity fixture will meet this and should not discover it twice.**

⚠️ **2. My first negative control was Ruling 337's own defect.** It asserted *"no office name
appears in `tools/authorship.py`"* by grepping the module — and it FAILED, correctly, against
the module's own prose citing `W305`'s refused *"add `dev1`"*. ⛔ **A negative over an
instrument is never established by grepping for a name.** ⭐ Replaced by the property the
claim actually is: the verdict is invariant under the NAME half of the line, and the two
tuples that are the whole of the predicate's knowledge hold no office name.

⚠️ **3. `ruff format` caught one construct the host run had passed over**, which is Ruling
78's point about the two gates being separate readings.
