### The escaping seam, and how it is asserted

⛔ **`verbatim.py` is its own module because `para` and `html` are byte-identical
in shape** — both `{"type": …, "text": str}` — and `html` is the only one of
eleven block types emitted unescaped. Three tests, and the third is the one that
matters:

1. `test_a_para_whose_text_is_tag_shaped_renders_as_visible_text` — `<blink>` fed
   through **`markdown.parse`**, never a hand-built dict, and the test first
   asserts the reader still returns a `para`, so a change on `SF-07`'s side fails
   with a sentence rather than a confusing diff.
2. `test_an_html_block_reaches_the_page_verbatim` — the converse, so a fix to (1)
   that escapes everything is caught here rather than by a reader.
3. ⭐ `test_exactly_one_block_type_is_emitted_without_escaping` — **derived from
   `BLOCK_TYPES`**: `blocks.RAW_TYPES == {"html"}`, `RAW_TYPES` comes from
   `verbatim.RENDERS` and nowhere else, and `len(BLOCK_TYPES) - len(RAW_TYPES)`
   is 10. A twelfth block type that quietly acquired a raw path fails here.

Plus `test_the_decision_is_the_declared_type_and_never_the_text`, which renders
the *same* payload under both types and asserts the outputs differ — the
mutation the survey named (`if text.lstrip().startswith("<")`) is caught by it.

⚠️ And `verbatim.py` **imports nothing but `__future__`**, asserted with `ast`:
its whole content is that it does not escape, so the escaper is not one keystroke
away.

## Decisions

### ⛔ Not one class name is typed outside a template file — `W9`, made structural

⭐ **The review `W9` asked for came out as "no rename is needed", and the reason
is worth more than the answer.** Every class in Python comes from
`pageassets.class_for(...)` or `SURFACE_HOOKS[...]`; every class in a template is
asserted against `SURFACE_CLASSES | SURFACE_HOOKS`. ⛔ **So this package cannot
invent a name the stylesheet does not target, because it does not spell one.**

⚠️ `test_surface` already asserts the contract from the stylesheet's side —
*every class the stylesheet targets is published*. This adds the renderer's
side: *every class the markup emits is published*. **Both are needed**; with one,
the two halves can still disagree, and a page that renders, carries every word
and is unstyled has no error anywhere.

⚠️ The one exception is `language-<lang>`, which is **Prism's** API read out of
the page the vendored bundle was shipped with. It is deliberately not in
`SURFACE_CLASSES` — a library's contract is not this project's to keep in step —
and `test_surface` says the same thing from the other side.

⚠️ Consequences, both deliberate: the source's `class="bar"`, `class="readout"`,
`class="hint"`, `class="ext"`, `class="skip"`, `class="section-note"` and
`class="tag"` did **not** come across, because none is published. See
`SF-12/5`.

### ⛔ The template loader is `render/templates/__init__.py` — not the survey's placement

`SF-12-survey/3` said the loader is owned by nobody and proposed
`render/pageassets/templates.py`. ⛔ **That would publish three new names from a
package this task does not own**, which R21 makes an escalation rather than a
placement. So it is in the directory it loads, which is inside `SF-12`'s declared
`Owns`. Three reasons that are not about ownership, in `SF-12/1`.

### ⛔ `SF-12` mints no speech id, and the player region is *derived*

⚠️ **`5.3`'s tension is real and both horns are bad:** minting `data-speech-id`
at M1 creates exactly the coupling the source's own docstring warns about;
emitting neither means every M1 golden page churns at M3.

⭐ **What was done.** Three things, and the third is the one worth carrying:

1. **No speech id, no audio href.** `SF-16` owns the derivation at M3.
2. **`page/navigation.py` mints anchors for headings and sections only** — what
   an outline and an inbound link actually address — and does so from `(section
   key, block position)`, both structural. ⛔ **Deliberately not one id per
   block**, which would be the speech-id scheme under another name.
3. ⭐ **`assets.AUDIO_ATTRIBUTE` is named a milestone before its writer**, the way
   `identity.py` was landed ahead of `SF-04`, and **the player region is gated on
   the page's own body containing it.** So no document field was invented to hold
   a gate, the region is empty at M1, and at M3 the transport arrives *in the same
   change* as the attributes rather than as a second one.

⚠️ **The churn is not avoided and is not pretended away** — it is now a single
stated product change. See `SF-12/3`.

### One variant per page — the CTO's round-20 ruling, followed

The 112 language-pill lines do not port. The served document already carries a
single `variant` and `Identity.variant` is a single required slug, so nothing
needed to change: the composer reads the document's sections in the order the
document records them and renders all of them.

### `render(document, placement, links=None)`

`placement` is a frozen `Placement` — `corpus`, `UnitLocations`,
`CorpusLocations` — and **not a profile**. ⛔ The profile has already answered by
the time a page is rendered, so `page/` holds locations rather than the engine
that computed them, which is what keeps it free of any branch on a profile name.
`links` is a keyword with a default, because nothing computes a reading order
before `SF-13`; a page with no bar renders exactly as it will once one does,
minus the bar.

### The section wrapper shows its heading only when the material carries none

⚠️ A section's `heading` is usually the archive document's title and its first
block is usually a heading saying the same words — under an `<h1>` that is often
a third copy. ⛔ But an authored `shared` section typically has **no heading at
all** and would otherwise reach the reader as an unlabelled run of prose.
⭐ **The test is structural, never textual:** show the recorded heading iff the
blocks contain no heading of any kind. Comparing the *words* would put the
heading back the day an author changed one character and take it away when they
changed it back.

### `_width` is narrower than the source's

`int(1.5)` is `1`, so a float width would reach the page as a one-pixel image —
a silently wrong number, which is worse than no number. A positive `int` and
nothing else. `SF-12/6`.

## Surprises

**⛔ `reading.css` styles the block vocabulary and nothing else, and that turned
out to be the largest decision in the task.** `SF-11`'s finding 3 assigns the
masthead, the layout grid and the rail to `SF-12`; `test_surface` asserts in
*both* directions that the published set and the stylesheet's set are equal. ⛔
So emitting a single chrome class means editing `surface.py`, `bundle.py` and
`render/assets/` — three files inside `SF-11`'s package. The page's chrome is
therefore addressed by **element, `aria-label` and `data-*`** and is unstyled.
⭐ **The good half: a chrome part added later needs no page change and no
re-render**, because nothing about the emitted markup has to move. `SF-12/5`.

**⚠️ `archive.markdown` leaves inline markers in `text` and nothing rendered
them.** Its own docstring says *"emphasis, inline code and links are left
untouched inside `text`, because stripping them is exactly the loss it exists to
prevent"* — and the extraction source's parser lives in `speakable.py`, which is
`SF-16`'s and arrives at M3. Without a renderer the reading floor shows a reader
literal backticks and `[label](href)`. `page/text.py` now owns the one split.
`SF-12/7`.

**⚠️ `python3.14` allows an unparenthesised multi-type `except` (PEP 758), and
two shipped modules already use it.** `src/studyforge/unit/served.py:69` and
`corpus/placement/identity.py` read `except TypeError, json.JSONDecodeError:`,
which looks like a Python 2 syntax error and is not. Recorded because half an
hour went into confirming it was not a defect, and the next reader will spend the
same half hour.

**⭐ The existing suite caught two real defects in this diff that its own tests
did not.** `tests/studyforge/archive/test_blocks.py` failed a literal list of
seven vocabulary names in a module that did not import the vocabulary — so
`prose.RENDERS` is now derived from `BLOCK_TYPES`. And `tests/test_emission.py`
found `assets.media_kind` echoing its argument into a refusal (rubric §1f),
which is now `describe`d. ⛔ **Both were in a package whose own 257 tests were
green.** That is the argument for repository-level checks, arriving as evidence.

**⚠️ A prose corpus renders "More to come" on every page unless the build passes
`declared_practices=0`.** `corpus.json` declares `"exercises": false`; the served
document only records `declared`, which is `None` when nothing said. `None` is
correctly *not* the same as zero — but a build that does not translate the
manifest's flag into a count makes every page of a complete prose corpus claim to
be unfinished. `SF-12/4`.

## Findings

⭐ Numbered per-document as `SF-12/<n>`, per the PO's round-18 ruling.

### SF-12/1 `[structural]` The template loader is in the directory it loads, not beside `pageassets`

`SF-12-survey/3` proposed `render/pageassets/templates.py`. ⛔ That publishes
`template`, `fill`, `names`, `placeholders`, `TEMPLATE_DIR` and `TemplateError`
from a package `SF-12` does not own, which R21 makes an escalation. It is
`render/templates/__init__.py`, and three reasons are not about ownership:
**(1)** it is a *sibling* of `page/`, so `SF-14`'s root index takes templates
without importing the unit renderer — which was the survey's actual requirement;
**(2)** the directory is `Path(__file__).parent`, so there is no cross-package
path arithmetic to drift; **(3)** `pageassets`' own test asserts templates and
asset parts are never confused, and two packages is a stronger form of that than
two functions in one.
**Measured** — `templates.names()` returns 8 files and no `.py`;
`test_the_loader_lives_in_the_directory_it_loads` asserts the loader and the
markup share a directory. 2026-09-10.

### SF-12/2 `[structural]` The markup contract is still unversioned, and this task did not mint a key

⛔ **The R21 escalation `SF-12-survey/5.2` raised stands, and the build did not
force it.** There is still no `PAGE_API` and no `SURFACE_API`; `identity_api`
versions the JSON block `SF-04` parses and **not** the class names `assets/*.css`
query, nor `data-speech-id`/`data-audio` that `SF-18` reads at M3. ⭐ This task
did not need to answer it, because the renderer types no class name at all and
mints no narration attribute — so there was nothing to version that was not
already `surface.py`'s. ⚠️ The producer is still unsettled (`SF-11` owns the
file, `SF-12` is the first writer of markup honouring it, `SF-18` is the second
reader) and the question is unchanged, not closed. **A version key was not minted
quietly, which was the instruction.**
**Measured** — `grep -rn 'API = ' src/studyforge/` returns `CONTENT_API`,
`IDENTITY_API`, `CONTAINER_API`, `CORPUS_API`, `RAW_API` and the unit builder's
`API`; nothing named for a page or a surface. 2026-09-10.

### SF-12/3 `[structural]` M1's golden pages change shape at M3, and that is a decision rather than a surprise

⛔ **`SF-12` mints no speech id** (the coupling the source's own docstring warns
about), so at M3 `SF-18` adds `data-speech-id` and `data-audio` to elements this
task already emits, and **both committed goldens move**. ⭐ The player region is
gated on the body containing `assets.AUDIO_ATTRIBUTE`, so the transport arrives
in the *same* change rather than as a second one — one product change, not two.
⚠️ R10 pins that a *rerun* is byte-identical, never that a page is frozen across
milestones; whoever regenerates the goldens at M3 should say so in their handoff
rather than discovering it as a diff.
**Measured** — `document.player("")` is `""` and
`document.player('<p data-audio="…">x</p>')` is the footer; both directions have
a test. 2026-09-10.

### SF-12/4 `[structural]` A build that does not translate `exercises: false` into a count makes every prose page claim to be unfinished

⛔ `corpus.json` carries `"exercises": false`; `unit.json` carries
`practices.declared`, which is `None` when nothing declared a count. `None` is
correctly **not** zero — *"a map that never said how many practices a unit has
cannot be shown as complete"* — but a build that passes no
`declared_practices` renders the "More to come" panel on **every page of a
complete prose corpus**. ⭐ Not a defect in `unit.builder` and not one here: it is
a step the build task (`SF-27`) owes, and it is invisible until a page is looked
at. The golden for `depth1` is generated with `declared_practices=0` for exactly
this reason, and `tests/studyforge/render/page/pages.py` says so in its
docstring.
**Measured** — `build_unit(depth1/unit-02)` gives `{"declared": None,
"archived": 0}`; the page then carries the panel. With `declared_practices=0` it
does not. 2026-09-10.

### SF-12/5 `[structural]` The page's chrome is unstyled, and styling it means editing three files in `SF-11`'s package

⛔ `reading.css` states its own scope: *"Masthead, navigation rail, narration
player, progress controls and practice panels are NOT here."* And `test_surface`
asserts the published set and the stylesheet's set are **equal in both
directions**, so a single new chrome class requires `render/assets/<part>.css`,
an entry in `SURFACE_HOOKS` and an entry in `STYLE_PARTS` — three files under
`render/pageassets/` and `render/assets/`, neither of which `SF-12` owns. ⚠️
`SF-11`'s own finding 3 assigns *"masthead and layout grid and the navigation
rail"* to `SF-12`, so this is a genuine disagreement about a boundary rather than
an omission. ⭐ **What was shipped instead:** the masthead, the outline and the
between-units bar are addressed by **element, `aria-label` and `data-*` only**,
so a chrome part added later needs **no page change and no re-render** — and
nothing has drifted in the meantime, because nothing was invented. ⛔ **Ruling
wanted**, and it is one commit either way.
**Measured** — every class the two goldens carry is in
`SURFACE_CLASSES | SURFACE_HOOKS | {language-java}`; the pages' `<header>`,
`<nav>` and `<ol>` carry none. 2026-09-10.

### SF-12/6 `[local]` `_width` is narrower than the extraction source's, deliberately

The source's `int(block.get("width"))` turns a width of `1.5` into
`width="1"` — a one-pixel image, silently. Here it is a positive `int` and
nothing else; anything else emits no attribute at all, which is what *"the
archive does not know"* already meant.
**Measured** — parametrised over `None, 0, -3, "wide", 1.5`; all five emit no
`width`, and `800` does. 2026-09-10.

### SF-12/7 `[local]` The inline-marker split had no owner, and `page/text.py` now holds it

`archive.markdown` deliberately leaves emphasis, inline code and links inside
`text`; the extraction source's `parse_inline` lives in `speakable.py`, which is
`SF-16`'s at M3. ⛔ Without a renderer at M1 the reading floor shows literal
backticks and `[label](href)`, so `page/text.py` publishes `SEGMENT_KINDS` and
`segments()` and its docstring says `SF-16` must import them rather than write a
second parser. ⚠️ **This inverts the source's dependency direction** (there,
display imported from speech). The argument is the ordering, not the direction:
display and speech must never disagree about where a marker begins.
**Measured** — `test_every_segment_kind_is_reachable_and_declared` derives the
kinds from a live parse and compares to `SEGMENT_KINDS`. 2026-09-10.

### SF-12/8 `[local]` The survey's template arithmetic says nine and its own table lists eight

`SF-12-survey` §1 states *"Nine of the twelve are SF-12's; three are not"*, and
the table beside it marks four as somebody else's — `practice-panel` (M5),
`lesson-credit` (R1), `nav-tree` (SF-14), `read-control` (SF-30) — which leaves
eight. ⚠️ Harmless: the count was not load-bearing and the dispositions were all
correct. ⭐ Recorded because *"if a document states a number, check it rather
than inheriting it"* found it in ten seconds, and this is the second survey
number in two rounds to be off by one.
**Measured** — 12 files in `CS/tools/study/templates/`, 4 marked not-SF-12 in
the survey's own table. This port ships 8, which is the same 7 that carried over
plus `player.html`, minus `inline-video.html` (merged into `video.html` — one
figure shape) and minus `disclosure` (a one-line container, so E03's rule keeps

## For dependents

### For `SF-14` (root index) and `SF-13` (contents)

- ⭐ **`studyforge.render.templates` is a sibling, not a child of `page/`.** Import
  it directly; do not reach through the unit renderer.
- ⛔ **`templates.fill(name, **values)` is exact in both directions** — an
  unfilled placeholder *and* a value with no placeholder both raise. The second
  is the one that matters: a slot deleted from the markup takes its content off
  the page and `Template.substitute` would have ignored it.
- ⚠️ **`templates/test_init.py::test_every_template_is_classified_as_one_line_or_many`
  will fail on your first new template until you decide which kind it is.** That
  is the point: *markup emitted on one line is authored on one line*.
- ⛔ **`test_every_template_is_asked_for_by_some_renderer`** scans all of
  `src/studyforge/render/**.py` for `"<name>.html"`, so a template referenced only
  through a variable will read as an orphan. Name it in a module-level constant.
- The in-page outline is `page/navigation.py`'s and reads **only the document
  being rendered** (`SF-12-survey/5.5`: the layering argument won). A contents
  document links *into* a page with `#s-<section key>` and `#<section key>-b<n>`;
  both are published as `section_anchor()` and `block_anchor()` — ⛔ derive them,
  never spell them.

### For `SF-18` (narration player, M3) and `SF-16` (speakable, M3)

- ⛔ **`page.AUDIO_ATTRIBUTE` is the spelling of `data-audio`, and it is named
  once.** `document.player()` is gated on the rendered body containing it, so the
  moment you write the attribute the transport appears. Do not add a second gate.
- ⛔ **`render/templates/player.html` already exists** and is the port of the
  source's `PLAYER` literal, minus four unpublished class names
  (`bar`, `readout`, `status`, `hint`) — its ids are unchanged.
- ⭐ **Take the inline split from `page/text.py`** (`SEGMENT_KINDS`, `segments()`)
  rather than writing a second parser. Display and speech must never disagree
  about where a marker begins; only the rendering differs.
- ⚠️ **`navigation.block_anchor(section_key, position)` is an *anchor*, not a
  speech id**, and it exists only on headings. Speech ids are yours. If the two
  must agree, make it one derivation and say so — do not let them agree by
  coincidence.
- ⚠️ Regenerating the goldens is expected at M3 —
  `python3 -m tests.studyforge.render.page.pages` — and `SF-12/3` is where that
  was decided.

### For `SF-27` / whoever builds a site

- ⛔ **Translate `corpus.json`'s `exercises` into `declared_practices`**, or every
  page of a complete prose corpus says "More to come" (`SF-12/4`).
- `render(document, placement)` returns **bytes**. Write them to
