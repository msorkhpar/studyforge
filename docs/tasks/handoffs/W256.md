## Decisions

- ⭐ **No digest at all for the person's module**, rather than a digest kept from the first install. This way a regenerate cannot re-record it by construction. Reversible.
- ⚠️ **`installed_api` is `2`, and this build still reads `1`.** An api-1 reader expects a digest on every entry. With the bump it refuses the new record by name instead of failing on the marked entry (`W256/3`). Reading `1` is not a migration: every api-1 entry has a digest.
- ⚠️ **`uninstall` re-derives the stub from `corpus.json` on disk** to decide whether the person's module is still untouched. This rests on the existing test that re-scaffolding from the written manifest is byte-identical.
- The record code moved out of `onboard.py`, which would otherwise have passed R11's ceiling.
