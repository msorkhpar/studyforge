  and `run` is a property that calls it. Each loader (`_validate`, `_plan`, `_narrate`, `_build`,
  `_serve`) is a plain `from … import main` inside a function body, and returns that `main`.
  `dispatch.main` still calls `VERBS[verb].run(...)`, and `skills/buildserve/verbs.py` still
  calls `verb.run(...)`, unchanged.

## Decisions

1. **The laziness is a loader function per verb in `dispatch.py`, not a lazy import in each
   verb's `main`**, which the row forbids. The verb packages are untouched, and each verb module
   is named once, in its loader, which only `VERBS` references.
2. ⛔ **Not `importlib.import_module` over a `module:attribute` string.** That design was built
   first and refused by
   [`test_isolation.py`](../../../tests/harness/test_isolation.py)`::test_no_framework_module_reaches_a_module_by_name_at_run_time`
   (R1). A plain import statement in a function body is what that test allows.
3. ⚠️ **`validate.cli` is still loaded with the dispatcher.** `UNUSABLE` is imported from it rather
   than respelled, as `dispatch.main`'s docstring requires. The tests therefore allow exactly that
   one verb module (`HELD`) and require every other to be absent. See `W293/3`.
4. ⚠️ **`tests/studyforge/narrate/test_wire.py` was edited, outside the declared surface, because
   this row's change falsifies one of its tests by design.**
   `test_the_plan_reaches_the_narrate_verb_through_the_dispatcher` pinned `W223/1`'s route as
   *inhabited*. `W293` closes that route, so the test was inverted and renamed
   (`…_no_longer_reaches_…`), and its comment points at `test_dispatch.py` as the clause's owner.
   No other line in that file changed.
5. **Build loading plan is not the dispatcher's coupling.** `cli/site/cli.py` imports `cli.plan`
   itself, so importing the build verb's module loads plan's entry point too. The per-verb test
   therefore asserts over what arrives *through the dispatcher's module body*, not over every
   module a verb loads, and never claims each verb module is isolated from every other.

## For dependents

- ⛔ **A new verb is registered as a private loader in `dispatch.py` (`from … import main` in the
  body) plus one `Verb(name, summary, _loader)` in `VERBS`**, never as a module-level import.
  `test_the_dispatcher_binds_no_verb_callable_of_its_own` and the fresh-interpreter tests go RED
  on such an import; `test_every_loader_in_the_dispatcher_is_reached_from_the_one_table` goes RED
  on a loader `VERBS` does not hold. ⚠️ That test reads every private callable defined in
  `dispatch.py` as a loader, so a private helper added there would trip it.
- ⭐ **`Verb.run` is still the callable.** Callers that read `verb.run` or compare it with `is`
  need no change. Reading it imports the verb's module.
- ⚠️ **Importing `studyforge.cli.<verb>` no longer loads any other verb through the dispatcher;
  it loads that verb's own imports, the dispatcher and `validate.cli`.** A test that relied on the
  package import loading some other verb has to import that verb itself. None in this repository
  did, apart from the `test_wire.py` control in Decision 4.
