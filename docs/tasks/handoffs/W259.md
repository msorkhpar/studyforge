## What landed

- [`classification.py`](../../../src/studyforge/validate/source/classification.py): `_walk` asks
  `SKIP_DIRS` of the corpus root's first path part only. A nested `.studyforge` is walked
  like any directory and classified by the manifest.
- **`nested-repository`**, a `Finding`, is on the package surface as `RULE_NESTED_REPOSITORY`.
  Each nested `.git`, whether a directory or a submodule's gitfile, is named once by its
  relative path and never entered. `Scan.stores` carries the stores.
- A store the repository's own ignore rules declare as output is not refused. Where no
  declaration can be read, it is refused.
- [`validate.md`](../../authoring/validate.md): one rule-id row, and the heading moved to the
  derived count.

## Decisions

- **A nested `.studyforge` is scanned, not refused.** The framework writes `.studyforge` only
  at the corpus root (`GENERATED_ROOT`, `PIN_DIR`), so a nested one is a source's own
  directory. This is `W248`'s answer for a nested `archive/`. A build's planned files are
  still recognised by the plan first.
- **A nested `.git` is refused by name, not scanned. This ruling is reversible.** Reading
  one as material would make every object file an `unclassified` finding: hundreds of
  lines of compressed history, which is the audit nobody reads that this module's docstring
  refuses. The only way out would be a per-store `not_material` glob, and the manifest
  refuses a leading wildcard. Git also treats a nested repository as a boundary. The
  parent's ignore rules do not answer for its files, and inside a submodule `check-ignore`
  exits 128. One named finding tells the author what to do. To reverse this, drop the
  store branch in `_walk` and the rule id.
- **The generated `test_emit` copy does not change.** It never called `_walk`, and
  `repository_ignores` is untouched. See `W259/1` for what the copy now diverges on.
- **`W248` and `W255` are unchanged.** A store beneath `archive/` is still `archive-stray`
  (tested). `completeness` shares no name with `classification`, as `test_init` asserts.

## Surprises

- The old walk skipped a nested `.git` directory but **scanned** a nested `.git` gitfile,
  because it tested `parts[:-1]`.
