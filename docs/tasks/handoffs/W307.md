## What landed

### ⭐ The floor DISCLOSES which identifier arms had a value to compare

⛔ **The defect, restated as a mechanism:** `check_personal_data` was the floor's only check with
no line in the second channel at all. R7's identifier arm derives this machine's own values and
reports any tracked file carrying one — and when it derives NOTHING it reports nothing, which is
byte-for-byte the output of a run where a real identifier *was* derived and found in no tracked
file. ⛔ **Two readings, one line, and only one of them is a guarantee** (`FND-07`).

- ⭐ **`IDENTIFIER_LABELS`** — every arm `identifiers()` can return, paired with what each derives
  FROM. It is the **denominator** the notice prints (Ruling 48) and the surface a test reads by
  name.
- ⭐ **`identity_notice(root)`**, registered in `NOTICES` **immediately above `lint_notice`**: both
  qualify the VERDICT line rather than any one check's output, so they belong together where the
  reader meets `quality floor:`.
- ⛔ **It reports what `identifiers()` RETURNED and derives nothing of its own.** A second,
  independent reading could disagree with the one the check actually used, and the disclosure
  would then be about a different run than the verdict.
- ⛔ **Labels, never values.** A notice that printed the value would be the leak the check exists
  to prevent. ⭐ An arm derived and absent from `IDENTIFIER_LABELS` is printed as **drift** rather
  than dropped, so the census cannot go stale in silence.

⚠️ **The reading below is quoted deliberately and it is NOT a gate's figure:** it is the row's own
SUBJECT — the state that was invisible — which is the exception the user decision names
([`review-rubric.md`](../../conventions/review-rubric.md#ruling-78-the-floor-prints-the-lint-state-including-its-absence)).
⭐ **The owed GATES quote no figure at all.** Taken in the pinned image on this branch:

## Decisions

⛔ **1. The disclosure is PER ARM, not a binary armed/unarmed line — and this is a MEASURED
correction to the row, not a widening.** The row says the arm *"derives NOTHING"* in the image and
*"compares against an empty set"*. ⚠️ **Measured, it derives the two hostname labels**, so a binary
line would have reported the shipped state wrongly in the one environment the row was written
about. ⭐ The remedy the row actually asks for — *a reader can tell the two states apart* — is
served correctly only per arm, because the arm that is unarmed there is the GIT one specifically.

⛔ **2. `identifiers()` is CALLED, never re-implemented.** The brief forbids a second copy of the
arm's logic and is right to: a notice that re-derived independently could report *armed* over a
verdict reached while unarmed. ⚠️ The cost is that the derivation now runs twice per floor run, and
it is filed below as `W307/2` rather than hidden.

⛔ **3. The scopes `W305` narrowed were NOT widened, and nothing about the arm's READING changed.**
This row is about what the run SAYS. `IDENTITY_SCOPES` is untouched, the pin on it in the mirror is
untouched, and ⭐ the notice now PRINTS those scopes, so a future widening is visible in the floor's
own output rather than only in a test.

⛔ **4. It is a NOTICE, and the exit code is untouched.** An unarmed arm is correct inside the
image, which configures no git identity by design. ⚠️ A red run for a condition nobody may be
failed for is a red run that gets muted, which is how a check stops being read — the same argument
`NOTICES` already carries for `lint_notice`.

⭐ **5. No convention document was edited, and none is needed.**
[`review-rubric.md`](../../conventions/review-rubric.md#ruling-78-the-floor-prints-the-lint-state-including-its-absence)
already carries Ruling 78 with its ground, and this row is that ruling applied to an arm rather
than to a tool. ⛔ Restating it would mint a second copy that can disagree with the first. ⭐ **The
contract for this arm is a property of the module and lives in the module**, where it cannot go
stale against the code it describes.

## Surprises

⛔ **THE ROW'S PREMISE IS PARTLY FALSE, AND IT IS SAID HERE RATHER THAN QUIETLY WORKED AROUND.**
The row and the register cell both state that inside the pinned image the arm *"derives NOTHING"*
and *"compares against an EMPTY SET"*. ⚠️ **Measured in the image, null checks only, no value
printed: it derives the `hostname` and `short hostname` labels.** ⭐ **What IS true is the sharper
and narrower claim:** the GIT arm — the one `W305` narrowed — derives nothing there, and so do the
account-name and home-directory arms; and the floor said nothing about any of it either way. ⛔ **So
the defect is real and the remedy stands; only the extent was overstated.**

⚠️ **The consequence, and it is why this is not pedantry:** had the notice been written to the row's
words, it would have printed *the identity arm is UNARMED* over a run in which two arms had in fact
compared — a fresh instance of the exact confusion the row exists to close, shipped by the row's own
remedy.

⭐ **The check's one-line summary was the only thing missing, not the data.** `identifiers()`
already returned exactly what a reader needs; nothing had to be derived, stored or plumbed. ⚠️ **The
whole defect was that no one printed the population** — which is Ruling 48's standing lesson
arriving for the fifteenth time in this package.
