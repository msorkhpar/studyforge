## Decisions

### ⛔ 1. `F19` needed a capability on `Profile`, and this is the caller `SF-25` did not have

`studyforge plan` must print ignore lines that differ by profile, and R1 —
`test_nothing_downstream_branches_on_a_profile_name`, an AST scan of all of
`src/` — forbids the caller reaching them by asking which profile it has. So
`Profile` gains **`ignore_lines(media=…)`** and **`media_ignore_lines()`**, and
the two shipped profiles answer.

⚠️ **`SF-25` measured that the collision check needed no new capability and
declined to invent one**, on the rule that *a capability designed by somebody
with no caller is a guess* — and the CTO's record exists specifically to stop
somebody adding one later. ⭐ **That argument is met rather than sidestepped:
the caller is in the same commit, and without the capability `cli/plan` would
hold a per-profile glob table, which is R1 in miniature.**

⛔ **This is the one place the diff reaches outside `cli/plan`** — three
placement modules and their three test modules. It is the acceptance clause's
minimum, and it is stated here rather than buried.

### ⛔ 2. What the ignore lines are, and the two things they deliberately do not cover

Derived from `names.py`'s own constants, never retyped:

```
/index.html                     /.studyforge/assets/     /.studyforge/site.json
*.section.html                  *.unit.html
```

and, **only when the corpus's `media` policy does not commit**, the profile's
own media globs — `*.audio/` and its three siblings under `sibling`,
`/.studyforge/**/audio/` and its three under `tree`.

- ⛔ **The archive is never ignored.** It is the ingested record an adapter
  wrote (R2) and it is the one thing under the generated root a clone cannot
  rebuild without — which is the whole reason `/.studyforge/` is not one line.
- ⛔ **Committed media is never ignored.** Generated media is committed by
  default (§5); a framework that ignored a corpus's narration by reflex
  produces clones that are silent with no error.

⭐ **`tree`'s globs are anchored and `sibling`'s are not, and that asymmetry is
load-bearing.** `audio`, `images`, `video` and `practice` are words a real
repository uses for its own material, and under `tree` every generated clip is
below `.studyforge/`, so the anchor costs nothing. Under `sibling` the names
carry the unit's stem, so `*.audio/` is both necessary and unanchorable.
⚠️ **The cost is stated in the docstring rather than guarded against**: a
repository that already keeps `lecture.audio/` has one git will now ignore. The
alternative is enumerating names that do not exist yet, which is exactly what
Ruling 91 refused.

### ⛔ 3. The media footprint reports itself UNPROJECTED, and that is the answer, not a stub

A footprint is clips × bytes-per-clip. **`SF-32` (M3) owns that measurement and
no narration exists for any corpus yet.** ⛔ **A number invented here would be a
guess wearing a measurement's clothes, in the one report a person reads to
decide whether to let this tool near a repository they care about.**

⭐ **So the knowable half is printed as fact** — how many units will each carry
media, the commit mode, and both limits — **and the projection names who owes
it.** ⭐ **The rate is a parameter, not a constant**: `plan_for(root,
bytes_per_unit=N)` and `--bytes-per-unit N`, so `SF-32` plugs in **without this
contract changing**, and a person asking *"would 200 MB a unit still fit?"* can
ask it today. Both verdicts — `fits` and `EXCEEDS max_total_bytes` — are
implemented and tested now.

### 4. `F18` / `not_material` does not reach this output — checked, not assumed

⛔ **Ruling 90 is owed *before* `SF-31` and has not landed**, so I checked
whether the plan must reflect it. **It must not.** `plan` never touches
`content`: it reports paths, declared edits, ignore lines and the media policy.
⭐ **And the two do not overlap by design** — Ruling 91's own argument is that
generated artifacts are declared in `.gitignore` *because* `content` cannot
take globs, while `not_material` is for the repository's own scaffolding. When
`content` gains its third state and `corpus_api` goes to 2, this command is
unaffected and its goldens do not move.

### 5. It reads the declarations, and a narrower set than `validate` does

`corpus.json` plus the container maps under the archive — **not**
`validate.corpus.read`, which also parses every archive document. ⚠️ A plan that
went red because one lesson's JSON was malformed would be answering
`validate`'s question with `plan`'s exit code. ⛔ `ARCHIVE_DIR` and
`CONTAINER_FILENAME` are imported from their owners rather than respelled.

## Surprises

⭐ **The one-file version was 455 lines, and the interesting part is *where* the
lines went.** Not code: the module has ~300 lines of substance and the rest is
contract. ⚠️ **Trimming to ~395 would have been shaving reasoning to fit a
number**, which `module-structure.md` warns against in the same paragraph that
sets the ceiling — *"a 380-line module that fails the isolation test is worse
than a 420-line one that passes"*. ⛔ The split was the right answer because the
seam is real and `validate/` had already found it, **not** because 455 > 400.

⚠️ **`Reversal.__str__` says it produces *"a one-line description a person can
read in a plan"* and produces `remove-line a str from pom.xml`.** It reaches
for `describe`, which refuses to reproduce any string — correct for a refusal
and useless in the report the docstring names. Finding `SF-31/1`.

⭐ **The R7 question this command raises is the opposite of the usual one, and
it resolves cleanly.** `plan` prints `title`, `why` and an edit's inserted line
**verbatim**, where every refusal site in this tree is forbidden to. That is
sound because it is not a refusal site: `manifest.parse` and `container.parse`
run `assert_clean` over the whole decoded document before any field is read.
⛔ **Asserted rather than assumed** —
`test_a_manifest_carrying_personal_data_is_refused_before_any_line_is_printed`,
using `tests.emission.POISON` so the repository's own R7 sweep is not asked to
make an exception for a new file.

⚠️ **The two fixtures' ignore lines are identical, and that is not a defect.**
Both commit their media, and what differs between the profiles is where *media*
goes — the page suffixes are this framework's own, minted so a scan can read
them off a listing whatever the profile. ⭐ Both facts are asserted, in the two
tests either side of each other, so neither can be read as the other.

## Findings

### SF-31/1 `[local]` — ⚠️ `Reversal.__str__` renders its content through `describe`

**`corpus/manifest/edits.py`'s `Reversal.__str__` renders its content through
`describe`**, so the line it promises *"a person
can read in a plan"* reads `remove-line a str from pom.xml`. ⛔ The R7 rule it
is following is right for a refusal and wrong for a report of a **gated**
declaration — the same text is printed in full one line above, from
`PermittedEdit.content`. ⭐ `edit_lines` composes the undo from `Reversal`'s
fields instead and says why in its docstring;
`test_the_undo_line_reproduces_the_line_being_removed` pins it so a later fix
cannot silently restore the unreadable form. **Owner: SF-02's module.**

### SF-31/2 `[structural]` — ⛔ one acceptance clause is not executable at M2

**Not executable by anybody, not merely by me.** *"Matches what a real build
then creates, path for path, asserted by running both and diffing"* needs a build; measured on
this tree, `src/` contains **no writer at all** — the only `write_text` /
`write_bytes` / `mkdir` occurrences are two docstring examples, in
`render/pageassets/__init__.py:12` and `render/page/__init__.py:17`. ⭐ **The
substitute is real and is three independent routes** — a second derivation, a
count identity, and a committed golden — **but it is not the clause.**
⛔ **The clause is owed at the first task that writes files** (`SF-28`'s build,
and `OPS-05` which asserts *what was planned is what happened*), and the
goldens committed here are precisely the instrument that will catch a
divergence. ⚠️ **Filed rather than quietly declared met**, because a clause
marked green on a substitute is one nobody runs later.

### SF-31/3 `[local]` — ⚠️ the archive root is a constant in two packages

**`ARCHIVE_DIR = "archive"` lives in `validate/corpus.py`** and is now imported by a second package. Its own
comment calls it *"a stand-in for `<archive-root>` (§6)"* and says *"a
consumer takes the root as a parameter, never as a constant"* — and both
consumers now take it as a constant. ⭐ Harmless while both agree; it becomes
a defect the day a corpus puts its archive anywhere else, which §6 permits.
**Owner: whoever makes the archive root a parameter — `SF-04` or `SF-28`.**

### SF-31/4 `[local]` — ⚠️ `FND-04`'s deferred-golden table is now one row stale

## For dependents

- ⭐ **`SK-07` takes `Plan.ignore` and `Plan.edits`, never the text.** The ignore
  lines are already the complete `.gitignore` body for the corpus's profile and
  media policy, in order; `Plan.edits` is `tuple[PermittedEdit, ...]` with
  `.path`, `.kind`, `.anchor`, `.content`, `.why` and `.reversal`. ⛔ **Do not
  add a media line to the rendered ignore rules yourself** — `Plan.ignore`
  already reflects the policy, and adding one would ignore committed narration.
- ⭐ **`OPS-05` takes `Plan.paths`** — sorted, root-relative, one entry per path,
  directories carrying a trailing `/`. Comparing a finished build against it is
  a set comparison and needs no parsing. ⚠️ **A path claimed by two artifacts
  appears twice**, adjacently; that collision is `validate`'s `duplicate-path`
  finding and `plan` does not restate the rule.
- ⛔ **`SF-32`: the seam is `plan_for(root, bytes_per_unit=N)` and it exists
  today.** Nothing about this contract changes when the measurement lands —
  pass the rate, and `fits` / `EXCEEDS max_total_bytes` are already written and
  tested. ⚠️ **`max_total_bytes` and `max_file_bytes` are now written by a
  fixture *and read by a shipped command*, so E04's note that renaming them is
  free "exactly until M2" has expired**: they are `corpus_api` fields and a
  rename is an R9 migration.
- ⚠️ **`SF-28`, and the convention this sets:** `cli/plan/` is `validate/`'s
  four-module shape, and `python3 -m studyforge.cli.plan` works today. The
  console-script callable is `studyforge.cli.plan.cli.main`, and `UNUSABLE` is
  imported from `validate.cli` so the two commands cannot come to disagree
  about exit code 2.
- ⛔ **The integration track is unblocked.** `studyforge plan <repo>` answers,
  from the manifest alone, every path that will land, every declared edit with
  its reason, and the ignore lines to paste — which is the placement contract
  the ISO integration has been waiting on since M1. ⚠️ **`ISO-09` is still
  blocked on Rulings 90 and 92**, which are ruled and unwritten; this task
  removes a different blocker and not those.
- ⚠️ **A third placement profile must now answer `media_ignore_lines()`.** It
  raises `NotImplementedError` on the base class, like `unit` and `container`,
  and `test_every_registered_profile_answers_with_ignore_lines` walks the
  registry rather than the two names — so a new profile that inherited a stale
  glob fails at registration time rather than reporting ignore rules that
  ignore nothing.
