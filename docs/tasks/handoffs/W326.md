## What landed

### The rail spans the reading column's rows instead of sizing one of them

```css
body > nav[aria-label="Containers"] {
  grid-column: 1;
  grid-row: 1 / span 10;   /* was: grid-row: 1 */
  align-self: start;
  margin: 0;
}
```

⛔ **That is the whole change to the product.** No template, no renderer, no new
token, no second markup, no script — `--rail` and `--page-max` are the two the
brief named and both were already painted. The two-column page is still asked for
by `:has()`, the narrow shape is still the card, and the page bytes are identical
to `W325`'s.

### ⛔ `1 / -1` is NOT the repair, and that is measured rather than argued

⚠️ **The brief named `grid-row: 1 / -1` as the likely fix. It was taken to a real
browser first and it leaves the layout EXACTLY as it was.** A negative row line
counts back from the end of the **explicit** grid; `chrome.css` declares
`grid-template-columns` and no `grid-template-rows`, so every row on the page is
implicit, row line `-1` **is** row line `1`, and CSS collapses a placement whose
two lines are equal to a one-row span. ⭐ **The defect survives it untouched.**

⛔ **So the span is a stated number, because nothing in CSS spells *every
implicit row*.** ⭐ **And the number is DERIVED AND JOINED rather than chosen:**
`page.html` declares ten top-level positions inside `<body>` — the masthead, the
eight slots and the script tag — which is the most grid items any page of this
framework can put in the reading column.
`tests/studyforge/render/pageassets/test_chrome_rail_rows.py` reads the span back
out of the stylesheet and asserts it against the skeleton's own count, so **a
slot added to `page.html` is a red check rather than a rail that stops short of
the page's last row and sizes it on the way past**.

### The arm that would have caught it, and it is a COMPARISON throughout

⛔ **No figure this row measured is written into any test.** Each clause opens the
same built page twice — once as built, once with the rail region cut out of it —
and asserts the reading column is laid out the same in both. ⭐ That is what *"the
masthead's row is sized by the masthead"* means operationally, and it is exactly
the brief's clause 2: *assert it as a comparison against the no-rail page, not
against a number you typed*.

⛔ **The fixture is WIDENED, and that is the row's second deliverable.** The gap
is the rail's overhang past the masthead, so it scales with the number of units
the reader's own container declares — and the reader's own container is the one
the rail leaves OPEN, which is why the page the arm opens must be inside it.
`tests/visual/test_rail_rows.py` copies a fixture corpus, carries its largest
container out to sixteen units, builds the whole site with `write_site`, and takes
every reading on a unit page inside that container.

⛔ **Two controls, because one of them is the answer to *why did this ship*:**

- the **no-rail** tree — the same build with the region cut out, which is the
  reading column laid out alone and is what every comparison is made against;
- the **regressed** tree — the same build with the rail's placement rewritten in
  its own generated stylesheet back to the single row `W325` merged. ⭐ **Both
  wide clauses are asserted to go RED on it**, so the arm is shown to notice this
  row's actual defect rather than an impression of one.

## Decisions

### ⛔ The brief's fix was taken in SHAPE and not in spelling — and it says which

⭐ *"The rail spans the reading column's rows"* is exactly what landed. ⚠️ **What
was not taken is `grid-row: 1 / -1`**, for the measured reason above. ⛔ The
refusal is not left in prose: `rail_row_span` in the unit mirror reads `1 / -1` as
**no span at all**, and a parametrised control asserts both that spelling and the
one that shipped are refused — so a reader who reaches for it again meets a red
check rather than a page that still opens on blank.

### ⚠️ `test_chrome.py` went past its ceiling, and it was SPLIT at a named seam

⛔ **Measured: the module reached 618 lines against a 600 ceiling.** Ruling 261
says the answer is a split at a seam you name, never a trim. ⭐ **The seam:** every
check in `test_chrome.py` is a claim about `chrome.css` and the regions the tree
emits; the W326 clause is a claim about **two artifacts agreeing** — the
stylesheet's placement and `page.html`'s shape — and neither file can be read
alone to answer it. ⚠️ `test_chrome.py` is back at its pre-row length and not one
of its own checks moved, so `W325`'s clause→test table still resolves.

### ⭐ The browser arm is a NEW module rather than a widening of `test_rail.py`

⚠️ It needs a fixture no other clause in that package needs — a container with
many units — and building one per session in `test_rail.py` would make every
`W324`/`W325` clause pay for it. ⛔ **`tests/visual/ACCEPTANCE` therefore has an
eighth row**, which is how a clause is agreed to there: a browser-driving module
without one is refused by `test_init.py`.

### ⛔ The comparison is made on the masthead and the element after it, and no further

⚠️ **Not a trimmed claim — a true one.** A grid item stretches to its row and
margins between grid items do not collapse, so further down the page the
two-column layout and the one-column layout differ for reasons that are grid's
and not this row's. ⭐ The defect is about **where the reading starts**, and the
clause about the rows past the first is made the other way instead: the rail's
computed span is asserted to be at least the number of grid items the reading
column has, read off the live layout.

### ⭐ The widened unit inherits its `origin` rather than being given one

⛔ **Measured: writing that key made `W95`'s sweep red.**
`tests/studyforge/corpus/container/test_origin_sites.py` asserts the tree holds
one declared reader and one declared writer of `origin`, and a fixture builder
that set it was a second writer nobody declared. ⚠️ The added unit copies the
entry it was cloned from; nothing in this row reads the value.

## Surprises

- ⚠️ **`grid-row: 1 / -1` does nothing on this grid**, and it is the repair the
  office that found the defect named. ⛔ It was measured in a browser before a
  line of the fix was written, and the measurement is what sent this row past it.
  ⭐ **This is the general shape and it is worth carrying:** `-1` counts from the
  end of the EXPLICIT grid, so in a grid whose rows are all implicit it is a
  synonym for `1`.
- ⚠️ **The widened container has to be the OPEN one or the fixture proves
  nothing.** The rail opens the reader's own container and closes the others, so
  a page in a small container beside a large one shows a SHORT rail. ⭐ The
  builder returns the address it widened and the arm opens a page inside it.
- ⚠️ **On the two-column page `main`'s box is laid out taller than its content**,
  because a grid item stretches to its row and the row takes up the rail's
  overhang. ⛔ **Measured identical before and after this row**, so it is `W325`'s
  geometry and not this one's, and it is invisible today because `main` carries no
  ground of its own. Recorded as `W326/3`.
- ⭐ **Nothing about the page bytes changed**, so the committed goldens under
  `tests/fixtures/pages/` were not regenerated and were not touched — a layout row
  that had to re-render its fixtures would be a markup row wearing a stylesheet's
  name. The same sentence was true of `W325` and is the reason this repair is one
  token wide.
