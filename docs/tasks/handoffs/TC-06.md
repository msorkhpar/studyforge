## What landed

⭐ **`editor.image.tag` — what a consumer is holding when it pins.** `scheme` is the shape and
`parts` describes each part; `computed_by` is the command that prints one; `build_inputs` is the six
roots the digest reads; `moved_by` and `not_moved_by` are the two halves of what moves it;
`promises` and `does_not_promise` are what it is worth; `mutated_in_place` is `false` and
`why_it_cannot_be` says why; `how_to_pin` is the one paragraph a consumer follows, and it is
rendered into the reference compose file above the `image:` line.

⭐ **The tagging scheme was DOCUMENTED, not designed.** `plan.tag_for` already computed
`<repository>:<set>-<arch>-<12 hex of the inputs' digest>`, and the editor folds the runner's digest
and any prime's into its own. So the tag already encoded the toolchain set and its pinned versions,
which is what the epic asks for; what did not exist was any statement of what that buys a consumer.
⛔ **Changing the scheme here would have moved every tag for no reader's benefit**, so nothing under
`build_inputs` was touched and no tag moved.

⭐ **A top-level `releases` array — the short upgrade note per release.** One entry per `provides`,
newest first, each with a summary, a `re_verify` list and **`moves_every_tag`**, because a change to
the image and a change to this contract are different events a consumer acts on differently. Entry 1
is `TC-05`'s and says `true` (its entrypoint change moved every editor tag, as its own handoff
recorded); entry 2 is this one and says `false`. `findings()` refuses a `provides` bump that arrives
with no entry, and refuses a gap.

⭐ **Ruling 5 — the root filesystem stays writable — which is `W390/3` landed** rather than restated.
`editor.filesystem` declares the root writable, names `/opt` and `/etc` as paths a mount must never
make read-only, and says why: the entrypoint's `fixuid` repairs the passwd record at every start,
and the warmed practice caches under `/opt` are written by Gradle and Maven on every build. The
rendered compose file now carries an explicit `read_only: false` with that reason above it.

⭐ **Both acceptance clauses are measured, one on the host and one in containers.** A pinned version
bump is planted in a temporary copy of the build inputs and computes a different tag while the
original still computes the one already pinned; and two editor images from two declared sets are
brought up side by side, in two compose projects on two ports, both healthy, each wearing its own
set's label.

## Decisions

1. ⭐ **The keys went under `editor.image.tag`**, where `TC-05`'s `not_yet_declared` entry pointed,
   and that entry was removed in the same commit. The runner's hole is untouched and still named.
2. ⭐ **`provides` moved to 2; `consuming_api` did not.** Keys were ADDED for a consumer to read and
   no existing shape changed — `TC-05`'s own rule for which of the two numbers moves.
3. ⛔ **No literal tag in `consuming.json`.** `editor.image.tag.example` is a worked shape with a
   fabricated digest, and `how_to_pin` says in the same block never to pin one you did not compute.
   The only real tag anywhere is the one the build prints.
4. ⭐ **The release notes are keyed by `provides`** rather than by a date or a version line of their
   own, because `provides` is the number a consumer already reads; a second version would give two
   answers to one question (`TC-06/4`).
5. ⭐ **`findings()` grew three groups rather than a separate checker.** A consumer's refusal path
   was already `findings()`, the CLI already exits 2 on one, and the renderer already refuses to
   render one — so a tag block that claims to be mutable, or a `provides` bump with no note, stops
   in the same place a Docker socket does.
6. ⭐ **The second consumer's declared set is a SUBSET of the first** (`java` beside `java,maven`),
   so the acceptance costs the layers the set changes and not a second toolchain.
7. ⛔ **The scheme is checked against the tag the build plans, end to end** — `runner_plan.plan` and
   `editor_plan.plan`, no Docker — rather than against `tag_for`. The first attempt used `tag_for`
   and measured the wrong seam (*Surprises*).

## Surprises

⛔ **`TC-05`'s sibling branch was not on the sibling's `main`, although its handoff is on the release
branch here.** The two halves of that task merge separately and only one had. So this branch merges
`task/TC-05-compose-and-mount` and carries both; the register's pin move must land this tip, not the
sibling's `main` plus this task alone.

⚠️ **A duplicate runtime is REFUSED, not folded.** A test written to say *the set is a set, so
naming one runtime twice is the same image* was RED: `plan` raises `a runtime is declared twice`.
The clause now asserts the refusal, which is the stronger promise — a consumer that writes
`java,maven,java` is told, rather than quietly given an image it did not describe.

⚠️ **`tag_for` does not sort its names; `plan` does.** A test asserting the declared ORDER is not
part of the tag passed the names to `tag_for` and failed, because sorting happens one layer up. The
tag is still order-independent — through the seam a consumer actually uses.

⚠️ **The reference fragment's booleans needed YAML's spelling, not Python's.** Nothing had rendered
a boolean before `read_only`; `_scalar` would have written `False`, which `yaml` resolves but no
consumer should have to read. It lowercases them now, and `docker compose config` parses the result.

  `releases` — `provides` unchanged if you changed no key, `moves_every_tag: true`, and a
  `re_verify` list. ⚠️ `findings()` checks the SHAPE of that entry, not its truthfulness: whether
  every tag really moved is `editor.image.tag.build_inputs` and your diff.

  scheme with its own repository and its own two input roots. Add `runner.image.tag` beside

  the checker already takes a block and nothing in it is editor-specific.
- ⚠️ **For anyone reading a tag to learn the set: do not.** `editor.image.tag.computed_not_parsed`
  is the reason — the set is joined with hyphens and cannot be split back out unambiguously. The
