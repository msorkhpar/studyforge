## Decisions

⭐ **These are the ones fourteen tasks will copy, so each says why and not just
what.** Overrule any of them explicitly — copying a bad precedent silently is
the failure this section exists to prevent.

1. **The package is six modules, not one file.** Not because 499 lines needs
   splitting, but because R11's real test is the isolation question and these
   are four separate concerns with four separate test surfaces: what a slug
   *is*, one segment as code, an ordinal, and the address itself. §3.2 says
   every unit is "a package of focused modules, not a file" and this is what
   that looks like at the small end.
2. ⛔ **`parse_key(key, depth)` — `depth` is required, and there is no escape
   hatch.** The extraction source's `parse_key` always checked arity because
   the arity was always 2. The v1 generalisation is that the number is data,
   so making it optional turns a check that always ran into one that usually
   does not. A caller with no declared depth is not parsing a key it can
   validate; it should build an `Address` from segments and say so.
3. ⭐ **The digit prefix is `_`, not the inherited `c`, and this is a
   correction rather than a preference.** `c` fixes the collision it was
   written for (`01-basics` and `basics` must differ) and quietly introduces
   another: `c01-a` and `01-a` both become `c01_a`. `_` cannot collide with
   anything, because **no slug contains an underscore** — `slugify` turns one
   into a separator — so no slug can produce an identifier that starts with
   one. ⭐ **`identifier` is therefore injective over slugs, which is a
   testable claim and is tested**, including the two adversarial `c…` pairs.
   The inherited docstring says the point is that two slugs must not collide;
   this is that intent, held to.
4. **`unit_name`, not `unit_dirname`.** The extraction source's name was
   accurate there because the string was always a directory. Here it is an
   identity (R4) — a progress key, a served address, an editor task file, an
   embedded identity block, and *sometimes* a directory. ⛔ A name that says
   `dir` invites the next reader to assume this package knows about the
   filesystem, which is what R1 and R4 forbid it to know.
5. **`identifiers` is returned per segment and never joined.** How they join —
   a dotted package, a directory chain, a class-name prefix — is a placement
   decision, and SF-03 owns those. The extraction source returned
   `paths.<id>.<id>`, which is a placement decision living in the identity
   layer.
6. ⛔ **There is no constructor that accepts titles.** `Address.of(*segments)`
   takes segments and validates them; it does not slugify. A convenience that
   slugified would make "a title passed where a slug is required" a silent
   success — the exact failure `require_slug` exists to make loud, and the
   acceptance clause it would defeat.
7. **A JSON list is accepted and a tuple is stored.** Every archive document
   spells its address as an array, so `Address(doc["address"])` is the common
   construction; refusing a list would make every caller write the same
   conversion and one of them would write it wrong. ⚠️ A bare **string** is
   refused with a message about lists, because `Address("a/b")` would
   otherwise iterate into single-character segments and fail talking about the
   letter `a`.
8. **`unit-7` and `unit-007` are refused, not accepted-and-normalised.** Both
   parse to 7 and would be written back as `unit-07`, so two spellings of one
   unit would exist and compare unequal on every surface that joins these keys
   by string equality. `parse_unit_key` round-trips the name and refuses a
   mismatch.
9. **`AddressError` subclasses `ValueError`** — a divergence from the
   extraction source's `Exception`-based `LayoutError`. ⭐ **Proposed as a
   precedent, not assumed:** a *value* error ("you passed something I cannot
   accept") subclasses `ValueError`; a *document* error ("this file is not one
   I can read" — SF-06's `RawDocError`) subclasses `Exception`. Two kinds, two
   bases. If the CTO prefers one base for everything, this is a one-line
   change in six modules and better decided now than after fourteen tasks each
   pick.
10. **`bool` is refused as an ordinal** even though Python says it is an `int`.
    `True` would format as `unit-01` and file a whole unit's material under a
    flag somebody passed by mistake.
11. **Errors name the offending value with `!r` and the field it came from** —
    `require_slug(value, "address segment 2 of 3")`. `test_errors.py` asserts
    every entry point does this, in one table, so a new entry point that
    forgets is caught by being absent from the table.

## Surprises

- **The `depth` argument is where SF-01 and SF-02 actually touch**, and it is
  a smaller seam than the task made it sound. SF-02 owns the *declaration*
  (`levels`, and validating that it is a non-empty list of labels). SF-01 owns
  the *comparison* (is this address that shape?). Neither validates the
  other's half, and the only shared vocabulary is one integer. See *For
  dependents*.
- **§4's table is now two-thirds depth 1 by count of real sources** — SPARQL
  and ISO-8583 — and writing the tests table-first rather than function-first
  made that impossible to forget. Every parametrised test in
  `test_address.py` runs all six shapes; there is no test that runs only the
  two-level case.
- **Ruff was clean on the first run**, which it has not been for the last two
  tasks. The difference is that FND-03's image now exists, so the formatter
  ran *during* the work rather than at the merge gate. That is C5's fix
  working, one wave after it was diagnosed.

## Findings

⭐ Triaged, not filed. The test is: *would this happen again to somebody else?*

1. `[structural]` ⚠️ **OPEN — `slugify` is lossy and nothing detects a
   collision.** It is ASCII-only, so `café` and `cafe` produce the same slug,
   and two distinct titles can therefore claim one address. This is bounded by
   §6's ruling that an address is **recorded, never derived** — measured at
   157 of 1,290 units served at a slug their title does not produce — so the
   framework never derives one at read time. ⛔ But an **adapter** that
   slugifies its titles owes itself a collision check, and the framework
   cannot make one for it: by the time the framework sees an address the title
   is gone. This belongs to **SK-02 (adapter authoring)** and **SK-01
   (reconnaissance)** — the same skill that already detects C2's duplicate
   material is the one that should detect two titles claiming one slug. It is
   not SF-01's to build, and it will happen to every adapter author.
2. `[local]` — **`tests/support.py` has no assertion for "a package exports
   exactly this surface".** I wrote `PUBLIC_SURFACE` and its three tests inside
   `test_init.py`; the next thirteen packages will each want the same thing.
   ⚠️ Not extracted here because `support.py` is shared and FND-06 is currently
   editing that tree — the collision is real, not hypothetical. It is three
   functions and it should move when FND-06 lands.
3. `[local]` — **the skeleton's own contract text was already right.** FND-01's
   `address/__init__.py` docstring needed no correction, only extension. Worth
   recording as evidence that the skeleton docstrings are load-bearing rather
   than placeholders; the other thirteen should be extended, not replaced.

## For dependents

⭐ **Import from `studyforge.address` and nothing deeper.** If you find
yourself writing `from studyforge.address.address import …`, this package's
contract has failed and that is a finding against it, not a workaround for you.

**The five things you will actually want:**

| You need | Call | Note |
|---|---|---|
| an address from segments | `Address.of("basics", "01-getting-started")` | validates each segment is already a slug |
| an address from an archive document | `Address(doc["address"])` | a JSON list is accepted; a tuple is stored |
| an address from a key you received | `parse_key(key, depth)` | ⛔ `depth` is required — see below |
| the string for one unit | `address.unit_key(n)` | ⛔ **never compose this yourself** |
| that string read back | `parse_unit_key(key, depth)` | returns `(Address, int)` |

⛔ **Never assemble a key, a unit key or an identifier by hand.** The joined key
exists so two segments cannot be passed in the wrong order without a type
saying so, and that guarantee is void the moment a caller re-derives it. The
extraction source records the unit-key case having already gone wrong once: the
keys are joined by string equality across surfaces that never see each other —
the page writes a read mark, the index reads it back, the run route names a
workspace — so a second spelling differing by one character simply never
matches anything, **with nothing failing anywhere**.

### ⭐ SF-02, and everyone who touches depth: where arity is validated

The boundary is decided and it is one integer wide.

- **SF-02 owns the declaration.** `levels` is a non-empty list of level labels;
  `len(levels)` is the corpus's depth. Validating that `levels` is well-formed
  — non-empty, strings, no duplicates if you rule that — is SF-02's, and SF-01
  never reads a manifest.
- **SF-01 owns the comparison.** `parse_key(key, depth)` and
  `address.require_depth(depth)` are the only places an address is checked
  against a declared depth, and they take the number as an argument.
- ⛔ **Do not re-implement the comparison.** If you have an address and a
  manifest, call `require_depth`. A second arity check with a different message
  is how two tasks come to disagree about which one is authoritative.

### Depth 1 is the common case

Two of the four designed shapes are one level — SPARQL's `["course"]` and
ISO-8583's `["group"]`. Every parametrised test here runs all six shapes,
including a synthetic depth 3 and 4, and there is deliberately no test that
exercises only two levels. ⛔ If your task's tests only have a two-level
fixture, that is the defect this project has already made twice.

### For SF-03 (placement)

`address.identifiers` gives you one identifier per segment and **does not join
them** — joining is your decision, not this package's. `unit_name(n)` gives you
`unit-07`; whether that becomes a directory is also yours. ⚠️ The identifier
form is injective over slugs, so two addresses can never collide in a source
tree; if you need that property, it is tested here and you can rely on it
rather than re-deriving it.

### For adapters (E07, and any second source)

`slugify(title)` is available and it is the **only** thing in this package that
turns prose into an identity. ⛔ Use it once, at ingest, **record what it
produced**, and address everything from the recorded value thereafter — §6:
*an address is recorded, never derived*. ⚠️ It is lossy (finding 1): check your
slugs for collisions before you commit to them, because nothing downstream can.
