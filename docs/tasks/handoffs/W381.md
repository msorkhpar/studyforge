## What landed

- ⭐ **(a) Host execution is now a partial state of its own, `host`.** It is reported when the corpus declares exercises, the served instance offers the `run` namespace, and `execute`'s `ModeProbe` answers `HOST`. The lines say that Run and Submit execute on this host without the runner's isolation, that everything works, and that the remedy is to start the runner container as `code-server-toolchain`'s README documents and then serve again.
- ⭐ **The probe comes from `execute` and is not copied.** `probe_for(root, source)` returns `execute.ModeProbe(root, execute.container_for(source))`, which uses the same container name and root that `serve.routes.runs.runner_for` gives a run. `states.py` does not spell `docker` anywhere except the one `docker inspect` in its docstring.
- ⭐ **(b) `NO_TOOLCHAIN` is removed, together with its test.** The ruling's condition was checked first. Both served forms take their namespaces from `serve.instance.namespaces_of`, and that function always includes `run`. No served form can lack the namespace, so the state described something the skill can no longer produce.

## Decisions

- **`exercise_states(declared, namespaces, probe)` has no default probe.** A default would let a caller skip the question silently. The probe is asked lazily, so a corpus that runs nothing never starts `docker inspect`.
- **`host` requires declared exercises** as well as the `run` namespace. A corpus with nothing to run has nothing that could run on the host, and it already reports `exercises` as finished (C5).
- **`run.py` and `__init__.py` were edited although the row names only `states.py`, its document and its tests.** `run.py` calls `exercise_states`, and nothing else in the package knows the corpus's `source` and root. `__init__.py` re-exports the states. Both edits follow mechanically from the ruling, and no other office in this wave has either file in its surface.
- **`test_thin.py` admits `studyforge.execute`.** Its closed import set would otherwise refuse the import the ruling requires. The admission is documented next to the others: it covers `ModeProbe`, `container_for` and `HOST`, and the skill still never starts, stops or enters a container.
- **The probe is asked once, when the site starts listening.** If the reader starts the container afterwards, the report is out of date. The remedy already covers this: serve again.

## Surprises

- The ruling's condition (b) settled in one direction: `namespaces_of` offers `run` unconditionally, and the only way a served site now lacks it is a test plant.
