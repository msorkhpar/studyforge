## What landed

- ⭐ **The diagnosis, and it is a POSITION and not a silence.** The absence notice was already printing on every host run — `lint: ruff is NOT installed, so this run carries no lint signal at all…` — and it was printing **above** `quality floor: clean`. That is the right place for a line qualifying *lint* and the wrong place for the one fact that decides whether a green may be handed back: the reader meets it before there is a verdict to misread, and has scrolled past it by the time there is. This is exactly the argument `W187/5` made for the scope line, applied to the half of the instrument that can be switched off.
- ⭐ **`lint_scope()` prints the same fact below the verdict, short, and as the last line an office copies.** Absent: `lint scope: this run has NO LINT SIGNAL — ruff is not installed here…`, naming both commands that did not run, that a green floor here is NOT lint-clean, that the two gates in `tests/test_repository.py` skipped rather than passed, and the one command that supplies the signal. Present: one clause saying the tool is installed, so the run HAS a signal, and that the signal is the `lint:` line above — which is a notice and never this verdict.
- ⭐ **The instrument is `shutil.which` and nothing else.** No invocation, no second run of a tool the notice above has already run, no new dependency and no new gate. The floor's exit code is identical in both states, so Ruling 77 stands: a floor whose verdict moved with `pip install` is the fix this row was not allowed to make.
- ⭐ **`FLOOR_IN_IMAGE` is the whole command** — the wrapper plus `python3 -m tools.quality`. `docker/dev/check` on its own runs nothing, and an office told only *"use the image"* still has to choose what to run in it.

## Decisions

- **The tail is two lines, and lint is the last of them.** `SCOPE` (`W187/5`) says the suite is a separate gate; it says the same words whether the run had a lint verdict or none, so it cannot be the line that distinguishes the two hosts. `lint_scope()` is that line, and it goes last because the state it reports is the one an office was measured to act on wrongly. Both stay **below** the verdict, which is all `W187/5` asked for, and `format_findings` is untouched — the verdict token is still exactly `quality floor: clean`.
- **`lint_scope()` takes no root and runs nothing.** Whether the tool is installed is the whole question at this position; what it *said* is the notice's job. Running the tool again to write the tail would double the floor's lint cost to learn something `shutil.which` settles.
- **Neither branch of the line claims a verdict**, which is what keeps it true in all four of `lint_notice`'s states — including the fourth, where the tool is installed and will not answer. It says *installed* and points at the notice; it never says *clean* and never says the checks ran.
- **The absence notice itself was left alone.** It still ends `or run the pinned environment: docker/dev/check`. Widening it to the whole command would be an improvement, but the line below the verdict now carries that command, and the row's subject is the position of the fact, not a second rewording of the notice.
- **`lint_notice` stays registered last in `NOTICES` and stays a notice.** Nothing was added to `CHECKS`.

## Surprises

- ⭐ **The disclosure an office needed was already being printed twice on the host**, not once: the notice above the floor's verdict, and the suite's own `unreachable population` line, which names the skipped ruff gates and the reason each gave. ⚠️ **Both were true, both were visible, and an office still handed back GREEN with the format check unclean** — which is the argument for position over volume, and against closing this row by making either of those lines louder.
- The pinned floor (`docker/dev/check python3 -m tools.quality`) already carries the linter, so the merge gate's declaration in `tools/gates.py` was never wrong about this; what was missing was any difference between the two environments' floor output visible to the office reading it.

## For dependents

- ⭐ **Anything that parses the floor's output must read from the end for `quality floor:`, not from the last line.** The last line now starts `lint scope: ` and the second-to-last is `SCOPE`. Nothing in `tools/` or `tests/` parsed the tail — the only consumers of the exact last line were `tools/tests/quality/test_main.py`, which this branch updates — but a future reader copying *"the last line is the verdict"* out of an older handoff will be wrong.
- ⭐ **An office certifying on the host floor alone now has the sentence it needs in the tail.** A hand-back that says the floor was GREEN while the tail said `NO LINT SIGNAL` is a hand-back that has not taken a lint reading, and the merge gate will take one for it.
