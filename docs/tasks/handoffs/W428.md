## Decisions

**`practice_origin` is a unit key in the CONTAINER MAP, not a key in the archive document.**
FND-04's ruling is that `origin` is provenance and provenance lives in the map; a second
provenance field in the other file would be the *two places to look for one fact* this project
keeps diagnosing. ⚠️ It also keeps the round trip honest: the region object replaces the string
**in place**, so `practice_origin` keeps its position in `UNIT_KEYS` and a map re-renders byte
for byte.

**The bucket is chosen by the document's `kind`, and by nothing else.** `practice_origin`
holds **all** of a unit's `practice` documents and **none** of its `lesson` documents. ⭐ That
is the only partition a corpus cannot get subtly wrong: it is already the archive's own word,
already what the section key is derived from, and already what decides whether a panel renders.
⚠️ The alternative — an origin per document ordinal — would have let a unit split one file
across two buckets, which is exactly the arithmetic the check exists to police.

**Both buckets are opened whether or not a document lands in them.** Opening a bucket only
where a document landed is the shape of the hole: a declared `practice_origin` that nothing
reads would be a source file counted by nobody, and `validate` would be silent about it. It is
now a short read against zero — observed, see *Surprises*.

**The version was minted rather than the key quietly added.** A build that cannot see
`practice_origin` sums both files' headings against one of them and reports a short read on a
corpus that is complete. ⛔ R9 says such a build must be **unable** to read the map, so a v2
map declaring the key is refused by name.

**A `practice_origin` with no `origin` is refused.** The key *means* "not the file the prose
came from". With no prose file there is no other file, and the one path belongs in `origin`,
where everything that places a page can see it.

**The practice files kept their names and lost a heading level.** ⚠️ `src/p1.md` is now the
`practice_origin` of a unit numbered 4, so its name says nothing about where it lands — and
renaming it would be churn in a file whose identity is already carried by the record. ⭐ What
did change is the heading level: the unit files open at `##` and section at `###`, so a
practice that opened at `#` would have printed a second page title. It opens at `###` and
sections at `####`, which is the level a reader expects of a section of that page.

**The corpus's `expected_units` no longer counts practices at all.** They add no unit, so
folding them in would make the audit's unit count answer a second question badly.
`ingest.practices.expected` is the count that would notice a practice vanishing, and it is
asserted by the corpus's own test.
