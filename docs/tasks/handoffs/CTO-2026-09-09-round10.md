### ⭐ The runtime-identity contract — CONFIRMED, and elevated to a convention

**This is the most valuable thing in the review and it was right to ask for it
explicitly**, because it constrains every gate written after it.

> ⭐ **A gate whose verdict is part of a published contract must be a pure
> function of its input.**

`assert_clean` is half of what `studyforge validate` promises an adapter (R2,
§6): a green/red signal *that depends on nobody's judgement*. ⛔ **A verdict that
differs by machine is not a contract.** Verified — the module imports exactly
`__future__`, `re` and `collections.abc`, so it structurally **cannot** reach the
environment, and an `ast` scan holds it there.

⚠️ **The mirror image is equally true, and that is why it is a rule rather than a
preference:** `FND-06`'s gate has the opposite subject — *this machine's* leak
surface — so refusing to look at the environment would make **it** useless. ⛔
Neither gate is a model for the other, and *"align them"* is the wrong instinct.

Written into `module-structure.md` as a table, including the ⛔ **do not align the
two email patterns** clause, so the next reader meets it before the duplication
looks like a defect.

### The prose-sweep divergence — ⭐ CONFIRMED, and its argument is decisive

⛔ ***Telling a source to phrase its lessons around our regexes is not
available.*** That single sentence settles it. `FND-06` can make the placeholder
bargain because the prose it sweeps is **ours to control**; the archive gate
cannot, because its subject is material somebody else wrote. Same rule, different
subject, opposite answer — which is the same shape as the runtime-identity split
and belongs beside it.

⭐ **And the live proof is the best kind:** writing *about* this gate turned the
floor red twice, because a comment spelled the token placeholder, which **is** the
shape. Two gates, one repository, catching each other. That is the belt-and-braces
discipline working rather than being described.

### The three surprises

1. ⛔ **The extraction source's token placeholder is a hole in its own gate —
   confirmed by running it.** Its placeholder is the keyword followed by eight
   unbroken `[A-Za-z0-9]`, which is exactly what the bearer pattern matches, so
   it matches the pattern it was written to satisfy; that gate stays green only
   via the identity skip. ⭐ **Second defect found in the extraction
   source by generalising it**, after the digit prefix — and both were found the
   same way: taking a stated intent seriously enough to test it.

   ⭐ **The response is the right one**: two of three placeholders chosen so they
   do **not** match their own shape (`/path/to/project`, `Bearer <redacted>`),
   and ⚠️ **the email one honestly cannot** — any email-shaped placeholder is
   email-shaped by definition. Verified: `contact@example.com` self-matches and
   is accepted only via the identity skip. ⭐ **One documented hole, named, with
   the reason it is irreducible** beats three undocumented ones.

2. ⭐ **Finding its own acceptance clause vacuous is the behaviour I most want
   copied.** *"This document is not refused"* passes on any clean document; the
   proof is the companion assertion that `json.dumps` of the **same** document
   **is** address-shaped. ⛔ A task that satisfies a weak acceptance as written
   has met the letter of a check that tests nothing — and this is the second time
   this project has caught that class (the first was `FND-04`'s negative fixtures
   being self-defending).

3. **Scrubbing `where` before formatting it into the refusal** is the
   exception-text rule from round 8 paying immediately, and in a place I did not
   anticipate: ⛔ a caller handing the gate an absolute path would otherwise make
   the gate emit the leak it exists to prevent.

## The two structural findings

### ⛔ A gate with no callers is green forever · ROUTE THE TABLE

⭐ **Same shape as *a skip every run reports is an untested claim*, and it gets
the same treatment.** A check that is never invoked passes every suite, forever,
and its coverage is invisible in exactly the way a green report always is.

> ⛔ **A check's coverage is part of its contract.** The task that adds a call
> site asserts the gate **is** invoked there — not that the data happens to be
> clean.

**PO: route the handoff's call-site table into the named tasks** — `SF-06`,
`SF-25`, E05, `SF-16`/`SF-17`, E07 — as a one-line acceptance clause each. ⚠️
Doing it as five clauses in five tasks is right and doing it as one central test
is wrong: a central list of call sites drifts from the call sites.

### The v1-output acceptance clause — ⭐ correct, and it is E10's

*"No generated file, log or report in the entire v1 output contains personal
data"* names an artifact that does not exist yet, so it cannot close in M1. ⛔
That is a mis-scoped clause, not a shortfall in `SF-08`.

**Ruling: it moves to the task that first produces a site directory, and E10
(`QA-01`) owns the v1-wide form.** ⚠️ It must not be quietly dropped in the move
— it is the only clause that checks the *output* rather than the gate.

## Ruling — the `FND-06` allow-list: ⛔ REFUSED

**Measured on the merged tip, three ways:**

| What was run | Hits |
|---|---|
| `FND-06`'s **shipped** check (`python3 -m tools.quality`) | ⭐ **0** |
| the rubric's **post-round-6** patterns | 4 |
| the rubric's **pre-round-6** patterns | **42**, including the E02 file it names |

⭐ **The coordinator's reading is exactly right.** The finding measured the
rubric's *older* patterns, and the E02 hit it cites is `n@router.get` — precisely
the false-positive class that round 6's two-character minimum eliminated. ⛔ **So
the allow-list is a mechanism for a hit that no longer fires**, which is X2's
shape for the third time in this project.

⚠️ **And the four post-round-6 hits are the second half of the argument**, because
the shipped check suppresses **all four** correctly: a lookbehind explained in a
comment, two reserved-TLD test fixtures, and the sanctioned personal-data
fixture. ⭐ The shipped check is not merely equivalent to the rubric's patterns —
it is **strictly better** than them on every case where they disagree.

### ⭐ So the structural fix, which is mine: the rubric defers

⛔ Two implementations of one rule is the duplication this project has now refused
five times, and this one had already produced a false finding. Rubric §1a is
replaced by:

```bash
cd "$TRIAL" && python3 -m tools.quality      # FND-06's sweep, the authority
```

§3a already defers to `FND-01`'s size checker for exactly this reason; this is
that, for R7. §1b is gone too — the shipped check does at run time what it asked
a reviewer to do by hand. ⭐ **What a reviewer still does is the part no checker
covers**: commit messages (§1c), the sanctioned-fixture judgement (§1e), and
§1d's question about where the rule is upheld in code.

⚠️ **Before building a mechanism for a class of failure, run the shipped check and
count.** A finding that a gate *"is not clean today"* must name **which** check it
ran and **what number** it got — otherwise it describes the patterns in a document
rather than the code that ships.

## Decisions

- **I refused the allow-list rather than routing it back.** The PO asked the
  right question and measured the wrong artifact; ⭐ the answer is a measurement,
  not a negotiation, and re-routing a settled empirical question costs a round.
- **I deleted rubric §1a's patterns rather than correcting them again.** Round 6
  corrected them once; a document that needs its regexes corrected every few
  rounds should not be holding regexes.
- **I elevated the pure-function rule to `module-structure.md` rather than
  leaving it in a handoff.** It constrains every future gate, and the two gates
  now in the tree disagree in a way that looks like a defect until you read why.
