## Decisions

- ⛔ **THE VERDICTS TRAVEL ON THE RUN'S STREAM AND THE `says` DOES NOT.** The
  page already carries every declared case's sentence, rendered by Python out of
  the corpus's own text (R1); a second copy on the wire would go stale the moment
  the corpus is regenerated, which is [`AX-01`](AX-01.md)'s and
  [`AX-02`](AX-02.md)'s own argument for recording the id. ⭐ So the line carries
  the **id and the verdict**, and the join happens in the page.
- ⛔ **The case line is TAKEN OFF the stream and every other line is shown.** It
  is the server talking about this run rather than the program's output, and the
  panel has already drawn it — leaving it in the log would show the reader the
  same thing twice. ⚠️ **The breakdown's own REFUSAL line is prose and still
  arrives**, which is the question `AX-02`'s handoff asked this row to answer.
- ⛔ **A population that does not match is shown as NOTHING.** Both directions
  are read — a declared case the run never named, and a name the panel never
  declared — because either alone lets a partial count through. ⭐ `AX-02`, *For
  dependents*, verbatim: a breakdown of a different practice is not *edge cases
  1/2*.
- ⛔ **The ungraded case says a SENTENCE, and that reverses what `SF-24`'s
  docstring said.** It read *"an ungraded exercise carries no line at all rather
  than a third sentence"*; spec §7 §9 was extended by `W389` afterwards and fixes
  four rows, the fourth being *Nothing here checks your answer.* ⭐ **A label is
  never omitted because it is unflattering**, and the spec is the authority.
- ⛔ **`is_quiz` is asked FIRST when choosing a label**, because a quiz's `graded`
  is `False` — `graded` means *a grader runs* — and reading it as *nothing checks
  this* would print the wrong one of the four (`AX-05`, *For dependents*).
- ⭐ **The quiz is its OWN section, `data-practice-quiz`, not the panel's
  `data-practice`.** The two shapes share a surface and not an element: nothing
  keyed on the panel's attribute — the maximise, the run, the output region —
  can reach a quiz by accident, and no rule had to be written for a part that is
  not there.
- ⛔ **`practice-quiz.js` does NOT ask `window.studyforge.run.available()`, and
  that is load-bearing rather than an omission.** A quiz grades with no compiler,
  no container, no network and no model (spec §7 §7), so the reading must be
  identical over `file://`; `practice.js` returns early when there is no origin,
  and a quiz inside that file would have worked only where a server happened to
  be. ⚠️ **There is a check that reads for it, so a later "tidy-up" that added
  the guard is RED.**
- ⛔ **The quiz writes NOTHING to browser storage, so a reload clears the
  answers.** A second, weaker record of *did this complete?* is the second answer
  `practice.js` refuses to keep for a run. ⚠️ **Recording a quiz's completion is
  a decision about the reader's own state** and is named as a finding below
  rather than taken here.
- ⛔ **The reference solution got NO new region, and that is the finding of the
  row rather than a gap.** `exercise.bundle.emit` already ships it as a
  `disclosure` block, which `page.blocks.prose` draws as a real `<details>`:
  closed until the reader asks, openable with scripting off entirely, and gated
  on nothing. ⭐ A region in the panel would have been a second place it could be
  withheld from. ⚠️ `REFERENCE_SUMMARY` is kept as the framework's constant and
  asserted, not re-spelled.
- ⛔ **Every word the breakdown and the quiz say lives in the TEMPLATES**, read
  back through `data-*` attributes — `W431`'s two-sided spelling, and the
  counting sentence is a pattern (`Edge cases {passed} of {total}.`) the script
  substitutes into rather than composes.
- ⭐ **`Done` and not `Passed` for a case mark.** `practice.js` already says
  *Passed.* for a RUN, and one word meaning two things on one screen is how a
  reader learns the wrong one. ⚠️ Caught by a check that reads the script for
  the breakdown's words.
- ⛔ **No new palette token and no invented green or red.** `--done` is the ink a
  finished thing is already marked in and `--accent` is the one that asks for
  attention; every verdict is a WORD first and the ink is a second signal, so the
  breakdown reads the same to a screen reader and in a high-contrast theme.
