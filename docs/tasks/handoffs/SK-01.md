## The four traps, and what stops each

| | trap | countermeasure | measured |
|---|---|---|---|
| 1 | the hierarchy is in filenames, not directories | find the document that **records** it; keep the prefix rule as a cross-check that must agree | ISO `src/`: 41 files, **0** directories, 3 prefix groups 16/11/11 — and `README.md` says the same three in the author's words |
| 2 | the same material twice | digest-exact concatenation, **and** heading-tree copies | ISO ships 3 aggregates covering 38 units; `README.md` lines 313–674 reproduce 361 of `TestCases.md`'s headings |
| 3 | a filename sort reverses the curriculum | the order is the document's, never `sorted()` | **37 of 38** ISO units land at the wrong index corpus-wide (**35 of 38** even group-by-group) — and unit 1 of each group still comes first, so the spot-check passes |
| 4 | heading level does not identify role | a label is *positional*: a line that introduces a run of entries and is not itself an entry | ISO: **21** top-level headings for a **3**-container corpus. Java: **0** headings for a **10**-section one |

⭐ **Both corpora fall out of the one positional rule and neither falls out of a
syntax rule.** That is the whole reason the rule is positional.

## Findings

⚠️ *`W25`, 2026-09-10: the triage markers below were added by the migration that made rubric §8a a build failure. Under Ruling 29 a finding **is** a marked item, so an unmarked one was unrepresentable rather than untriaged — which is exactly what this handoff shows. No wording is changed; every *structural* one still owes a routing.*

**41 `[local]` — the ordinal that *is* the list marker was silently dropped.** `_split`
stripped the whole list marker before looking for an ordinal, so
`1. [Title](src/1.md)` — ⛔ **the form every top-level entry of all three
measured corpora uses** — was read as unnumbered. Fixed in this task
(`BULLET_MARKER`, bullets only) with a negative control: reverting the one
expression re-reds the new test. ⚠️ It changed no level vocabulary, which is
exactly why it would have survived review.

**42 `[local]` — Markdown emphasis was being carried into titles.** **22 of ISO's 38**
recorded titles are written `**Like This**`, and the proposal showed the marks
to the reader. Fixed (`_plain`), and only when the emphasis wraps the *whole*
title: `**Basic** setup` keeps its marks, because removing those would be
editing the author's text rather than reading it.

**43 `[structural]` — depth could exceed the names available, and was silently truncated.**
Java's deepest linked ordinal has **4** components, which evidences 3 container
levels; `NESTED_LEVELS` has 2 names and the slice hid the difference. Now the
excess raises an `Uncertainty` instead of disappearing. ⚠️ **The underlying
question is real and is a person's**: whether `1.1.1.1` is a fourth container or
a heading *inside* a unit. The proposal still says `["section", "module"]`,
which is the answer the spec's table gives — but it now says it is unsure.

**44 `[structural]` — three inherited numbers were right at a scope the documents did not
state.** ⚠️ **Two of the three came from PO-Integration, so the integration
catalogue wants the same pass** — flagged there rather than fixed here, and
none of the three is a contradiction:

| 14 of 38 titles collide (36.8%) | **15 of 38 (39.5%)**, 7 slug classes | 14 are the mirrored server/client pair; the 15th collides *across* series |

⭐ The *lessons* are untouched, and the skill now states the scope with the

**45 `[structural]` — `exercises: true` for the Java corpus rests on 47 build files and 168

## What this skill deliberately does not do

- ⛔ **It does not decide the level vocabulary.** §4 rules the names are the
  corpus's own. It proposes the names real corpora chose and asks.
- ⛔ **It does not derive an address from a title.** `slugify` exists **only**
  to find collisions. §6 rules an address recorded, never derived.
- ⛔ **It does not widen a closed set on its own.** An unrecognised build system
  or suffix produces a named question, not a guess. ⭐ The cost of the closed
  set is exactly one question, and the question names what was looked for —
  which is also how the set grows.

## ⚠️ One correction carried in the skill, because the ruling was wrong

E10 says `slugify` collides on **accents**. ⛔ Measured: it does not — an accent
is a non-alphanumeric, so it collapses to a *separator*, and `Café`/`Cafe` give
`caf` and `cafe`. ⭐ The class that actually occurs is **punctuation**:
`'Streams: an API'` and `'Streams, an API'` both give `streams-an-api`. A skill
built for the accent case would miss the case that happens.
