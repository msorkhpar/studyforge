**Rule 1a is enforced mechanically, in one sentence of code:** the fixed
prefix of an entry — everything before its first `*`, `?` or `[` — must end in
`/`, or the entry must have no wildcard at all. So `docs/studyforge/*`,
`docs/**` and `src/notes/*.md` are accepted, `LICENSE` and `.gitignore` are
accepted as exact paths, and `[CLR]*`, `*.md`, `*`, `[A-Z]*`, `?ICENSE`,
`docs*/notes.md` and `docs/study*/x.md` are refused. ⛔ **The refusal does not
reproduce the pattern** (R7, W19's rule), and there is a test asserting that.

## Decisions

1. ⛔ **`CONTESTED` is a classification, not a flag on the side.** Ruling 90
   says rule 3 is *"never a precedence"*, and the only way to make that true
   for **every** consumer — not just for `validate` — is for `classify` to
   refuse to answer `INCLUDED` or `NOT_MATERIAL` when both match. A boolean
   predicate beside a `classify` that still said `INCLUDED` would have left a
   precedence in place for anybody who did not call the predicate.
2. ⛔ **That obliged one line in `edits.py`.** `_reject_forbidden_target` asked
   `classify(...) is Classification.INCLUDED`; without the change, a
   `CONTESTED` path would have become an editable target and R3's check would
   have gone quiet on precisely the file nobody has decided about. ⚠️ It is in
   the diff because I changed the contract it reads, not as scope.
3. ⛔ **A `content` key may not be used under a version that did not have it.**
   The task's acceptance asks for `not_material` at `corpus_api: 1` to be
   *refused by name*, and it is: `CONTENT_KEY_VERSIONS` in `document.py` maps
   the key to the version that added it, and the refusal names both numbers.
   ⭐ A map rather than a branch, because the second entry is the one that gets
   written as a branch beside the first and then disagrees with it.
4. ⚠️ **`from_document` discarded the version it had just checked**, so a
   `Manifest` always reported the default. While `KNOWN_CORPUS_API` held one
   number that was true by coincidence; at `{1, 2}` a manifest declaring `1`
   would have reported `2`. `_check_version` now returns the checked value and
   the `Manifest` carries what the corpus declared. ⭐ Asserted both ways.
5. ⛔ **`KNOWN_CORPUS_API` is spelled `frozenset({1, 2})`, not
   `{1, CORPUS_API}`.** A set derived from the writing version silently stops
   speaking `2` the day somebody writes `3`, and R9's refusal for `3` has to
   stay exactly as sharp as it is today — which the mutant `M4` below tests
   from the other side.
6. ⚠️ **`content.py` was tightened, not split.** It came out at 413 lines; I
   removed 13 lines of docstring repetition rather than making it a package,
   and it now sits at **exactly 400 of 400**. ⭐ The reason is Ruling 100's own
   context: the board's sequencing note for this row states, as a measurement,
   that `SF-35` *"adds no module"*, and `W40`'s licence was granted against
   that. ⛔ **So the split is owed to the next task that adds a line here** —
   filed as `SF-35/1` rather than left implicit.

  Ruling 98 between them decided every question this task could have asked,
  including the two I expected to have to escalate: what `README.md` is, and
  whether rule 3 is a precedence.
- ⚠️ **The acceptance clause *"a manifest declaring `not_material` at
  `corpus_api: 1` is refused by name (R9)"* asks for something neither ruling
  spells out** — R9 refuses *unknown* versions, and `1` is known. I read it as
  written (a v2 key under a v1 declaration is refused, naming both numbers)
  because the alternative reading makes the clause vacuous, and because the
  version is the corpus's statement of which contract it was written to. ⛔ If
  the CTO meant something narrower, this is the sentence to correct.
- ⚠️ **`why_excluded` has no consumer in the tree today** and neither does
  `why_not_material` — the audit's retrieval half is written and tested but
  nothing reads it yet. Recorded rather than trimmed: a `why` nobody can
  retrieve is a declaration nobody audits, which is the argument that makes it
  mandatory in the first place.
