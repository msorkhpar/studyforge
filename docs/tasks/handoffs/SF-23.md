## Decisions

**1. The three states are read off the structure and there is no `state`
field.** `state_of(None)` is `none`; a practice document with no `exercise` key
is `ungraded`; the key's presence is `graded`. ⛔ The common case therefore
writes nothing, which is what stops the contract being fitted to the one source
that ships 168 graders.

**2. `completes_practice(state, command, *, passed)` takes all three, and
`passed is True` rather than truthiness.** A runner returning `1` for "one test
failed" would otherwise complete the practice, and a shell exit code is exactly
that shape. It returns `False` for anything it does not recognise rather than
raising: this is asked on the completion path, and a caller that must catch an
exception to learn "no" will eventually not catch it.

**3. R5's rule is imported from `unit.trust`, never re-spelled.** SF-09 already
owns the vocabulary, the defaults and `FORBIDDEN`, and its own docstring says
*"SF-23 consumes it"*. ⭐ `test_record::test_the_rule_is_not_re_spelled_in_this_package`
drives the refusal from `unit.trust.FORBIDDEN` itself, so a pair added there is
covered here on the day it is added.

**4. `archive.document` depends on `studyforge.exercise`, and the direction was
checked rather than assumed.** The alternative — the object's validity checked
by each consumer — leaves R5 depending on somebody remembering, and there are
at least two consumers (`validate` and any renderer). ⚠️ The import chain
`archive.document → exercise → unit.trust → unit.content → archive.blocks` was
**probed for a cycle before a line was written**; there is none, because
`archive/__init__.py` imports nothing.

**5. Every field is required except `trust`.** The key's presence means graded,
and graded means a workspace **plus** a grader; a record missing `test_command`
is an ungraded exercise wearing the graded key, for which the contract already
has an answer — write no key at all.

## Surprises

**A test found a rule the design missed, and it is worth naming because the
design looked complete without it.** `SAFE_ARGUMENT` permits `/`, because a real
command carries `-pl practice/basics-01` — so an *absolute* path passed as an
argument was accepted. See finding 25.

**The failing SF-02 test was the instruction.**
`test_build_reproduces_every_committed_document_byte_for_byte` asserts that the
committed fixtures collectively exercise **every** optional key. Adding
`exercise` to `OPTIONAL_KEYS` turned that test red, and the only way to make it
green was to ship the fixture — which is exactly what the PO had ruled
independently. ⭐ A test that tells you what to build next is worth more than
one that tells you what you broke.

## Findings

### 25 `[local]` — an absolute path was legal as a *command argument*. Fixed here.

**Measured:** `require_command(["/home/<name>/private/run.sh"], …)` was
**accepted** — the token matched `SAFE_ARGUMENT`, which permits `/` because
`-pl practice/basics-01` needs it. Found by
`test_safety::test_a_command_refusal_never_reproduces_the_argument`, which was
written to check a refusal's wording and instead discovered there was no
refusal.

⭐ **The fix refuses more than the R7 case, and the wider reason is the better
one.** `/usr/bin/mvn` carries no identifier and is refused too: a command runs
in a pinned toolchain image (spec §8.1) where the program is on `PATH`, so an
absolute path is a fact about the machine that wrote the record rather than
about the corpus, and a build depending on one is not reproducible (R10).
⚠️ `./gradlew` stays legal and has its own negative control — a rule that
refused it would be refusing correct material.

### 28 `[structural]` — `user` + `authoritative` is **accepted**, and I did not change it

**Measured**, pinned, 2026-09-09:

```text
FORBIDDEN = (('generated', 'authoritative'),)
  bundled    + authoritative -> ('bundled', 'authoritative')
  generated  + authoritative -> REFUSED
  user       + authoritative -> ('user', 'authoritative')
```

So a grader **the reader wrote themselves** may declare itself the source's
own. ⚠️ R5's sentence is *"nothing generated is presented as more authoritative
than it is"*, and a `user` grader is not the material's grader either — spec §7
says an authoritative grader is one that *"shipped with the material and passes
the gates"*, which `user` by definition did not.

⛔ **Not changed here, and that is the point.** `unit.trust` owns the rule
(decision 3), E06's acceptance names only the `generated` pair, and my own
belief that the set should be `AUTHORITATIVE_PROVENANCE = ("bundled",)` is an
argument, not a measurement. ⭐ Following the existing decision and reporting
the disagreement is what Ruling 23 was decided on.

**Owner:** CTO. The change, if wanted, is one entry in `unit.trust.FORBIDDEN`
and nothing else — this package drives its refusal from that tuple, so it
follows automatically and `test_the_rule_is_not_re_spelled_in_this_package`
already covers the new pair.

## For dependents

**`SF-24` (practice panel)** — ask `state_of` before rendering anything that
implies a grade, and `exercise.authoritative` before rendering a badge. ⛔ A
`none` unit gets **no practice affordance at all**, not disabled ones. The two
commands are `RUN` and `TEST`; `TEST` is what the page calls **Submit**, and
`completes_practice` is the only thing that may mark a practice done.

**`E08` / the Java exercise generation** — a generated grader is written into
**this same document**, and it may only ever write `advisory`. `to_document`
gives you the exact bytes; `require_path` and `require_command` tell you
whether what you generated is writable *before* you write it.

**Any adapter** — an `exercise` is written on a `practice-M.json` and nowhere
else, all six fields, commands as **argv lists** and never strings, paths
relative and inside the workspace. ⛔ And a key the archive format does not
define is now **refused**: if you were carrying extra keys through, they were
being silently ignored and now fail loudly.

**`SF-25` on its rebase** — `validate` gains the whole of this for free through
its walk: `parse_document` raises `ArchiveError` and `validate/corpus.py`
already turns that into a `document` finding, so spec §7's *"studyforge
validate refuses the pair, exit 1"* holds with no change to `validate`. Worth
one assertion in `test_run.py` to pin it, and finding 27's one command.
