## Decisions

1. ⭐ **`tracked_readers` filters `tracked_python_modules`, rather than
   intersecting `document_readers`' output with the tracked set.** Intersecting
   would still `rglob` and `ast.parse` every file on the disk — including a
   nested checkout's — so the contamination would still cost the time and could
   still raise from a file that is not ours. The population is derived, then
   read.
2. ⭐ **The content is read from the WORKING TREE, not from the index**
   (`git show :path`). The population is a claim about the repository; the
   *contents* of a tracked file are what a reader would run. ⛔ The one state
   where those disagree — a tracked file missing from the tree — is refused by
   name rather than resolved silently either way.
3. ⭐ **`root` is a parameter on both helpers, for exactly one reason: Ruling
   11.** Without it the mechanism could only be watched working against this
   repository, which means writing plants into the tree the gate measures.
4. ⛔ **Two assertions added to the vacuity test, not one.** Sweep rows 3 and 4
   are the argument: a derivation that inverts its filter, and one that drops
   it, both keep every pre-existing assertion true. The anchor kills the first,
   the strict subset kills the second.
5. ⭐ **The `.gitignore` amendment names ruff FIRST**, because ruff is what fired
   for `SK-08` and it presents as a lint failure in the branch — the reading
   that cost that author a 15-row sweep. ⛔ **Ruling 153's "artifacts, never a
   checkout" is POINTED AT, not copied** into `.gitignore`: the rule lives in
   `agent-protocol.md`, and a rule written in two places goes stale in the copy
   nobody re-measures.
