## What landed

- **The liveness test, and it is exact (clause 1).** pytest writes `.lock` into every
  numbered run directory and removes it when the process exits; the file holds the
  owning **pid**. `judge` reads that pid and asks `os.kill(pid, 0)`. A lock whose holder
  is alive is `IN_USE` **however old the directory is** — which is the reading the
  refused merge was missing, because a forty-minute suite owns a directory that has
  looked stale for twenty-five of them.
- **Age is kept, and demoted to what it actually is.** The fifteen-minute grace survives
  as `DEFAULT_GRACE_SECONDS`, but it is consulted **only** for a directory no live
  process holds, and the module says in its own docstring that it is a belt and never
  the safety property. A run started with `tmp_path_retention_policy=none` writes no
  lock at all; that blind spot is recorded in the module and in the office rules rather
  than discovered later.
- **The command reports counts, never paths.** Run directories live under
  `pytest-of-<account>`, so a path printed here would carry the host account (R7). The
  report is a headline figure plus one line per verdict a directory was kept under.
- **Scope is by owner, not by name.** `run_directories` filters `pytest-of-*` roots by
  `st_uid`, so "your own" needs no account name read anywhere, and symlinks
  (`pytest-current` and its siblings) are never candidates.
- **The office rules say it in one command.** [`docs/conventions/agent-protocol.md`](../../conventions/agent-protocol.md) now
  carries `python3 -m tools.pytesttemp`, names `find … -mmin +15 -delete` as OUT, and
  records why.

## Decisions

- **A liveness test, not a private temp root per run.** A private `--basetemp` was the
  other candidate. `W375/3` measured three tests in the serve CLI going RED under one,
  because they bind a Unix socket inside the temp root and the longer path exceeded what
  `sun_path` can hold. A liveness test moves no path and costs one signal.
- **The rule was not made stricter; it was made expressible.** *Never one in use* did
  not change. What changed is that an instrument can now answer it, so the rule stops
  depending on an office guessing which directory a neighbour is inside.
- **`EPERM` answers *alive*.** A pid this account may not signal is a pid that exists.
  The conservative reading is the only safe one when the cost of being wrong is a
  refused merge.
- **`_pytest.pathlib` is not imported.** Its cleanup helpers are private API and its own
  lock timeout is three days. The rule is four lines; it is written out here where it
  can be read and tested.
- **`REMOVABLE` is not printed twice.** Its count is the headline figure; a second copy
  in the per-verdict list could disagree with it.

## Surprises

- **pytest's own cleanup would never have caused this.** It already honours the lock;
  its retention keeps the three newest run directories and treats a lock as dead only
  after three days. The defect was entirely in the hand-rolled `find` the office rules
  invited, not in pytest.
- **A dead pid is harder to fabricate honestly than a live one.** The test starts a real
  child, waits for it and uses its pid, rather than picking a number.

## Findings

### `W398/1` `[structural]` — nothing in the repository ran the cleanup, so nothing was measuring it

The fifteen-minute rule lived only in the wave's dispatch text, never in a tracked
document, so no gate could see it and no office could test it. That is why the defect
reached a merge gate before it reached a test. The rule now lives in
[`docs/conventions/agent-protocol.md`](../../conventions/agent-protocol.md) and the
instrument in `tools/`, where both are tracked. ⛔ Not fixed further and outside this surface: no gate *runs* the sweep, and
this row does not argue that one should — an office runs it, as the office rules say.

### `W398/2` `[environment]` — a lockless run is invisible to every instrument, ours included

`tmp_path_retention_policy=none` makes pytest skip the lock entirely. No liveness test
can see such a run, so the office rules now say not to use that policy. Recorded rather
than guarded, because guarding it would mean this sweep refusing to run whenever any
neighbour *might* have set it, which is not a reading anything can take.

## For dependents

- ⭐ **Clear temp directories with `python3 -m tools.pytesttemp`.** `--dry-run` prints
  the same verdicts and removes nothing; `--grace SECONDS` moves the belt, and `--root
  DIR` points the sweep at a temp directory other than pytest's own.
- ⛔ **Do not hand-roll a `find … -mmin` variant.** It is not a smaller version of this
  check; it is the check the refused merge was taken with.
- The verdict names (`IN_USE`, `TOO_YOUNG`, `REMOVABLE`, `UNREADABLE`) and `judge` are
  the API to read if a gate ever wants to disclose what it would have removed.
