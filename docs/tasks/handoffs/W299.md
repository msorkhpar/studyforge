## Decisions

### ⛔ RULED: `headings` is EXPORTED, as `headings`, shadowing its own module

⭐ **The row said any of rename, qualify, or leave-off-surface is acceptable if
argued, and none is acceptable if silent. This is the argument.**

⛔ **Ground 1 — it is this project's STANDING SHAPE, measured, not a novelty.**
At `5fca2ea`, **twelve** `(package, name)` pairs in `src/` already export a
callable whose name is one of that package's own modules: `address.identifier`,
`contents.order`, `contents.status`, `corpus.discovery.assemble`,
`corpus.discovery.freshness`, `corpus.discovery.scan`, `generate.containers`,
`skills.adapter.scaffold`, `skills.delivery.export`, `skills.onboarding.onboard`,
`skills.personalarchive.export` and `skills.reconnaissance.survey`. ⚠️ **Refusing
it here would make `validate` the exception to a convention twelve packages
already keep** — and would do so to avoid a cost those twelve already pay.

⛔ **Ground 2 — the shadowing hides nothing, and that is measured too.** The
binding rebinds the PACKAGE attribute and never touches `sys.modules`, so
`from studyforge.validate.headings import count_headings, region` still
resolves, the module keeps its name, and the exported function is the module's
own object rather than a copy. ⭐ Both halves are asserted in the mirror, so the
claim is not resting on this paragraph.

⛔ **Ground 3 — both renames reach OUTSIDE this row's surface, and that is the
decisive one.** Renaming the FUNCTION reaches into `skills.reconnaissance`: its
import, its call site and its contract prose. Renaming the MODULE reaches into
that package *and* `corpus.container`, whose own contract names
`validate.headings` in prose. ⚠️ **The brief holds this row inside `validate`
precisely because a sibling row owns the tree-wide version**
([`W300`](../rows/W300.md)), so a remedy whose diff lands in two other packages
is the wrong remedy for this row regardless of its merits.

⛔ **Ground 4 — leaving it off-surface was refused because it is not neutral.**
It would permanently license `skills.reconnaissance` to reach past this surface,
which is the exact defect [Ruling 101](../../conventions/module-structure.md)'s
producer half names. ⭐ A declared exemption is still a declared defect
([`W199`](W199.md) ruled this, and this row inherits it).

⚠️ **THE COST, STATED RATHER THAN BURIED — and it is the first thing to attack.**
`import studyforge.validate.headings as m` binds the package ATTRIBUTE, so `m`
is the FUNCTION, not the module. ⛔ **This is a real trap and I fell into it:**
this mirror's own first draft used that form and broke immediately. ⭐ Three
things contain it: no module in the tree writes that form (measured — every
caller uses a `from` import), the contract says so in the package docstring, and
the mirror now asserts it, so the behaviour is pinned rather than discovered.
⚠️ **The cost is not new either** — all twelve existing shadowing packages
behave identically, measured at the same ref.

### ⭐ The four remaining names were a line each, and deliberately only a line

⛔ **No taker's import spelling was changed.** Ruling 101's table says a name on

## Surprises

- ⛔ **The collision turned out to be already-settled precedent, not an open
  question.** The row frames `headings` as needing a ruling because it is
  unprecedented; measuring first found twelve instances of the same shape
  already on surfaces in this tree. ⭐ **The ruling was still owed** — the row is
  right that it must not be closed by whichever spelling a taker preferred — but
  the argument it needed was a census, not a design debate.
- ⚠️ **The sharp edge is `import … as`, not the attribute expression.** The
  hazard I expected to document was reading `studyforge.validate.headings` after
  an import statement. The one that actually bites is the `as` form, because it
  looks like it is binding a module and silently binds a function. ⛔ It cost me
  a broken mirror before it cost a reader anything, which is why it is asserted.
- ⭐ **Adding to `__all__` alone would have met the row's letter and weakened its
  spirit.** With `OFF_SURFACE` empty, the sweep is the only thing holding the
  five on the surface, and it is conditional on a consumer's spelling that a
  later row is *supposed* to change. The surface pin exists because of that.

## Findings

- `W299/1` `[structural]` — against [Ruling 101](../../conventions/module-structure.md) and [`W300`](../rows/W300.md). ⛔ **Ruling 101's two remedies are in tension, and nothing says so.** Its table tells a consumer to import from the package once the name is exported; doing that removes the name from the only sweep that holds it on the surface, because such a sweep is defined over cross-package submodule imports. ⭐ **A surface pin must land before the spellings are fixed, or the fix silently un-asserts what it was cleaning up.** Not fixed here: the spelling change lands in three other packages, which this row is scoped out of. ⚠️ **`W300` should take the pin first and the spellings second.**
- `W299/2` `[local]` — against the twelve shadowing packages named in Decisions. ⛔ **`import a.b.c as x` binds the callable, not the module, on every one of them**, and no instrument in the tree asserted that anywhere until this row asserted it for `validate`. ⚠️ It is currently harmless — measured at `5fca2ea`, no module in `src/` or `tests/` uses that form on a shadowed name — but it is an unasserted property of eleven other surfaces, and `test_the_shadowing_binds_the_callable_in_the_as_form_too` is the shape that would generalise.
- `W299/3` `[structural]` — against `validate`'s remaining takers. ⛔ **Four names ON this surface are still imported by their submodule spelling** — `UNUSABLE` from `validate.cli`, and `INVALID`, `OK` and `Finding` from `validate.report` — across `cli.dispatch`, `cli.narrate`, `cli.plan`, `cli.serve`, `cli.site` and `skills.buildserve`. ⭐ These are Ruling 101's FIRST row, not its second: the surface is right and only the spelling is a deviation. Not fixed — every line is in another package, and this is `W300`'s population.
- `W299/5` `[structural]` — against the release branch, not against any row. ⛔ **The pinned-image suite is RED at `5fca2ea`, the base every row in this wave was cut from**, because four ruff defects are in the tree and `tests/test_repository.py` enforces them wherever ruff is installed. ⚠️ **Measured at the base in a trial checkout, not inferred**: the same two gates fail with no row's changes present. ⭐ **The consequence is why it is filed against the branch rather than against any one row: every office in this wave inherits a RED suite it cannot certify away, and the honest reading is indistinguishable from a red one caused by real work** — which is precisely the signal self-certification depends on. ⛔ Not fixed here: all four files are outside this row's surface, and three of them are `tools/quality`'s. ⭐ Cheap to clear — three `D401` docstring rewordings and one `ruff format` run.
- `W299/4` `[local]` — against `corpus.placement`. ⚠️ **One package exports the MODULE under a shadowing name where twelve export a CALLABLE**: `placement.identity` is the module object, reached by `from studyforge.corpus.placement import identity`. ⭐ Legitimate and probably deliberate, but it means one spelling on this tree's surfaces carries two different kinds, and nothing records which a reader should expect.
