### ⛔ Coverage of *"every palette token"*, which is three checks and not one

⚠️ 27 colour tokens, and they do not all have the same job. `--fg` is text and
has a ratio; `--rule` is a hairline with no text on it; `--hl-bg` belongs to a
narration highlight that does not exist until M3. ⛔ **A check that walked "every
token" would silently cover the third it can reach and report success for all
27** — the shape of defect this whole task exists to catch.

1. **Every token resolves in both themes, and no token resolves the same in
   both** — the *"defined once, therefore wrong in one of them, invisible to
   whoever authored it"* failure `palette.css` names in its own docstring, taken
   from the browser rather than from the file.
2. **Every element painting text on a real page clears WCAG AA** for its size and
   weight, against the ground it actually sits on (walked up the ancestors,
   because a paragraph's own `background-color` is transparent).
3. **Every `MEASURED` token clears AA against its declared ground**, so
   `--tok-number` is covered even though neither fixture contains a numeric
   literal. ⭐ Both colours still come from the browser; the ledger picks the
   *pair*, never supplies a value.

⭐ Plus the other direction: **no text on either page is painted in a colour no
palette token defines** — an unstyled link at `rgb(0, 0, 238)` passes AA on a
light ground and would never be caught by a ratio check.

## Decisions

### ⛔ Shape 2, argued: the harness is host-run — and its state is `unpinned green`, **not** `host-verified`

⚠️ **The brief offered two shapes and named this the case Ruling 53 exists for.
I disagree, and the disagreement is the decision.**

Rubric §4b bounds `host-verified` by *the image is right to exclude the subject*,
and gives the tell as one question: **would the image's answer be wrong, or just
absent?** The three qualifying shapes are a check whose subject is the
**workspace**, the **image itself**, or the **host's own toolchain**.

⛔ **This is none of them.** The subject is how a page **this repository
generates** behaves in a browser engine. A Chromium inside the image would
answer the same question *better*, because it would be pinned. So the answer
there is **absent**, which §4b calls *"a gap to close"* — and *"a check that is
merely inconvenient in the image is `unpinned green`, and the image gap is a
finding with an owner."*

⭐ **So I claim the weaker state and file the gap.** `QA-03/1` is routed to
whoever owns `docker/dev/` (`TC-00`, `FND-03`). ⛔ **I did not touch that image**,
per the brief and per R21.

⚠️ **Shape 1 is the better end state and I am not arguing against it** — it is
simply not mine to make. What `QA-03/1` needs from its owner is one decision
about image size.

## Surprises

**⛔ `dash` cannot redirect from a two-digit file descriptor, and it failed only
under `pytest`.** The obvious way to put the pipe on fds 3 and 4 is
`sh -c 'exec 3<&N 4>&M; exec chrome …'`. ⚠️ `/bin/sh` on Debian — **and therefore
inside this project's own image** — accepts only a **single digit** in `n<&word`.
Run by hand the pipe ends land on fds 5 and 6 and it works every time; under
`pytest` the session already has files open, the ends land above fd 9, and the
shell dies with `Bad fd number`. ⭐ **The harness now does the `dup2` in Python
with `close_fds=False`**, because `subprocess` runs `preexec_fn` *before* its own
descriptor sweep and would otherwise close what the hook just made.
⭐ **It was found in one run rather than an afternoon because the browser's
stderr is kept**, which is now a permanent feature: `Browser.diagnostics()`.

**⛔ A settle timeout that expired and let the test proceed cost 10 seconds a page
and nothing noticed.** The first `_settle` polled for a copy button or a syntax
token. `depth1-unit-02` has no code block, so every open of the prose page waited
the full ceiling for something that was never coming — **and then passed**. The
visual suite took **122 seconds**; it now takes **2.9**. ⚠️ *A check that times
out and still says yes is a slow check that still says yes*, and neither a green
run nor an exit code shows it. The correct wait needed no list at all: `page.js`
is `defer`red, so it has already run by `load`.

**⚠️ `ruff check` and `tools.quality` disagree about line length, and the floor is
the stricter one.** `tests/visual/theme.py:93` was **102 characters** and ended
in `# type: ignore[arg-type]`. ⛔ **Ruff's E501 exempts a line ending in a pragma
comment; the standard-library floor does not** — so `ruff check .` returned *All
checks passed!* and `python3 -m tools.quality` failed the same file in the same
image. `QA-03/4`. ⭐ It is the exact inverse of the `SF-12` mutant the CTO found
that only `ruff F401` kills: **neither checker is a superset of the other, and a
review that runs one runs half.**

**⚠️ `--accent` and `--focus` are the same colour in both themes**, so inverting
"token → resolved colour" into "colour → token" silently drops one of them. A
`dict` inversion reported `--accent` as never painted, and the natural fix would
have been to *delete a check*. `theme.tokens_by_colour` returns a **set** per
colour. ⭐ Caught only because the token walk printed what it had seen.

**⭐ The negative-control discipline caught a bad mutant, not a bad harness.**
`M3a` — making the `:focus-visible` rule invalid — **SURVIVED**, and it should
have: Chromium's own default focus ring takes over, so the property under test
(*focus is visible*) still holds. `M3b`, which removes the ring outright, is
killed. ⚠️ **Recorded because "a mutant survived" and "the test is weak" are not
the same sentence**, and reporting only `M3b` would have hidden the difference.
