## What landed

**`docker/dev/Dockerfile`** installs Node.js **v24.21.0** (LTS "Krypton"),
pinned by **version and SHA-256 checksum**, per architecture.

| | |
|---|---|
| Version | `ARG NODE_VERSION=24.21.0` |
| amd64 | `6e1db87ef58b8819e5d5402eff1536491b18edd8eb7bee5ef7897876e88dc5ff` |
| arm64 | `724282c3b43aec998aa9527380465b45d229e021b58035f5f4f63095eabfe5d5` |
| Verified by | `sha256sum --check --strict` before anything is extracted |
| Selected by | `TARGETARCH`; an unrecorded arch **fails the build**, naming itself |
| Removed on the way in | `npm`, `npx`, `corepack`, headers, docs, man pages |

⭐ **Two-part pin, for exactly the reason the `FROM` line above it is pinned by
tag *and* digest**: the version says what it is for a reader, the checksum is
what makes the build reproducible. ⛔ `apt-get install nodejs` was rejected —
it would have reintroduced this task's own problem one layer down, with the
tests running and *what they ran against* depending on the day the image was
built.

⛔ **No package manager survives into the image**, and that is the stronger
guarantee rather than tidiness: with no `npm`, `network_mode: "none"` is not the
only thing standing between this suite and an unpinned tree of packages. The
grammars are vendored in `src/`; the runtime's only job is to execute them.

**Six new guards** in `tests/docker/test_dev_image.py` (static, no daemon, no
network): the version is pinned; the checksums are recorded and 64 hex digits;
an unrecorded architecture fails loudly; the runtime does not come from a
package manager; `npm`/`npx`/`corepack` are removed; and — the one that asks the
environment rather than a file — **the runtime is on `PATH` in here**.

### ⛔ And the change that stops the acceptance rotting

`tests/studyforge/render/pageassets/test_highlight_grammars.py::node()` now
**fails inside the dev image and skips only on a host**.

⭐ **The asymmetry is the whole of Ruling 21.** The pinned container is
authoritative *because it is pinned*, so a check that quietly does not run in
there turns green into a claim nobody made. On a contributor's host the same
absence is a stated partial state and stays a skip.

⚠️ **This is a deliberate edit to a file outside `docker/dev/`, and it is
reported rather than slipped in.** Without it, "8 skips" is true today and
silently reversible: anyone rebuilding the image without a runtime would get 38
quiet skips back and a green suite. The edit is four lines in one helper whose
current behaviour — skip, in the authoritative environment — is precisely what
Ruling 21 declared unacceptable. ⛔ The runtime itself did **not** arrive in
SF-12's branch, which is the coupling the separate branch exists to prevent.

## Decisions

**1. Node.js v24.21.0, the current patch on the active LTS line.** Not
"whatever `apt` has", and not a `latest` tarball. ⚠️ It was released two days
before this task; the LTS line's newest patch is the standard recommendation and
the pin makes the age irrelevant to reproducibility — what matters is that
resolving it twice gives the same bytes.

**2. `TARGETARCH`, so the pin is not secretly a pin to one machine.** A
hardcoded `x64` builds on this repository's hardware and fails on a
contributor's arm64 laptop, which breaks *"Docker and nothing else"* for
everyone it does not happen to fit. ⛔ An architecture with no recorded checksum
**fails**, and the message tells the reader to add a checksum rather than
install an unpinned runtime — because the person who meets it is on hardware
this repository has never built on.

**3. The `.tar.gz` rather than the `.tar.xz`.** The base image has `tar` and
`gzip` but no `xz`, so the compressed form chooses whether `xz-utils` has to be
installed and then purged. ⭐ One temporary package (`curl`) instead of two, for
a difference of a few megabytes of download at build time only.

**4. `curl` is installed, used and purged in the same layer**, so it does not
survive into the image. The download and its verification happen at **image
build** time, which is the same build/run split `pip install` already relies on
— `compose.yaml`'s `network_mode: "none"` is untouched and the run still needs
no network.

## Findings

### 30 `[local]` — my first version of the "not from a package manager" check fired on the correct implementation. Fixed.

**Measured:** `test_the_runtime_arrives_pinned_rather_than_from_a_package_manager`
matched the substring `nodejs` anywhere in the Dockerfile and failed on
`nodejs.org` in the download URL — i.e. on the *right* answer.

⛔ **A check that fires on the correct implementation is a check somebody
deletes**, and it would have been deleted for a reason that had nothing to do
with the rule it was guarding. Now scoped to the `apt-get install` lines, which
is what the rule was ever about. ⚠️ Same shape as SF-25's finding 18 — the
sibling-collision check that reported a non-defect — and it is worth noticing
that both were caught by a negative control rather than by review.

### 31 `[structural]` — the "8 skips" acceptance is a number no test holds

⚠️ Ruling 21's acceptance is a **count**, and nothing in the suite asserts it. A
future task can reintroduce a skip and no test will notice; the only thing that
would catch it is somebody reading `-rs` output.

⭐ **Partly closed here and deliberately not fully.** The 38 that mattered are
now structurally unable to return quietly — they fail in the image (measurement
2). The remaining 8 are *structurally* unfixable rather than merely unfixed:
5 would recurse, 3 need a repository that is not this one.

⛔ **A test asserting "exactly 8 skips" would have to run the suite inside
itself**, and would go red for any new legitimate skip — turning a useful signal
into a chore. **Owner:** CTO, if a mechanism is wanted. My recommendation is the
rule rather than the number: *no test may skip for want of a tool the pinned
image could install*, which is what the six new guards assert for this one.

### 32 `[structural]` — 121 MB of runtime for 38 tests, and the trade is worth naming

**Measured:** `du -sh /usr/local/bin/node` → **121M**; the image is now 399 MB.

⚠️ Not a defect and not free. The alternative was leaving 38 claims
uncertifiable, which Ruling 21 already weighed and rejected — *"did not run is
not evidence"*. ⭐ It is recorded here so the next person to add a runtime to
this image weighs it against **this** number rather than against zero, and so
that "the dev image is 400 MB" is a known fact rather than a discovery.

⚠️ One thing that would move it: the tests need a JS *engine*, not Node's
standard library, and the driver uses only `process.stdout`, `JSON` and regex.
⛔ I did **not** substitute a smaller engine — `node` is what the test already
looks for by name, and swapping the runtime is a change to SF-12's surface with
a real risk of subtle Prism incompatibility, for a saving nobody has asked for.
Named, not acted on.

### 33 `[local]` — the container cannot modify its own `/usr/local/bin`, which is the `user:` setting working

**Measured:** the first attempt at measurement 2 was
`mv /usr/local/bin/node /tmp/` inside the container →
`mv: cannot move … Permission denied`.

⭐ Not a problem — it is `compose.yaml`'s *"never root, and never a uid written
into a file"* doing exactly its job, and the proof was done through `PATH`
instead. Recorded because the next person who tries to prove something by
mutating the image will meet it, and the workaround is not obvious.

## For dependents

**`SF-12` (and anything vendoring a grammar)** — the 38 grammar tests now run in
the pinned container, so ⛔ **a grammar vendored without a sample is now a red
gate rather than a skipped one**. That is the whole point of this landing first
and separately: if the runtime had arrived inside SF-12's branch, SF-12's tests
would have been the first thing it ran and a green SF-12 would have certified
itself.

**Anyone refreshing the runtime** — change `NODE_VERSION` *and* both checksums,
from `https://nodejs.org/dist/v<VERSION>/SHASUMS256.txt`. ⛔ Changing the version
alone fails the build, loudly, which is the intended behaviour and not a bug to
work around. The guards in `tests/docker/test_dev_image.py` check the shape of
the pin, not its value, so they do not need touching.

**`E12`'s `code-server-toolchain`** — this runtime is the *framework's build
environment* and has nothing to do with a reader's IDE. ⛔ Do not read this as a
precedent for putting a corpus's toolchain in here; the Dockerfile's own opening
comment states the split and it still holds.
