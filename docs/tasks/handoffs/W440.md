## Decisions

1. ⭐ **The directory names are the keys of `runner.prime.seeds`.** They arrive as `seeded`, as
   before, and are the only names the prime's top holds. A tool the contract does not seed gets no
   directory. ⚠️ The contract does not state that a seed key IS the directory name. That is
   `W440/1`, below, and the sibling reading is what shows the inference is right today.
2. ⭐ **A project is rooted at the SHALLOWEST directory holding one of the tool's build files.**
   Every build file under it is kept (multi-module), and the specimens are taken from inside it
   only, re-rooted with their package path intact. ⛔ **Two builds at the same shallowest depth are
   refused, naming both**, because the component warms one project per tool and picking one would
   be a silent choice.
3. ⛔ **Exercise material is excluded by the framework's own layout names.** Everything under
   `exercises/` (`BUNDLES_DIRNAME`) is excluded. So is every `practice/<tail>/` workspace that a
   `bundle.json` on disk owns, because the two roots share one tail (`exercise.bundle.Places`).
   ⚠️ A `practice/` directory with no bundle is the corpus's own material and is still read, so a
   corpus whose own build sits under `practice/` is not broken by this.
4. ⭐ **A corpus that declares no seeded tool gets an empty prime and no refusal.** Before, a
   `python` corpus had a python specimen selected and copied into the prime. The component would
   have refused that directory, and nothing warms python. `EXECUTION.md` now says there is no prime
   and prints no `--prime`.
5. ⭐ **The flag comes from the contract.** `EXECUTION.md` printed a typed `--prime <relative
   path>`. The build runs from the component's checkout, so the relative path resolved nowhere.
   It now prints `runner.prime.declared_by` with `<this corpus>/…` in the slot, and a contract
   without that key is refused by the key it lacks.

## For dependents

### ⛔ `ISO-20` — the runtime set and the prime for jPOS 2.1.7

- ⭐ **Declare `java` and `maven`.** `maven` is a key of `runner.prime.seeds`, so the corpus gets
  `.studyforge/execution/prime/maven/`, and `java` gives it its specimens.
- ⭐ **Give the corpus ONE Maven build of its own, in Maven's standard layout**: a `pom.xml` with
  a real source under `src/main/java/` and a real test under `src/test/java/` beside it. Its
  directory becomes the project's root, and everything under it is copied at the same relative
  path. ⛔ **Its `pom.xml` must declare every dependency any exercise's build role names**
  (`org.jpos:jpos:2.1.7` and the JUnit you choose). Exercise poms are NEVER swept in, so a library
  only an exercise declares is never warmed, and that exercise fails `G1`.
- ⚠️ **Where it sits:** anywhere except under `exercises/` or inside an exercise's workspace. A
  second `pom.xml` at the same depth elsewhere is refused by name. Nest it as a module, or remove
  it.
- ⚠️ **The smallest `.java` under that build's directory is the specimen.** Keep the build's
  directory free of loose `.java` files outside `src/`, or the warm refuses the prime (`W440/3`).
  The ISO corpus's current `practice/<name>/*.java` files are outside any standard layout, so do
  not root the build at `practice/`.
- ⭐ **Then build from the component's checkout** with the flag `EXECUTION.md` prints, the full
  path in the slot, and pin the tag `tag_from` prints for the same argv.
