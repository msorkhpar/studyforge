## ⛔ First: my round-8 miss, reproduced exactly

⚠️ **The diagnosis I was given is not what happened, and I checked before
accepting it.** The suggestion was that my compensating run *"was not what
`./docker/dev/check` runs"*. It was: `tests/test_repository.py` shells
`ruff format --check .` from the repository root, which is exactly what I ran, at
the same pinned version.

**What actually happened, measured:**

| | |
|---|---|
| `686cc9f` — the base I reviewed against | **red**, 1 file (`SF-01.md`), 107 formatted |
| `feat/SF-02-corpus-manifest` | ⭐ **contained the fix** — its diff un-aligns those four comments |
| my trial merge of the two | **green**, 122 formatted — *correctly* |
| release tip today | green, 123 formatted |

⭐ **So the run was sound and the number was right. The sentence was wrong.** I
wrote *"SF-01's format follow-up has landed; round 7's outstanding item is
closed"* — attributing the fix to a follow-up that had not happened, and
declaring a **release branch** healthy from a measurement of a **merge**.

⛔ **A trial merge tells you the merge is good. It tells you nothing about the
base.** A green merge over a red base is a normal result: the branch may simply
carry the fix, which is precisely what happened. ⚠️ And a red release branch
blocks every other trial merge, so that claim was load-bearing for four other
people for a full round.

**Fixed — rubric §0a-i: measure the base separately and report both numbers.**
They answer different questions, and a red base is ⛔ a finding **against the
release branch**, urgent, not a mark against the change under review.

⛔ **I then tried to correct the framing and was wrong, which is the more useful
half of this entry.** I wrote that `ruff format` does not read `.md`, that no
Markdown fence is checked, and that the red file was really a docstring. ⚠️ **I
had it backwards, and I caught it only because I went to verify the mechanism
before shipping the claim.** Measured:

```text
  ruff format --check docs/   ->  1 file would be reformatted, 36 already formatted
  ruff format --diff .        ->  --- docs/tasks/handoffs/SF-01.md
                                  --> docs/tasks/handoffs/SF-01.md:24:14
```

⭐ **`docs/` holds only Markdown, so ruff discovers `.md`, formats the Python
inside its fences, and the red file was the handoff itself.** The account I was
given was right in every particular and my correction was the false mechanism.

⚠️ **This changes the weight of the round-8 convention rather than its content.**
*Tag an illustrative fence `text`, not `python`* is not a style preference — it is
the difference between a fenced example the formatter owns and one it leaves
alone, **in every Markdown file in this repository**. ⭐ And it means the trap is
already caught mechanically: it fires at the gate, on `docs/`, every run. What was
missing is that the convention lived in `module-structure.md`, which somebody
writing a handoff has no reason to re-read — so it is now in the handoff section
of `agent-protocol.md`, where the trap is actually sprung.

⭐ **And the integrator's fix was the right call.** *A red suite that stays red is
how people learn to stop reading it* is exactly right, and disclosing it beats
merging it quietly.

### ⛔ The type 6 / type 7 resolution — CONFIRMED, and it was right to ask now

**Take CommonMark type 6. ⛔ Do not take type 7.** Verified by running it:

```text
  <div class="callout">…                       -> ['html']        type 6, known block tag
  <details>…                                    -> ['disclosure']  the Q1 ruling
  <marquee>hello</marquee>                      -> ['para']        type 7 declined
  <marquee>x</marquee> and *emphasis* survives  -> ['para']        <-- the decisive case
  a fenced xml block (ISO)                      -> ['code']        fence-awareness
```

Four reasons, and the fourth is the one that settles it:

1. It makes both sentences of the task **literally true**, and those sentences
   are my own ruling's text.
2. ⭐ It **agrees with the extraction source**, so it is one fewer divergence.
   The divergences are enumerated and justified; an unnecessary one is pure cost.
3. The measured constituency is fully served: `details` and `div` are both type-6
   tags, and SPARQL's six files are `<details>`.
4. ⛔ **Type 7 is the rule that silently destroys inline structure in ordinary
   prose.** The fourth case above — a paragraph *opening* with something
   tag-shaped — becomes one opaque `html` block under type 7, and its
   `*emphasis*`, links and inline code stop being structure. ⭐ This parser's
   governing rule is *never silently drop*, and type 7 is the clause that would
   break it while raising nothing.

⚠️ **One consequence to route, because "stays prose" only holds if the renderer
holds it up.** A `para` whose text contains `<marquee>…</marquee>` must be
**escaped** when rendered, or "stays prose" quietly becomes "is injected into the
page as markup" — the loss coming back by the other door. ⛔ **`SF-12` owns this**
and it is a one-line acceptance clause: *a `para` containing tag-shaped text
renders as visible text, not as an element.*
