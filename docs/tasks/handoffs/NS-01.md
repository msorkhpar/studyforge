## Decisions

**1. ⛔ The batch tension is REPORTED, not silently resolved — see `NS-01/1`.**
I built a **single-text** `POST /v1/speech`. No `/v1/jobs`, no manifest, no
cache, and `test_there_is_no_batch_route` asserts the absence rather than
leaving it to be noticed.

**2. The artifact id is random and opaque, deliberately not a content address.**
A content address here would be half of `NS-02` — the half callers can see and
start depending on for idempotence the service does not have. A test asserts
that two identical requests produce **two** artifacts, so the absence is
pinned rather than merely true today.

**3. `format` is a closed set containing `mp3` only.** An MPEG elementary stream
is independently decodable frames, so its chunks concatenate with no muxer; a
container format such as `wav` cannot be joined that way. Half-supporting one —
correct for short input, broken for long — is worse than a refusal that names
what is permitted (*enumerate the legal*, `module-structure.md`).

**4. The engine has no `ports:` at all.** This is the sharpest available
statement of what the row asked for: not *a client pointed at somebody else's
container*. The engine is reachable only from the compose project's network, by
the service. Verified: `docker port narrate-service-engine-1` printed nothing.

**5. The service binds `127.0.0.1` on the host and `0.0.0.0` inside the
container.** ⚠️ **Not a contradiction, and the Dockerfile says why in place:** a
container's interfaces are not the host's, and what decides reachability is the
`ports:` line. Binding loopback *inside* would make the published port
unreachable and tempt somebody into host networking instead — the outcome the
rule exists to prevent. Verified: `8870/tcp -> 127.0.0.1:8870`.

**6. No `consuming.json`.** `E13`'s preamble assigns it to whichever tasks land
the profiles (`NS-03`) and the voice catalogue (`NS-04`), *"both must contribute
their half"*. Shipping a half here would be the hand-authored copy `R19` calls a
hole. Named in `docs/api.md` instead.

**7. No personal-data gate in the service, and the tests assert the R7 shape
around it.** §8.2 and `E13` are emphatic that the gate is client-side and
pre-request. What I *did* build is the neighbouring half: no refusal, header or
log line echoes the text or an environment value. `test_no_failure_message_echoes_the_text`,
`test_a_response_never_carries_the_text_that_was_sent` and
`test_a_refusal_names_the_variable_and_never_its_value` pin it.

**8. No docker socket anywhere** (spec §8.3). Verified by inspecting both
containers' mounts: the service has exactly one (its artifacts volume), the
engine has none.

## For dependents

**`NS-02` (batch job API and content-addressed cache).**
- The seam you extend is `narrate/synthesis.py::synthesise()` — it already does
  split → synthesise → verify → store for **one** text. A job is that, per
  segment, plus a manifest.
- ⛔ **`narrate/artifacts.py::mint_id()` is the ONE place an id is minted, and
  replacing it with a content address is your task's whole storage change.** The
  id is validated by a closed pattern (`_ID_PATTERN`, 32 lowercase hex); a
  sha256 hex digest is 64, so widen that pattern deliberately and keep it
  closed — it is what stops a URL path component reaching the filesystem.
- ⛔ **`test_two_identical_requests_are_two_artifacts` asserts today's
  NON-idempotence and MUST be inverted by you, not deleted.** It exists so the
  change is visible.
- ⭐ **`test_there_is_no_batch_route` is yours to delete** when `/v1/jobs`
  exists. It is the only test that will fail, and that is the design.
- The store already handles overwrite atomically, which is what a cache hit
  re-writing the same address needs.

**`NS-03` (engine adapters, CPU and GPU profiles).**
- ⛔ **The seam already exists and is one method**: `synthesize_chunk(text,
  voice, fmt)` plus `reachable()` and a `name`. `narrate/engine/__init__.py`
  documents what is deliberately absent — no registry, no plugin loader, no
  profile selector, because one implementation does not need a lookup table.
- `GET /healthz` already reports `engine` by name, which is your Acceptance's
  *"the engine in use is reported by the service"* — already true.
- `compose.yaml`'s engine service is the GPU profile, carried over unchanged and
  **labelled in place** as not acceptable as *the* deployment. Its image is
  pinned by tag **and** digest
  (`…kokoro-fastapi-gpu:v0.8.2-cu128-amd64@sha256:a95e53e3ed3d…`).
- ⚠️ **A CPU profile will need a different engine image; I did not pull one, so
  nothing about a CPU path is proven here.**

**`NS-04` (voice catalogue).** `voice` is passed to the engine **unvalidated**;
an unknown voice surfaces as a `502`. The live engine's own
`GET /v1/audio/voices` is the raw material. `am_liam` is the default, carried
over from the previous implementation.

**`NS-03` + `NS-04` jointly own `consuming.json`** — nothing of it exists yet.

**Any framework caller (`SK-07`, `SF-17`).**
- ⛔ **Gate the text before the request. This service does not.**
- ⛔ **It never writes into your tree** — placement is yours (R4).
- Send **one text of any length**; do not chunk, and do not stitch.
- `Narrate-Seconds` is summed from the artifact's own frames, so it is a
  measured duration rather than an estimate — usable for a highlight-sync
  budget.
- ⚠️ **Artifacts are not garbage-collected**; the store grows until somebody
  empties it.
