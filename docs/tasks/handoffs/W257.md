## What landed

- **The generated `emit` dates each container AFTER the reader.** `container = dataclasses.replace(reading, ingested=ingested)` runs before the map is rendered and before `read.documents` is called. `read`'s signature is unchanged, so a hand-written `read.py` needs no edit.
- **The generated `test_emit` copies through the one ignore reader.** `validate.source.classification._declared_output` (`W28`) is renamed to the public `repository_ignores` and exported from `studyforge.validate.source`.
  - `_copy` asks the reader once per directory, so an ignored directory is never walked.
  - At the corpus root it also leaves out the archive and its staging directory, which are the suite's own output, and `.git` at any depth.
  - A repository that stops answering part-way raises. There is no pattern list.
- **Outside a git working tree, such as a `git archive` export, nothing is declared ignored.** An export holds only tracked files. The copy takes everything but the archive and emits a `UserWarning` saying so.
- **The generated `test_emit` gains `test_every_container_is_dated_with_its_documents`**, so a regenerated corpus carries the property (R19).

## Decisions

- **After the reader, not handed to it.** Handing it over would change a hand-written signature, and every existing `read.py` would break on regeneration.
- **The rider is dated in place, not re-derived.** Rule ids have no public registry to derive from (`W257/1`). A pin derived from `len(CHECKS)` would also go RED whenever an in-flight row adds a check. The `f816454` figures stand, marked stale. The check count is a fence the test executes (Ruling 163).
- **The reader is renamed, not wrapped.** Two names for one reader would be the second reader the row forbids.
