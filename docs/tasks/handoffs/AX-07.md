### ⛔ THE LEDGER'S GATE-FACING FACE WAS ALREADY LANDED, AND IT IS KEYED BY PATH

⚠️ **MEASURED, not chosen.** `exercise/gates/code.py`'s `_g5` and
`exercise/gates/quiz/mechanical.py` both take the ledger as a
`Mapping[str, str]` and ask it exactly one question — `ledger.get(origin.path)`
— compared against the `Cited` digest a gate record carries. ⛔ **So the ledger
had one shape it was not free to choose**, and `digests(ledger)` is it: the
digest of the whole file, per path, taken with `gates.digest_of_bytes`.

⭐ **The per-entry digest is a different value for a different reader** and is
never handed to a gate: an example's digest is the bytes of that example, which
is what lets a re-run say *which* example moved rather than only which file did.

### ⛔ THE SHAPE OF A LEDGER

```json
{
  "ledger_api": 1,
  "sources": [{"path": "…", "digest": "sha256:…", "sections": ["Adding up", "Edge cases"]}],
  "entries": [
    {
      "kind": "example", "path": "…", "ordinal": 2,
      "sections": ["Adding up", "Edge cases"], "language": "java", "digest": "sha256:…",
      "exercises": ["unit-01/practice-1"], "reason": null
    }
  ]
}
```

- ⛔ **Two entry kinds and the set is closed**: `example`, one fenced block, and
  `tests`, one test file whole, whose `ordinal` is `0` because it has no
  position inside itself.
- ⛔ **An entry carries the CHAIN of headings that encloses it**, outermost
  first, so an origin naming any ancestor section resolves against it — Ruling
  92's region read from the inside.
- ⛔ **`sources[].sections` keeps its repeats**, because a name a file carries
  twice is what makes a region ambiguous, and dropping the repeat would hide it.
- ⭐ **An entry's key is `example:<path>:<ordinal>` or `tests:<path>`** — the
  token a written reason is filed under, and `<what>:<which>` is the shape
  `gates.digests` already uses for `plant:<case id>` and `question:<id>`.

### ⛔ THE SHAPE OF A PLAN

```json
{
  "plan_api": 1, "words": 900, "skills": 3, "tier": "core",
  "band": "standard", "count": 3,
  "reasons": [{"moves": 0, "says": "the page is 900 words, which puts it in …"}]
}
```

⭐ **Every movement is a recorded `Reason` carrying how far it moved the
count**, so `band.floor + sum(moves)` equals the count — the reasons are
checkable arithmetic rather than a note beside a number, and the clamp into the
band is itself one of them.

## Decisions

⭐ **Things the task did not specify, chosen here, each with the reason:**

1. ⛔ **THE TWO POPULATIONS ARE DATA AND THERE IS NO PATTERN FOR *WHAT A TEST
   FILE LOOKS LIKE*.** `src/test/java/**`, `test_*.py`, `*_test.go` and
   `check_*.py` are four sources' conventions, and a framework carrying them
   would know four sources (R1). ⭐ What is material and what is a grader is the
   corpus's own declaration — the thing `corpus.json` already exists to say —
   and it reaches `take` as two lists of paths. ⚠️ **The consequence for
   `AX-08` is a real obligation**, and it is stated under *For dependents*.
2. ⛔ **AN ORIGIN MUST RESOLVE TO A FILE THE LEDGER READ; IT NEED NOT RESOLVE TO
   AN ENTRY.** ⚠️ The stricter rule was written first and would have refused
   every quiz: **a quiz question cites a PASSAGE, and a passage of prose holds
   no fence** (spec §7 §7). ⭐ So the checks are the file and — where a section
   is named — that the file carries it exactly once. Read at
   `test_accounting.py::test_an_origin_that_accounts_for_no_entry_is_not_a_fault`.
3. ⛔ **AN ENTRY WITH BOTH AN EXERCISE AND A REASON IS REFUSED, NOT ONLY ONE
   WITH NEITHER.** A written reason SAYS no exercise was built from this entry,
   so a reason beside an exercise is a row contradicting itself. ⭐ Cheap to
   check and it catches the copy-paste that would otherwise leave a stale
   excuse in a ledger that looks complete.
4. ⛔ **ZERO AND TWO ARE BOTH LOUD, AND THE WORDING IS `SF-36`'s.** An origin
   naming a section the file carries `0` or `2` times is refused with the count
   and without the section (R7) — the same two faults `validate/source.py`
   keeps apart as `origin-section-missing` and `origin-section-ambiguous`.
   ⚠️ They are ONE refusal here and two rule ids there, because this module
   raises rather than reporting findings a script filters.
5. ⛔ **`scan` REPORTS AN UNCLOSED FENCE AND `take` REFUSES IT.**
   `headings.Region.occurrences` is the precedent character for character: the
   module that owns the grammar returns the fact and refuses to pick, and the
   caller — which knows what the file was being read *for* — raises.
6. ⭐ **THE BAND IS A FRAMEWORK CONSTANT AND A CORPUS CANNOT WIDEN IT** (R1). A
   ceiling an author sets is not a ceiling. ⚠️ The four bands' numbers ARE a
   convention, said so in the module, and stated in one place so a reviewer can
   argue with them; ⛔ what is not a convention is that the count cannot pass
   the ceiling, which is the property `AX-11` reads on a real corpus.
7. ⛔ **`ceiling` IS THE HARD BOUND AND `floor` IS ONLY FOR A PAGE WITH WORK.**
   ⚠️ Written first as `low`/`high` with the count always inside, and that made
   *a page with no checkable skill plans none* unrepresentable in any band whose
   floor is 1. ⭐ Zero is permitted in every band and is the one value below the
   floor — reached only with a recorded reason, never quietly.
8. ⛔ **A SHORTFALL'S GATE IS CHECKED AGAINST `gates.family_of`.** A report
   citing `G7`, or citing nothing, names something nobody can go and read.
   ⭐ This is the half of spec §7 §11 a module can hold; re-authoring inside a
   budget is `AX-08`'s.
9. ⛔ **`LEDGER_API` AND `PLAN_API` ARE THEIR OWN VERSIONS**, following the
   archive document's rule and `bundle_api`'s: bumped when a reader of the old
   shape would be *wrong* rather than merely incomplete. Nothing of either shape
   is on disk anywhere yet, so the key order is free and both are version 1.
10. ⭐ **AN EXERCISE'S NAME IS CHECKED WITH `gates.require_role` AND THE
    REFUSAL IS RE-RAISED AS `LedgerError`.** `exercise.cases.origin_in` is the
    precedent: the sentence that states the shape belongs to the module that
    owns the rule, and the type changes so a caller of this package catches one
    family. ⛔ Both values are tokens written into a record and printed in a
    refusal, so a second spelling of the rule would be duplication.

## For dependents

### ⛔ `AX-08` — the authoring skill: what you inherit, and what NOT to re-derive

⭐ **You inherit two finished readings. Do not re-derive either.**

- ⛔ **The ledger's scan, its entry vocabulary and its refusals are DONE.** Call
  `take(root, sources, tests, where)` and then
  `account(ledger, origins, reasons, where)`. ⚠️ **Do not write a second fence
  scanner, a second heading rule or a second idea of what an entry is** — the
  grammar is `validate.headings`'s, the walk is `scan`'s, and both are pinned.
- ⛔ **THE TWO POPULATIONS ARE YOURS TO SUPPLY, and that is decision 1, not an
  omission.** The skill reads the corpus's own `content` policy for what is
  material and the corpus's own declaration for what its graders are. ⚠️ **The
  framework will never guess a test-file pattern**, so a skill that needs one
  is reporting a hole in `corpus.json`, which is where it belongs (C2).
- ⛔ **`digests(ledger)` is what you hand every gate.** `gates.check(...)` takes
  `ledger: Mapping[str, str]` and asks `ledger.get(origin.path)`; that mapping
  is this function's return value and nothing else needs building.
- ⛔ **`bundle.origin` is required on every bundle** (`AX-04` decision 6), so
  the `origins` mapping you hand `account` is `{name: bundle.origin}` read
  straight off the bundles you just wrote. ⭐ The name is checked with
  `gates.require_role`, so a practice key, a `unit-NN/practice-M` or a bundle id
  all pass; a name with whitespace does not.
- ⛔ **A written reason is REQUIRED for every entry no exercise was built from**,
  and it is a sentence a person reads. ⚠️ There is no way to switch this off and
  there is not meant to be: the refusal is `E14`'s first property.
- ⛔ **The plan is a CEILING.** Author against `plan.count`, ship what clears the
  gates, and call `shortfall(plan, shipped, refusals, where)` — it refuses a
  page that shipped past its ceiling and refuses a gap not named with a gate
  `exercise.gates` declares. ⭐ That is the arithmetic half of spec §7 §11; the
  attempt budget and the re-authoring loop are yours.
- ⛔ **`words`, `skills` and `tier` are YOUR readings.** This module refuses a
  tier it does not define rather than defaulting one, because defaulting would
  hide a typo as a judgement. ⚠️ Nothing here counts words for you: what a word
  is on a page with tables and fences is a decision, and it is the skill's.
- ⛔ **TWO MANIFEST LINES ARE STILL YOURS** (`AX-04/2`, unchanged by this row): a
  corpus committing bundles must declare `exercises/**` and `practice/**` under
  `content.not_material`, needing `corpus_api` **2**, or `check_unclassified`
  refuses every file in both before any check of this milestone runs.
- ⛔ **AND THE IGNORE RULE** (`AX-04/3`): a run's JUnit report lands in the
  reader's workspace, carries the machine's hostname, and only a rule the corpus
  writes keeps it out of a commit (R7).
- ⭐ **Where the ledger and the plan land is YOUR decision, not this row's.**
  Both modules return decoded objects and neither writes a file: `emit`'s own
  rule — *the framework answers, placement decides* — applied one level up.
