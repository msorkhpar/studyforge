## What landed

⭐ **What the software does now:**

- `corpus.json` may carry `"narration": true|false` under **`corpus_api: 5`**
  (`KEY_VERSIONS[(None, "narration")] = 5`, `CORPUS_API = 5`, known set `1`–`5`).
  `Manifest.narration` is `True` when the key is absent, so every existing corpus
  keeps its voice whenever it has a record.
- The onboarding skill asks, and `promote` writes the answer at `corpus_api: 5`. The
  onboarding report prints `narration  yes|no|not asked`. `reonboard(settle={"narration":
  False})` changes the answer, and the version rise travels with a settled answer
  (see `W460/2`). The standing command prints `narrated: off …` rather than `0 of N`.
- `studyforge build` and `studyforge serve` take `--narration` / `--no-narration`
  (`argparse.BooleanOptionalAction`, default `None` = `corpus.json`'s answer).
- Off, the build is **byte for byte the build of a corpus with no record**: no player,
  no `data-audio`, no gap notice, and no clip copied into `--out`. The record is not
  opened. Nothing is deleted, moved or rewritten; `--narration` plays the same clips
  again with no re-synthesis.
- Off, `serve` refuses a site built with narration (exit `1`, one `narrated <page>`
  line each, naming the fix), refuses every clip file under the served root by path
  (`404`), and prints `narration off …` per corpus. Both serve forms do this.
- `studyforge plan` of a corpus whose `corpus.json` says `false` names no clip copy and
  reads no record, which matches the build.
- The build-and-serve skill takes `--narration` / `--no-narration`, hands the same
  answer to `build` and `serve`, prints **no** `partial narration*` state when off, and
  prints one `narration off  chosen: …` line. `--voice` with narration off is refused
  before anything runs (exit `2`).

## Decisions

- ⭐ **The choice lives in `corpus.json`, not in the skill's committed record.** Every
  later stage (`build`, `serve`, `plan`, `validate`, the skills) already reads the
  manifest through one reader, and R19 says customisation enters as manifest data. A
  skill record would be a second authority that the verbs would have to learn to find,
  and a corpus onboarded by hand would have nowhere to say it. Versioned like
  `runtimes` (`W350`): a top-level `KEY_VERSIONS` entry, a bump, and old manifests
  unchanged.
- ⭐ **Asked and unasked are different.** A draft carrying the key writes it, `true` or
  `false`, at `5`. A draft without it writes no key and keeps its version. The report
  says `not asked` rather than inventing a `yes`.
- ⭐ **Serve refuses a narrated build; it does not edit pages or merely hide clips.**
  The player and every `data-audio` are in a built page's bytes, and R8 makes the built
  page the product. Stripping them per request would make serve a second author of the
  page, disagreeing with the file. Hiding only the clips would serve a player whose
  every passage fails, which is `W202`'s broken state and not the reading floor. So
  serve refuses and names the build that fixes it, the same way it refuses an unbuilt
  page. It also withholds every clip by path, because an in-place build leaves clips
  inside what serve serves (R3). `cli.unvoiced` carries the argument.
- ⭐ **A clip is recognised by its name, not its folder.** `is_clip` needs an `audio`
  directory **and** a name that `narrate.speakable.parse_clip_name` accepts, so a
  source's own `audio/lecture.mp3` is still served.
- ⭐ **Off reads no record at all.** A broken record cannot stop a build that will not
  voice it. On, it still stops the build, as before.
- ⭐ **The skill refuses `--voice` with narration off.** Synthesising clips the same
  run will not serve is a contradiction, and saying so costs one line.
- ⭐ **`write_narration` (the pass after `studyforge narrate`) follows `corpus.json`
  only.** It has no caller outside `generate`, and a run override belongs to
  `build` and `serve`.

## Surprises

- ⚠️ **`/tmp`'s per-user quota ran out mid-row.** The shell could not start for a
  while. From then on every pytest run used `--basetemp` inside this row's scratch
  directory, which was removed afterwards. Nothing outside it was deleted.
- ⚠️ **The first serve-refusal test hung under its plant, and did not fail.** It called
  the verb with no `started=` hook. With the refusal planted away, the verb served
  forever, so the planted run hit `timeout` (exit `124`) instead of going RED. It now
  stops any server it starts at once and asserts that none was started. Re-planted:
  RED.
- ⚠️ **A long `--basetemp` makes `test_serve_process.py` fail for a reason unrelated to
  the change.** Its decoy Docker socket must be under the kernel's 108-byte `AF_UNIX`
  limit (the test asserts `< 100`), and a path under the session scratchpad is longer
  than that. The host reading of that file was taken with pytest's default basetemp.
- ⚠️ The Chrome extension's first navigation to a served page is refused by `serve`'s
  cross-site guard (`Sec-Fetch-Site: cross-site`). The browser reading navigated from a
  same-origin page by script. This is serve working as designed, not a defect.

- `[local]` **`W460/2`: a `settle` that needs a newer `corpus_api` was refused.**
  `reonboard(settle={"narration": False})` was refused as `corpus_api (2 -> 5)`,
  because `recorded.moved` compares every field and the version is one of them. Fixed
  here: a settled answer carries the version rise with it, and without a settle there
  is no rise. `W350/1` has the same shape for `runtimes` and `media.max_files` in
  `promote`'s `_api_for`, and it is **still open** for those two keys.
- `[local]` **`W460/3`: the shared page script still bundles `narration.js`.** It is
  inert without a player. A corpus that was never narrated ships the same script, so
  "no narration asset" holds exactly as it does on the reading floor. Splitting the
  bundle per page is out of scope.
- `[local]` **`W460/4`: clips a previous build copied into a separate `--out` stay
  there** after a rebuild with narration off. A rebuild never deletes a copy the
  record no longer names (`generate.clips`, answer 2). They are not linked, and
  `serve --no-narration` refuses them by path. Not deleting them is R3's side of the
  line.

## For dependents

- ⭐ **The seam, for every reader of narration: `studyforge.narrate.narration_on(root, *,
  asked=None)`.** The run's answer wins when given; otherwise `corpus.json`'s
  `narration` decides; otherwise narration is on. `validate` already asks it (`W457`),
  so a corpus that recorded `false` reports no stale clip. That is
  `tests/studyforge/validate/test_narration_recorded.py`, planted RED. ⛔ **Never read
  `Manifest.narration` to decide a run.** It is the data the predicate reads.
- ⭐ **Inside a build, the record is read through `generate.narration.narrated(corpus)`**,
  which returns the record's absent state (`present=False`) when the corpus is not
  voiced. ⛔ Do not call `generate.narration.recorded` directly.
  `test_no_pass_reads_the_record_around_the_one_gate` holds that line for `generate/`.

  `depth1` copy with a quiz and 24 real WAV clips, plus a `runnable` copy. The
