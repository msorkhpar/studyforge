## What landed

### A page now reaches the other containers, and says which one the reader is in

The markup a unit page carries, as a built `depth2` page emits it (elided at the second
container, and the paths are the fixture's own):

```html
<nav aria-label="Containers"><ol>
<li data-readable="true"><details><summary><a href="../../advanced/02-going-further/going-further.section.html"><span data-kind="level">module</span> Going Further</a></summary><ol>
  <li data-readable="true"><a href="../../advanced/02-going-further/advanced.02-going-further.unit-01-composition-over-inheritance.unit.html"><span data-kind="numbering">1</span> Composition over inheritance</a></li>
  …
</ol></details></li>
<li aria-current="true" data-readable="true"><details open><summary><span data-kind="level">module</span> Getting Started</summary><ol>
  <li aria-current="page" data-readable="true"><span data-kind="numbering">1</span> Your first class</li>
  <li data-readable="true"><a href="basics.01-getting-started.unit-02-fields-and-constructors.unit.html"><span data-kind="numbering">2</span> Fields and constructors</a></li>
</ol></details></li>
</ol></nav>
```

- ⭐ **Every container the corpus declares is a row, and every unit under every one of them is
  a row inside it.** So a reader in `basics` has a direct link to any lesson of `advanced`, not
  only to its course page — which is what *"a link to a unit in another container"* asks for.
- ⭐ **The container the reader is in carries `aria-current="true"` and the unit they are on
  carries `aria-current="page"`**, in the markup and not only in styling. Neither is a link: a
  page that links to itself is a way to get nowhere, which is the trail's own rule.
- ⛔ **The reader's own container renders `open` and every other renders closed.** A closed
  `<details>` still carries its links, so nothing is hidden from a reader who wants it — and
  `<details>` opens, closes and takes keyboard focus with scripting off entirely, which is why
  the region is built out of it rather than out of a script (R8, and
  `render/index/disclosure.py` makes the argument first).
- ⛔ **A corpus with ONE container gets no region at all.** `RAIL_MINIMUM` is 2, on the same
  argument `BREADCRUMB_MINIMUM` makes: a rail listing one course is a list with no choice in
  it, and the trail and the bar already say where the reader is. Asserted on the artifact —
  no page of a built `depth1` corpus carries the region.
- ⛔ **The root index carries none either**, and the reason is a row in that module's table of
  absences: its body already lists every container there is, so a rail there would be the same
  tree rendered twice on one page.

### The build-side join, and the geography it asks rather than composes

`generate.navigation.rail(contents, from_page, above, container=…, unit=…, absent=…)` is the
only producer, and `generate.units` and `generate.containers` are its two callers.

- ⭐ **`deepest(contents)` is the container population** — the groups that hold units — and
  `tests/studyforge/generate/test_navigation.py` asserts it is exactly `page_paths(corpus)`'s
  key set, which is the build's own answer to *which containers get a page*. An intermediate
  level has no container map and therefore no page, so it is not a row (`SF-14/3`).
- ⭐ **Every href is `corpus.placement.relative_href(from_page, target)`**, and every target is
  asked of the type that owns it: a container page from `generate.containers.page_paths`
  (which asks `corpus.profile.container`), a unit page from `contents.Entry.page` (which is
  `profile.unit(...).page`). ⛔ **Not one path shape is spelled in this row's diff**, in `src/`
  or in tests — see *For dependents* for what that means for `W323`.
- ⚠️ **A unit this build has no material for is a DECLARED absence** — listed, `data-readable="false"`,
  no href — exactly as the between-units bar's neighbours are (§7's third state).

## Decisions

### ⛔ The region is a card in the ONE column, and not a rail beside it

⚠️ **The user's words are *"there is no left navigation bar between courses"*, and what landed
is a navigation region at the top of every page rather than a sticky side rail.** ⭐ The brief's
five settling clauses are about what the navigation REACHES, what it SAYS, and that it works on
`file://` — all five are met — and *"a design overhaul"* is in its *Must not become*.

⛔ **The measured reason it is not beside the column:**
`tests/visual/test_site.py::test_every_chrome_region_resolves_the_same_column_as_the_reading_surface`
asserts, live in a browser, that every chrome region resolves the SAME column as the reading
surface. ⭐ A region parked to the left of the column is a two-column page: it moves that
assertion, `body`'s one bound in `chrome.css`, and the two tokens `palette.css` defines and
nothing paints (`--rail`, `--page-max`). ⚠️ **Doing half of that is the full-bleed-islands
defect wearing a third face**, which is what `W98` and `SF-34` were. ⛔ The whole change is one
decision and it is a layout row, not this one — recorded as `W324/1`.

### ⛔ The label is `Containers`, a fixed framework word

⚠️ `chrome.css` reaches every region by its `aria-label`, so the label cannot vary per corpus —
and a corpus's own word for a depth (`manifest.levels[-1]`) is what a corpus-varying label would
have to be. ⭐ So it is this framework's structural word, exactly as
`render.container.listing.LIST_LABEL` (`"Units"`) and `render.index.disclosure.LIST_LABEL`
(`"Contents"`) already are, and each row still carries the corpus's OWN word for its depth in
the `data-kind="level"` chip (R1).

### ⛔ The rail emits no `id`, so a container page keeps one element per unit key

⚠️ `read-mark.js` resolves a mark with `document.getElementById(key)`, and
`render.container.listing` already puts `id="<unit key>"` on every row of a container page's own
listing. ⭐ A rail that keyed its rows the same way would put **two** elements under one id on
that page, and the mark would light whichever the document held first. ⛔ So the rail is not
deep-linkable and carries no read marks — recorded as `W324/2`.

### ⛔ Ruling 164 here: a refused href drops the LINK and keeps the ROW

⚠️ This is the **trail's** reading and not the two lists', and it is the trail's reason: a
container or a unit dropped out of this list is a **true statement about a different corpus** —
the reader counts the courses, finds one fewer than the material has, and nothing says so. ⭐ A
row with no anchor is visibly not openable and costs the reader a trip through the root index,
which is where they were before this region existed.

⚠️ **`data-readable` therefore reports what the row EMITTED, not what it was handed**: a
declared absence and a refused href both leave a row nobody can click. ⛔ **The CURRENT row is
`true` and carries no anchor** — it is the most readable row on the page, and marking it
*"listed, not openable"* would be a false sentence rendered in italics.

### ⚠️ An existing clause was narrowed, and its other half added — flag this first

⛔ **`tests/visual/test_keyboard.py::test_every_chrome_link_is_reachable_by_tab_and_in_document_order`
read `nav[aria-label] a` and compared that population against the Tab order.** ⚠️ **An anchor
inside a closed `<details>` is not in the browser's focus ring** — that is the user agent's rule,
not this page's — so the moment any tree carried a closed disclosure the clause went RED for a
reason that has nothing to do with the page being navigable.

⭐ **It was never true; it was only unreachable.** `render.index.policy.open_to` closes levels
once a corpus exceeds `VISIBLE_ROW_BUDGET`, and both fixtures are under it — so no tree this
harness had ever opened held a closed disclosure, and the same RED was waiting for the first
corpus large enough.

⛔ **What landed:** the population is now what a keyboard reader can REACH, and a new check,
`test_every_closed_disclosure_in_the_tree_is_itself_reachable_by_tab`, asserts the other half —
every closed `<summary>` is itself in the Tab order, so nothing is hidden without an affordance.
⭐ It asserts its own inhabitation first (Ruling 48) and walks every page in one check rather
than skipping per page, so the harness's skip census is unchanged at zero.

- ⛔ **`page.html` has a new slot.** `templates.fill` refuses a placeholder with no value AND a
  value with no placeholder, so any other composer filling that skeleton must pass `rail`,
  by name. `render.index.document.EMPTY_SLOTS` is how the root index does it.
- ⭐ **`nav[aria-label="Containers"]` is region 10** in
  [`tests/studyforge/render/pageassets/test_chrome.py`](../../../tests/studyforge/render/pageassets/test_chrome.py)'s
  disposition table, chrome-ruled, with its rules in `chrome.css`. A stylesheet part that wants
  to reach it reaches it by that `aria-label` and by `data-readable`/`data-kind` — no class
  joins the published vocabulary.
- ⚠️ **`tests/visual/ACCEPTANCE` has a sixth row.** That mapping is asserted total against the
  package's own test modules, so a browser-driving module without a row is refused — adding the
  row is how a clause is agreed to here, not a formality.
