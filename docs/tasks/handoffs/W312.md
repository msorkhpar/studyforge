## What landed

- ⛔ **`close()` removes the launch's profile**, in this order: close the pipe, stop the browser
  (terminate, then kill if wedged), read the log's tail into memory, close the log, remove the
  directory. The removal sits in a `finally`, so a failure earlier in `close()` still removes it.
- ⭐ **`diagnostics()` answers from the kept tail once the log is closed**, so the browser's last
  words outlive the directory they were written in. While the browser runs it reads the live log,
  as before, and `_receive`'s closed-pipe error still quotes it before anything is removed.
- ⛔ **A launch that fails part-way leaves nothing.** The profile is made first; everything after
  it (both pipes, the log, `Popen`) runs in `_launch` under a handler that calls `close()` and
  re-raises. `close()` skips whatever was never opened, and a second call does nothing. Tests
  plant a failing `Popen` and call `close()` twice; the other half-made states are read, not run.
- ⭐ **`_remove_profile` retries** (`REMOVAL_ATTEMPTS`) because a browser's helper processes can
  still write into the profile just after the main process exits. ⛔ A profile that survives
  every attempt raises `BrowserError` naming it, never a silent leftover.
- ⭐ A fresh profile per launch is unchanged (R10).

## Decisions

1. **The real-browser arm takes its binary from the session `browser` fixture**, the one licensed
   ambient reader (`W128`), rather than calling `discovery.require_browser()` itself, which
   `test_host_environment.py` would refuse without `pinned_environment`. It therefore skips
   loudly wherever the session browser skips, and runs wherever it runs.
2. **Kept in memory, not copied out to a file.** Moving the log somewhere else would be a second
   temp writer, which is the defect's own shape. The tail is the same 2000 characters
   `diagnostics()` always returned.
3. **Removal failure raises.** A silently ignored `rmtree` is how a quota fills without anyone
   reading why.
4. **`test_init.py` gained one line.** A new test module in `tests/visual/` is refused unless it
   is a declared clause or machinery; this is machinery. No assertion there changed.

## Surprises

- ⚠️ **A binary that does not exist does not raise at launch.** I first wrote that check to expect
  `FileNotFoundError` from `Popen`, and it went red. The child-side hook
  (`_place_pipe_on_three_and_four`) closes every descriptor above fd 4, and that includes
  `subprocess`'s own exec-error pipe (read from the order `subprocess` runs the hook in; the red
  check is the measurement), so the parent never learns that exec failed. The failure arrives at
  the first call as *"closed the protocol pipe"*. Filed as
  `W312/1`. The check now asserts that behaviour and that the profile still goes.

## For dependents

- ⭐ **`Browser.diagnostics()` stays valid after `close()`** and returns the tail kept at close.
- ⛔ **`close()` can now raise `BrowserError`** if a profile cannot be removed. Nothing in this
  repository catches it, and a test that closes a browser will go red on a leftover, not pass.
- ⚠️ **A `Browser` that is never closed still leaves its profile.** Use `with Browser(...)`, as
  `conftest.py` does.
