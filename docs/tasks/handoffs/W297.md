## Decisions

### ⭐ 1. The guard is a GENERATOR, and it is before the layout rather than at the fence

⛔ **Guarding `tail[0]` alone would have met the letter of the row and left the defect's
neighbour standing.** Only that one read crashed — but `_is_h2` merely returns `False` for a
non-object, so a string anywhere else in a practice's blocks was silently unread and the
document was refused for the WRONG reason: *"its blocks do not carry the three headings"*,
when the truth is that one of them is a string.
⭐ That is [`module-structure.md`](../../conventions/module-structure.md)'s *a guarantee does
not extend to what sits beside it*, and it is asserted at every position rather than argued.

⚠️ **A generator rather than a check beside a loop**, so a caller cannot take the blocks
without taking the refusal — there is no unguarded way left to iterate them, which is
exactly what `W297` found missing one function away from `W289`.

### ⛔ 2. `parse` takes the docstring option, and it is FORCED

⭐ `validate` imports `archive`; `archive` importing `validate` is a cycle. So `parse`
**cannot** run the §6 shape reading, and saying so is the honest answer rather than the
cheap one. ⚠️ The docstring is asserted, not trusted: a test reads it back and fails if it
stops naming `validate.blocks`, `read_layout` and `counts_of`.

### ⛔ 3. A NEW test module, because `test_blocks.py` is at its ceiling — Ruling 261

⚠️ **Measured: `tests/studyforge/archive/test_blocks.py` stood at `517` lines against R11's
`600`-line test ceiling.** ⛔ Appending this row's assertions to it left it **three lines**
from the wall — headroom the next office to touch the block vocabulary would have had to pay
for. ⭐ Ruling 261 is explicit that the answer to a module at its ceiling is a **split**, not
a shorter comment, so the read-path assertions live in
`tests/studyforge/archive/test_read_path_guard.py` and `test_blocks.py` is returned
**untouched**.

⭐ **The mirror permits it**: `tools/quality/mirror.py` is source→test only and its docstring
records that the reverse direction was deliberately rejected. Subject-named test modules with
no source counterpart are already the norm (`test_acceptance.py`, `test_no_synthesis.py`,
`test_never_editable.py`).

⚠️ **`NOT_OBJECTS` and the `practice()` fixture are spelled again rather than imported from
`test_blocks.py`.** ⛔ A test module importing another test module's fixtures couples the two
subjects this split exists to separate. ⭐ The three headings are IMPORTED from the
vocabulary, so the fixture cannot drift from what `read_layout` matches — which is what
"derive from one source of truth" actually asks of a test.

### ⛔ 4. `W301`'s test lives in `tests/docker/`, and it cost a registry entry

⭐ **Clause 3 says the invocations are asserted where the contract lives**, and that contract
is `docker/dev/check`'s own header — so the check reads BOTH the rubric and the wrapper and
fails if they ever disagree. A check reading only the rubric would assert that the rubric
agrees with itself.

⚠️ **That directory keeps a CLOSED register of every reader of `docker/dev/` text** (`W131`,
Ruling 258), and three new sites had to be classified or the suite goes red — which is the
register working, not a defect. ⛔ **`DECOMPOSITION_SITES` moved `38` → `41`**, a count this
row moved. The verdicts, taken against the register's own definitions:

| site | verdict | why |
|---|---|---|
| `obliged_block` | `not-dev-text` | it reads the rubric and no `docker/dev/` text at all |
| `default_command` | `line-anchored` | `startswith("set --")`, the anchor `test_dev_check_timeout.py` already declares for the same line |
| `test_the_wrapper_still_documents_the_bare_form_as_the_whole_suite` | `per-physical-line` | ⛔ its subject is a line of `check`'s HEADER, and a **comment is not** a construct the grammar pins to the start of a logical line — so it owes the verdict carrying an exact count, never one resting on an anchor |

### ⚠️ 5. What was deliberately NOT done

⛔ **No frozen record was edited and no past reading was corrected.** `W301` clause 2 says

## For dependents

- ⛔ **`archive.blocks` refuses a non-object top-level block by name on BOTH doors now** —
  `counts_of` on the way in through `build`, `read_layout` on the way out. A consumer may
  rely on every block reaching it from either being a `dict`.
- ⚠️ **`read_layout`'s refusal spelling changed shape.** It now emits
  `<where> blocks[<i>] is <described>; a block is an object with a type` for a malformed
  block, alongside its existing *"does not carry the three headings"* refusal for a practice
  that is merely not laid out. ⭐ **The two are deliberately distinct and asserted so** — a
  document with the wrong headings must not be told a block is not an object.
- ⛔ **A lesson is still untouched by `read_layout`**: its `kind` returns before any block is
  reached, so nothing is refused. A malformed block in a lesson remains `counts_of`'s to
  refuse and `validate.blocks`'s to name in full.
- ⭐ **`parse` is NOT a shape gate and now says so in its own docstring.** Anything needing
  the full spec §6 reading calls `validate.blocks.block_problems`; do not add a shape check
  to `archive.document`, which cannot import `validate` without a cycle.
- ⛔ **Run the floor as `docker/dev/check python3 -m tools.quality` and the suite as
  `docker/dev/check python3 -m pytest -ra`.** A bare `docker/dev/check` is the SUITE — that
  is now enforced by a test, so a handoff that pastes the old form fails the suite rather
  than filing a quiet mistake.
- ⚠️ **Adding any reader of `docker/dev/` text costs a `CLASSIFIED` entry and a bump to
  `DECOMPOSITION_SITES`** in `tests/docker/test_dev_continuations.py`. That is by design; the
  failure message names the site and the verdict it needs.
