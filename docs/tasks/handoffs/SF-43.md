## What landed

⭐ **`src/studyforge/generate/footprint.py` — `Footprint`, and the one call that
derives one.** `footprint_for(root, profile)` asks `plan_for(root)` for the
paths a build creates and splits them on the plan's own printed distinction: a
line ending in `/` is a directory prefix, every other line is a file. ⛔ **There
is no second list of what a build writes anywhere in the diff.**

⛔ **`place` and `copy` take a required keyword-only `footprint`.** An existing
target inside it is replaced and recorded in the new `Written.replaced`;
everything else is refused by name exactly as before. `mint` is untouched.

⛔ **`Corpus.footprint`, filled by `read_corpus`, defaulting to
`Footprint()` — which owns nothing.** Every pass gets it for free and no pass
derives one; a `Corpus` built by hand, a plan that refused, and the emission
census's own filler all land on R3's floor rather than on a licence.

⭐ **`studyforge build` gained a `replace` verb and keeps its exit codes.** A
replacement is not a refusal, so a rebuild exits `0`; a refusal still exits `1`
and is still named. Every path prints exactly once, so the report stays the
path-for-path diff against `plan` that Ruling 99 asks for.

## Decisions, with their reasons

⛔ **A hand-edited generated page IS replaced, and the question was
malformed.** A build has no prior content to compare against, so *"was this
edited by hand"* is not askable; inventing an answer — a manifest of digests —
would be a second declaration of what the plan already enumerates. ⭐ **Ruled
rather than chosen**: R19 says a hand-edit to a generated artifact is *a
finding, not a fix*, and every placement profile already puts those pages in the
corpus's own ignore lines. ⚠️ Asserted plainly rather than left to a reader, in
`test_units.py` and `test_media.py`, and pinned as a rule in `test_writing.py`
by the clause whose name ends *…purely_on_which_path_they_sit_at* — identical
bytes at two paths get opposite treatment, so no reading of the file can be what
decided, and a content tie-breaker smuggled in later breaks it.

⛔ **The archive is the one planned directory excluded from the footprint.** An
adapter writes it (R2); its prefix covers the corpus's whole source material,
so owning it would make *"the build's own output"* mean *"everything the reader
has"*. Asked of `Profile.corpus()`, never spelled. ⚠️ `site.json` is NOT
excluded: no pass writes it either, but it is one regenerable cache file, so a
wrong answer costs a rebuild rather than a corpus.

⛔ **A plan carrying any refusal yields a footprint that owns nothing** — the
previous behaviour. An incomplete enumeration is not a footprint, and the
failure mode of a bad plan should be a build that does too little.

⛔ **`replaced` is cross-cutting, like `refused`, not a fourth category.** A
replaced page stays in `pages`, so `Written.paths` diffs against the plan
identically on a first build and a rebuild.

⭐ **The policy is general, not special-cased to edited material** — so the
coordinator's item-3 clause (*a `narrate` run after a build is answered by a
rebuild*) is already carried: clips arrive in the archive, the media pass
copies them, and the unit media directories are in the footprint.

## Surprises

⛔ **The interesting case is the FIRST build, not the rebuild.** The brief
framed the hazard as *a file that IS in the plan's enumeration but that a person
edited by hand since the last build*. ⭐ The measured case is one run earlier: a
foreign `index.html` in an empty output directory, with no prior build at all,
is replaced. There is no history to reason about — which is the clearest
demonstration that the rule is about paths and cannot be about edits. See
`SF-43/1`.

⛔ **Importing the plan's enumeration from a library is a circular import**, and
it fails at interpreter start rather than at the call. `studyforge.cli`'s
package contract imports the dispatcher, which registers `build`. See
`SF-43/2`.

⭐ **A plant survived a green run and corrected the test that let it.** Removing
the *"a refusing plan owns nothing"* fallback changed no verdict, because the
clause broke the corpus at its **manifest** — and a plan with no manifest has no
creations either, so an empty footprint came back for the wrong reason. Breaking
a **container map** instead gives a plan that refuses AND names paths, which is
the only state the fallback affects; the clause now asserts that premise before
asserting the fallback. ⚠️ Seven other plants were caught first time.

## For dependents

- ⛔ **A new write site takes `footprint=` or it will not compile.** It is
  required and keyword-only on both `place` and `copy`, so a pass added later
  cannot reach the disk without answering *whose file is this*.
- ⛔ **`Written` gained `replaced`.** A consumer that renders a build report
  must subtract it from `paths`, or every replaced path prints twice.
- ⭐ **`Corpus.footprint` is already derived** — do not call `footprint_for`
  again in a pass; the corpus is read once and passed down.
- ⚠️ **A test that asserted *"a second build refuses everything"* now asserts
  the opposite.** Four such clauses were rewritten in `generate/` and one in
  `cli/site/`; a branch carrying another will conflict, and the new behaviour
  is the intended one.
- ⛔ **The rule to carry forward is two lines, and it is in
  `generate/writing.py`'s contract**: a path the plan's enumeration names is
  replaced; a path it does not name is refused by name. ⚠️ Nothing opens a file
  to decide, and a change that made it do so should break
  `test_the_same_bytes_are_replaced_or_refused_purely_on_which_path_they_sit_at`.
