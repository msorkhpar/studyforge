## The design

- ⭐ **A pass owns exactly the files it read**: its `material` and its `graders`. `merged`
  replaces the rows of those files and keeps every other committed row as the dict it was
  decoded into, so it re-encodes byte-identical. Rows are sorted as `take` sorts them, so the
  result does not depend on pass order. **Measured:** container A then B, B then A, and one
  pass over both write the same bytes.
- ⛔ **A row leaves only when its file is gone.** `dropped` is exactly the rows whose file is not
  on disk. ⚠️ A file the pass DID re-read owns its rows outright. A fence it no longer carries is
  reported under `changed`, because the page changed and is not gone. That is how I read
  *"a DROP happens only when the page itself is gone"*.
- ⭐ **The pass reports it.** `Authored.ledger` is `Delta(kept, added, changed, dropped)`. Each
  one is a sorted tuple of keys: `example:<path>:<n>` and `tests:<path>` (the `key_of` spelling),
  and `source:<path>` for the file row, so a prose page with no fence still shows.
- ⭐ **`_elsewhere`**: a pass may read a file whose page it was not handed (all material, some
  pages). The exercises of units outside the pass still account for that file's rows. They are
  read from those units' committed `coverage.json`, so a built-on row is never re-excused.
- ⛔ **`writes.commit`'s one exception is `replaces`, and the pass names only the ledger in it.**
  It never replaces a directory. ⚠️ Before this row, a second container's pass was refused here
  (R3). The one way past was to delete the ledger, and that lost every earlier container's rows.
- ⭐ **`validate.ledger`** runs only when `exercises/ledger.json` is committed. The pages it
  checks are every unit's `origin` in every container map, plus every page a committed
  `coverage.json` names. The graders are every other file a coverage report fingerprints. Each
  page must be a file the ledger read. Each fence on it, re-scanned from disk by the same `scan`
  the ledger uses, must have a row. Each grader must have a `tests:` row. Every such row must
  end one way: exercises or a reason, never both and never neither. It reports one finding per
  page or grader and names the first missing row. The skill import is deferred, as
  `membership` defers `skills.adapter`, because `scan` imports `validate.headings`.
- ⭐ **The ledger's committed shape is unchanged: `ledger_api` 1.** A corpus re-runs nothing.

## Decisions

- ⭐ **What "re-read" means: the files handed in as `material` and `graders`**, not the pages
  handed in. The ledger already worked at that grain. A caller passing one container passes
  that container's files, which is the ISO office's workflow.
- ⭐ **`changed` carries a fence that a re-read page no longer carries.** The alternative was to
  refuse the pass. Then editing a page, removing its unit and re-authoring could never shrink
  its row set.
- ⭐ **`validate`'s pages are every unit `origin`, not only the authored containers.** Once a
  ledger is committed, a page it does not account for is a finding, even in a container
  nobody has passed yet. The row's clause says *"every material page"*. See `W456/1`.
- ⭐ **`commit` moved to `writes`** instead of trimming `corpus`, which the merge took to 407
  lines (R11, Ruling 261). It is still exported from the package as `commit`.

## Surprises

- ⚠️ **The base code did not clobber by itself. It refused.** The second pass was stopped by R3

## Findings

### W456/1 `[structural]`: a partly authored corpus now validates RED

Once `exercises/ledger.json` exists, every unit `origin` must be in it. A corpus authored one
container at a time (`M9`) is RED at `validate` until its last container is passed. That is
honest, because those pages are not yet accounted for. But `validate` cannot yet tell *not
authored yet* from *lost*. If staged validation is wanted, the register could scope the check
to containers that hold a `coverage.json`. That would weaken the catch for a container whose
reports were deleted along with its rows.

### W456/2: a row's digest is not compared by `validate`

`validate` requires a row per fence. It does not require the row's digest to match the fence on
disk. A page edited after authoring keeps rows that account for its old bytes, and `validate`
does not say so. A `ledger-stale` rule would be one comparison. It is outside this row.

### W456/3: records that still say to delete the ledger, left unedited

[`AX-08`'s handoff](AX-08.md) and [`W453`'s](W453.md) item 1 both tell a corpus to remove
`exercises/ledger.json`. So does the ISO corpus's `handoffs/ISO-23.md` (the *"to reverse it"*
paragraph). The first two are records. The third belongs to the ISO office. After this row
that instruction is harmful: it recreates `ISO-M10/11`, which `validate` now refuses.

### W456/4: `AX-10/3` still stands

The moved-page refusal still does not name the unit's `practice/` workspace. I changed only its
ledger clause.

### W456/5: `Authored.written` now includes a rewritten ledger

A caller that read `written` as *files created* now also sees the ledger when the pass
rewrote it. `Authored.ledger` is the row-level answer.
