## Decisions

- ⛔ **The key is PER OPTION and not a question-level `key` field**, and that is what makes
  two of the four Acceptance clauses real. A `key` naming one option makes *"exactly one is
  keyed"* true by construction, and *"a question with two keyed options is refused"* becomes
  a clause no document could ever fail — a gate that measures nothing.
- ⛔ **Identity is an `id`, never a position.** A reader's state outlives the document it was
  recorded against; two options reordered by a re-authoring pass would silently turn a
  recorded answer into a **different** answer under positional identity, which is a wrong
  recorded state rather than a lost one. ⭐ Both the question and the option carry one, each
  distinct within its scope.
- ⭐ **`QUIZ_ID` is NARROWER than `cases.CASE_ID`, and the difference is argued.** A case id
  is compared byte for byte with what somebody else's test report spells; a quiz id is ours,
  written by an authoring skill and used to file the reader's own state, so it is a plain
  token. ⚠️ Anchored `\A…\Z` rather than `^…$`, so a trailing newline is refused — `AX-00/1`
  is a live finding and this is the spelling that does not have it.
- ⛔ **`states.py` IS UNTOUCHED, deliberately, and that is the answer rather than an
  omission.** A quiz names no `test_path`, so `state_of` reads it as `UNGRADED` and
  `completes_practice` answers `False` for it in every act — which is the correct answer to
  *"may this RUN complete the practice"*, since a quiz produces no run. ⚠️ Teaching
  `completes_practice` about quizzes would have created the one path spec §7 §7 forbids: a
  run verdict completing a quiz. ⭐ The quiz's own rule is `quiz.completes`, and the two
  never answer the same question about the same practice. ⛔ **This is asserted, not
  argued** — see the table above.
- ⛔ **A quiz is `generated`/`advisory` ALWAYS, and the closure is over the LEGAL pair.**
  `unit.trust` leaves `bundled` + `authoritative` open, correctly, for tests a source really
  ships; a quiz's gates Q1–Q3 are model judgements taken once at authoring and **cannot be
  re-run by whoever holds the bundle**, so the record refuses anything but the one pair.
  ⭐ Stated positively (Ruling 35's shape), so a fourth provenance added to `unit.trust` is
  refused on a quiz the day it is added, without anybody deciding. ⚠️ The reading is taken
  over **every** pair that module admits, not over the one R5 already refuses.
- ⚠️ **`provenance` and `trust` are OPTIONAL on a quiz and are WRITTEN BACK**, which is
  `trust`'s own ruling both ways: a field an author must fill in to say the only thing it may
  say is a field an author fills in wrongly, and a defaulted field that disappears when it is
  obvious cannot be told from one nobody wrote. ⛔ **The cost, stated and asserted:** a quiz
  document omitting the pair round-trips to one carrying it. ⭐ Affordable here and not for
  `kind`, and the difference is measured rather than argued — **the installed base of quiz
  records is zero**, so no document in existence is re-rendered (R10).
- ⭐ **`questions` joins `AUTHORED_KEYS`, so the record's key partition stays three-way.**
  It is an authored key in exactly `AX-00`'s sense: written only where the record carries it,
  never because the record's shape has it.
- ⛔ **`cases` and `report` are still refused on a quiz** — `AX-00` asked for this to be said
  rather than relaxed, and it is said here: they report what a test RUN found, and a quiz has
  no run. A per-question breakdown, if one is ever wanted, is not those two keys.
- ⭐ **Grading NEVER RAISES**, which is `states.completes_practice`'s rule applied to the same
  path. An answer naming an option the question does not offer, an answer naming a question
  the quiz does not ask, a mapping that is not a mapping and no answers at all are each **not
  a correct answer** rather than a failure. ⛔ The refusals live at the boundary, in
  `questions_of`: the record is validated once, when it is read.
- ⭐ **The verdict has one row per QUESTION and never one per answer**, so stale reader state
  cannot add a row, and `complete` is false for a quiz that asks nothing.
- ⭐ **`questions_in` takes the RECORD, not the value** — `cases.origin_in`'s shape and its
  reason: the key is read where it is handed straight to its one reader.
- ⛔ **A question's `origin` is REQUIRED where a record's is optional** (gate Q5): the record
  says what the exercise was built from, and a quiz's questions are built one passage at a
  time.
- ⭐ **The normal form folds NFKC, case and whitespace and nothing else**, stated with its
  limit: `1,000` and `1000` stay two answers, because a normal form that folded them would
  refuse a real question as a duplicate. The narrow form refuses what is certainly the same
  and never guesses.
- ⭐ **A question offers at least two options.** One option is not a question: nothing can be
  ruled out, gate Q3 has no wrong option to refute, and the reader cannot be wrong — which is
  a practice that completes itself.
- ⛔ **`correct` must be a real boolean.** A merely truthy value would make the key depend on
  how a reader of the document coerces it, and the key is what the practice is graded against.

### ⛔ `AX-09` — the panel

- ⭐ **`grade(questions, answers)` and `completes(questions, answers)` are the whole rule**,
  and `answers` is a mapping **question id → option id**. ⛔ **Neither ever raises**: pass the
  reader's stored state in as it is, and anything unrecognised is simply not a correct answer.
  ⚠️ Do not validate that state first — that is what makes this total.
- ⭐ **`Verdict.answered` has one row per QUESTION, in order.** Each row carries
  `chosen` (`None` for unanswered), `correct`, `answered`, and `says` — **the sentence for
  whatever the reader chose**, right or wrong, or `''` for unanswered. ⛔ The word *unanswered*
  is the page's to write; this rule does not word it.
- ⛔ **`Verdict.complete` is the ONLY completion predicate for a quiz.** Do not call
  `states.completes_practice` for one — it answers `False` in every act by design, because a
  quiz produces no run, and that is asserted in `test_grading.py`. ⚠️ **Recording completion
  is yours and `AX-02`'s**, through the reader's own state; nothing here touches `progress`.
- ⛔ **`AX-05/3` is yours and it is MEASURED, not predicted**: the panel offers a **Run
  button** for a quiz today and renders no grader label. `Exercise.is_quiz` is the branch, and
  the §9 sentence for `generated`/`advisory` + `quiz` is *"Written for this site from this
  page."*
- ⚠️ **`Exercise.graded` is `False` for a quiz**, because `graded` means *a grader runs*.
  ⛔ Do not read it as *"nothing checks this"* on a quiz page — the key checks it. Read
  `is_quiz` first.
- ⭐ **The key is IN the document and the page must not pretend otherwise** (R5's theatre
  clause). Show the reader the answer once they have answered; there is no scrubbing pass and
  no flag that removes `correct`, and asking for one would be the pretence.
- ⭐ **`normalised` is exported** if you need to compare what a reader typed; it folds NFKC,
  case and whitespace and nothing else.

### ⛔ `AX-06` — the quiz authoring gates

  ⭐ **Your row is the gate RECORD and `validate` re-running them** — do not re-spell the
