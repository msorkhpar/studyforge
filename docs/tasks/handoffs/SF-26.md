## Decisions

### ⛔ The index's isolation is OBSERVED, not argued — and that is why it has teeth

⚠️ **`tests/studyforge/render/index/test_init.py` already asserts this clause**
(*"the page is built from the two documents and nothing else"*), and it is the
right test — ⛔ **but it cannot fail when the rule is violated.** It writes the
two documents into an empty directory and renders from them, while **the real
corpus is still on disk**: a renderer that opened an absolute path into
`tests/fixtures/depth1/` would pass it, and produce **identical bytes**.

⭐ So the harness observes instead, with the interpreter's own audit hook. The
population is three paths and the claim is legible in them:

```
index: 3 read(s), 0 spawn(s)
  read   open	/tmp/pytest-…/toc.json
  read   open	/tmp/pytest-…/status.json
  read   open	/workspace/src/studyforge/render/templates/page.html
  made   1059 bytes, sha256 b65aef59…
```

⛔ **The planted subject produces the SAME sha256.** That is the whole argument
for the mechanism, and it is printed side by side in the test output: a renderer
that reaches the corpus is invisible to every byte comparison in the suite, the
goldens included, and visible only here.

⚠️ **`sys.addaudithook` cannot be removed once installed**, so the probe is a
**child process** rather than a fixture. A hook installed in the pytest process
would observe every test that ran afterwards.

### ⭐ The probe says what it PRODUCED, because an empty population reads as a pass

⛔ **Ruling 191, at the exact place it bites.** A probe that silently rendered
nothing reports `opened: []` — which is indistinguishable from a renderer that
read nothing, and the second is this check's pass reading. So every rendering
subject returns a digest and a length, and the test asserts the digest **equals
the committed golden's** before it reads the verdict.

### ⛔ The census, and why `orphans` and `collisions` are separate from the comparison

⚠️ **Three renderers already compare their own goldens.** What nothing asserted
was the shape *between* them. ⭐ A golden nobody regenerates is compared against
nothing, so it is evidence of nothing, and it outlives the renderer that wrote
it. ⛔ And a **collision** — two cases naming one file — satisfies *"every case
has a golden"* **and** *"every golden has a case"* while pinning only the case
that writes last. **Ruling 187: asserted in both directions proves surjectivity,
never injectivity**, and the goldens are exactly the shape where that matters,
because `Case.golden` is **derived from a title** through `placement`, which is
`slugify`'s collision arriving from a third direction (`SF-25`'s own finding).

### ⭐ `authorable ⊆ scanned`, the subset and never the equality

⛔ **Ruling 192, and the direction is load-bearing.** The control-character census
is derived from what the tree **emits**, and that is blind to what the tree can
**author**: a stylesheet part no bundle includes, or a template no renderer
fills, carries its control byte invisibly until something starts emitting it —
and that day is the day nobody is looking. ⚠️ Equality is the wrong assertion
because an emitted stream has no single authorable source: a bundle is thirteen
parts, a page is a template plus a document. `authorable ⊄ scanned` is the only
direction that can hide a file.

### ⛔ Unicode category `Cc`, not `byte < 0x20`

⚠️ The C1 control block is **two bytes** in UTF-8, so a byte scan sees `0xc2 0x85`
and reports nothing while the page carries a NEL. ⭐ The planted reading includes
that case precisely because it is the one a byte scan passes, and the three
allowed characters are `\t`, `\n`, `\r` by the epic's own words.

### ⭐ Three doors per isolation assertion, and a lookalike for each

⛔ **A check that watched one spelling would be walked around by whichever of the
others the next author reached for.** `import subprocess`; `os.system(...)`;
`from os import execv` then `execv(...)`. ⚠️ And the third reading is a
**lookalike that must NOT be reported** — `json.loads`, a local function called
`system`, the word inside a string, an attribute called `fork` on something else
— because a negative check's pass reading and its broken reading are the same
empty list, and only a subject that *contains the search term without being the
thing* separates them.

### ⛔ Ruling 178's two rows, recorded separately — and the relative one is a POPULATION argument

⚠️ **Two of these sweeps ask *"does this reach module X?"***, which is exactly the
class Ruling 178 binds: the relative form is the shorter spelling, so it is the one
a hurried author reaches for, and `ast.ImportFrom.module` has the dots removed.
⛔ **Both rows are recorded, and they are not the same row:**

- **row 2b, absolute through the module's own name** — `from subprocess import run`
  and `from importlib.util import find_spec` are both planted and both caught, by
  the root **and** by the bare name they introduce. ⭐ Two reports from one module,
  which is how I found out my own `== 1` assertion was asserting the wrong thing.
- **row 2, relative** — ⛔ `spawn_reach` does **not** report `from . import helper`,
  and that is correct rather than a hole: a relative import can only reach *inside*
  the package, so it is not itself a way out. ⭐ What makes it sound is that the
  sibling it reaches is **in the same population**, and the absolute import it must
  contain is caught there. ⚠️ **Asserted as a reading rather than argued**:
  `test_the_relative_door_is_covered_by_quantifying_over_the_package` hands the
  sweep two modules and asserts **1** report, naming the sibling — and asserts the
  relative importer **alone** is silent, which is the half a disjunction would have
  hidden (Ruling 178's second clause).

⚠️ **`level == 0` in `foreign_imports` is the sound filter, not this defect**, and
the rubric says so in §7b-i: that sweep's question is *"does this reach a non-stdlib
third party?"*, which a relative import cannot do. ⭐ A relative import is in the
lookalikes for it, so the distinction is a reading too.

### ⛔ The third R1 door is new, and it is the one the closed set cannot see

⭐ **`importlib.import_module(name)` is in the standard library.** So a framework
module could reach a corpus-specific package with **no import statement** for the
closed-set check to catch and **no corpus name** for `tools/quality`'s sweep to
find. ⚠️ Asserted **empty** rather than policed: a framework that never needs a
run-time import is a stronger statement than a list of permitted ones, and the
measurement says it is true today — `0` dynamic imports across **165** framework
modules.

**3. ⛔ My own plant contradicted me a SECOND time, and the assertion was the
thing that was wrong.** Predicted: each spawn door reports **exactly one** finding.
**Measured:** `from subprocess import run` reports **two** — `imports subprocess`
from the root, and `subprocess.run, imported bare` from the name — because that
subject walks through two doors at once. ⭐ `== 1` was asserting *which* doors a
subject happens to open rather than that each door is watched; it is `>= 1` now,
with every report required to name the module. ⚠️ Same shape for
`from importlib.util import find_spec`.

**4. ⭐ Only `page.html` is opened during an index render.** I expected several
templates. `render.index` composes its rows in code and fills exactly one
template, which is a fact about where `SF-34`'s `STYLE_PARTS` boundary sits
rather than a defect — recorded because the population looked too small and I
spent a measurement confirming it was right.

**5. ⚠️ Templates are re-read from disk on EVERY `templates.fill` call** — there
is no cache — so the index's steady-state read set includes `page.html` and the
allowed set has to say so. ⛔ Not a defect (R10 is unaffected; the bytes are
identical), but it is the reason the probe's allowed roots include the framework's
own package directory rather than being *only* the two documents.

**6. ⚠️ The pinned image redirects the bytecode cache out of the workspace**
(`sys.pycache_prefix` = `/tmp/pycache`), and a first-run `.pyc` read would have
appeared in the probe's record as a path outside every allowed root. ⛔ Fixed by
reading `sys.pycache_prefix` — the interpreter's own attribute — rather than by
warming the render first, which would have hidden a renderer that cached a corpus
read. A flake avoided and no strength given up.
