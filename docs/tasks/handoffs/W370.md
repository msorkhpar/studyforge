## What landed

- ⭐ **The decision, in `E05` § `SF-22`** — the section `SF-24` depends on and whose output it
  reads: the server adds the client; the built panel only reads `window.studyforge.run` after
  `DOMContentLoaded`, and its absence or `available()` false is the `file://` floor, where no
  Run and no Submit are drawn.
- ⭐ **The enforcement, in R8's floor**: a third reading beside *names the serving origin* and
  *a reference that resolves to no file*. It is derived from the route's own constants, so the
  served path and the file cannot move without the floor following.

## Decisions

- ⭐ **Server insertion over every alternative**, because each alternative puts the client's
  address in the build: a rooted `<script src>` names the API; a relative path joined to
  `location.origin` loads it while naming no origin; a copy of the client names the API on every
  line. Only the server knows it is one.
- ⭐ **The floor matches names, not loads.** `run/client.js` and `run-client.js`, each bounded so
  `prerun/client.js`, `run/client.json`, `run/client.jsx` and `my-run-client.js` read green.
- ⚠️ **The insertion is decided, not built.** It needs a change to the static route
  (`serve/routes/assets.py`, `SF-19a`'s), which is outside this row; `E05` says it lands with its
  first consumer, `SF-24`, with the served page's validator taken over the served bytes.

## Surprises

- ⚠️ **A bare `<script src="run-client.js">` in a page was already RED** — as *no such file* — so
  the plant for the file name is a script string, where the reference reader does not look.
