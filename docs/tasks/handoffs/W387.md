## What landed

⭐ **What the software does now that it did not:** `docker/minimal/build.py --runtimes
java,cobol` exits 2 with `refused: ['cobol'] not pinned in pins.json, so the runner cannot build
it; the pinned runtimes are [...]`. Before, it said how many names were unpinned and never which.
A name not shaped like a runtime id (`^[a-z][a-z0-9-]{0,31}$`, the editor's `_NAME`) is refused
first, with only the pinned list, so nothing malformed that arrived is ever echoed. The runner
and the editor now answer the same mistake the same way (`TC-02/2`).

## Decisions

- ⭐ **The shape check comes before the duplicate and the unpinned checks.** Every later refusal
  may then echo a name, knowing it is id-shaped. That is the editor's order.
- ⭐ **The pattern is written in both components, and a test holds them equal.** The runner
  cannot import the editor's module (the dependency runs the other way: the editor plans the
  runner). `test_the_runner_and_the_editor_accept_the_same_id_shape` reads the editor's
  `_NAME` from its source and compares it with `plan.NAME`, so a change to either one alone is RED.
- ⭐ **The wording follows the editor's form:** `<list> not pinned in pins.json, so the <component>
  cannot <verb> it; the pinned runtimes are <list>`.
