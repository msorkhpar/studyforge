### What the new instrument reads, and against what

- **Every Python fence on the page is parsed.** Every `studyforge` import must resolve, and
  every call to a name it imported must **bind** to the callable's real signature
  (`inspect.signature(...).bind`). So a renamed function, a dropped required field or an
  invented keyword fails. Three planted fences (a missing name, a field left out, an invented
  keyword) are parametrized controls that must go RED, and each fence must bind at least one
  call, so no fence is read vacuously.
- **Every dotted name the procedure uses** (`brief.places.workspace`, `authored.shortfalls`,
  `emission.document`, …) is walked through the real classes' annotations.
- **The worked corpus is re-computed**, not trusted: `authoring.write_corpus` into a temporary
  directory, then `take`, `source_case`, `plan_for` and `accounts_for`. The page's case, band
  and plan table and its ledger table are compared both ways.
- **Closed sets both ways**: `SOURCE_CASES`, both registered gate families (derived from
  `gates.registered()`), `BANDS` in order, `TIERS` with `TIER_MOVES`, the fields of `CodeDraft`
  and of `Brief`, `SHORTFALL_REPORT_KEYS`, and the six paths a pass writes (computed from
  `Places` and substituted to placeholders, `W330`'s shape).
- **The `not_material` fence** is merged into a real manifest and parsed at `corpus_api` 2,
  and refused at 1. That is the guide's *needs 2 or later*, read rather than asserted.
- **`ATTEMPTS` is named and never counted**: a regex refuses a number word or digit before
  *attempts/drafts/tries/retries* anywhere on the page.
- **The struck sentence is absent**, and *Author, then prove* names every gate id of every
  registered family.

## Decisions

1. ⛔ **A SIBLING MODULE, NOT A PACKAGE.** `tests/test_authoring_reference.py` is at its R11
   bound, and the brief said to split rather than trim. ⭐ The precedent in this tree is
   `W117/2` and `W330`'s `tests/test_authoring_geography.py`: a sibling at a named seam. The
   reference module reads the **record vocabularies** (keys, checks, rule ids), and this one
   reads the **authoring procedure** (the skill package and the worked corpus). ⚠️ Turning the
   reference module into a package would have broken the gate command's path and the index's
   citation of it, for no gain. Nothing in `tests/test_authoring_reference.py` changed.
2. ⭐ **The worked example is `AX-08`'s corpus, and the guide says so by path.** It is the
   only corpus on disk that carries all three cases and a quiz page, and it is already run
   end to end by `test_corpus.py`. The guide's tables about it are re-computed, so a fixture
   edit shows up as a red instrument rather than a stale page.
3. ⛔ **THE DRIVING SCRIPT IS PYTHON, AND THE PAGE SAYS THERE IS NO COMMAND.** `AX-08`'s note
   was right: no console entry point exists. No fence gives a command for the pass, and the
   existing console-script and runnable-module checks keep it that way.
4. ⚠️ **The judge fence calls a function the reader writes** (`ask_an_independent_pass`), and
   the page says so. It is not a `studyforge` name, so the bind check does not read it, and it
   is the one honest placeholder on the page.
5. ⛔ **The page states what `validate` does NOT do.** It does not re-run the tests and it
   does not check `G5` or `Q5` against the source again. That is what the code does, even
   though spec §7 §7 says otherwise (`AX-10/2`).
6. ⭐ **The page's ledger table shows the worked corpus's test file carried by a written
   reason**, because that is what the code does (`AX-10/1`). Writing that it was *built on*
   would have been the natural sentence, and a false one.
