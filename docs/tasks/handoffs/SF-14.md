## Decisions

### ⛔ 1. Which side of Ruling 164's fork this is — CONTENT, so a refused href RAISES

⭐ **The ruling's own table already answers it** — *"CONTENT — a container's unit
list, **the root index's tree** → RAISE"* — and the module states the argument
rather than citing the ruling:

> ⛔ *If this element vanishes, has the reader lost a WAY TO GET SOMEWHERE, or has
> the page lost THE THING IT EXISTS TO SHOW?*

⛔ **This page is nothing but its tree.** A dropped anchor here is every title
present, `validate` passing, nothing logged, and not one unit openable **from the
page a reader lands on first** — `SF-13/1`'s defect with the blast radius of the
whole corpus. ⚠️ `page.navigation._link` **drops** and is right to: a bar is
chrome, and the reader still has the outline, the masthead and the page.
⭐ `render.container.listing` reaches the same answer for the same reason one page
along, so the three are consistent **by argument** rather than by imitation.

⚠️ **And absence is the third state, not a quiet version of either.**
`Item(href=None)` is a unit this machine has no page for: listed,
`data-readable="false"`, and raising nothing (§7). ⛔ **The type is what makes the
rule applicable rather than a coin toss** — a renderer that could not tell *"no
page yet"* from *"bad href"* would always pick the wrong one.

⭐ **Sweep row `M1` is that decision inverted and it dies twice; `M2` is its
mirror** — the declared-absence path deleted — **and it dies 15 times.**

### ⛔ 2. `from_contents` lives in the package, and that is what makes the acceptance clause true

⚠️ **E03: *"It reads only the two contents documents — never the filesystem,
never a catalog. That isolation is the point."*** ⛔ Left to the caller — which is
what `render.container` does with its `Document` — the clause would be a claim
about *a caller*, and every consumer would retype the same twenty lines, which
R19 calls a hole in the thing that should have produced it.

⭐ **So the mapping is here, and the isolation is asserted two ways:**

- **behaviourally** — `test_the_page_is_built_from_the_two_documents_and_nothing_else`
  writes `toc.json` and `status.json` into a `tmp_path`, asserts that directory
  holds **exactly those two files**, reads them back through the real readers,
  renders, and compares with the **committed golden**;
- **over the source** — `test_assemble.py`'s AST sweep: no module of this package
  imports a corpus reader, `os`, `io`, `glob`, `shutil` or `subprocess`; none
  calls `open`, `read_text`, `rglob` or their siblings; and the only name taken
  from `pathlib` is `PurePosixPath`, because `Path` opens files and it cannot.

⚠️ **The limit is stated rather than discovered** (Ruling 56): the *corpus* input
is those two documents. The package still loads this framework's own page
skeleton and asset names, as every renderer does, and neither carries anything
about any corpus (R1).

⛔ **The pair is JOINED, never zipped.** `contents.join` refuses a stale pair
naming which half it is; `M14` defeats it and dies.

### ⛔ 3. The default open/closed policy is computed, and the constant is a claim about a READER

⭐ **A one-level corpus and a four-level one want opposite defaults and neither
wants a flag.** A level starts open exactly when opening it — and every level
above it — leaves the rows the page shows at once inside `VISIBLE_ROW_BUDGET`.

⛔ **The top level is visible before anything can expand**, so the policy opens
*levels* rather than deciding whether to render one; a corpus with more top
containers than the budget still renders all of them.

⚠️ **Why a bare integer here is not what Ruling 165 clause 4 forbids:** that
clause is about a bare integer in an **Acceptance**, where it is a corpus reading
wearing a number. ⭐ This one is not a reading of any corpus — it is roughly two
screenfuls of the reading column, the same for every corpus this framework will
build — and it is **published**, with `row_counts` and `visible_rows` beside it,
so a test sits exactly on the boundary and the population is readable before it
is a verdict. ⛔ `test_one_more_row_at_the_boundary_closes_the_level` is the
negative control, and `M11` (`>` → `>=`) dies on it.

### ⛔ 4. The root index carries NO identity block, and nothing looks for one

⚠️ **R4's block answers *which unit or container is this*, and the index is
neither.** `placement.identity.KINDS` holds exactly two members and an `Identity`
requires a non-empty address; there is no address the page *about* every address
could give. ⭐ **Checked rather than assumed:** `scan` globs the two page suffixes
this framework mints, and `is_unit_page(ROOT_INDEX_FILENAME)` and
`is_container_page(ROOT_INDEX_FILENAME)` are **both false** — so the index is
outside every scan's population, by name, before a file is opened. ⛔ Minting a
third kind would be an `identity_api` change made to satisfy a rule that does not
reach this page, in a package this task does not own. `SF-14/6`.

### ⛔ 5. Six of the eleven skeleton slots are empty, and each absence is a FACT

⭐ **The skeleton is `page.html`, the unit page's own** — `SF-27`'s ruling one
page further, and E03's *"share the palette and type stack by importing them
rather than restating them"* taken as far as it goes. ⛔ `identity`, `meta`,
`nav`, `outline`, `pending` and `player` are passed `""` **by name**, so the day
the skeleton gains or drops a slot this module fails by name.
`test_document.py` asserts `EMPTY_SLOTS | FILLED_SLOTS == templates.placeholders`
on **both** sides, so neither list can drift alone.

⚠️ **`meta` empty is a decision, not an oversight**: a second masthead line would
be this framework's own sentence about a corpus, and there is no corpus datum for
it the tree does not already say (R1).

### ⛔ 6. A row's anchor IS its unit key, and `anchor()` is the one composer

⭐ Every row and every section carries the key the rest of the framework joins on,
so **the disclosures standing between a deep link and its target are exactly the
prefixes of the link's own fragment** — no table to consult, nothing to mint.
⛔ The target of a deep link is the row **inside** its disclosures, never the
disclosure itself, which is what lets a user agent implementing the HTML
Standard's auto-expanding `details` open every ancestor on fragment navigation.

⚠️ **What this does NOT guarantee, stated in the module** (Ruling 56): that a user
agent opens them. ⭐ Where one does not, the reader lands on the section holding
the target — every ancestor addressable, focusable and one keystroke from open —
rather than on nothing. ⛔ **And no script is involved either way**, which is why
*works with JavaScript disabled* holds in its strongest form: there is nothing to
disable. That is also subtask (d) discharged — an enhancement gated on protocol
is one that can be absent, and the one that is absent here cannot be a
dependency.

### ⭐ 7. The index needs no placement profile at all, and that is asserted

`Profile.corpus()` is identical under every registered profile, so `Placement`
holds **one** field. `test_the_index_needs_no_placement_profile_at_all` renders
the same document under **every** registered profile and asserts one distinct
byte string. ⚠️ The unit **hrefs** still differ between corpora, because the
profile's answer was already recorded in `Entry.page` — which is the whole reason
the two documents are sufficient.

### ⚠️ Writing an R7 test is how you find out the R7 checker reads Python attributes

⛔ **The quality floor refused a dataclass field named `local`, read as *"a local

⭐ The guard was written for `settings.<the word>.json` — a trailing `.` — and an
attribute access at the **end of an expression** is outside it. Renamed the field
to `status` and filed `SF-14/4`.

⚠️ **This handoff cannot spell the shape either**, which is the finding
demonstrating itself: every probe below is written with a placeholder for the
same reason `docs/conventions/personal-data-shapes.md` stores its examples as
fragments.

⚠️ **And it refused four real home-path literals in my own tests, correctly.** The
fix is the technique `docs/conventions/personal-data-shapes.md` already uses on
itself: the path is stored as **fragments** and joined
(`indexes.A_HOME_PATH`). ⛔ A test that proves a refusal does not echo a home path
cannot itself write one.

### ⚠️ `depth1`'s and `depth2`'s trees are too small to collapse, so the collapsed case is PLANTED

⛔ Both fixtures render entirely open — 4 and 9 visible rows against a budget of
60 — so *"working deep links into **collapsed** sections"* could not be
discharged against a fixture at all. ⭐ `indexes.planted(shape)` builds a corpus
of a declared shape through the **real** manifest and container readers;
`(10, 5, 10)` is the row that closes level 2, and the acceptance test asserts
`open_to(document) < document.depth` **before** it looks at anything, so it
cannot silently degrade into the easy case.

### ⚠️ `docker/dev/check` captures buildkit's progress on stdout, and it landed in a readings file

⛔ My first reading counted **139** lines where the bands hold **86**: 53 of them
were `#1 [internal] load …`. ⭐ Caught because the number could not be right;
fixed by filtering the harness's capture to the band prefixes. ⚠️ Recorded because
any harness that pipes `docker/dev/check` into a diff will hit it, and the noise

### SF-14/3 `[structural]` — ⛔ the root index cannot link a section to its container page, because the contents do not record one

⛔ **`contents.Entry` carries `page`; `contents.Group` carries `level`, `segment`,

  `ENTRY_KEYS` carries `page`. `git grep -n 'container_page_name' -- src/` reaches
  `corpus/placement/names.py` and `corpus/placement/{tree,sibling}.py` and nothing
  in `contents/`.
- **Measured, and this is why it is not merely cosmetic:** `SF-27`'s own handoff
  says *"a container page's **up** link is the root index"* — so the edge exists
  in one direction only, and the reader who lands on the index has no way to
  reach a container page at all.
- **Received** from `E03-rendering.md`: this page reads *only* the two contents
  documents, so composing the container page's filename here — even though

- ⛔ **Not fixed here:** `contents/` is `SF-13`'s, and a new key in the stable

- ⭐ **Why structural:** every corpus of depth ≥ 1 has container pages and no

  renders, every unit opens, `validate` passes, and the missing edge is invisible

### SF-14/4 `[local]` — ⚠️ the quality floor's hostname shape fires on a Python attribute named `local`

⛔ **`tools/quality/personal_data/shapes.py`'s *local hostname* pattern —

`<object>.<the word>)` as readily as it matches `<host>.<the word>`.**
⚠️ **Every probe below is written with placeholders, because a document that
spelled them would be a finding against itself — which is this finding, twice.**

- **Measured** at `9b9a695`, 2026-09-10 — **[measured]**: the pattern against six
  probes returns **True** for `<object>.<the word>)`, `<object>.<the word>,`,
  `x = <object>.<the word>` and `toc.<the word>`, and **False** for
  `settings.<the word>.json` and `self.<the word>_status`.
- **Measured:** the floor reported **3** such findings in my own test tree before
  I renamed the field, at `quality floor: 10 findings`.
- ⭐ The trailing guard's own comment says it exists to keep `settings.local.json`

- ⛔ **Not fixed here**, and not worked around silently either: the field is named
  `status`, which is honest on its own terms. `tools/quality/` is outside this

  side alone is not a developer's call.
- ⚠️ **Marked local rather than structural:** it is one lookahead in one pattern,

  shipped source, and a checker people rename fields around is a checker on its

  is git-ignored at the corpus root; the page is found by **name**, which is what
  `ROOT_INDEX_FILENAME`'s own comment — *"named here so nothing else mints a
  second one"* — already establishes.
- ⭐ **Why it is worth a line at all:** R4 says every generated artifact carries
  its identity, and the one page that does not is exactly the shape a later
  reader will file as a defect. ⛔ It is not one **today**; it becomes one the
  moment anything scans for `index.html`, and the remedy then is a third `KIND`,
  which is an `identity_api` bump.

## For dependents

### ⭐ `SF-28` — the build

- ⛔ **This package writes nothing.** `render(document, placement)` returns bytes
  and `placement.shared.root_index` says where they go; the write is yours.
  ⚠️ `studyforge plan` already lists the root index — `cli/plan/derive.py`'s
  `Creation(where.root_index.as_posix(), "the root index")` — so the path is
  agreed on both sides.
- ⭐ **Assembling the document is one call**, and it is `from_contents(contents,
  status, placement)`. ⛔ **Do not walk the two documents yourself** — `join` is
  what refuses a stale pair, and this package calls it.
- ⛔ **The order matters:** the pages must exist before `contents.found(site,
  corpus)` can say so, and the index must be rendered **after** that scan, or
  every unit renders `data-readable="false"`. ⚠️ There is no way for this
  renderer to tell a build that ran the two steps the wrong way round from a
  corpus that genuinely has no pages yet.
- ⛔ **`status.json`'s producer is you or `SF-14`'s caller**, per `SF-13`'s
  *For dependents*: `toc.status(built, toc.found(site, corpus), read=…)` then
  `toc.write_status(path, local)`.

### ⭐ `SF-15` — in-page navigation

- ⭐ **A deep link into the index is `index.anchor(key)` appended to the index's
  href** — `#<unit key>`, the key `Address.unit_key` mints. ⛔ **Ask, never
  compose**; the fragment's shape lives in one function on purpose.
- ⚠️ **`contents.order.links`' `index` slot carries no fragment today**, so a unit
  page's *up* link lands on the top of the index rather than on that unit's row.
  ⭐ That is a one-line change in `contents/order.py` — `_link(...)` plus
  `anchor(key)` — and it is **yours or `SF-13`'s**, not this package's: `contents`
  must not import `render` (its own `test_order` asserts that), so the fragment
  has to be appended by whoever builds the `Links`.
- ⛔ **A section's summary is not a link**, and `SF-14/3` says why.

### ⭐ `SF-34` — page chrome styles

- ⛔ **Read `SF-27/2` and then `SF-14/1`.** There is now a **fifth** region: the
  root index's tree, `<nav aria-label="Contents">` around nested `<ol>`s of
  `<details>`/`<summary>`.
- ⭐ **Its hooks, and none of them is a class:** `data-readable` (`"true"`/
  `"false"`) on every unit row, `data-kind="numbering"` on the numbering span,
  `data-kind="level"` on the corpus's own word for a section's depth, and an `id`
  on **every** row and **every** disclosure.
- ⚠️ **Those ids contain `/`.** They are valid HTML ids and valid URL fragments,
  and `document.getElementById` handles them — ⛔ but a CSS selector must escape
  the slash (`#basics\/01-intro`), so reach them by attribute selector or by
  `:target` rather than by id selector.
- ⛔ **A closed disclosure must be visibly different from an open one, and a
  `data-readable="false"` row from a link.** Today nothing paints either, and
  `tests/visual/` cannot see this page at all.
