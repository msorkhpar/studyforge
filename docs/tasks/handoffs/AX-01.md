### ⭐ The surface, in one block

```python
from studyforge.exercise import Breakdown, breakdown_of

started = time.time()  # BEFORE the run is started
...  # the run
breakdown = breakdown_of(exercise, source_root, where, started=started)

breakdown.ask  # bool  — did the main ask pass
breakdown.edges_passed  # int   — n of "edge cases n/m"
breakdown.edges_total  # int   — m
breakdown.failed_edges  # tuple[str, ...] — each failed edge's `says`, in declared order
breakdown.complete  # bool  — every declared case passed
breakdown.cases  # tuple[Case, ...] — as the corpus wrote them
breakdown.passed(case)  # bool  — one case's verdict
```

## Decisions

- ⛔ **`started` is a PARAMETER and is never inferred.** The stale clause is a claim about
  time, and the only clock that can settle it is the one the **run** was started on. ⭐ The
  alternative — comparing the report against its own neighbours, or against the record's
  files — measures the corpus rather than the run, and every such comparison is green for a
  report that no run this session produced. ⚠️ So this module never starts a run and never
  imports `execute`; a caller that has a run hands over the reading it already had.
- ⛔ **Every mtime is read BEFORE any file is parsed**, and that ordering is the Acceptance's
  word *"never read"* made structural rather than asserted. ⭐ **A second property falls out
  of it, and it is worth naming:** the only JUnit this module ever parses was written by a
  run that just happened, so an XML document a corpus **committed** at the declared path is
  refused unparsed — which matters, because `xml.etree` is not hardened against a hostile
  document and the standard library is all this framework may use.
- ⚠️ **`CLOCK_SLACK` is a measurement tolerance, not a grace period**, and it is named so the
  reason cannot be mistaken: a filesystem with coarse timestamps can stamp a file written
  *during* the run with a time before it, and a false *stale* would refuse a run that really
  did write its report. ⛔ It is seconds wide and a stale report is a previous run's, so
  nothing the clause exists to catch survives it. Both directions have a reading.
- ⛔ **The pass set is closed on the PASSING side** (Ruling 8, *enumerate the legal*):
  `PASSING_CHILDREN` is what a testcase that passed may still carry — `system-out`,
  `system-err`, `properties` — and **not** a list of the children that mean failure.
  ⭐ A verdict element this build has never seen, `rerunFailure` among them, therefore reads
  as *did not pass* instead of walking through an unfinished list of failure tags. That is
  the difference between the two lists in one line of code, and it has its own test.
- ⭐ **A declared case the report never names did not pass, and that is not a refusal.** A run
  that stops early names fewer tests; the honest breakdown is *edge cases 1/2* with the
  missing edge named by its `says`. ⚠️ Refusing here would turn every partial run into an
  error and tell the reader nothing about the part that did run.
- ⛔ **A test the map does not name IS a refusal**, and the asymmetry above is deliberate. The
  silent alternative turns a report of four results into *edge cases 1/1* — green, and a lie
  about what ran. ⚠️ **The cost is stated:** the declared path must hold this exercise's
  report and nothing else, so a surefire directory shared with an unrelated test class is
  refused. That is `AX-03`'s gate G4 defect, caught here too, because a gate that runs at
  authoring time does not run on the reader's machine.
- ⭐ **Three id spellings, and none of them is repaired**: a pytest node id
  (`file::Class::name`), a JUnit one (the class, a number sign, the method), and the bare
  `name` a runner that reports neither leaves. Each is compared byte for byte.
  ⛔ **One element that two cases each claim is refused** — no result can be attributed, and
  attributing it to the first would be a coin toss written down.
- ⛔ **The declared id is taken APART; no spelling is composed from the report.** `_spells`
  asks *does this testcase spell THIS case's id*, reading the declared value with
  `rpartition`, rather than building `Class#method` out of two attributes and testing
  membership. ⭐ It is the honest direction — the case map is the authority and nothing
  invents a string to test it against — ⚠️ **and it is also what `W107`'s tree sweep
  requires**; see the surprise below.
- ⚠️ **`_node_id` is RE-SPELLED, not imported.** `tools.quality.gated._node_id` has read this
  repository's own reports since `W309` and is the same rebuild — but `src/` never imports
  the developer tooling, so the seam is a citation in the docstring rather than a dependency.
- ⭐ **A file or a directory, read off the DISK rather than off the format token.** Surefire
  writes a directory of `TEST-*.xml` and pytest writes one file; `AX-00` left that decision
  here. ⛔ The directory sweep is `*.xml` and **not recursive**: descending would pull in a
  nested module's report, which is exactly the unrelated test this module refuses to count.
- ⛔ **`Breakdown` carries two things and derives the rest** — the cases in the order the
  corpus wrote them, and the ids that passed. Every number a reader is shown is a property
  over those two, so there is no second place a count can disagree with the case map.
- ⭐ **A `report.format` outside `JUNIT` is refused**, a sixth refusal beyond the five the
  Acceptance names and a cheap one: the set is closed at one, an `Exercise` is frozen rather
  than validated, and the refusal is where a second format's reader is added.
- ⭐ **A refusal names the declared path, and that is not a departure from R7.** The path
  passed `safety.require_path` before the record was accepted — no absolute form, no `..`,
  no backslash — so it **cannot** carry a home directory, and *"a malformed report is a named
  failure"* is unsatisfiable if the failure may not name the file. ⛔ Everything else is
  withheld as this package already withholds it: no case id, no test name, no XML element
  name, and a parse failure gives its **position** rather than the parser's sentence.

## For dependents

### ⛔ `AX-02` — Submit records the breakdown

- ⭐ **`started` is yours to take, and it is taken BEFORE the run.** `time.time()` on the
  wall clock, in the same process that starts the run, handed to `breakdown_of` afterwards.
  ⛔ **Do not take it after the run and do not read it off the record or the report** — the
  whole stale clause is the comparison between those two numbers, and a `started` sampled
  after the run makes every report look fresh, including the previous run's.
- ⛔ **`None` is the answer twice and neither is an error**, so a `None` is recorded as *no
  breakdown* and never as a failure: the record declares no breakdown (`breaks_down` is false
  — every exercise shipped before `M10`), or the run wrote no report (a compile failure
  writes no surefire file). ⭐ Your Acceptance's *"a run with no report records no breakdown"*
  is this return value and needs nothing else from you.
- ⚠️ **Everything else raises `ExerciseError`**, and a raise means *this run's breakdown
  cannot be stated honestly* — stale, malformed, unreadable, a test the map does not name, a
  format this build cannot read. ⛔ **Decide what a Submit does with that and write it down**:
  recording no breakdown is defensible, and swallowing the sentence is not. The message is
  R7-clean and safe to log.
- ⛔ **`is_pass` is untouched by this task and must stay untouched by yours.** A breakdown is
  a **report**, never a second definition of a pass: `breakdown.complete` is `True` exactly
  when every declared case passed, and it is not the pass rule — a test-mode run that exited
  zero is. ⚠️ A reader shown *edge cases 2/3* is looking at an incomplete practice.
- ⭐ **What to record, if `last.cases` is to be re-read rather than re-derived:** the four
  numbers a reader is shown are `ask`, `edges_passed`, `edges_total` and `failed_edges`, and
  **all four are derived** from `breakdown.cases` plus `breakdown.passed(case)`. ⛔ Record the
  per-case verdicts and derive the counts, or record the counts and never both — two spellings
  of one claim is the defect `describe` was extracted over.
- ⚠️ **A `says` is reader-facing corpus text** and is already in the practice document, so a
  progress document that copies it carries the same sentence twice and goes stale when the
  corpus is regenerated. ⭐ **The id is the stable key**; `says` is a rendering.
