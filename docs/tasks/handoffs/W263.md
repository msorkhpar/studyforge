## What landed

- [`validate/blocks.py`](../../../src/studyforge/validate/blocks.py): ONE reader,
  `list_problems(blocks)`. It walks every `list` block, top-level, inside container blocks and
  nested in items, and names by path where one breaks [spec §6](../../specs/2026-09-08-studyforge-v1-design.md#6-the-ingestion-contract):
  its keys (the fields, then only `start`), an item that is not a string or an array of strings
  and whole lists, or a `start` that is not an integer (`0` allowed).
- `check_list_blocks` yields each as a `document` finding, exit `1`, after `check_counts` in
  [`structure.py`](../../../src/studyforge/validate/structure.py)'s `CHECKS`.
- [`fixture_checks/shape.py`](../../../tests/fixture_checks/shape.py): `check_blocks` reads a
  `list` block through that same function, called on its module, and accepts a type's
  `BLOCK_OPTIONAL` keys after its fields (`W264/2`).
- [`validate.md`](../../authoring/validate.md): the new check's row, and the `document` row.

## Decisions

- ⛔ **One reader, imported by the test harness.** `tests/fixture_checks/vocabulary.py` already
  imports `studyforge`, so a test→src import is the existing direction and needs no copy.
- **The `document` rule, not a new rule id.** Its row already says *malformed*, and a new id
  would collide with `W266`'s change to the same rule-id count. Reversible.
- **Only a `list` block's shape is refused.** `validate` still does not refuse an unknown block
  type or a wrong field set (`W263/1`); widening it is not this row.
- **`start` is type-checked only.** A `start` of `1`, or one on an unordered list, is not
  refused: §6 says when a writer records it, and the rider asks for its type.
