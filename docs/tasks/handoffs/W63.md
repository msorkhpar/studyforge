### ⭐ The remedy is a CLOSED SET, not a fifth accepted shape

⛔ **Ruling 29 records four accepted-shape lists, each of which worked on the
handoffs its author had seen and failed on one they had not.** ⭐ **So the rule
is inverted: nothing before the marker may carry a CLAIM, and the markup that
carries none is enumerated ONCE, in `LEAD_TOKENS`, each token named by what it
is** — horizontal space, a heading, a bullet/emphasis/hyphen run, an em or en
dash or colon, an attention glyph, a finding number (backticked or not).

⛔ **A word is in no token. A table cell's pipe is in no token. A blockquote's
angle bracket is in no token.** ⭐ **So prose stays refused BY CONSTRUCTION
rather than by a pattern that happens to miss it** — and that property is what
makes this a closed check rather than a longer list.

⚠️ **One token set, two readers, and the second was owed:** `check_finding_ids`
reads the number off the line itself, so it uses the same set **minus** the
number. ⛔ **`_FINDING_NUMBER` learned the backticked form in the same commit**,
because the module's own docstring had already earned the warning: *a vocabulary
is read in two places or in neither*. Without it the ID rule would have been
**vacuous** on all 196 lines the lead newly admits.

## Decisions

- ⛔ **`_MARKERS_ON_LINE` is derived from the constant rather than deleted in
  favour of a string scan.** ⭐ A compiled pattern is what `findall` needs for
  the two-on-one-line rule; what was wrong was that it was *typed*, not that it
  existed.
- ⛔ **The lead became a token LOOP, not a longer regex.** ⭐ A loop over a named
  closed set is the only form in which *"nothing before the marker carries a
  claim"* is the actual rule rather than a summary of one.
- ⛔ **`_FINDING_NUMBER` was widened in the same commit**, because the alternative
  was shipping a rule that had stopped being able to fail. ⚠️ **Declared here
  rather than slipped in: it is the same module and the same vocabulary, and the
  module's docstring had already ruled on the case.**
- ⛔ **The table-row finding format was NOT taught to the reader.** ⭐ **Ruling
  148 names the bulleted form, and 161 lines is a population that deserves its
  own row with its own negative controls** — a table row's first cell is
  sometimes a finding ID and sometimes a column header, and telling those apart
  is a second subject. ⚠️ **`W63/2`, and it is what stops `W64`.**
- ⛔ **RULING 186'S NAMING DEFECT IN MY OWN TWO ROW FILES: NOT FIXED, and the
  refusal is deliberate.** ⭐ **Three reasons, in order:** the floor prints it as
  a **notice with no bound** (*"no bound — Ruling 186"*), so it is not a failure
  I am leaving red; it is **one defect in six files across four owners**
  (`W60 W63 W64 W66 W67 W72`) and fixing two of six leaves a reading that is
  harder to interpret than the one it replaces — four is not obviously better
  than six to anyone reading the trend; and ⛔ **`docs/tasks/rows/` is the PO's
  register surface, live in `chore/po-round41` this wave.** ⚠️ **`W63/5`: it
  wants ONE row over all six, held by one owner, and it is not this one.**
