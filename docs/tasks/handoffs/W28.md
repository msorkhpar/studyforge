## What landed

- **`source_files(root)` now returns a `Scan`**, not a `list[Path]`:
  `files` plus `consulted`, the second saying whether the repository's own
  declaration of generated output was read. ⛔ **One value, because the two
  halves may never be read apart** — a caller holding the list without
  `consulted` reports a hundred generated files as unclassified and prints a
  clean-looking run.
- **`_declared_output(root, candidates)`** asks git, once, for the whole tree:
  `git check-ignore --stdin -z`, `cwd=root`. It returns a `frozenset` when git
  answered and ⛔ **`None` when it did not** — not-installed, not a repository,
  or any return code that is not `0`/`1`. ⭐ `frozenset()` and `None` are
  different answers, and keeping them different is the whole fix.
- **`SKIP_DIRS` is three names**: `archive`, `.git`, `.studyforge`. `node_modules`
  and `__pycache__` are gone.
- **`check_unclassified` announces the fallback**: a new rule id
  `ignore-declaration`, yielded as an `Unchecked` — loudly, counted, and it does
  not fail the run. The walk stands; the report says the declaration was not read.
- **13 tests** in `tests/studyforge/validate/test_source.py`, and the module
  docstring carries the measurement and the reasoning.

## Decisions

- **`git check-ignore`, not `git status` or `git ls-files`.** §11.2 clause 11
  says `git status`; what matters is the *declaration*, and check-ignore reads
  it in one batched call. ⛔ **`ls-files` would have been wrong**: a file written
  and not yet committed is exactly the file an adapter author is about to
  ingest, and "not tracked, therefore not material" would hide it. A test holds
  that.
- **No `--no-index`.** git's index wins over its ignore rules by default, so a
  committed file stays material even if a later pattern names it. A test holds
  that too, with its control.
- **The fallback keeps the walk rather than refusing.** R2: an archive is a
  shippable artifact on its own. ⛔ It may not *pretend it checked*, which is why
  it is an `Unchecked` and not silence.
- **Its own rule id, not `unclassified`'s.** The classification check did run;
  what could not be read is the declaration. Different fact, separately filterable.
- **The `Unchecked` is not emitted for a corpus with no material at all** — that
  case already says "nothing to classify" and does not need a second claim about
  a declaration it had no use for.

## Surprises

- ⛔ **The acceptance number was unreachable, and reaching for it was the trap.**
  The brief said *117→12, being `F18`'s 17 minus the 5 the `include` glob
  covers*. Measured: **the include globs cover 0 of the 17**. The only route to
  12 is widening `include` over the five root files, which puts `README.md` in —
  and `README.md` becoming a unit that is its own table of contents is `F18`
  exactly, the CTO's open schema question and out of scope. ⭐ **The acceptance
  is therefore restated as a decomposition, not a total** (below). PO-Integration
  reached the same conclusion independently and their `verify.py` @ `1e49225`
  asserts the decomposition for the same reason.
- ⚠️ **The totals moved twice while this was in flight.** 112 → 117 as
  `graphify-out/` went 91 → 96, and the coordinator reports 99. `F20`'s *"the
  exclusion list has no fixed point"* is now four independent readings. ⭐ **The
  100 reproduces exactly; only the total moves** — which is the argument for the
  decomposition over the count.
- ⚠️ **A mutant sweep can be silently invalidated by `__pycache__`.** Restoring a
  mutated file with `cp` within the same filesystem-mtime second leaves Python
  loading the *mutant's* bytecode: the sweep ran, went green, and was measuring
  the previous mutant. It surfaced as a restored tree failing 7 tests with
  correct source on disk. ⭐ **Purge `__pycache__` between mutants**; the sweep
  below was re-run from scratch with that fix and the results are the second run.

### W28/2 `[structural]` An acceptance stated as a total is false one commit later

`docs/studyforge/` held 11 files at round 4 and holds 12 now, so the residual
grows by one every time the integration documents itself — and `graphify-out/`
has been read at 79, 91, 96 and 99. ⛔ **The brief's target of 12 was not merely
stale, it pointed at the out-of-scope trap**: the only arithmetic that reaches
it widens `include` over the five root files, which ingests `README.md`.

⭐ **State the decomposition instead** — *scanned = declared-output + kept*,
*tracked-but-not-scanned = 0*. That is re-runnable; a total is a snapshot.
This is `W22`'s rule reaching an acceptance criterion.

## For dependents

- ⛔ **`source_files()` returns a `Scan`, not a list.** One caller existed
  (`check_unclassified`) and it is updated. `scan.files` is the tuple;
  `scan.consulted` is whether the declaration was read. **`SF-31` and `F19` both
  land on this function** — take the `Scan`, and if you report anything derived
  from the file set, propagate `consulted` rather than dropping it.
- ⭐ **The acceptance to re-run is a decomposition, not a number.** For any
  corpus root: *scanned = declared-output + kept*, *kept ⊇ tracked*, and
  *tracked-but-not-scanned = 0*. On ISO @ `08e6290` that reads
  `159 = 100 + 59`, `59 tracked`, `0`. ⛔ **Do not re-assert 117 or 17** — both
  move with the corpus, and the composition does not.
- ⚠️ **`F19` gets its cheapest half free.** A `sibling` build's generated paths
  are git-ignorable, so a corpus that declares them stops reporting them. What
  `F19` still has to answer is the corpus that declines to ignore its own
  generated pages.
- **New rule id: `ignore-declaration`**, an `Unchecked`. Assert on the id, never
  on the message text.
- ⚠️ **Every fixture corpus built under `tmp_path` is not a git working tree**,
  so it takes the announced fallback and carries one extra `Unchecked`. That
  changes no `rules` tuple (`Unchecked` is not a `Finding`) and no exit code, but
  a test asserting an exact `unchecked` set in a temporary corpus will now see it.
