## What landed

- [`completeness.py`](../../../src/studyforge/validate/source/completeness.py): when no origin
  is on disk, `_source_beside` reads the WHOLE corpus root (skipping `NOT_SOURCE` at the root
  only), not the top-level directories the origins name. Origins written against the wrong
  root, beside source the manifest declares elsewhere, are `origin-missing`, exit `1`. The
  unchecked reason now says *no file under the corpus root*.
- W255's declared-gap test is inverted into
  `test_an_origin_whose_top_directory_is_ABSENT_beside_source_ELSEWHERE_is_RED`, with a twin,
  `test_a_ROOT_file_declared_NOT_MATERIAL_is_not_a_present_source`.
- Six FND-04 invalid fixtures declare `corpus_api` 2, `include: ["solo/*.md"]` and their own
  `VIOLATION.md` as `not_material`. `bad-corpus-api` is unchanged.

## Why each fixture's rule still fires alone

A root `VIOLATION.md` included or excluded is source, so it would add `origin-missing`. Left
undeclared, it is `unclassified`. Only `not_material` is neither, and `corpus_api` 2 added it.

| fixture | why it is one rule |
|---|---|
| `address-directory-mismatch`, `count-mismatch`, `digest-mismatch`, `user-authoritative` | `VIOLATION.md` is not source and `solo/` is absent, so `short-read` stays `Unchecked`. A plant forcing presence turned each RED |
| `ordinal-gap`, `personal-data` | Narrowed for one shape. A plant forcing presence left each on its own rule |
| `bad-corpus-api` | `corpus_api` 99 is refused before any source check; manifest untouched |

## Decisions

- **The fixture checker reads the framework's version set** (`CORPUS_APIS = KNOWN_CORPUS_API`),
  as `CONTAINER_APIS` already does. Pinning `1` would refuse the only manifest that can
  declare `not_material`. Reversible.
- **Whole root, sorted, stops at the first declared file.** No git, no plan, no name of any
  corpus (R1).

## Surprises

- Narrowing `include` alone was not enough: it made `VIOLATION.md` `unclassified`, a second
  rule on six fixtures.
