## Decisions

### ⛔ The skeleton is the unit page's own `page.html`, and no template was added

⭐ **The two documents are one product.** A second skeleton would be a second
`<head>`, a second masthead and a second place a `<meta viewport>` has to be
remembered — and the day one gains a region the other silently would not. ⚠️ The
epic asks `SF-14` to share the unit page's palette and type stack *by importing
them rather than restating them*; this is that ruling one page earlier.

⛔ **Three of the eleven slots are passed `""` by name, not omitted.**
`templates.fill` is exact in both directions, so the day the skeleton drops a
slot this module fails **by name** instead of quietly losing a region.
`EMPTY_SLOTS` is published and `test_document` asserts it against
`templates.placeholders`.

### ⛔ A refused href RAISES; an absent one is listed unlinked

⚠️ **`SF-13/1` is why this is spelled out rather than assumed.**
`page.navigation._link` **drops** a slot whose scheme is refused, on the argument
that chrome which cannot be followed is worse than chrome that is not there.
⭐ **That argument is right for the bar and wrong for this list**: the bar is
chrome and this list **is** the page. ⛔ A silently dropped anchor here turns a
container's contents into unclickable text — every title present, `validate`
passing, nothing logged, and not one unit openable.

⭐ **So the two states are separated in the type**: `Item(href=None)` is *declared
absence* — §7's three states, a unit whose page has not been generated, listed
and marked `data-readable="false"` — and a *present but refused* href is a fault
that raises, naming the position and never the value (R7).

### ⛔ The reader's list is a loop body in code, not a template file (R13)

⭐ `render/page/__init__.py` draws the line and this is on its far side: *"loop
bodies and inline wrappers stay in code, because a file for a closing tag removes
no duplication and adds a hop."* ⚠️ `navigation.outline` renders exactly this
shape — a `<nav>`, an `<ol>`, a row per entry — the same way.

### ⛔ Every hook is an element, an `aria-label` or a `data-*`, and not a class

⭐ **That is the property `SF-34` was scheduled late on**, and it is preserved:
`SURFACE_CLASSES | SURFACE_HOOKS` is untouched, so this page costs no edit in
`pageassets` and none in `bundle.py`. ⚠️ The cost is stated rather than hidden —
the new hooks have **no rule anywhere**, which is `SF-27/2`.

### ⛔ `Item` and `Document` are records the CALLER assembles, not documents read from disk

⚠️ A renderer that took a `corpus.container.Container` would have to know how a
corpus declares itself; one that took the *contents* documents would need
`SF-14`'s inputs. ⭐ Both are the caller's to join — `SF-13`'s *"which caller does
that mapping is not mine"*, one layer out — so this package **reads no file**,
imports neither `corpus.container` nor `contents`, and is a pure function of what
it is handed.

### ⛔ One renderer at every depth, and no branch on how deep a corpus is

⭐ The only thing that varies is the address and the corpus's own word for the
level, and both arrive as data. `test_init` renders the depth-1 fixture's single
container and the depth-2 fixture's two from the same call.

### SF-27/2 `[structural]` — ⛔ the container page emits a region `SF-34`'s scope does not cover, and nothing paints it

- ⛔ **Not fixed here:** `render/assets/` and `render/pageassets/` are outside
