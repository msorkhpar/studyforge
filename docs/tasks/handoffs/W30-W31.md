## Decisions

### ⛔ `W30` — the mechanism, because the ENV line alone reads as a tidiness setting

⭐ **CPython validates a cached module against the source's `(mtime, size)`.**
That is the whole finding. `PYTHONDONTWRITEBYTECODE=1` stops this image
**creating** a `__pycache__` in the bind-mounted checkout and does **nothing**
about **reading** one a host run left there — and a host run leaves 64 of them
in this worktree the moment a contributor types `python3 -m pytest`. ⚠️ **Ruling
40 is necessary and not sufficient**, and `PYTHONPYCACHEPREFIX` closes the read
side by the same mechanism that would have closed the write side: it moves the
cache path the **loader computes**, so the tree's `__pycache__/` is not
consulted at all.

⛔ **Proved end to end through the real mount before a line of test was
written**, because a mechanism asserted from a manual page is a mechanism
nobody checked. Planted on the **host**, read in the **container**:

```text
$ python3 …   # compile VALUE="old", then rewrite the source to VALUE="new"
              # at the same length, restoring the mtime
planted on the HOST: sweepprobe/__pycache__/hostwritten.cpython-314.pyc

$ ./docker/dev/check … python3 -c "import hostwritten as m; print(m.VALUE, m.__cached__)"
PYTHONPYCACHEPREFIX=/tmp/pycache PYTHONDONTWRITEBYTECODE=1
new /tmp/pycache/workspace/sweepprobe/hostwritten.cpython-314.pyc

$ ./docker/dev/check … env -u PYTHONPYCACHEPREFIX python3 -c "…"
old /workspace/sweepprobe/__pycache__/hostwritten.cpython-314.pyc
```

⭐ **The second line is `CTO-21/1`, reproduced**: the container executed code
that is in nobody's working tree, from a file the host wrote, with
`PYTHONDONTWRITEBYTECODE=1` set throughout. The probe tree was removed; it is
not in the diff.

### ⛔ Both directions, and **which side runs which**

| Test | Runs | Why there |
|---|---|---|
| `test_the_bytecode_cache_is_redirected_out_of_the_workspace` | **both** | Reads the declaration. On its own it asserts only that a variable is set — ⛔ which is the test the acceptance forbids standing alone — but the **value** has to be checked somewhere, and *outside the mount* is the whole requirement |
| `test_a_stale_bytecode_file_in_the_tree_is_ignored_when_the_prefix_redirects` | **both** | Direction one, against a real interpreter. ⭐ A fact about CPython is as true on a host as in the image, so gating it on Docker would buy nothing and cost a skip |
| `test_without_the_prefix_that_same_stale_bytecode_is_read` | **both** | ⛔ Direction two — **the defect reproduced**. `env -u PYTHONPYCACHEPREFIX` is the image's own line removed and nothing else; inside the image that is a real removal, on a host a no-op, and the assertion is the same either way |
| `test_no_bytecode_from_the_bind_mount_is_read_in_here` | ⛔ **inside the image only** | Asks the **running** interpreter: `sys.pycache_prefix` is set and outside the repository root, and **no** loaded module's `__cached__` is under it. A host cannot answer it — a host legitimately has 64 `__pycache__` directories in the checkout |

⚠️ **The fourth is a skip, and it is on the HOST side by construction.** The
brief's warning was against a **sixth** invisible skip inside the image, beside
the five *"already inside the dev image"* recursion guards. ⭐ **Container skips
are unchanged at 8**; the host gains one, named, in the same shape as the
existing `test_the_runtime_is_actually_on_the_path_in_here`, whose message says
what only a run inside the image can assert.

### ⭐ `plant_stale_bytecode()` — two things a reader would otherwise get wrong

- ⛔ **The two revisions are the same LENGTH and the mtime is restored.** A
  mutant of a different size invalidates the cache, and the scenario stops
  being a stale-cache scenario *while still looking like one*. The helper
  asserts `(size, mtime)` survived, so that failure is loud. **Mutant C in the
  sweep below is exactly this**, and it kills both stale-cache tests.
- ⛔ **The `.pyc` path is spelled out rather than taken from
  `importlib.util.cache_from_source`**, because that function honours
  `sys.pycache_prefix` — inside the image it hands back the *redirected* path,
  and the test would plant its evidence somewhere the scenario does not need
  it. ⚠️ The one place where the fix would have quietly disarmed its own test.

### ⭐ `W31` — one word, and the assertion is against the **tree**

`PO-19/5` measured it: `ruling record` said *"a **CTO** round"*, `session log`
says *"a **coordinator's** record"*, and a **PO round** is neither — while four
of them sit in `docs/tasks/handoffs/`. ⛔ **No new kind.** A role is not a kind
of document, and `DOCUMENT_KINDS` is a closed set whose entries are decisions.

⭐ **The test asserts the sentence against the four shipped PO rounds**, not
just against the string: every `PO-*.md` in the tree must declare
`ruling record`, and the sentence must name both roles. ⚠️ A sentence about what
may live here is only true if what lives here matches it, and that is the half
a spelling check cannot see. It also asserts **no kind's name contains
`round`**, which is the acceptance's *"no new kind is minted"* made permanent.

### ⛔ The `W33` friction, which is the confusion `W31` fixes — met twice more here

⭐ **First-hand, two hours before this row:** writing an unnumbered task's
handoff as `**Kind:** ruling record` was the right interim form, and

apply to it**, and the registry's sentence is the only place a reader learns

declaration surface being wrong about its own domain.

⚠️ **And it happened again, in this handoff, over the finding IDs** — see

measurement that says the surface, not the authors, is what needs the word.

### ⭐ What a later row can lean on

- ⛔ **The redirect is now a property of the image, not of a purge.** Ruling
  70's purge step covered the same hole procedurally; it is still right to
  purge, but a run that forgets to no longer certifies stale code.
- ⚠️ **`/tmp/pycache` is never created** in practice, because
  `PYTHONDONTWRITEBYTECODE=1` means nothing is written. ⛔ Do not assert its
  existence — assert `sys.pycache_prefix`, which is what the loader reads.
- ⭐ **`plant_stale_bytecode()` is the reusable half.** Anything that needs a
  genuinely stale `.pyc` — a later row on the host-side taint, or on
  `code-server-toolchain`'s mount — takes it from here rather than rediscovering
  the `(mtime, size)` rule.
