## Decisions

**Where a justification ends: the next blank line.** Not the end of the
docstring. A docstring may legitimately go on to say other things after the
exception, and swallowing them would inflate the character count into
meaninglessness and drag unrelated ids into `row_ids`. Tested both directions.

**`size_exception` joins continuation lines with a single space.** So the
result reads as the sentence it is and a sweep can print it on one line — which
is the shape the wave-open sweep needs and the shape the defect denied it.

**The id requirement binds deferrals only.** A justification naming no row is a
design claim and passes untouched; the refusal fires only on *names a row, but
not on the marker line*. A rule that demanded an id everywhere would have
outlawed the permanent form, which is the same mistake Ruling 114 is fixing in
the other direction.

**`ROW_ID` lives in `config.py`, next to `SIZE_EXCEPTION_MARKER`.** Same
argument as the marker: it is a fixed token a rubric will want to cite, and a
second spelling elsewhere would pass one reader and fail the other. The board's
`Owns` anticipated `config.py` moving and it did.

⛔ **`row_ids()` answers *"is a row named here"*, never *"is that row live"*,
and it cannot.** `tools/quality` may not read `BOARD.md`: that is a document
changing hourly, checked against a tree that is not, and Ruling 31's argument
about a checker importing its subject applies to a checker importing a board.
**A deferral pointing at a landed row stays the wave-open sweep's finding and a
human's**, exactly as §3c says — this row narrows what that human has to
notice, it does not replace them.

⛔ **I did not touch `review-rubric.md`.** The brief is explicit that the ruling
is the authority and the *check* is my job, and the rubric is not in my `Owns`.
The disagreement it leaves behind is `W45/1` below, with the replacement
written out so it is a paste and not a re-derivation.

⛔ **I did not edit `src/studyforge/validate/source.py`, including
transiently.** My first attempt at the negative control was to strip the marker
in place and restore it; the sandbox refused the write, and on reflection the
refusal was right — `W44` is in that file concurrently and a restore is not a
guarantee. The control was rebuilt from a **copy of the file's exact bytes**
into a temporary root, which is a strictly better instrument anyway: it cannot
lose a race. `git status` is clean of that path throughout.

## Findings

### W45/1 `[structural]` — §3c's sweep re-implements the reader, so it does not inherit this fix

⛔ **The instrument that produced the reported symptom is not the function this
row repairs.** Rubric §3c's wave-open sweep iterates `doc.splitlines()` itself
and prints `line.strip()`. It will keep truncating every deferral after this
merges.

**Measured**, on `fix/W45-size-exception` with the fix landed, in the pinned
image, 2026-09-10 — the rubric's script run verbatim:

```text
src/studyforge/validate/source.py: Size exception: W44 splits this module into
a package, and it is deferred to
```

**Measured**, same tree, same walk, asking `size.py` instead:

```text
src/studyforge/validate/source.py: Size exception: W44 splits this module into
a package, and it is deferred to that row rather than done here because this
file crossed the ceiling only when SF-35 and SF-36 merged — each is under it
alone, and neither task may restructure a file the other is concurrently
editing.
   rows named: ['W44', 'SF-35', 'SF-36']
```

⭐ **The replacement, and it is shorter than what is there** — the two inner
lines of the loop become one call, and the sweep gains the id line for free:

```text
    reason = size_exception(module_docstring(text, path))
    if reason:
        print(f"{rel}: {config.SIZE_EXCEPTION_MARKER} {reason}")
        print(f"   rows named: {row_ids(reason) or 0}")
```

⚠️ **Why it is structural and not local:** this is Ruling 103's shape one door
along. A hand form in the rubric that duplicates a shipped check is subordinate
to it — ⭐ **and a hand form that duplicates a shipped check's *bug* is how the
fix stops at the module boundary.** The rubric is not in this row's `Owns`; the
PO or the CTO owns the edit.

### W45/2 `[structural]` — Ruling 116's instrument cannot produce the reading it names, and `W44` is in flight against it

⛔ **`W44`'s acceptance clause names `git grep -c 'Size exception:' -- src/` →
`0`.** That command cannot return `0`. On a match it prints `path:count`; on no
match it prints **nothing** and exits **1**.

**Measured**, this worktree, 2026-09-10:

```text
$ git grep -c 'Size exception:' -- src/
src/studyforge/validate/source.py:1
exit=0

$ git grep -c 'Size exception:' -- src/studyforge/serve/     # a subtree with none
exit=1
captured=[]
```

⭐ So the pass state prints an empty string and returns non-zero, and the
**fail** state returns zero. A reviewer scripting the clause as written gets it
exactly backwards. Two forms that do work:

```text
git grep -c 'Size exception:' -- src/ | wc -l        # pass reading: 0
git grep -q 'Size exception:' -- src/ ; [ $? -eq 1 ] # pass: exit 1 = no match
```

⚠️ **This claim is measured; the clause it is against was *received*, from
`chore/po-round27`'s `BOARD.md` (`W44`'s Ruling 116 row), which I read at that
branch and did not modify** (Ruling 115). ⛔ **`W44` is dispatched right now
against this clause**, which is why it is filed rather than left for the sweep.

### W45/3 `[structural]` — a `Size exception:` on a file UNDER its ceiling is read by nothing at all

⛔ **`check_sizes` skips a file at or under its ceiling before it ever opens the
docstring**, and §3c's sweep applies the same guard. So a marker left behind in
a module that later **shrank** below 400 is invisible to the floor, invisible to
the wave-open sweep, and invisible to this row's new `size-exception-id` rule.

**Measured**, reading `tools/quality/size.py` at `426672c` and on this branch:
`if lines <= ceiling: continue` precedes `module_docstring(...)` in both.

⭐ **Ruling 116 found the instance and this is the class.** The ruling reasons
about it for `W44`'s file specifically — *"once the package is split, every
file is under the ceiling, so `check_sizes` never opens the docstring"* — and
answers it by making deletion `W44`'s last step plus a grep. ⚠️ **That answer is
per-row, and `W45/2` says the grep half is broken.** Any future split leaves the
same residue, and the residue is a deferral pointing at a landed row, which §3c
already makes a finding against the release branch.

⛔ **This row could not fix it**: the fix is a check that reads docstrings
regardless of length, which is a new rule and a new coverage story
(`agent-protocol.md`, *a new check reports its coverage, not just its hits*),
and minting that is not mine. ⭐ **Cheapest shape I can see:** the existing walk
already reads every file's text — dropping the ceiling guard for the
*marker* question alone costs one pass and no new I/O.

### W45/4 `[local]` — `config.py`'s R17 contract said `pathlib` only, and had been wrong since `FND-08`

⛔ **`tools/quality/config.py`'s docstring read *"**Depends on.** `pathlib`
only"* while the module imports `shutil` and `subprocess`.**

**Measured**, `426672c`: `from pathlib import Path`, `import shutil`, `import
subprocess` at lines 16–18, against the contract line at line 11.

⭐ **Corrected in this branch** rather than filed and left, on the narrow ground

it is one. ⛔ **I did not go looking for others** — no other module's
`Depends on.` line was audited, and that sweep is somebody's row, not a thing I
should do inside this one.
