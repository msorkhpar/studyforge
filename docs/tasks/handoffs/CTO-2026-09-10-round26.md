# ⛔ Ruling 90 — `F18`: the third state is real, it is `not_material`, and it takes globs

⛔ **`content` gains one key. `include` and `exclude` are untouched.**

```json
"content": {
  "include": ["src/*.md"],
  "exclude": [{ "path": "src/ISO.md", "why": "whole-series aggregate: a concatenation of 1.md…16.md (C2)" }],
  "not_material": [
    { "glob": "docs/studyforge/*", "why": "this integration's own working notes about the corpus, not the corpus" },
    { "glob": "LICENSE",           "why": "the repository's licence; it teaches nothing and is not withheld from anyone" },
    { "glob": ".gitignore",        "why": "the repository's own build declaration, read by git and by studyforge, never read aloud" } ] }
```

## ⛔ The four rules, and the third is the load-bearing one

| | |
|---|---|
| **1. Entries are globs, each carrying a `why`** of `MIN_WHY_CHARS` | ⛔ **`exclude` names one file and this one does not**, and the difference is the arity of the harm — see below |
| **2. `exclude` still wins over everything** | unchanged |
| **3. ⛔ A file matched by BOTH `include` and `not_material` is a FINDING** — new rule id, exits 1 | ⭐ **never a precedence.** This is what stops the third state becoming a drain |
| **4. Matched by none of the three is still `UNCLASSIFIED` and still exits 1** | ⛔ **C2's countermeasure is not weakened by one line** |

## ⭐ Why globs here and one named file there, which is the objection I had to answer

⛔ **`exclude`'s refusal of globs is right and I am not touching it:** *"one
justification covering a pattern is one justification for a set whose membership
changes."* ⚠️ **The reason it does not carry over is that the two audits are
about different harms.** ⭐ **An `exclude` entry withholds material from a reader,
so a new member of the set is a new harm and needs its own reason.
A `not_material` entry says a file was never material, so a new member of the set
is not a new harm — unless it is actually material, and rule 3 is what catches
exactly that case, loudly, per file, against a real tree.**

⛔ **And the finding's own line is the argument for globs.** *Writing the finding
took the count from 100 to 101, because the new entry is the file containing it.*
⚠️ **A category that grows every time somebody writes in it cannot be enumerated
file by file** — `docs/studyforge/` gained four documents in two days. ⭐ **A
per-file third state would have shipped a rule that is wrong again tomorrow,
which is the same sentence `W28` wrote about a framework carrying its own
exclusion list.**

## ⛔ `README.md` is `not_material`, and it is not a special case

⚠️ **The trap was real and the way out is to name what the three states are
actually about.** ⛔ **They are not about materiality in the abstract; they are
about whether a file's prose is read into the archive.**

- `include` — **read into the archive.**
- `exclude` — **prose that would be read, deliberately not read**, per file, with
  its `why`. ⭐ *Withheld* is the honest word here because it is true here.
- `not_material` — ⛔ **not prose to read at all: the repository's own scaffolding,
  content *about* the material rather than the material.**

⭐ **`README.md` is the corpus's navigation, and navigation is scaffolding.** ⛔ **Its
`why` does not have to say "withheld", because it is not withholding anything** —
every address, title and ordinal it records is declared in this manifest's own
container maps, which is what the site navigates by. ⚠️ **The reader loses
nothing; the record moves from a hand-authored file to the manifest, which is
`R19` in its usual direction.**

## ⭐ `X1` is not weakened, and its domain is now stated

⛔ **The PO recorded `F18` as a defect in their own `X1` — a rule stated without
its domain, Ruling 52 arriving against its own author.** ⭐ **The asymmetry
survives verbatim and gains its arity:** *an inclusion needs no justification;
**every declaration that the framework will not read a file** needs one.*
⚠️ **`X1` said "an exclusion needs one" and was right about the asymmetry and
wrong only about how many ways there are to not-read a file.**

## ⛔ R9, and it is a `corpus_api` bump

⛔ **`corpus_api` goes to `2`, and `KNOWN_CORPUS_API` speaks both.** ⚠️ **Not
because old manifests break — they do not; `not_material` is optional and an

# ⛔ Ruling 92 — `F21`: `origin` may name a **region**, and the region is a heading

⛔ **Shape chosen: sub-file units. Not a generated split, and not one unit.**

```json
{ "n": 3, "title": "Card issuance", "origin": { "path": "TestCases.md", "section": "3. Card issuance" } }
```

| | |
|---|---|
| `origin` stays a **string** for a whole file | ⛔ unchanged, and every existing manifest keeps parsing |
| `origin` **may be an object** — `path` + `section` | `section` is the **exact text** of the ATX heading that opens the region |
| the region **ends** at the next heading of the **same or shallower** depth | ⛔ **not at the next heading of any depth** |
| `section` must occur **exactly once** in the file, or the manifest is **refused** | ⚠️ ambiguity here is sixteen silent short-reads |
| ⛔ **`TestCases.md#…` stops being accepted** | ⭐ it is accepted today and means nothing — `F21/2`'s *"validates and then fails at render, except it never fails"* |

## ⛔ Why a heading and not a line range, which is the only real choice here

⭐ **`check_completeness` exists to disagree with the parser.** ⛔ **So the region
boundary may not come from the Markdown reader** — a heading *anchor* would, and
that would destroy the independence the whole check is built on.

⭐ **`count_headings()`'s own regex already knows depth**, so it can find the
opening heading and the next one at that depth or shallower with no help from the
reader, and count what lies between. ⚠️ **A line range would also be
parser-independent and was rejected for a different reason: it is brittle against
an upstream file that grows a paragraph**, and the corpora this framework targets
are living repositories.

## ⭐ The two consequences worth writing down

1. ⛔ **`_origins()`'s per-unit sum keeps working unchanged.** Seventeen units
   sharing one `path` have **disjoint** regions, so seventeen comparisons against
   seventeen counts — ⭐ **not seventeen against 361**, which is the finding.
2. ⚠️ **`origin_directory()` takes `.parent` of the path**, and an object origin
   still has a path — so media placement is unaffected. ⛔ **`F21/3` (17 pages in
   the repository root under `sibling`) is real, is a *placement* question, and
   is `SF-31`'s, not this ruling's.**

**Owed to `ISO-09`, which it unblocks.** ⛔ Framework task, with tests, in
`corpus/manifest`, `validate/source.py` and `studyforge.sourcepath`.

# ⛔ Ruling 93 — `Q20`: a fence is not narrated, whatever its language, and **no new field**

⛔ **Option 2 of the three: skip fenced blocks in narration entirely — a
vocabulary-wide rule, not a corpus one.** ⭐ **Option 3 is refused, and refused
on a precedent this project already paid for.**

⚠️ **A manifest field listing *"which fence languages narrate"* is a list of
language names in the framework's configuration, answering a question a fence
already answers about itself.** ⛔ **That is the CodeSignal failure verbatim: one
list answered *"can this be filed here?"* and *"can we generate a test for it?"*,
and eight SQL courses were unfileable because of it.** ⭐ **The spec already ruled
this exact shape once — `variants` is a filing and presentation key and is **not**
a code fence's language, which is *"a block's own attribute from the archive"*.
A `narrate_languages` field would re-merge the two questions the spec just
separated.**

## ⭐ And the escape hatch is the archive, which costs no field at all

⛔ **If a corpus genuinely wants its Given/When/Then narrated, its adapter emits
those steps as prose blocks rather than as `gherkin` fences.** ⭐ **The decision
is made once, at extraction, by the side that knows the material, and it arrives
as data (R1).** ⚠️ **The framework never learns the word "gherkin".**

⛔ **What the reader loses: nothing on the page.** The 2,106 lines render, in a
fence, exactly as written. ⚠️ **What the *listener* loses is 2,106 lines of
`Given`/`When`/`Then` read aloud**, and catalogue entry 10 already ruled that
direction — *a 23-line box-drawing tree read aloud is 23 lines of punctuation*.
⭐ **The reading floor narrates prose and shows everything; those are two
surfaces on purpose.**

**Owed before M3; `ISO-12` is unblocked by it.** ⭐ **It costs E04 one condition
and the block vocabulary one sentence, and it costs the manifest nothing** —
⛔ **which is the whole reason to rule it now, while R9 says a field is cheap:
the cheapest field is the one not minted.**
