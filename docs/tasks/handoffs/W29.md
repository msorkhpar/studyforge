**Kind:** task handoff — W29

repeated in three test bodies and becomes a named row in a map asserted total
over the repository.*

**Status:** done — one commit, `tests/test_gate_coverage.py` only. No source

## What landed

**One constant, one docstring paragraph, four tests**, all in
`tests/test_gate_coverage.py` (478 → **600** lines).

- **`GATED_TREES`** — every tree in this repository that holds a document
  reader, mapped to the R7 gate that covers it, `None` where a tree is ungated
  on purpose. Three rows, and they are Ruling 67's three:

  | row | gate | why it is that gate |
  |---|---|---|
  | `src/studyforge` | `studyforge.archive.scrub.assert_clean` | what this file measures — the only row whose gate is `GATE` |
  | `tools` | `tools.quality.personal_data` | Ruling 31 forbids `tools/` importing the framework |
  | `tests` | `None` | Ruling 60 — an oracle that calls the code under test agrees with its bugs |

- **`SCAN_ROOT = "src/studyforge"`** — the literal that was repeated in three
  test bodies, now one name, and asserted to be *the row of `GATED_TREES` whose
  gate is `GATE`*. ⭐ The root and its justification can no longer drift apart.

- **The module docstring** gained Ruling 67's paragraph: why the root is right,
  why extending it is refused, and why `tests/fixture_checks/corpus.py` stays
  ungated — Ruling 60's oracle-independence, **with the cost bounded rather
  than waved**: it decodes only the §1e fixture trees this repository itself
  ships, no user data and no corpus the framework did not author.

- **Four tests.** `test_the_scan_root_is_the_one_tree_this_gate_covers` binds
  `SCAN_ROOT` to its row; `test_no_fourth_tree_of_readers_exists_unnamed` walks
  **the whole repository** and fails on a reader in a tree no row names;
  `test_every_named_tree_is_populated_so_the_bound_is_not_vacuous` is the
  control on that totality — every row must be a real directory that really
  holds readers, and the counts are asserted as a decomposition;
  `test_a_fourth_tree_is_caught_rather_than_scanned_past` is the Ruling 11
  negative control, planting a reader in an unnamed tree because nothing in the
  real repository is in that shape.

## Decisions

**The `tests` row is spelled `tests`, not `tests/fixture_checks`.** Ruling 67's
table names `tests/fixture_checks/` because that is the file `W26/1` reported.
⛔ **A map keyed on `tests/fixture_checks` is not total** — the other **17**
readers under `tests/` are ordinary test modules and would have come back as a
"fourth tree" on the first run. ⭐ Ruling 60's reasoning covers them all
identically: a test module that gated its own decodes would agree with the
gate's bugs. So the row is the tree and the docstring names the file. Raised as
`W29/2` in case the CTO wants the narrower row spelled differently.

**Totality is the half with teeth, and it is why this is not just a rename.**
Naming the root would have satisfied the letter of the acceptance and caught
nothing: the failure mode Ruling 67 exists against is a *fourth* tree of
readers arriving unnoticed, which no assertion about `src/studyforge` can see.
⛔ So the bound is asserted over the repository, not over the scan.

**The file was trimmed to land on 600, not granted a size exception.** R11's
test ceiling is 600 and the first draft was 606. ⭐ A task whose whole remit is
*"one constant plus a docstring sentence"* is the wrong place to spend the
project's first `Size exception:`. See `W29/1` — it now has zero headroom.

## Surprises

**⭐ `CTO-20-2` reproduces exactly, and so does the CTO's whole table.** Run in
the pinned image over the tip: `src/studyforge` **6** readers, `tools` **2**,
`tests` **18** — and **20** readers outside `src/studyforge`, which is the raw
number `CTO-20-2` reported. Both numbers in the `W26/1` dispute are true; they
are true of different sets, which is the entire point of this task.

**⚠️ `except OSError, ValueError:` in `tools/knowledge/index.py` is correct, not
a Python 2 relic.** It stopped me long enough to check, because it is a
`SyntaxError` on every Python before 3.14. PEP 758 landed in 3.14 and the AST
confirms it parses as a two-element tuple. ⛔ **Nothing to fix, recorded so the
next reader does not "correct" it** — and it is a reason the pinned image
matters, since a host on 3.13 would fail to import the module at all.

**⚠️ `tools.quality.personal_data` sweeps *tracked* files, so it covers only one
of the two readers in its own row.** This is `W29/3`, and finding it is the
first thing the constant did — writing the gate name down forced the question
"does that gate actually reach what this module decodes?", which nobody had to
answer while the root was implicit.

## Findings

### W29/1 `[local]` The file now sits exactly on R11's test ceiling, with no headroom

`tests/test_gate_coverage.py` is **600 lines**, and 600 is the ceiling. It
passes today; the next line added anywhere in it turns the quality floor red.
⭐ The fix when that comes is the one the floor already names — split it into a
package (`tests/gate_coverage/`), with the origin-resolution helpers, the probe
table and the assertions as separate modules. ⛔ Deliberately not done here: it
is a structural change to a file two branches touched this wave, and Ruling 67
asked for one constant. ⚠️ The first draft was 606 and was **trimmed rather than
granted a size exception**, which is why the margin is zero rather than
comfortable.

### W29/2 `[structural]` Ruling 67's third tree is spelled narrower than a total map allows

The ruling's table names `tests/fixture_checks/`; `GATED_TREES` names `tests`.
⛔ The narrower spelling **is not total** — 17 further readers sit under
`tests/` outside `fixture_checks/`, and every one of them would have come back
as a "fourth tree" on the first run. ⭐ I read this as the ruling naming the
*file it was shown* rather than the *tree it meant*: Ruling 60's
oracle-independence transfers to all 18 unchanged, since a test module that
gated its own decodes would agree with the gate's bugs exactly as the oracle
would. ⛔ **Confirmation wanted, not a patch** — if `tests/fixture_checks`
should be its own row, the map needs a fourth row for the remaining test
modules, and that is a ruling rather than a refactor.

### W29/3 `[structural]` The `tools` row's gate covers one of its two readers

`tools.quality.personal_data` sweeps the **tracked** tree. That covers
`tools/workspace/__init__.py`, which decodes `workspace.json` — tracked. ⛔ It
does **not** cover what `tools/knowledge/index.py` decodes: the graph under
`graphify-out/`, which `.gitignore:2` excludes precisely because the index is
local, derived and rebuildable (R14). ⭐ **Nothing leaks today, and I checked
rather than assumed** — of everything decoded from that graph, only a commit
sha (`_stale(commit)`) and integer counts from `census` reach any output; no
node id or path is printed anywhere. ⚠️ So this is an imprecise coverage claim
rather than an exposure — and it is exactly the *"a gate per root"* cost that
Ruling 67 refused to take on. Out of scope by that ruling; filed so the refusal
stands on a known cost rather than an unexamined one. ⭐ Writing the gate name
down is what surfaced it: the question *"does that gate reach what this module
decodes?"* is unaskable while the root is implicit.
