- `Index.of(epics, sequence)`: the sequence is **required**. `Index.milestones` is the declared order, and it keeps empty milestones. `Index.later(m, than=g)` is the one milestone comparison, and `after` uses it.
- `capability_index(documents, order)`: the step-1 command in [`delivery/SKILL.md`](../../../src/studyforge/skills/delivery/SKILL.md) now passes [`README.md`](../README.md) as `order`.

- The rider: [`reconnaissance/SKILL.md`](../../../src/studyforge/skills/reconnaissance/SKILL.md) no longer treats `M8` as the end of the plan.

## Decisions

- **Where the order is declared: read from the task index, never typed.** [`README.md`](../README.md)'s milestone sections already run in the order the user decided. Reading them means the order exists in one place, and nothing is copied that could go stale.
  - The package still goes looking for no file (R1): the caller names the document, just as it names the epics.
  - A second repository retypes nothing (R19): the same call reads its own task index.
  - A module constant was rejected because it would be a second copy of the plan.
- **No fallback to id order.** An optional `sequence` would quietly sort by id when omitted, which is the defect this row removes.
- **`gated_by` naming a milestone the order does not declare now raises `IndexRefused`.** Before, a string comparison let it through quietly.
- **The first-command test now reads the command out of `SKILL.md`** instead of keeping its own copy, so the two cannot drift apart.
