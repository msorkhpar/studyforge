## Decisions

⭐ **Self-ignore beside the settings, not a move of the settings.** The editor
reads a folder's settings from `<folder>/.vscode/settings.json` and that folder
is the corpus's own practice directory (the bind mount), so moving the write
would mean changing what code-server opens — a far larger row. The ignore file
is `W425`'s shape: a rule *inside* the directory the framework writes into.

⭐ **Argued against R3** ([spec](../../specs/2026-09-08-studyforge-v1-design.md)):

- R3 forbids moving, renaming, deleting or rewriting an existing file, and
  editing the repository's root ignore file or any version-control
  configuration. ⭐ **This adds one new file inside the directory written
  into** — "write new ignore files *inside* generated directories instead" is
  R3's own remedy. `.git/info/exclude` is version-control configuration and
  was refused by the row (`W425`).
- ⛔ **An ignore file already there is NEVER rewritten**: the create is
  exclusive (`open("x")`), so one the source or reader carries — or one that
  appears between a check and a write — is left byte-for-byte.
- ⛔ **Anchored NAMES, never `*`**: `/settings.json`, `/settings.json.studyforge`,
  `/.gitignore`. A `.vscode/` the source tracks keeps every file tracked (git
  never un-tracks on an ignore rule anyway), and a file the reader adds there
  later is still reported by `git status`. ⭐ It self-ignores because it carries
  nothing else — `W425`'s clause: a file holding only machine-local rules is
  itself machine-local.
- ⛔ **`write_settings`' refusal of a settings file it did not write survives
  and now runs first**: a refused write adds nothing at all, not even the
  ignore file (asserted).
- ⭐ Written before the settings, so there is no instant in which a settings
  or staging file exists unignored.
