## Decisions

### 1. The single block-type list is a row per type, not four tuples

Four copies existed: `BLOCK_TYPES` and `CONTAINER_TYPES` in the reader,
`COUNT_KEYS`, `BLOCK_FIELDS` and `CONTAINER_BLOCKS` in the fixture checker —
which wrote its copy knowing this task would come and said so in its docstring.

```text
BlockType(name, count_key, fields, holds_blocks)
BLOCKS            -> eleven rows, in the order `counts` is written
BLOCK_TYPES       = names
CONTAINER_TYPES   = names where holds_blocks
COUNT_KEYS        = {count_key: name}
BLOCK_FIELDS      = {name: fields}
```

⭐ **Four parallel tuples that must stay in the same order are three chances to
get the order wrong.** One row per type makes adding a block type a single
edit — and it is a `raw_api` change, because a block type is a contract.

⛔ `count_key` is **declared, not pluralised.** `code` counts as `code` and
`html` as `html`; a rule with two exceptions is a lookup table that has not
admitted what it is.

### 2. The two copies disagreed about order, and the disagreement was data

⚠️ The reader's tuple had **`list` before `table`**. Every fixture's `counts`
object has **`tables` before `lists`**.

⭐ **The reader's order moved.** `counts` is serialised in that order and
reaches disk, so it is the format (R10); the reader's tuple was only ever a
membership test, and **nothing in the tree asserted its order** — which is
exactly why the wrong one was the easy one to keep. `test_the_count_keys_are_
the_ones_that_reach_disk` now pins it, and
`test_the_counts_in_every_fixture_agree_with_this_module` checks it against
every committed document rather than against my memory of one.

The second disagreement was a name: `CONTAINER_BLOCKS` against
`CONTAINER_TYPES`. **The published name won** — `CONTAINER_TYPES` is in the
reader's `__all__`, so it already had consumers — and the checker's five uses
were renamed.

### 3. `video` is a block type *and* a document record

⚠️ Kept as two things, deliberately, because folding one into the other is the
mistake a consolidation is most likely to make.

| | what it is | keys |
|---|---|---|
| `video` **block** | content, in reading order | `type`, `src`, `title` |
| `video` **record** | the unit's headline video and its provenance | `VIDEO_KEYS` — `src`, `poster`, `mime`, `remote`, `poster_remote` |

`test_the_video_block_and_the_video_record_are_different_things` asserts they
share exactly one field name, so a later "tidy-up" that merged them fails.

### 4. SF-33 owns the check; this module owns the set

```text
check("raw_api", document.get("raw_api"), KNOWN_RAW_API,
      where=where, error=ArchiveError)
```

⛔ `KNOWN_RAW_API` is here because which versions the archive speaks is this
contract's business. The membership test is nowhere twice, and
`test_this_module_owns_the_set_and_not_the_check` asserts the source contains
no `not in KNOWN_RAW_API` — the same rule SF-33's tree test enforces, asserted
from the other side.

⭐ **The exception-type precedent held up in use.** `error=ArchiveError` means
the shared check does not leak a shared type, and
`test_a_version_refusal_arrives_as_an_archive_error_not_a_version_error`
records why.

### 5. The gate is asserted to be *invoked*, not merely to work

⛔ My own SF-08 finding, binding on me first: a gate nobody calls is green
forever. The test that carries it is not a mock:

⭐ **`test_a_leak_in_the_metadata_alone_is_refused_by_build` puts the leak in
`source`** — not a block, not the title — so only the whole-document gate can
see it. A `build` that stopped calling that gate would pass every "clean input
passes" test and fail this one. The same shape covers `parse`, an asset
record, and a block nested inside a quote. Two spy tests sit behind them, so a
refactor that removed the inner gate fails loudly rather than quietly.

### 6. One deliberate divergence from the extraction source

⛔ **`parse` does not gate a file's raw text when it fails to parse.** The
source's `gate_json_text` does, on the grounds that personal data must never
pass unexamined.

⚠️ Text that is not JSON has **no decoded strings**, so a text-level gate is
reading escaping again — the exact shape of the defect that refused three
clean lessons — and a nearly-valid file is precisely where an escaped newline
before an `@` still lives. It would also report a leak where the honest answer
is *"this file is malformed"*. Nothing reaches the archive either way, and the
refusal never echoes the text: it names `exc.msg`, `exc.lineno`, `exc.colno`.

⭐ **Routed for review rather than assumed**: SF-08's acceptance says *every*
gate reads decoded strings, and this is the one place the inherited code says
otherwise. If the CTO prefers the source's behaviour, it is four lines.

### 7. Refusals that would have been leaks

Three places where R7 arrives inside an error path, all tested:

- `load` names `path.name`, never the path it read.
- a missing file names `exc.strerror`, never `exc` — `OSError` formats itself
  with the filename it was given, so `{exc}` would produce a refusal carrying
  an absolute path.
- `_require_iso_date` names the field and not the value, because `ingested`
  is caller-supplied and a caller can put anything in it.

### 8. What was *not* ported, and why

`unitdoc.py` is **827 lines** — measured, not inherited (see *Findings* 1) —
and it is not SF-06's: it builds `unit.json`, which is E02's *other* half.
What SF-06 ports is `rawdoc.py` and `blocks.py`.

⛔ **`declared_media` and `DeclaredFile` are deliberately left behind.** They
answer "what should be beside this document" for an audit, which is SF-25's
question, and `tests/fixture_checks/media.py` already answers it for fixtures.
Porting them here would have put a validation walk inside the format module.


## Round 12 — the vocabulary collision, and what it took to compile

⛔ **Both sides changed, and a third one had to.** SF-11's `surface.py` landed
between SF-06 being written and being reviewed, carrying a literal class-name
table keyed by five block types. It tripped the scanner, correctly.

### Half one — `surface.py` takes its keys from `BLOCK_TYPES`

```text
_CLASS_OF      every block type, answered either way: a class, or None
SURFACE_CLASSES  {t: _CLASS_OF[t] for t in BLOCK_TYPES if _CLASS_OF[t]}
```

⭐ **Deriving the keys strengthens the file rather than only satisfying a
check.** A block type added to the vocabulary now raises at import, where
before it silently acquired no class and rendered unstyled — which is the same
silent failure `surface.py` exists to prevent, arriving by a different door.
`SURFACE_CLASSES["list"] == "items"` is untouched; the non-identity entry was
never about where the keys come from.

⚠️ A `KeyError` at import cannot state the other half — a type *removed* from
the vocabulary would leave an answer here for something that no longer exists —
so `test_every_block_type_is_answered_for_either_way` asserts
`tuple(_CLASS_OF) == BLOCK_TYPES`, both directions.

`test_surface.py` also stopped retyping the unstyled types: they are now
`tuple(t for t in BLOCK_TYPES if t not in SURFACE_CLASSES)`, so a block type
added tomorrow is covered by that test on the day it appears.

### Half two — the scanner is import-aware, not narrowed

> ⛔ A literal collection of four or more vocabulary names **in a module that
> does not import the vocabulary.**

⭐ **The allow-list is now empty**, and that is the result rather than a
tidy-up: `SPELLERS = ()`. This module's own test spells the vocabulary out and
is cleared by the same rule that clears every other module — it imports from
the owner. A path allow-list would have grown by one entry the day SF-11
landed and by three more later, and a list of files nobody re-examines is not
a check.

Three tests carry it, and the middle one is the rule: the **same literal**
is an offender without the import and clean with it. The third states that a
re-export chain does not count as deriving — the point is to say where the
names came from.

### The third side — SF-11's R1 boundary test refused the ruling

⚠️ **The ruling did not compile until a test neither half mentioned was
narrowed.** `test_the_assets_know_nothing_about_a_corpus` forbade
`studyforge.archive` wholesale, so `surface.py` importing `BLOCK_TYPES` failed
R1's boundary check at the page-assets package.

⭐ **The exception narrows the rule rather than widening it.**
`archive.blocks` is the block *vocabulary* — not a corpus, not a document, not
anything a source wrote — and a surface that did not know the block types is
precisely how the two came to disagree silently. The check now compares on
**equality**, not on a prefix, so `archive.document` and `archive.markdown`
are still refused, and a second test pins that the vocabulary is the only
thing under `studyforge.archive` the assets reach for.

## Surprises

1. ⭐ **`rawdoc.py` is 447 lines** — over R11's ceiling itself, which the task
   did not say. It came apart cleanly into format / vocabulary / errors, so no
   opt-out was needed; but the "arrives as a package or not at all" rule
   applied to SF-06's own source and nobody had counted it.
2. ⚠️ **The first sweep of "every fixture document" swept the negative
   fixtures too**, and `digest-mismatch` carries a deliberately wrong
   `content_sha256`. The test asserted that a negative fixture is positive and
   failed — correctly. The helper now names the two valid corpora and says why
   in its docstring. **A sweep needs to state what it is sweeping**, or the
   invalid corpora silently become part of the contract.
3. ⚠️ **The extraction source's `blocks.py` had already deleted its own
   `BLOCK_TYPES`**, with a comment saying the vocabulary belongs to whichever
   module still *produces* blocks. ⭐ studyforge's answer is different — the
   vocabulary belongs to the *format*, because `counts` carries one key per
   type and the fixture checker needs the list without the reader — and the
   source's comment is the argument for why the question is worth answering
   explicitly rather than by habit.
4. `starting_code` is written even when empty, while `media_skipped` and
   `assets_sha256` are not. Not an inconsistency: an empty starting fence is a
   fact about the practice, and falsy `media_skipped` means what the absent key
   already meant.

## For dependents

**The vocabulary is imported, never restated.**

```text
from studyforge.archive.blocks import BLOCK_TYPES, CONTAINER_TYPES, COUNT_KEYS
```

⛔ `test_there_is_exactly_one_block_type_list` parses every module under `src/`
and `tests/` and fails if a literal collection carrying four or more block
names or count keys appears anywhere else. The vocabulary's own test module is
the single exemption, named in `SPELLERS` — a contract's assertion is not a
second definition, because nobody imports their vocabulary from a test.

| task | what it takes from here |
|---|---|
| SF-09 / unit document | `walk`, `counts_of`, `read_layout` for a practice's parts — ⛔ do not re-parse blocks |
| SF-12 renderer | `BLOCK_FIELDS` for what each type carries; ⛔ `<details>` is yours, not the archive's (R13) |
| SF-16/17 narration | `walk` and `CONTAINER_TYPES`. ⭐ **Q1b**: narration speaks a disclosure's summary and stops; the body gets no speech ids; the withheld count goes to the coverage report; no manifest knob. `disclosure` is a block type, so the body needs no heuristic to identify |
| SF-25 validate | `parse`/`load` for reading, `leaks()` from `archive.scrub` to report rather than raise, and `declared_media` is **yours to write** — see *Decisions* 8 |
| SF-11 container map | `container_api` is your `KNOWN_*` set; call SF-33's guard |
| E07 adapter authors | `build` + `render` is the definition of the format, but ⛔ **the seam is on disk** (R2): an adapter in another language writes the same bytes and `studyforge validate` is its definition of done |

⚠️ **Adding a block type is a `raw_api` change.** One row in `BLOCKS`, a bump
in `RAW_API` and `KNOWN_RAW_API`, and every fixture's `counts` object gains a
key. It is deliberately not cheap.
