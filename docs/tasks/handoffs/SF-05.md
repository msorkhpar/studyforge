## Decisions

### 1. `folder` is `origin`, and it is **not** `address`

⛔ **FND-04's ruling 10 is measurably wrong and this corrects it.** It recorded
that `folder` "is exactly what `address` already is, so it is subsumed, not
dropped".

**Measured** — of the 116 maps that carry a `folder`, **0** are derivable from
their titles:

```text
folder : advanced-interview-prep-…-in-java/backward-compatibility-in-software-development-2
derived: advanced-interview-prep-…-in-java/backward-compatibility-in-software-development

folder : advanced-coding-…-with-kotlin/mastering-algorithms-hashmaps-two-pointers-and-beyond-in-kotlin
derived: advanced-coding-…-with-kotlin/mastering-algorithms-hashmaps-two-pointers-and-beyond
```

They are **truncated** and carry **disambiguating suffixes** (`-1`, `-2`).
⭐ A site's own URL scheme is not a function of its titles — which is the same
argument SF-03 made about filenames, arriving one level up. So `folder` needed
a home, and the field it needed already existed: **`origin`**.

E01's warning was right about both fields. `folder → origin`,
`url_slug → url_slug`, and `test_no_field_is_lost` asserts every key of the
real shape has a destination.

### 2. `origin` lives in the container map and **not** in the archive document

⭐ **Ruled, closing FND-04's open condition.** Two places to look for one fact
is the defect this project keeps diagnosing. The archive document already
carries what it needs to stand alone, and that is its **identity** (R4), not
its provenance; provenance is the container's to declare.

⚠️ **Optional**, and that is measured rather than generous: `folder` is present
in **116 of 285** maps. A required `origin` would refuse the other 169 and take
V2-03's migration harness with them.

⛔ **A placement profile that needs it must say so and fail loudly when it is
absent.** SF-03's `sibling` does — the Java corpus's directories are flat while
its address is two levels, so the directory comes from `origin` and the address
is *only* identity. **SF-03 depends on this field; it is now a contract.**

⚠️ `origin` and `url_slug` are **both** provenance and neither is redundant:
`origin` is a path *inside* the source, which a repository corpus has;
`url_slug` is the source's own addressing, which a web source has instead
because it has no file. A corpus normally carries one. `depth2`'s second
container carries both because it is the fixture that exercises both.

### 3. `label` goes in now

⭐ **Taken.** Optional, per unit, and the ruling that bounds it is written into
the module: **presentation carried as data, never identity.** `Unit.display`
returns the label or the ordinal; `n` is untouched by it; there is no inverse,
so nothing can be tempted to parse `4.4.1` back into an ordinal — R4's argument
about paths, applied to numbering.

The two arguments, and why the first wins:

- **For now (R9).** Adding a field later is a `container_api` bump, and every
  map written under the old version is **refused, never migrated** until its
  adapter is re-run. That is not symmetric with the cost of one optional key.
- **For later (§4's YAGNI).** ⚠️ But YAGNI refuses flexibility *nobody has
  asked for*. SF-03 measured a corpus that needs it (`4.4.1`), built the
  consumer, and pinned it against §5's worked example character for character.
  The constituency is named, the consumer exists, and the field is what
  connects them.

⛔ **What it must never become:** the address is still the address, ordinals are
still contiguous, and a page's *name* still comes from identity — because two
of the four designed source shapes differ only in zero-padding (`src/1.md`
against `src/04.md`), and a reader taking the number from the filename would
have to know which corpus it was reading (R1).

### 4. "Hand-authorable" is two fields, and the round trip is its whole content

⛔ Generated by the adapter; the render pipeline never writes it. What a person
may amend is a corrected `title` or an explanatory `note`, and `render` exists
so that amending one does not rewrite the document around it.

Two tests, and the second is the one that matters:
`test_an_edited_note_and_title_survive_a_re_read_unchanged`, and
`test_nothing_but_the_editorial_fields_moved` — which asserts that the rendered
bytes differ by **exactly** the substring that was edited.

### 5. Refusals that would have been leaks

⭐ **`fields.py` exists so a new field reader cannot forget this.** The field
refused most often is `origin`, and **the one shape being refused there is
precisely the shape that carries a home directory** — so a refusal quoting it
would copy personal data into a log *from the check that exists to catch it*.
`said(value)` describes by type, following `version._said`.

⭐ **And the order turned out to matter more than the care.** The gate runs
before the shape checks, so an `origin` carrying a home directory is refused by
R7's gate — which never echoes a matched value — rather than by the path rule.
Both are careful; the order means only one of them ever has to be.
`test_a_home_shaped_origin_is_caught_by_the_gate_before_the_path_check` pins it.

Also: `load` names `path.name` and never the path it read; a missing file names
`exc.strerror`; malformed JSON names `exc.msg` with line and column and never
the text.

### 6. A package, and the ceiling found it

The flat `container.py` reached **435 lines against R11's 400**. ⛔ No opt-out
taken. The seam was already there and is worth having a name: *reading one
declared field, and refusing it without reproducing it* is the discipline SF-03
got wrong, and it now lives in a module called that rather than in five private
helpers at the bottom of a format file.

### 7. SF-33's third caller, SF-08's second

```text
check("container_api", document.get("container_api"), KNOWN_CONTAINER_API,
      where=where, error=ContainerError)
```

⛔ This contract owns the **set**, not the check.
⭐ **The gate's invocation is asserted with the `source`-field technique, not a
mock:** the leak goes in `note`, which is checked only for being non-empty
text, so it passes every other check in the package. Only the gate can reject
it, and a reader that stopped calling the gate would pass every other test
here.

### 8. Which of SF-01's rules escape, and which are converted

⚠️ **SF-02's precedent, followed exactly and then extended with a reason of its
own.** The address **arity comparison** raises `AddressError`, because SF-01
owns that comparison outright. ⛔ Every other rule of SF-01's applied here —
what a slug is, what an ordinal is — is **converted** to `ContainerError`.

⭐ And converting them is not only consistency: SF-01's messages format the
offending value with `!r`, and these values are read straight out of a file
somebody else wrote (R7). The conversion is a refusal that describes rather
than reproduces.

## Round 14 — the seam `label` opened, closed where it opens

⛔ **The map accepted `a/b`, a tab and a newline as a `label`; SF-03's
`label_of` refuses all three.** So a corpus would **validate and then fail at
render** — a milestone later, in another package, with nothing in between
saying why. Taking the field now was still right; what was missing was the
constraint at the point of entry.

**`fields.optional_label`** refuses a label carrying anything in
`LABEL_FORBIDDEN` (`/`, `\`, space, tab, newline, **and a carriage return**,
which `label_of` does not list). ⭐ Strictly stronger at entry, so a validated
map can never carry a label that fails downstream, and `label_of` keeps its own
guard for callers that never came through a map — defence in depth, neither
substituting for the other.

⛔ **The refusal names the character class and never echoes the label** (rubric
§1f): a label is read straight out of a file somebody else wrote. The negative
control is in `test_fields.py` — `4.4.1`, `vii`, `A`, `1-2` and `§4` are all
accepted, because the constraint is a **character class, not a slug**.

### `numbering`, not `display`

⚠️ `Unit.display` returned `7` where `label_of` returns `unit-07`: two answers
to *"what is this unit called"* and neither said which was which.

⭐ **They are one rule with two fallbacks.** When a label is present they are
identical and both *are* the label. When it is absent, a **filename** wants a
prefixed, zero-padded, sortable form and a **page heading** does not. So the
property is now `Unit.numbering` — *this unit's numbering as a reader sees it*
— and its docstring names `label_of` as the other one and says why they differ.
`test_the_reader_s_numbering_and_the_filename_s_are_named_apart` pins both,
including that `display` is gone rather than aliased.

⚠️ **One definition, two spellings, and that is the residual risk.**
`LABEL_FORBIDDEN` is exported so `label_of` can import it rather than spell the
set a second time. ⛔ Routed to SF-03 — see *Findings* 6 — because the two
branches land adjacently and no test spans the seam today.

## Surprises

1. ⭐ **The acceptance said "loads a real CodeSignal `course-map.json`", and a
   test cannot.** The extraction source's path is an absolute home path (R7)
   and a task never cites a path inside it (R20). ⛔ Not quietly rewritten:
   the acceptance was met **at development time**, by loading all 285 through
   `from_document`, and what the suite pins is the *shape* — the measured key
   set, a real map reproduced field for field as `SAMPLE`, and
   `test_no_field_is_lost`. The numbers are in *Findings* with their commands.
   ⚠️ This is a general problem, not this task's: **every acceptance clause
   phrased "loads a real X" is unmeetable by a test under R7 and R20** — see
   *Findings* 3.
2. ⚠️ **FND-04's ruling was verified by the CTO and was still wrong**, because
   what was verified was that the fixture was *consistent*, not that the claim
   about the extraction source held. ⭐ The rule that caught it is the project's
   own: *if a document states a number, it is checkable — check it rather than
   inheriting it.* One `slugify` comparison over 116 files.
3. `test_a_label_that_is_present_but_not_text_is_refused` originally carried
   `None` in its parameter list and needed a branch inside the test to handle
   it. ⚠️ **A test with an `if` in it is two tests wearing one name**; absent
   and empty are different questions and they are now two tests.

## Findings

Every finding carries what was run, what came back, and when.

1. `[structural]` **`folder` is not derivable from the titles, in any of the
   116 maps that carry one.** FND-04 ruling 10 says it is subsumed by
   `address`; it is not, and it is now carried as `origin`.
   **Measured:** a script over `study/paths/*/*/course-map.json` in the
   extraction source comparing `folder` against
   `slugify(path) + "/" + slugify(course)` →
   `folder present: 116  derivable from titles: 0  NOT derivable: 116`, on
   **2026-09-09**. ⭐ **FND-04's handoff should be annotated**, because the
   claim will otherwise be inherited again.
2. `[local]` **The real shape, counted.**
   **Measured:** a key census over the same 285 files →
   `doc keys: {'path': 285, 'course': 285, 'language': 285, 'captured': 285,
   'units': 285, 'folder': 116, 'note': 2}`;
   `unit keys: {'n': 1290, 'title': 1290, 'practices': 1290, 'url_slug': 1290,
   'note': 13}`, on **2026-09-09**. And: `units 1290, non-slug url_slug 0`,
   which is what makes `url_slug`'s slug requirement a contract rather than a
   hope.
3. `[structural]` **An acceptance clause that says "loads a real \<source\>
   file" cannot be a test in this repository.** R7 forbids the absolute path
   and R20 forbids citing one inside the extraction source, so the clause can
   only be met at development time and pinned by shape.
   **Measured:** `grep -rn "a real " docs/tasks/E0*.md | wc -l` → `12`, on
   **2026-09-09** (not all of them name a file, but SF-05's did and it will not
   be the last). ⭐ The convention worth writing down: *such a clause is met
   by a measurement recorded in the handoff, with its command and output, plus
   a shape test in the suite.* That is what this task did; naming it stops the
   next task inventing a different answer — or quietly pasting a path.
4. `[structural]` **`fields.py` is the second module in this repository to hold
   "read a declared value and refuse it without reproducing it".** The
   manifest package has the same job spread through `document.py`, and
   SF-02's `parse` still formats `json.JSONDecodeError` straight into its
   message.
   **Measured:** `grep -n "not valid JSON" src/studyforge/corpus/manifest/document.py`
   → line 144, `f"{where} is not valid JSON: {exc}"`, on **2026-09-09** — the exact
   pattern `module-structure.md` now forbids, written before that rule existed.
   ⛔ Not patched: SF-02's file. **Needs routing**, and `fields.py` is where it
   would land.
6. `[structural]` **`LABEL_FORBIDDEN` is spelled twice and should be spelled
   once.** This module now refuses what `label_of` refuses, plus a carriage
   return; the constant is exported so placement can import it.
   **Measured:** `grep -n "in label" src/studyforge/corpus/placement/names.py`
   on `feat/SF-03-placement` → `if any(character in label for character in
   "/\\ \t\n"):`, on **2026-09-09**. ⛔ Not patched — SF-03's file, and its
   branch is in review. ⚠️ **No test spans this seam**, which is the same
   vantage-point problem the `folder` disproof exposed: each side is verified
   against itself. The cheapest fix is `label_of` importing the constant; the
   cheapest *check* is one test in whichever branch merges second.
7. `[local]` FND-06 finding 4 is still open — a `#:` doc-comment with nothing
   under it in `tools/quality/personal_data/shapes.py`. SF-05 never opened that
   tree.

## For dependents

**SF-03 (placement).** ⭐ `origin` is a contract now: optional on the container
and optional per unit, always a location **relative to the corpus root** —
absolute and escaping paths are refused here, so a profile need not re-check.
⛔ A profile that requires it must fail loudly when it is absent; 169 of the
extraction source's 285 maps have none.

**SF-12 / rendering.** `Unit.display` is what a unit is **called**;
`unit.n` and `address.unit_key(n)` are what it **is**. ⛔ A page's name comes
from identity. Never invert `display`.

**SF-25 (validate).** `unit.practices` is the **declared** count, preserved
verbatim — checking it against what is on disk is your job, and a reader that
corrected it here would have deleted the disagreement you exist to find.

**Adapter authors (E07, JS-05).** You generate this document. ⛔ Everything
derivable — address, titles, variant, unit list — is yours to generate, and
hand-writing it is a finding against the adapter-authoring skill. ⭐ What you
must **round-trip rather than overwrite** is `title`, `titles` and `note`
(`EDITORIAL_KEYS`); a generator that would discard one stops (R6). `render`
gives you the exact bytes so that "everything untouched is untouched" is
checkable rather than hoped for.

**Anyone adding a field.** ⛔ It is a `container_api` bump, and every map
written under the old version is refused until its adapter is re-run — which is
the whole reason `label` went in now rather than at M6.
