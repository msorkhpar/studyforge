## Decisions

⭐ SF-01 set the precedent that these say *why*. Overrule any of them
explicitly.

1. ⭐ **`content` is a schema field, not a heuristic.** C2 is a schema problem:
   ISO ships per-unit files *and* three whole-series aggregates that are
   digest-identical ordered concatenations of them, so `src/*.md` ingests all
   38 units twice and nothing complains. "These two files overlap" is a
   finding for reconnaissance to report, never a guess for an ingest to make.
2. ⭐ **`include` is plain globs; every `exclude` entry carries a `why`.** The
   asymmetry is the design: an inclusion needs no justification, an
   **exclusion is material withheld from the reader**, and a withholding
   nobody has to explain is one nobody audits. Same argument `permitted_edits`
   already makes about an edit, and the same 20-character floor
   `tools.quality.config` already uses for a size exception. Two rules, one
   precedent.
3. ⭐ **An exclusion names one file, never a pattern**, and that follows from
   the `why`: one justification covering a glob is one justification for a set
   whose membership changes when somebody adds a file — the audit quietly
   widening itself.
4. ⛔ **A file matching neither list is `UNCLASSIFIED`, and that is a refusal
   at validate time, not a third kind of content.** Silence is the failure C2
   describes. SF-25 enumerates the source root and exits 1 on the leftovers.
5. ⭐ **R3's third prohibition is checkable because `content` exists.** "Any
   file the material's own reader depends on as content" used to be
   unenforceable prose; it is now `content.classify(path) is INCLUDED ⇒
   refused`. That is why `content` and `permitted_edits` belong in one
   release, and it is why `parse_edits` **requires** the content policy rather
   than taking it optionally — a prohibition checked only when convenient is
   not one.
6. ⚠️ **There is no `reverse` field, and the reversal is derived.** ⭐ *For
   the CTO to confirm or overrule.* An `insert-line` declaration already
   records the insertion exactly — the anchor and the line — so the reverse is
   that line, removed. A second field is a second thing to keep in step with
   the first, and the failure mode of a **stale** undo is worse than of no
   undo. If the reversal should be declared rather than derived, that is a
   schema change and it is nearly free while `corpus_api` has no consumers.
7. ⛔ **One `EDIT_KIND`, and an unknown one is refused rather than guessed
   at.** Widening the vocabulary is a decision with a source behind it.
8. ⭐ **An absent `media` key returns `DEFAULT_MEDIA`, not `None`.** No caller
   ever asks "did they declare one?", so no caller ever gets the answer wrong.
   ⚠️ `auto` **commits** — it is not "decide later", it is "commit, and stop
   loudly when the limits say to". *Regenerable is not the same as available*
   (R8): a clone that carries its own audio speaks with no synthesis service,
   no GPU and no network.
9. ⭐ **`Manifest.parse_key(key)` is the one place declaration meets
   comparison.** SF-02 declares the depth (`levels`); SF-01 owns the
   comparison. No caller writes `parse_key(key, len(manifest.levels))`, so no
   caller passes the wrong number. ⛔ There is **no** second arity check here
   with a different message.
10. ⚠️ **Reading a manifest raises `ManifestError` and nothing else — even
    where the rule is SF-01's.** A bad `source` or `variants` entry is checked
    by SF-01's `require_slug`, and `_slug_of` re-raises SF-01's message as this
    package's type. ⭐ One deliberate exception, and it is not a leak:
    `Manifest.parse_key` raises `AddressError`, because that call *is* the
    arity comparison and SF-01 owns it outright.

## Surprises

Three defects the tests found in my own source. Each is fixed in this branch.

1. ⛔ **`1.0 in {1}` and `True in {1}` are both true in Python**, so the one
   gate R9 puts in front of everything else let a JSON `true` or `1.0` through
   as `corpus_api`. `_check_version` now checks the *type* before the value.
   Found by `test_an_unknown_corpus_api_is_refused[1.0]` and `[True]`, which
   were written as routine parametrisation and were not.
2. ⛔ **R7 in a failure message.** `load` formatted `OSError` with `{exc}`, and
   an `OSError` formats itself with the filename it was given — so a missing
   `corpus.json` produced a refusal carrying an absolute path, which is the
   user's home directory. It now uses `exc.strerror`. Found by
   `test_a_missing_manifest_refusal_carries_no_absolute_path`, which exists
   only because R7 is a standing rule and it seemed worth asserting.
   ⭐ **Routing:** this is a pattern, not one line — see the finding below.
3. ⚠️ **`errors.py` claimed "every public function in this package raises it
   and nothing else" and that was false** the moment `source` and `variants`
   used SF-01's slug rule. Rather than weaken the promise, the promise now
   holds (decision 10) and the one exception is named in the contract.

## What moved, and which one

⚠️ The instruction was to say which moved when the manifest and the fixture
disagree. Twice they did.

1. **The fixtures moved.** `content` is a required key, and FND-04's five
   `invalid/` fixtures each carried no `content` — so each violated *two*
   rules, and "exactly one violation per fixture" is the property that makes
   them useful. All five gained a minimal `content` block.
   `test_an_invalid_fixture_whose_fault_is_elsewhere_still_has_a_readable_manifest`
   and `test_the_bad_corpus_api_fixture_is_refused_for_its_version_and_nothing_else`
   now hold that property structurally instead of by inspection. ⭐ The
   manifest did **not** move: a corpus that cannot say what its material is has
   not stated a policy, and defaulting `content` to "everything" is exactly the
   double ingest C2 describes.
2. **My test moved, and the model was right.** I asserted that a variant
   `01-java` is refused. It is not: SF-01 accepts a leading digit in a *slug*
   and repairs it only where the slug must become a code identifier, which a
   variant never does. The assertion is now
   `test_a_variant_may_begin_with_a_digit_because_a_slug_may`, stating the
   accepted behaviour rather than a guess about it.

## Findings

Triaged. ⛔ None of these entered this diff.

### `[structural]` R7 in exception text is a pattern, not a line

Surprise 2 is the general case: **any** `except OSError as exc: … {exc}` puts
an absolute path into a message that ends up in a log and a bug report. There
is one such site now because there is one file reader now; SF-04, SF-25, SF-28
and every adapter will add more.
⭐ **Proposed:** a rule in `tools/quality/personal_data/` that fails an
f-string interpolating a caught `OSError` (or a `Path`) into a message, plus
one line in `docs/conventions/module-structure.md`. ⚠️ **Needs a ruling before
the next wave**, because a check that arrives after twenty sites exist is a
check nobody turns on. Not done here: `tools/quality/` is not SF-02's, and a
commit that adds a check must bring the whole tree into compliance in the same
commit.

### `[structural]` The two `media` limit field names are FND-04's invention

`max_total_bytes` and `max_file_bytes` are **not in the spec**. I invented them
for a fixture in FND-04, and `media.py` carries them forward so the fixture and
the reader agree rather than disagreeing silently. ⭐ **SF-32 owns the real
names** (it owns the measurement). ⚠️ Renaming them is nearly free *now* —
`corpus_api` is at 1 and has no consumers — and stops being free the moment an
adapter writes one. Route the rename into SF-32 explicitly, or confirm these
names and delete this finding.

### `[structural]` `PLACEMENT_PROFILES` is a seam SF-03 must own

`document.PLACEMENT_PROFILES = ("tree", "sibling")` is the set a *manifest may
name*. SF-03 owns what a profile *does*. Two constants that must not drift.
⭐ **Proposed:** when SF-03 lands, it registers its profiles and this constant
derives from that registry rather than restating it; until then this is the
one place a third profile is added. Confirmed or overruled by SF-03's author,
not by me.

### `[local]` `content.classify` takes a path and does no I/O, by design

Enumerating a source root — and therefore *finding* the unclassified files — is
SF-25's job. Stated here so SF-25 does not assume this module already did it:
it did not, deliberately.

### `[local]` `MIN_WHY_CHARS` is duplicated in spirit with the size-exception floor

Both are 20, both exist only to stop a token being a way through a gate. Not
extracted to a shared constant because they are two rules that happen to agree
on a number, and coupling them would mean changing one changes the other. If a
third appears, extract.

## For dependents

### For SF-25 (`studyforge validate`)

- `content.classify(path)` is the three-way answer. ⛔ `UNCLASSIFIED` is
  **exit 1**, not a warning — that is the whole point of the field.
  `why_excluded(path)` gives the recorded reason for a withheld file, and
  belongs in the report.
- SF-01's handoff already routed you "no two containers claim the same
  address". This adds: **no file in the source root is unclassified**, and
  **every declared `permitted_edits` path exists**. Neither is checkable here —
  both need the disk.

### For OPS-05 (onboarding)

- ⛔ Read `manifest.allows_edit_to(path)`. Never hardcode a corpus's exception.
  The Java repo's additive `<module>practice</module>` line in the root
  `pom.xml` is **one entry in a list**, and `tests/fixtures/depth2/corpus.json`
  is that entry as data.
- `edit.reversal` gives the undo (`remove-line`, the same content). ⚠️ Whether
  the declared edit turns out to be additive *in fact* is yours to detect —
  this module only refuses declarations that cannot be additive by
  construction.

### For SF-03 (placement)

- `manifest.placement` is validated against `PLACEMENT_PROFILES` and nothing
  else. See the finding above: the two must not drift.

### For SF-32 (media footprint)

- `manifest.media.commits`, `.has_limits`, `.max_total_bytes`,
  `.max_file_bytes`. ⛔ A corpus that crosses its limits **stops and names the
  number and the limit**; it never silently switches to ignoring media (which
  produces clones that are silent with no error) and never silently keeps
  committing. The extraction source reached 11.42 GiB of pack against a ~5 GB
  soft limit with one file at 150.9 MiB against a hard 100 MiB block, and found
  out when the push became *impossible*.
- ⚠️ The field names are yours to confirm or rename. See the finding.

### For SF-07 and anything that reads a corpus

- ⛔ **`variants` is a filing and presentation key and nothing more.** It says
  how the archive is partitioned and what a variant selector offers. It never
  implies anything is buildable, runnable or gradable — that is declared per
  exercise (§7) — and it is **not** a code fence's language, which is a block's
  own attribute from the archive. The extraction source blocked eight SQL
  courses because one list answered both "can this be filed here?" and "can we
  generate a test for it?". Three questions, three answers, none derived from
  another — and `test_no_module_maps_a_variant_to_a_capability` now fails the
  build for the shape of that mistake anywhere under `src/`.
