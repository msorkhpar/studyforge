## Decisions

Why option 1, with one rule shared between the writers:

- **R19 is advice only if a regenerate can run.** The scaffold's caller is a person following [`SKILL.md`](../../../src/studyforge/skills/adapter/SKILL.md). After step 4 of that procedure the hand-written module always exists, so the old refusal failed every regenerate. The only way through was to delete the person's file or write the parts one at a time, which is what `W257`'s re-read did. Option 2 would have given the adapter skill a flag that refuses in every real state.
- **One rule rather than two agreeing copies.** Onboarding composes the scaffold's `Written` set, so the rule can sit in the adapter package and onboarding stays downstream of it. The disagreement was two copies of one rule, so the fix removes the second copy.
- **The kept module is `Written.generated`**, never a name. That is the same declaration W256's record reads.

## Surprises
