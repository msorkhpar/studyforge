## Decisions

⭐ **The PO put SF-11 last so its shape could be chosen carefully; SF-12 and
every renderer after it inherits these.** Overrule any of them explicitly.

1. ⭐ **`surface.py` publishes the class names the stylesheet targets, and a
   renderer takes them from there.** This is the decision I would most like
   reviewed. The failure it prevents is silent and total: a stylesheet and a
   template that disagree about one class name produce a page that renders,
   carries every word, and is **unstyled, with no error anywhere**. In the
   extraction source they were one codebase and could not disagree; here
   SF-11 lands before SF-12, so the agreement has to be written down. ⚠️ SF-12
   may rename any of them — that is a change to `surface.py` and the
   stylesheet **together**, and `test_surface` fails a rename that touches one
   side. ⛔ What it may not do is invent a second name for something already
   there.
2. ⭐ **A class exists only where an element needs a hook.** `heading`, `para`,
   `rule`, `quote`, `table` and `html` are styled as `h2`, `p`, `hr`,
   `blockquote` and `table` — a class that adds nothing is a class that has to
   be kept in step for nothing. Five block types have one: code, image, video,
   disclosure, list.
3. ⛔ **`SURFACE_CLASSES["list"] == "items"`, deliberately not `"list"`.** A
   class name is a *hook*, never a block type read back — R4's argument about
   paths, applied to markup. One entry where the two strings differ is what
   makes inverting the mapping impossible rather than merely discouraged.
4. ⭐ **The bundle order is a stated tuple; `names()` sorts and composes
   nothing.** Two rules of equal specificity: the last wins, so the sequence
   *is* the design. R10 forbids depending on directory order, and `names()`
   exists only to prove the directory and the bundles agree.
5. ⛔ **Plain names, `page.css` and `page.js`.** §8.2, and SF-11 is the task it
   was written for. ⚠️ Recorded in `bundle.py` next to the **opposite** rule
   for narration clips, whose filenames *do* carry a digest — the difference is
   that nothing links a clip by a name a thousand pages repeat.
6. ⭐ **The palette is the only file allowed to hold a colour**, asserted both
   ways: no raw colour outside it, and no `var(--x)` anywhere without a
   definition. Two exemptions, by file *and* by value: `#000` and `#fff` in
   `video-player.css`, because black behind a video is the absence of picture
   and a control drawn on it stays white in both themes.
7. ⭐ **The highlight check is split by what it needs to run.** The runtime-free
   half asserts what the stylesheet does with a combination; the node half
   *discovers* which combinations exist. ⛔ And they are chained:
   `test_every_combination_a_grammar_emits_is_recorded_for_the_runtime_free_half`
   fails if a grammar emits something the in-gate table does not record, so the
   half that always runs cannot fall behind the half that sometimes does.
8. ⛔ **No module under `src/` holds a list of languages** (R1). The extraction
   source's `LANGUAGES = ("kotlin", "java", "python", "javascript", "sql")` did
   not come across. What is highlightable is whatever grammars the vendored
   bundle carries; the node harness reads them **out of the bundle** and fails
   if one is vendored without a sample. SF-02's
   `test_no_module_maps_a_variant_to_a_capability` already fails the build for
   the shape of that mistake, and this task is the first to have been tempted.
9. ⭐ **Vendored CSS is themed from outside, never forked.** `video-player.css`
   loads after `plyr.css` and sets Plyr's own custom properties, so
   re-vendoring Plyr does not strand it.
10. ⚠️ **`AssetError` subclasses `Exception`, not `ValueError`** — SF-01's split
    applied rather than re-derived: every failure here is "this file is not one
    I can read", never "you passed me a bad value".

## Surprises

1. ⛔ **The vendored Plyr bundle contains remote URLs** — YouTube, Vimeo, a CDN,
   an ad SDK — for streaming providers this site never uses. A naive R8 check
   (`no https:// in any asset`) fires on it, and the only way to make such a
   check pass is to **edit vendored code**, which is the rule this project
   actually holds. ⭐ So the check is precise instead: no *authored* asset
   fetches anything, and every network path Plyr has is disarmed by
   configuration (`loadSprite: false`, `iconUrl: ''`, `blankVideo: ''`).
   `test_a_vendored_bundle_may_contain_a_url_and_that_is_not_a_defect` pins
   that so a later reader does not "fix" it.
2. ⚠️ **`FETCHING` had to learn the difference between a URL and an
   identifier.** `plyr.svg` carries an XML namespace and a DOCTYPE system
   identifier, both `http://www.w3.org/…`, and a browser fetches neither. A
   check that could not tell them apart would have been switched off the first
   time an SVG was vendored.
3. ⚠️ **`plyr.svg` had no vendoring header and `plyr.css`'s did not say how to
   re-vendor it.** Both fixed — an XML comment and a CSS comment, which is the
   one permitted modification. Without a header, "unedited" is not a checkable
   claim, and the acceptance clause asks for one.
4. ⭐ **The extraction source's contrast claim is correct — I checked.**
   "Every one clears 4.5:1, the lowest being `--tok-comment` at 5.0": measured
   **5.02** light and **5.10** dark. `test_palette` recomputes both rather than
   inheriting the sentence.
5. ⚠️ **`plyr.css` opens with a comment and then `@charset "UTF-8";`, which is
   inert.** `@charset` is honoured only as the very first bytes of a
   stylesheet, and this one is concatenated fifth. Harmless — the page declares
   UTF-8 and it is the CSS default — and left alone, because removing it would
   be editing vendored code. Recorded in the file so nobody re-discovers it.
6. ⚠️ **The first draft of the class contract failed on 33 Prism token
   classes.** Right failure, wrong scope: `code-highlight.css` selects on
   classes *Prism* writes at run time, and no renderer emits one. The contract
   is now about the parts a renderer must match, and two separate tests pin
   that the highlight and player stylesheets reach for one hook each and
   otherwise only for classes their library writes.

## Findings

### 1. `[structural]` ⛔ The dev image has no JS runtime, so an acceptance clause cannot run in the gate

38 tests skip in the container. They are the half of the highlight check that
runs the **real vendored grammars** — the half that caught the original defect,
where a string-literal variant filed under `comment` italicised every string in
one language and *the tests still passed*.

⭐ **Mitigated, not ignored.** The split above puts every assertion that does
not need a runtime into `test_highlight.py`, which always runs, and chains the
two so the in-gate table cannot go stale. But **a new combination can only be
discovered where node is installed**, and SF-12, SF-14 and every later
highlight change inherits that.

⚠️ **Needs a ruling before the next E03 task.** Three options, cheapest first:
add `nodejs` to `docker/dev/Dockerfile` (FND-03's surface, ~40 MB, and its own
comment warns against an image that quietly grows a toolchain — so it is a
decision, not a patch); or run the node half in CI only and accept that a local
gate cannot; or accept the mitigation and require that any change to
`code-highlight.css` be verified on a host with node. ⛔ I did not edit the
Dockerfile: it is another task's surface, and the standing rule is a finding,
not a patch.

### 2. `[structural]` The markup contract is a seam between two tasks and only one of them exists

`surface.py` is SF-11 guessing at SF-12's element names. It is guarded from
drifting, but it is not *agreed*. ⭐ **Proposed:** SF-12 reviews
`SURFACE_CLASSES` and `SURFACE_HOOKS` as its first act and renames whatever it
wants, in one commit touching both the mapping and the stylesheet. Confirmed or
overruled by SF-12's author, not by me.

### 3. `[structural]` The reading surface stops where the page chrome starts, and the line is mine to declare

Not ported, deliberately, and each is another task's: masthead and layout grid
and the navigation rail (SF-12), the contents tree (SF-13/SF-14), the narration
highlight and the player footer (E04 — `--hl-bg`, `--hl-bar`, `--hl-fg`,
`--hl-code`, `--player-height` and `--shadow` are defined for them and used by
nothing yet), progress controls (SF-30), practice panels and language pills
(E08 — `--practice`, `--practice-soft`). ⚠️ **The palette therefore defines
tokens nothing currently paints with**, which the palette test deliberately
does *not* fail — the palette is the shared vocabulary later surfaces draw
from. ⛔ If E04 and E08 land without claiming theirs, that leniency should be
withdrawn and the unused tokens pruned.

### 4. `[local]` The narration/video interlock did not come across

The extraction source wires "a video starts ⇒ pause the narration" and the
reverse, from the elements' own events. Half of it is here (two videos on one
page do not talk over each other); the narration half needs an element E04
renders. ⭐ `video-player.js` says so, and the convention it uses — wire from
the elements' events, in the capture phase, so neither module knows the other
exists — is what lets E04 add it without editing this file.

### 5. `[local]` The copy button is created by script, not rendered

⛔ A button written into the markup would sit there doing nothing with
scripting off, and a control that does nothing is worse than none. So SF-12
renders the `figcaption`; `copy-code.js` adds the button. ⚠️ `navigator.clipboard`
needs a secure context and `file://` is not one in every browser, so there is a
selection-and-`execCommand` fallback and, when neither works, the button says
so rather than silently failing.

### 6. `[local]` `page.css` is 51 KB, of which 33 KB is vendored Plyr

A corpus with no video pays for the player on every page. Not addressed here —
one shared file that every page links and every browser caches once is worth
more than two conditional ones, at this scale. ⚠️ If a reading-floor-only
profile ever matters, the seam is `STYLE_PARTS`/`SCRIPT_PARTS`, and it is one
tuple each.

## For dependents

### For SF-12 (unit page renderer) — read this first

- ⛔ **Take class names from `SURFACE_CLASSES` and `SURFACE_HOOKS`, never
  retype them.** `class_for(block_type)` returns `None` for the types styled as
  the elements they are, and that `None` is the answer, not a gap.
- The markup the stylesheet expects, per block type:

  | Block | Element |
  |---|---|
  | `heading` | `<h2>`…`<h6>` |
  | `para` | `<p>` |
  | `code` | `<figure class="code"><figcaption><span class="what">…</span></figcaption><pre><code class="language-X">` |
  | `list` | `<ul class="items">` / `<ol class="items">` |
  | `table` | `<div class="scroll"><table>` — ⛔ the wrapper is not optional, or the page scrolls sideways |
  | `image` | `<figure class="image"><img><figcaption>` |
  | `video` | `<figure class="video"><video controls>` — keep `controls`, it is the no-JS fallback |
  | `rule` | `<hr>` |
  | `quote` | `<blockquote>` with real blocks inside |
  | `disclosure` | `<details class="disclosure" [open]><summary>` — ⭐ `open` is the **author's**, from the archive |
  | `html` | passed through |

- ⛔ **Link, do not inline.** `written_files()` gives `{"page.css": …,
  "page.js": …}`; write them once beside the pages and link them **relative to
  the page** (R8, R4). Never a digest in the name.
- ⚠️ **The template loader is yours.** The extraction source keeps `text()` and
  `template()` in one module; here `template()` is SF-12's, and the byte-exact
  read (`read_bytes().decode`, never `read_text`) is the part worth copying —
  universal-newline translation silently changes what ships.
- `render/templates/` does not exist yet; ⛔ `[tool.setuptools.package-data]`
  already covers it, so **add files, not build configuration**.

### For SF-14 (root index) and SF-13 (contents)

Add a part beside these rather than a second stylesheet: one file every page
links is the whole argument (79% of each page in the extraction source, and
byte-identical across all of them). `STYLE_PARTS` is where it goes, and its
position in that tuple is the decision to think about.

### For E04 (narration)

`--hl-bg`, `--hl-bar`, `--hl-fg`, `--hl-code`, `--player-height` and `--shadow`
are defined in both themes and are yours to use. ⭐ Wire the "video plays ⇒
narration pauses" half from the elements' own events, in the capture phase, the
way `video-player.js` already does the video-to-video half — that convention is
what lets you add it without editing this file. ⛔ And a `disclosure`'s body
gets no speech ids: speak the `summary` and stop.

### For anyone touching the highlighting

⛔ **Do not reorder the groups in `code-highlight.css` without reading its
header.** Every selector has the same specificity, so the last group to match
wins and the order *is* the mapping. ⚠️ If you change it, run
`test_highlight_grammars.py` **on a machine with node** — the container will
skip it and report green.
