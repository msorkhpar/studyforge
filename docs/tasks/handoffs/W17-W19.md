## ⛔ 54 of the 58 were one class nobody had named

Every reader listed its unknown keys **verbatim**:

```text
container.json carries unknown key(s) ['/srv/build-artifacts/material']; a container map is […]
```

⭐ **`describe_keys` existed for exactly this and was used at none of the ten
sites.** Ruling 37 minted it a round ago with the right contract — *`describe`
may never reproduce a `str`; `describe_keys` may name a structurally safe key*
— and nothing had applied it where the keys actually arrive from a document.

⚠️ **That is the shape worth keeping: the helper landing and the sites adopting
it are two pieces of work, and the second is invisible without a check.** W1
had the same gap in reverse — it created `describe.py` and ten modules adopted
it in the same commit, which is why nobody noticed that the *key* half had not.

## ⛔ Two poisons, because one class of site was protected by luck

**`POISON`** is a home path. Most readers now gate it: `assert_clean` runs over
the whole document first and refuses it, so the field's own message never runs.

**`ESCAPING`** — `/srv/build-artifacts/material` — is absolute and carries
nothing personal. ⛔ The gate does not refuse it, so it reaches the field
validation underneath. **That is where the worst sites in the tree live**, and
they are the ones the CTO flagged:

```text
def _reject_absolute(pattern, where):
    if pattern.startswith("/") or pattern.startswith("~") or ".." in ...:
        raise ManifestError(f"{where} must be relative … got {pattern!r}")   # ⛔
```

⭐ **Worse than the site W1 fixed, and the CTO's reason is exactly right.**
`require_slug` fired on *"not a slug"*, which is only **sometimes** a path.
This branch tests `startswith("/")`: it fires **because** the value is an
absolute path, which is precisely when it carries a home directory. The check
written to keep a path out of the corpus put it in the log instead.

⚠️ **Ruling 17's finding, made visible rather than assumed.** A field that
refuses the home path only because the gate's shape list happened to name it is
safe by a list, not by construction — and
`test_the_gate_protects_some_fields_and_the_probe_says_which` asserts the
distinction is real rather than describing it.

## Decisions

### 1. W17: the disagreement was resolved in favour of the copy that had made the case

Developer 1's table was the whole scope, as promised. Three behaviours differed
and each was decided on its own argument:

| | before | after | why |
|---|---|---|---|
| `3` | `describe` `3` · `said` `an int` | **`3`** | An integer cannot carry an identifier, and a refusal that will not say `unit 4` is unactionable |
| `True` | `describe` `True` · both others `a bool` | **`a bool`** | ⛔ Safety was never the question — a bool carries nothing either way. `True` is **not what the integrator typed**: they wrote JSON `true` where `1` was wanted |
| `""` | `said` `an empty string` · others `a str` | **`an empty string`** | Absent and present-but-blank are different mistakes; the second is somebody who meant to write something |

⭐ **The bool case is the one worth recording.** `version._said` had the
argument written down *and pinned by a test* while the extraction quoted the
opposite — **the extraction was the copy that had never made the case.** ⚠️ It
is also why the disagreement survived three copies: R7 was indifferent, so
nothing forced a decision.

⭐ **`describe_keys` is untouched.** Ruling 37 is right that one name for two
contracts is the defect and two names for two contracts is not, and the
sentence it left owed is Developer 1's — not duplicated here.

### 2. ⛔ The document probe, and why the per-callable one could not do this

`tests/emission/probe.py` poisons an argument at a public boundary. A refusal
raised *inside* a reader fires only when the rest of the document is valid, so
poisoning the whole argument gets refused at the first gate and never arrives.
⚠️ **It reported zero on a tree with 58.**

⭐ **That is not the probe being wrong — it is its stated coverage limit, and
the limit is what made this buildable.** W1's handoff named the number before
this code existed. A check that says what it cannot see is worth more than one
that implies it sees everything.

### 3. ⭐ The reader table is a table of readers, and it is guarded

`test_every_module_that_reads_a_document_is_probed` derives every module
defining a public `from_document` or `parse` and fails on any that no fixture
poisons. ⛔ **It found one on its first run: `exercise/record.py`** — a reader
nobody had probed, added because the guard said so rather than because anybody
remembered. (It had no leaks; Developer 1 had already used `describe_keys`
there.)

⚠️ **A missing entry costs coverage, reported as a number.** A missing
allow-list entry would cost a silent pass. Same list, opposite failure
direction — Ruling 38, which is why this shape and not the other.

### 4. What is left quoted, and the property that makes each safe

**23 sites**, all one class: **the value has already been proved to be this
framework's own vocabulary before the message runs.**

| what | where | proved by |
|---|---|---|
| an address key, a container key | `address/`, `placement/profile.py`, `validate/structure.py` | every segment passed `require_slug` |
| a unit name, an ordinal, a separator | `address/address.py` | matched `unit-<digits>`, or a module constant |
| a member of a closed set | `unit/content.py`, `edits.py`, `sections.py` | membership tested on the line above |
| an asset filename | `render/pageassets/source.py` | refused unless it is one of the shipped assets |
| a placement profile's name | `placement/profile.py` | registered by this build |

⛔ **`validate/paths.py:124` and `structure.py:59` are the two I want a
reviewer to look at**, because their proof is weaker than the rest: a placement
path is computed by the framework from validated slugs, and `on_disk` is a
directory name **relative to the archive root**. Both are structurally
incapable of holding an absolute path, but neither is *validated* — they are
safe by where they come from.

## Findings

### 1. `[structural]` A helper landing and its sites adopting it are two pieces of work

**Measured:** `describe_keys` shipped with the right contract and **zero of the
ten sites that needed it**. ⭐ W1 did the same thing correctly by accident — it
created `describe.py` *and* migrated ten modules in one commit, so nothing was
left to notice.

⛔ **The general rule: a commit that adds a helper says which sites it replaces
and migrates them, or files the migration as a task with a number.** ⚠️ "It is
available now" is how a helper acquires zero callers and a good docstring.

### 2. `[structural]` The personal-data gate protects field checks by accident

**Measured on this branch:** poisoning `corpus.json`'s `title` with a home path
is refused by `assert_clean`; poisoning `placement` with `/srv/…` is not, and
reaches the field check underneath. ⛔ Ruling 17 said this about `validate`;
it is true one layer down as well, and **the two probes now tell the cases
apart by construction** rather than by anybody remembering to try both.

⚠️ Not a defect to fix — the gate is doing its job. It is a **reason not to
count a field as safe because a home-path poison came back clean**, which is
the mistake the single-poison probe would have made.

### 3. `[local]` `validate/structure.py` reads raw JSON and formatted three fields with `!r`

`document.get('unit')`, `document.get('kind')` and `document.get('ordinal')`
were quoted from an **unvalidated** document — the finding is a mismatch, not a
leak in the usual sense: the code treats them as an int and a member of a
closed set, and at that point they are whatever the file said. Fixed with
`describe`. ⚠️ Worth flagging to `validate`'s owner as a pattern, not just
three lines.

### 4. `[local]` `archive/markdown/leaf.py` quoted a raw source line

`f"line {lineno} is an <img> tag with no src attribute: {line!r}"` — a markdown
line is the corpus author's own text and can hold anything. ⛔ The line
**number** is what a reader needs; they have the file. Fixed.
