## Decisions

⭐ **Things the task did not specify, chosen here, each with the reason:**

1. ⛔ **THE AUTHOR IS A PROTOCOL, AND THE TESTS' AUTHOR IS A SCRIPT.** `Author.draft(brief)`
   and `Author.excuse(entry)` are what a converting agent (a model) implements at ingestion.
   In the tests, `authoring.Scripted` answers from a per-page list, one draft per attempt, so
   what is under test is the loop, the budget and the report. ⭐ **The runner is real in the
   tests**: every gate reading comes out of a `pytest` process over real files, as in
   `AX-03`'s `workspace.py`. So every plant's effect was observed and not typed in.
2. ⛔ **THE JUDGE IS A SEPARATE CALLABLE FROM THE AUTHOR.** Spec §7 §7 calls `Q1`–`Q3` *"an
   independent pass"*. An `Author` that also judged would be grading its own work, so
   `author_corpus` takes `judge` as its own argument.
3. ⛔ **THE SOURCE CASE IS READ, NEVER DECLARED.** `source_case` reads it off the ledger's
   entries for the page and the graders the page declares. ⚠️ An author that could name its
   own case could file a page with tests under `neither`.
4. ⛔ **EVERY EXERCISE THIS SKILL WRITES IS `generated`/`advisory`, CASE (a) INCLUDED.** The
   two words are `drafts` constants and not draft fields. ⚠️ Spec §7 §1 row (a) is *"derived
   by blanking … `bundled` · `authoritative`"*, and that derivation is `SK-04`'s. It is not
   re-implemented here. ⭐ What case (a) gets from this skill is the row's second sentence:
   *"may ALSO gain authored exercises … those are `generated`"*. The fixture's case (a)
   exercise uses the source's own test as its main ask and authors one edge on top, because
   `G3` requires an edge and the source's test has none.
5. ⛔ **ORDINALS ARE HANDED OUT AS EXERCISES SHIP.** A refused planned exercise leaves its
   ordinal for the next one, so a page never numbers `1` and `3`. Both
   `bundle.require_no_gap` and `validate`'s `practice-ordinals` refuse that shape.
6. ⛔ **A RETRY THAT CARRIES FEWER CASE IDS OR QUESTION IDS IS REFUSED, AND THE PASS STOPS.**
   It is compared by id and not by count, so swapping the refused edge for an easier one is
   caught too. ⭐ It raises rather than becoming a shortfall. A shortfall is an honest
   failure; a retreat is the author trying to game the gate, and the pass does not go on
   reading from an author that did that.
7. ⛔ **R10 IS MET BY NOT ASKING AGAIN, NOT BY COMPARING BYTES AFTER.** A model's second
   draft is never byte-identical to its first, and a run's output carries timings. ⭐ So a
   unit whose committed `coverage.json` still matches its page's digests and its plan is not
   re-authored at all. A ledger entry whose bytes are unchanged keeps the reason already
   committed for it.
8. ⛔ **R3 IS CHECKED WHOLE BEFORE A BYTE IS WRITTEN.** `commit` refuses the entire pass if
   any target exists with different bytes, so a refusal never leaves half a pass in the tree.
   ⚠️ **A unit whose page moved is refused, naming its directory.** Its bundles were proven
   against the old material, and rewriting them is exactly what R3 forbids. The refusal
   names what to remove: that unit's directory and `exercises/ledger.json`.
9. ⛔ **THE CITATION IS READ OFF THE LEDGER'S `Source` ROWS, NEVER OFF `digests()`.** That way
   the one thing a gate is handed is the one thing it is tested against. It is also why the
   plant above reds at the gate and not in a lookup `gating` did first.
10. ⛔ **A RUN IS STAGED IN A FRESH DIRECTORY, AND ITS OUTPUT IS MADE RELATIVE AND SCRUBBED.**
    Nothing a run leaves behind reaches the next run, and nothing is written into the corpus
    while gates are read. ⚠️ The output reaches a committed `coverage.json`, where this
    repository's personal-data gate never looks, so the staging root becomes `.`, each line
    passes through `scrub`, the tail is kept, and `assert_clean` runs before any document is
    written.
11. ⭐ **`words_of` IS THE SKILL'S ONE SPELLING OF A PAGE'S WORD COUNT** (`AX-07` left it to
    the skill). It counts prose, with each fence's body and language tag left out, and it
    uses `scan`'s fence grammar rather than a second one.
12. ⛔ **THE SKILL DOES NOT EDIT `corpus.json`.** The two `not_material` lines (`AX-04/2`) and
    the ignore rule (`AX-04/3`) are stated as preconditions in [`SKILL.md`](../../../src/studyforge/skills/exercises/SKILL.md). An existing file is
    never rewritten (R3). See `AX-08/4`.

## Surprises

⛔ **`validate` FIRES ON A QUIZ, AND THE BUNDLE'S CLOSED FILE SET DECIDED WHERE A QUIZ LIVES.**
`AX-04`'s handoff, in its note to `AX-06`, says `validate.exercises` *"triggers on a
`generated` grader, which a quiz record does not carry"*. ⚠️ **Read in the code, that is not
what it does.** `validate.exercises._authored` asks `exercise.provenance != GENERATED`, and
`quiz.require_quiz_shape` makes every quiz's provenance `generated`. So a quiz practice needs
`gates.json` at `Places.gates`, and its directory is held to the closed set
`layout.unpermitted` enforces. ⭐ That left one legal name for a quiz's own document, under
`tests/`, and a quiz's key IS its grader. See `AX-08/1`.

⛔ **TWO TREE-WIDE INSTRUMENTS WENT RED ON THE FULL HOST SUITE, AND BOTH WERE RIGHT.**
- `tests/gate_coverage/test_coverage.py::test_every_document_reader_calls_the_gate` refused
  `gating.py`, which round-tripped a record through `json.loads` without calling
  `assert_clean`. ⭐ The round-trip was unnecessary: `record_of` reads `record_document`'s
  output directly.
- `tests/studyforge/corpus/container/test_origin_sites.py::test_the_tree_holds_no_second_reader_of_origin`
  refused `corpus._accounts_in`, which read `entry.get("origin")` and rebuilt a record around
  it. ⭐ `origin_in` takes the whole record (`W109`), and handing it the entry is the fix.

⚠️ **The package suite was green for both.** This is the third row in a row where only the full
host suite found the defect.

⚠️ **THE LEDGER REFUSED THE FIRST FIXTURE, CORRECTLY.** A page titled `# Shouting` with a
`## Shouting` section carries that name twice, and a region origin naming it is ambiguous
(Ruling 92). The fixture was renamed. ⭐ Worth knowing for anyone authoring: a page's title
heading counts as a section.

⚠️ **The context budget (~40k) was short by the seam, as `AX-07` found.** Most of the reading
was not in any `Context` field: `validate/exercises.py` (what fires on a quiz),
`bundle/layout.py`'s closed set, `bundle/emit.py`'s path-argument rule, `execute`'s contract
(to decide not to depend on it), and the two sweeps above.

## For dependents

### ⛔ `AX-10` — the authoring guide

- ⭐ **The worked example is in the test tree.** `tests/studyforge/skills/exercises/authoring.py`
  is a small corpus with one page per source case and a prose page for the quiz. It has a
  draft for each, a planted defect for each of `G2`, `G3` and `Q4`, and two retreats the loop
  refuses. Every claim the guide makes about the three cases can be read against it.
- ⛔ ***"Do not invent assertions"* becomes *author, then prove*.** The proof is the ten gates
  `gating` hands a draft to. ⚠️ Name the fixed budget as the constant `ATTEMPTS`, and do not
  write its value into the guide: a count in prose goes stale.
- ⚠️ **Say what the author writes and what it must never write.** It writes the ask, the
  cases (each with the sentence a reader sees), the reference, the starter, the tests and one
  plant per edge. It never writes provenance, trust, a path outside its workspace, or a retry
  with fewer case ids than the draft before it.
- ⚠️ **Commands are spelled from the corpus root, inside `brief.places.workspace`.** `emit`
  refuses any argument holding a `/` that leaves the workspace, and this is the first thing
  a new author gets wrong.
- ⛔ **`words_of` is the rule for a page's words.** A page under the `short` band's opening
  count plans zero, and the guide should say so before an author wonders why nothing ran.
- ⚠️ **No console entry point exists.** An agent drives `author_corpus` from Python. The guide
  shows a short driving script, or a finding asks for a CLI.

### ⛔ `AX-11` — `M10`'s acceptance reading

- ⭐ **"Every page has a plan, and ships its planned exercises or is named with the gate that
  refused each one"** can be read from the committed `exercises/**/coverage.json` without
  running anything. Each file carries the plan document and every shortfall with `slot`,
  `gate`, `says` and `output`. `plan.shortfall` already checked the arithmetic before the
  file was written.
- ⭐ **"Every shipped exercise's gate record verifies against the files beside it"** is
  `gates.drifted(root / bundle, record.inputs, bundle) == ()` per bundle, quizzes included,
  because a quiz's `tests/quiz.json` is a digested input.
- ⚠️ **A plan of zero is a legitimate answer** (`AX-07`). A page listed in `Authored.bare`
  with a non-zero plan is a shortfall. One with a zero plan is not.
- ⛔ **Read the quiz on a prose corpus with material on disk** (`AX-08/3`).

### ⛔ Step 10.4 — the three-page ISO pilot

- ⛔ **Two manifest lines and one ignore rule come first** (`AX-08/4`). Without them,
  `validate` refuses every file the pass writes before any check of this milestone runs.
- ⛔ **The runner is the pilot's to supply, and it runs in the pinned runner image** under
  `--network none`. Every jPOS-dependent exercise also needs `W390`'s warm cache, or `G1`
  refuses every one for a reason that has nothing to do with the exercise.
- ⚠️ **The pages' graders are the corpus's declaration.** The ledger never guesses a
  test-file pattern, so the pilot hands `author_corpus` its graders list, and each `Page`
  names the ones that are its own.
- ⚠️ **A second pass over a page that moved is refused, by design.** To re-author after the
  user's review, remove that unit's `exercises/…/unit-NN` directory and
  `exercises/ledger.json`, then run the pass again.
