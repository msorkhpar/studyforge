## The three states, and how a reader tells them apart on a real page

| the record | the page | the byte that says so |
|---|---|---|
| ⭐ none at all | clean prose, **no player, no notice, nothing marked** | no `data-audio` anywhere, so no `<footer id="player">` |
| every clip on disk | the player, and it plays | `data-audio="audio/<clip>"` on each passage |
| ⛔ a clip **promised** and absent | the player **and** a panel naming the gap | `data-audio=""` on that passage, plus `<section data-section="narration-gap">` |

⭐ **The panel says both halves out loud, and that sentence is a contract**
(plant `P13`): the count — *"N of M narrated passages on this page have no audio
file on disk"* — and the distinction — *"a unit that has never been narrated
carries no player at all, so this is audio that went missing, not audio that was
never made."*

## Decisions

### ⛔ A broken promise emits an EMPTY attribute, and that REVERSES a stated note

⚠️ `render/page/narration.py` used to state that `data-audio=""` is never
emitted. ⭐ **That decision stands for the case it was taken for** — an element
nothing promised a clip for still carries no attribute at all — ⛔ **and a
promise the disk did not keep is a different state.** Three reasons, all of them
already in the tree:

1. ⛔ **`narration.js` was written for this shape and says so**: *"a passage may
   arrive with an empty source — the renderer emitted the attribute and synthesis
   has not run"*. It maps such a passage to `playable = false`, keeps it in the
   passage count, and **never assigns it to `audio.src`** — so the *"a control
   that loads the page itself"* hazard the old note named is guarded by the
   transport rather than by withholding the attribute. ⚠️ **The script and the
   renderer had disagreed about this since `SF-18`** — finding `SF-38/1`.
2. ⭐ **The player's gate is DERIVED from the body**, and it survived this row
   **unchanged**: the empty attribute is still the attribute, so the transport
   arrives for a broken promise with no new gate and no new document field. That
   is the payoff for `SF-12` having written the gate as a derivation.
3. ⛔ **Withholding it is what made the two states identical.** With every clip
   absent and no attribute emitted, a broken corpus rendered **byte-for-byte**
   like a corpus nobody had ever narrated.

### ⛔ The notice rides inside the player's region, not in a skeleton slot of its own

⭐ So a page can never say *"some narration is missing"* with no transport to say
it about, and `page.html`'s slot list did not have to grow — which
`test_chrome.py` asserts EQUAL to `chrome.css`'s region table and would have
reddened for a reason that is bookkeeping rather than product.

### ⛔ The caller partitions the four silent states; this package does not

⚠️ `render/page/` **must not import `narrate`** (its own contract), so `missing`
arrives as data. ⭐ It is the positions whose record entry **exists** and cannot
be played — `playable.py`'s `NOT_PLACED`, `MISFILED`, `NOT_ON_DISK`. ⛔
**`NOT_RECORDED` is NOT one of them and must never be passed**: a unit the record
does not mention was never promised anything, and passing it would put a notice
on every corpus somebody narrated half of.

### ⭐ Nothing in `playable.py` was rebuilt

`W187` already distinguishes these states; this row **surfaces** them. The two
directions it added are: a position that is both playable and missing is
**refused** rather than resolved, and a gap given with a list block path is
**normalised** rather than trusted — both because the failure otherwise is a page
that quietly says nothing is wrong.

## Findings

### ⚠️ `SF-38/1` — `[local]` — the script and the renderer had disagreed about the empty attribute since `SF-18`

`narration.js` handles a passage whose `data-audio` is empty and documents that
the renderer emits one; `render/page/narration.py` documented that it never
does, and never did. ⭐ **Neither was wrong on its own** — the branch was simply

row in the script's favour, because the script's answer was the better one.

### ⚠️ `SF-38/4` — `[local]` — `Playable` has no promised/unkept partition, so every caller must build one

⛔ A caller must decide which of `playable.py`'s four silent states are broken
promises, and the only way is to compare `Unmatched.reason` against the module's
constants: **`Unmatched.filename` cannot tell `NOT_RECORDED` from `NOT_PLACED`,
because both carry `''`.** ⭐ Reported rather than patched — `playable.py` is
another row's delivered contract and nothing forced it — but a `Playable.unkept`
alongside `Playable.silent` would stop the third state being re-derived by every
consumer. ⚠️ This is the one thing a second consumer would have to retype (R19).

### ⚠️ `SF-38/5` — `[local]` — a reader with scripting OFF sees the notice and not the transport, deliberately

The panel is **not** hidden; the footer ships `hidden` and needs the script.
⭐ So a no-script reader is still told the audio is missing, which is the half
that matters. ⚠️ Stated so it is a decision rather than a surprise.

## For dependents

- ⭐ **The door is `Narration.of(clips, placement, missing=…)`.** `clips` is
  `playable.filenames` unchanged; `missing` is the positions of the `silent`
  entries whose reason is **`NOT_PLACED`, `MISFILED` or `NOT_ON_DISK`**.
  ⛔ **Never `NOT_RECORDED`** — see the decision above, and `SF-38/4` for why the
  partition is yours to make today.
- ⛔ **Pass `audio=` to `playable_of` or the third state cannot arise.** With the
  directory absent, `playable.py` takes a recorded clip at its word and
  `NOT_ON_DISK` is never reached — so a build that omits it renders a broken
  corpus as a working one, with the suite green. ⭐ Ask
  `synth.incremental.audio_dir`; compose nothing (R4).
- ⚠️ **A page with no record is untouched and must stay so.** `SILENT` is still
  the default and still renders the pre-narration page byte for byte; that
  equality is asserted, and it is the spec's own position (§7 C5, §11.0) rather
  than a convenience.
- ⭐ **What these assertions will and will not cover once something really
  narrates** (the coordinator asked, against the new `studyforge narrate` row):
  ⛔ **covered** — the join from a record to the page, all three states end to
  end, the count, the empty attribute, the panel's prose, and both directions of
  the never-narrated control. ⛔ **NOT covered, and it needs real clip files** —
  that `playable.py`'s disk probe answers `NOT_ON_DISK` against a directory
  synthesis actually wrote, that the href a page emits **resolves** to a file
  under the placement profile in use, and that the transport plays it. ⚠️ `W187/3`
  named the same hole and this row does not close it: no clip file exists in
  these fixtures, and committing binary audio to make a check pass would be a
  fixture built to satisfy the check.
