## What landed

### `plan` exits non-zero on a crossed limit, and says which and by how much

- `MediaProjection.verdict` asks `corpus.media.verdict_for` for the verdict on the measurement,
  and returns `None` only when the policy weighs its media and no reading could be taken.
  `always` and `never` get their verdict with no footprint, exactly as `verdict_for` defines,
  so a policy whose limits are inapplicable is never refused.
- `MediaProjection.crossed()` returns one sentence per crossing — the `Crossing`'s own sentence,
  which names the limit, the measured number, its unit and the files responsible — plus the
  clause that a build stops on it too. `derive` turns each into a `Refusal` at `corpus.json`,
  the file a person edits to answer it.
- So a crossing is counted in the plan's summary and reaches `Plan.exit_code` through
  `refusals`, which is unchanged. The `media footprint  EXCEEDS …` line is unchanged too: the
  plan now **refuses** what it already **said**.
- ⛔ **A projection is not a refusal.** A rate the person supplied is a question asked before
  the bytes exist; only a measurement may decide a commit (§5). `--bytes-per-unit` over the
  limit still prints `EXCEEDS max_total_bytes` and still exits `0`.
- ⛔ **A reading that could not be taken refuses nothing about the limits.** An unreadable
  narration record is already the record's own refusal, with its own line and its own exit; a
  limit nobody measured is not reported as crossed.

### The build stops, before it writes and after it writes

`cli/site/cli.py` gained `media_stop(media, *, measured)`, which asks
`corpus.media.require_committable` for the refusal that already existed and had no caller
(`W311/3`). It is called twice:

- **before anything is written**: media already on disk over a limit prints the verdict's whole
  report — the number, the limit, the files responsible and the two ways forward — then
  `build refused: …, so nothing was written`, and exits `1` with the output directory empty.
- **after the site is written**: a build into the corpus root copies the archive's media into
  the unit directories its pages address, and those bytes exist only once they have been
  written. Weighing them earlier would mean predicting them, which is the second measurement §5
  refuses. So the build re-measures the corpus root and, on a crossing, prints the report and
  `build stopped: after this build, …; commit nothing yet`, exiting `1`.

⚠️ **The second stop is after the write and not before it, and the row's clause 2 asks about
"before it leaves the corpus in a state that would be committed".** The reading this row takes
is that a build never commits: a person or a script does, after the build returns. A non-zero
exit carrying the report reaches them before that step, which is the stop that was available
without inventing a projection of the build's own output. ⛔ **The register decides whether that
is the whole of clause 2**; nothing here claims the bytes are absent from disk after the stop —
they are written, and the report says the corpus is not committable as it stands.

⭐ **A reading that could not be taken after a build is said** — never silently passed: it goes
through the same branch that stops a crossing, so it prints its reason and exits `1`. Before a
build it is not this command's refusal: the build's own reader refuses the same record with its
own exit code, and refusing it here would answer one fault twice with two codes.

## Decisions

- ⛔ **A crossing is a `Refusal`, not a second exit-code branch.** `Plan.exit_code` is still
  `INVALID if self.refusals else OK`. The alternative — a crossing that exits `1` while the
  summary says `0 refusal(s)` — is a report that contradicts its own exit code.
- ⛔ **The refusal is at `corpus.json`.** The crossing is answered by editing the manifest
  (raise the limit, or declare `never`), and `Refusal.where` is where a reader is sent.
  `Refusal.rule` stays `None`: it is not a `validate` rule, and the build reads that field to
  find `duplicate-path` refusals only.
- ⭐ **A SPLIT AT A SEAM, named** (R11, Ruling 261). `report.py` reached 401 lines and
  `test_derive.py` 658, over the 400/600 ceilings. One seam settles both: what a plan says about
  **media** is `cli/plan/media.py` and `tests/…/plan/test_media.py`; what it says about
  **paths, edits and declarations** stays in `report.py`, `test_report.py` and `test_derive.py`.
  ⛔ The dependency runs one way — `report` imports `media`, and nothing in `media` imports
  `report` — which is why `crossed()` returns sentences and `derive` builds the `Refusal`.
- ⭐ **The build asks the plan, not the disk.** The footprint the build stops on is the one
  `plan_for` measured, so `plan` and `build` cannot disagree about what a corpus weighs.

## Surprises

- ⭐ **A build into the corpus root was already reachable and already wrote media there**; no

## For dependents

- ⭐ **`studyforge plan` now exits `1` for a corpus whose measured media crosses a limit**, with
  one `refuse corpus.json  …` line per crossing. A script that read `plan`'s exit code as
  *"the paths could not be derived"* now also gets *"this corpus is not committable as it
  stands"*. The `media footprint` line is unchanged in either direction.
- ⭐ **`studyforge build` exits `1` on a crossed limit**, writing nothing when the media was
  already over, and writing the site and then stopping when the build's own copies cross it.
  ⛔ Neither stop changes what is ignored: a crossing is a refusal, never a switch (`verdict.
  ignore_media` is the policy inverted and only that).
- ⭐ **`MediaProjection` and `UNPROJECTED` moved to `studyforge.cli.plan.media`.** Both are still
  exported from `studyforge.cli.plan`, which is the import a consumer uses.
- ⚠️ **`MediaProjection.refusals()` does not exist**; the method is `crossed()` and it returns
  sentences. A caller that wants `Refusal` records reads `Plan.refusals`.
