## Decisions

⭐ **1. `chrome-headless-shell` from Chrome for Testing, not a distribution
package and not full Chrome.** A distribution's `chromium` moves with the
distribution and records no version a reader can pin; Chrome for Testing is
immutable per version. `chrome-headless-shell` is already in
`discovery.CANDIDATES`, speaks the same DevTools protocol over
`--remote-debugging-pipe`, and links against **21** shared libraries rather than
full Chrome's desktop set (measured with `ldd`; zero `not found` after the
install).

⭐ **2. `shm_size: "1gb"` in `compose.yaml`, and it is a MEASUREMENT.** At
Docker's 64 MB default the first run **hung** — not failed. `page.py` asks for
`captureBeyondViewport` (a full-page screenshot, transferred through shared
memory); the GPU process crash-looped with
`VALIDATION_ERROR_DESERIALIZATION_FAILED` on `viz.mojom.CopyOutputResultSender`,
5 of the 7 capture checks passed and the 6th never returned. ⛔ **Fixed in
`compose.yaml` rather than by adding `--disable-dev-shm-usage` to the harness's
launch flags**: the size of `/dev/shm` is a fact about how the image is RUN,
which that file owns, whereas the flag would route the browser's shared memory
onto disk and change what every reading is taken against, in a file this row
does not own.

⭐ **3. The pass-through carries NO default of its own** — bare names, so unset
on the host is unset in the container. ⛔ **I tried `STUDYFORGE_VISUAL:
"${STUDYFORGE_VISUAL:-required}"`, measured it, and REJECTED it** — see
`W36/1`. It would set the demand for every run of the pinned image, which
changes what every reading is taken against, and W36 installs a browser rather
than legislating what a run does when one is missing. ⭐ **What guards the
browser instead is `test_a_browser_is_actually_on_the_path_in_here`, the idiom
the Node.js runtime already uses (Ruling 21's shape)** — and Instrument 3 above
proves it fires.

⭐ **4. A NEW test module, `tests/docker/test_dev_image_browser.py`.**
`test_dev_image.py` is **583 lines** against R11's 600 for tests; these checks
would have taken it over. They also have one subject — which browser this image
carries and how a rebuild gets the same one — so the split is along a seam.

⛔ **5. I corrected the harness's own evidence-state sentence, and that is a
deliberate scope call I am flagging rather than hiding.**
`tests/visual/discovery.py` printed *"evidence state: unpinned (the dev image
has no browser — QA-03/1)"* **at the end of every suite run**, and this row makes
that sentence false — twice over, in the one environment Ruling 40 makes
authoritative. ⚠️ **An instrument that lies about the thing this row changed is
a defect this row CREATES**, not one it inherits, so leaving it would have been
the "freshly wrong" failure `CLAUDE.md` is built around. ⭐ The change is
minimal: `evidence_state()` reads the image's own `STUDYFORGE_DEV_CONTAINER`
marker and says `pinned` **only where a pin exists** — a host with Chrome
installed has a browser and **no pin**, and still reads `unpinned green`, which
is what Ruling 204's debt clause requires. Both tokens are the rubric §4b rows
verbatim. ⛔ **Nothing else in `tests/visual/` is touched** — no launch flag, no
assertion, no threshold.

⭐ **6. I did NOT trim the browser's `locales/` or `hyphen-data/`.** Trimming

### W36/2 `[structural]` The visual harness HANGS instead of failing when the browser is alive but silent

⛔ **MEASURED BY ME.** `browser.py::_receive` loops `while b"\0" not in
self._buffer: chunk = os.read(self._reader, …)` — `os.read` on a live pipe
blocks with no deadline, so `call()`'s `CALL_TIMEOUT` guard is never evaluated.
⚠️ **`BrowserError(f"{method}: no answer in {CALL_TIMEOUT:.0f}s")` is
unreachable for a browser that is up and not answering**; it only fires if the
pipe closes. ⭐ **Observed:** with the 64 MB `/dev/shm`, the run printed 5 dots
and then sat for **10+ minutes** with the browser's GPU process crash-looping,
until I stopped the container by hand. ⛔ **A hang has no verdict, so it is
strictly worse than a red check**: nothing is reported, `pytest` never
summarises, and a CI job's only signal is a job timeout. ⭐ **The remedy is a
deadline on the read** (`select` with the remaining budget, or a non-blocking fd
with a poll), not a larger `/dev/shm` — `shm_size` removes today's *cause* and
leaves the *class* open. Routed to `QA-03`'s owner.
**Measured** — `a0d7e88` + this row's Dockerfile, NEW image without `shm_size`,
2026-09-11. Browser stderr: `GPU process exited unexpectedly: exit_code=9`,
`VALIDATION_ERROR_DESERIALIZATION_FAILED` on `viz.mojom.CopyOutputResultSender`,
`The GPU process has crashed 3 time(s)`.
