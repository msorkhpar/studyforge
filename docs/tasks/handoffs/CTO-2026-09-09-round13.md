## Ruling — the narrowed R1 boundary: ⭐ STANDS, as an interim with a trigger

**Do not revert.** The developer's judgement was right and its reasoning is the
right reasoning: ⭐ *`archive.blocks` is the block **vocabulary**, not a corpus,
and a surface that did not know the block types is precisely how the two came to
disagree silently.*

**Equality rather than prefix is the correct narrowing**, and I checked the
shape: `archive.document` and `archive.markdown` stay refused, with a second test
pinning that the vocabulary is the only thing reached for. ⛔ That is a narrowing
of one name, not of a rule.

⚠️ **But the boundary test was never really about R1.** R1 forbids the framework
knowing about **a source**; `studyforge.archive` is the framework's own package.
What that test actually protects is **layering** — page assets must not depend on
the content pipeline — and the vocabulary is not the content pipeline. ⭐ It is a
*shared contract that happens to live inside one consumer's package*, which is
why a correct rule and a correct import collided.

### ⛔ And that is a situation this project has already ruled on once

`version.py` was promoted out of `corpus/manifest/` for exactly this: a contract
with more than one consumer, living inside one of them. ⭐ **The block vocabulary
is the same shape**, and the tasks say so already — `SF-16` *"decides how each
block type becomes speech"*, `SF-12` renders *"one module per group of block
types"*, `SF-10` builds a document that carries them. **At least three
non-owner packages will need it.**

⭐ **So the tell is this: an exemption that must be repeated in every future
package is not an exemption — it is a misplaced module.**

**Ruling: the vocabulary moves when the *second* non-owner package needs it**, in
the way `version.py` moved. ⛔ Not now — one consumer does not justify the churn,
and moving speculatively is the error I have refused three times this month.

⚠️ **And "when the second one arrives" is a promise with no enforcer, which I
have ruled against twice — so it is a tripwire instead.** A test asserts that
**exactly one** package outside `archive/` carries an equality exemption for
`studyforge.archive.blocks`. ⭐ The second package to need one fails that test,
reads why, and promotes the module rather than copying the exemption. Cheap,
self-firing, and it retires itself.

**PO: that test belongs with the next task that would add the second exemption —
`SF-12`, `SF-16` or `SF-10`, whichever lands first.** ⛔ It is one assertion, not
a task.

## The rest, and it is all good

### ⭐ `SPELLERS = ()` — the allow-list shipped empty

The outcome I predicted, reached by a better route than I specified: the test
module spells the vocabulary out and is cleared **by the same rule as everything
else**, because it imports from the owner. ⛔ No path allow-list at all, so there
is nothing to grow.

⭐ **And it says the middle of its three tests is the rule** — *the same literal
is an offender without the import and clean with it.* That is the assertion that
makes the other two meaningful, and naming which one carries the weight is
exactly the *tests are arguments* habit. The third — that a re-export chain does
not count as deriving — closes the obvious evasion without inventing an
adversary.

### ⭐ It found a hole in my ruling's own mechanism and closed it

I specified that a block type **added** to the vocabulary should break
`surface.py` loudly, via a `KeyError` at import. ⛔ **A type *removed* would
leave the class table answering for something that no longer exists, and nothing
would fail.** `tuple(_CLASS_OF) == BLOCK_TYPES` asserts both directions.

⭐ **That is the *assert the premise* pattern applied to a ruling rather than to a
bug**, which is a use I did not anticipate when I named it two rounds ago. ⚠️ It
is also the fourth task in a row to improve on the instruction it was given.

### The two scanners — ⭐ its answer is better than the question

⛔ **Correct, and I am adopting it as ruled: they share exactly one piece, and it
is not the scanner.**

The *detectors* ask different questions — *does this module read an R9 field*
versus *does it spell four vocabulary names* — and merging them yields a
parameter meaning *which kind of duplication is this*, ⛔ which is worse than two
functions. ⭐ But **"does this module import the owner of the contract it is
touching"** is one question with one answer, currently written twice.

**Extract `imports(path, module) -> bool` into `tests/support.py`** — which
already holds `is_ignored`, consolidated at `FND-06` for this reason. ⚠️ Small,
and worth doing before a third scanner writes a third copy.

⭐ **And its note is the part to keep:** *a check that drifts is worse than code
that drifts, because nothing checks the checks.* That is the sharpest statement
anyone has made of the duplication class this project keeps meeting, and it is
why the scanners deserve the same discipline as the code — not less.
