## Decisions

- ⛔ **The per-case VERDICTS are recorded and every count is derived.** *Main ask*, *edge
  cases n/m* and each failed edge's sentence are all properties of this map joined with the
  practice's declared `cases`, so there is no second place a count can disagree with the
  case map (`AX-01`, *For dependents*: record one or the other, never both). ⭐ The id is
  the stable key; a `says` is reader-facing corpus text, already in the practice document,
  and it goes stale the moment the corpus is regenerated.
- ⛔ **`cases` is the one OPTIONAL key in `last`, and that IS the backward-compatibility
  clause.** `_exact` gained an `optional` set rather than a second key list, so a document
  written before this task validates, re-renders to the same bytes and reads back equal —
  and a key that is neither required nor `cases` is still refused.
- ⛔ **The shape is checked and the ids are NOT.** A key is refused for being blank or not a
  string, never for failing `exercise.cases.CASE_ID`. ⭐ The ground is a property of where
  the file is read: `studyforge archive` reads a progress document on a machine that has
  neither the corpus nor its case map, so a validator that needed the case map would be a
  validator that cannot run. ⚠️ **A case map that has since changed makes an entry's
  breakdown unreadable to the panel, not the record invalid.**
- ⛔ **A breakdown is refused on a `run`-mode run**, both in the writer and in the reader.
  Only a Submit produces a grader report, so a Run carrying one is a record no honest
  writer could have produced (Ruling 8: enumerate the legal).
- ⛔ **`passed` is NOT cross-checked against `cases`, deliberately.** A rule that made a
  false verdict un-pass a run would be exactly the second definition of a pass this row is
  forbidden to write. ⚠️ **There is a reading for it**: a Submit that exits `0` with a
  failed edge is recorded `passed: true` *and* `cases[edge]: false`, and both the writer
  and the validator accept it.
- ⛔ **`started` is read in `routes.run`, immediately before `Runs.claim`, and never
  after.** The whole staleness clause is the comparison between that instant and the
  report's own, so a clock sampled afterwards makes every report look fresh — the previous
  run's included, which is the one thing the clause exists to catch.
- ⛔ **A refusal is said on the stream and never swallowed**, which is the decision
  `AX-01`'s handoff asked this row to make and write down. `Outcome.record` now returns
  **the lines to say** rather than a bool, so the stream has one channel for both
  sentences; `NO_BREAKDOWN` carries the refusal's own words, scrubbed on the way out (R7:
  the response is where it leaves the process), and it is deliberately NOT `NOT_RECORDED` —
  ⭐ **the outcome IS recorded, without a breakdown, because a run whose report cannot be
  read is still a run that happened.**
- ⛔ **A workspace this reader cannot parse costs the breakdown and not the run.** The
  archive accepted that record and `render.page.practice` renders it; a `500` here would
  take a working Submit away over a report nobody was going to be shown.
- ⭐ **The fold is its own module, and that was forced rather than chosen** — see the first
  surprise. `routes.runs` is *what a started run IS until it ends*; `routes.breakdown` is
  *what a grader's own report says about it*, and the module's docstring carries the
  measurement that put it there.

## For dependents

### ⛔ `AX-09` — the practice panel

- ⭐ **What is recorded is `{case id: did it pass}` and NOTHING ELSE.** No counts, no
  `says`, no order. ⛔ **Join it with the practice document's own `cases`** — which carry
  `id`, `kind` and `says`, in the order the corpus wrote them — and derive the four things
  a reader is shown:

  ```python
  passed = entry["last"].get("cases")  # None -> no breakdown, show nothing
  edges = [case for case in declared if case["kind"] == "edge"]
  ask = all(passed[c["id"]] for c in declared if c["kind"] == "main")
  shown = f"edge cases {sum(passed[c['id']] for c in edges)}/{len(edges)}"
  failed = [c["says"] for c in edges if not passed[c["id"]]]
  ```
- ⛔ **`AX-02/3` is yours to close or to escalate**: `serve/routes/state.py`'s `_summary`
  drops the key, so nothing reaches the page until one line adds it. ⭐ The line is
  `"cases": last.get(CASES_KEY)` inside the `"last"` object it already builds, with
  `CASES_KEY` imported from `studyforge.progress` — ⚠️ **the framework's one spelling of
  it; do not retype the string.** ⛔ **Answer `None`, never `{}`**: absent and empty are
  different claims, and an empty map is refused by the record.
- ⛔ **A key the practice document no longer declares may be in an old entry**, and one it
  declares may be missing from the map. ⚠️ Treat the entry's map as a *reading of a run that
  happened*, not as a contract: a corpus regenerated after a Submit can change the case map
  under it. ⭐ **Show nothing rather than a partial count when the two disagree** — a
  breakdown whose population does not match the practice is not *edge cases 1/2*, it is a
  breakdown of a different practice.
- ⭐ **`complete` is not recorded and must not be re-derived as a pass.** `last.passed` is
  the verdict; the breakdown is the report. ⛔ A panel that showed a practice as complete
  because every case passed would be the second definition of a pass this row exists to
  avoid — and the two genuinely differ, which has its own reading in
  `tests/studyforge/progress/test_document.py`.
- ⚠️ **The reader may see a line on the run stream that the panel knows nothing about**:
  `--- the case breakdown could not be read: … ---`, just before the exit line. ⭐ It is
  plain text on the same stream as the grader's output and needs no special handling; ⛔ but
  a panel that hides raw output will hide it too, so decide whether that sentence deserves
  a place in the UI.
