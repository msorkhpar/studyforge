## Decisions

1. ⛔ **The remedy is in the GRAMMAR, never a second reader in `reach.py`**
   (clause: *not a second grammar*). `reach.py` gains no citation logic; its only
   change is the declaration and the numeral derived from it.
2. ⛔ **The exclusions run PER LINE, BEFORE the join**, so `prose_lines` and
   `strip_code_spans` are used exactly as `pointers` wrote them and not one byte
   of the fence or code-span rule is weakened (clause 2).
3. ⭐ **A BLOCK, and its boundaries are a CLOSED CLAIM** (Ruling 258) — a blank
   line, a gap in the line numbers (a fence stood there), a different blockquote
   prefix, a heading or table row above, a line that opens a block below, or a
   line leaving a code span open. ⚠️ Clause 3 named four of those; the blockquote
   prefix and the list marker are mine, and both are CommonMark's own block
   rules rather than taste.
4. ⛔ **An ordered-list breaker of `1` and never `\d+`.** ⭐ CommonMark lets only
   a list starting at one interrupt a paragraph, and `166. That is …`
   mid-paragraph is a SENTENCE — a `\d+[.)]` reading would have refused the very
   wraps this row exists to read.
5. ⛔ **An UNCLOSED code span ends the block.** ⚠️ `strip_code_spans` is
   LINE-scoped, so a span opened on one line and closed on the next survives
   both; joining across that pair would carry a MENTION into the reading, which
   is the one way this change could have weakened `W133`'s exclusion. ⭐ Refused
   rather than declared, and the refusal is MEASURED to cost nothing: all 14 live
   pairs above leave both of their lines balanced.
6. ⭐ **The live test asserts a POPULATION, not a line number** — *some pair of
   prose lines under `docs/conventions/` carries a citation neither line carries
   alone.* ⚠️ A test naming `review-rubric.md:1824` would go red on the next
   re-wrap and teach the next office to delete it; this one needs all fourteen to
   disappear, and says so in its own message.
