## What landed

⛔ **The blindness, restated so the fix is readable against it.** `verify` compared each
component's `HEAD` to the pin and said nothing at all about the working tree. A pin records a
**commit**, and a commit cannot carry a working tree — so *"this component is at the commit
recorded"* was being read as a reproducibility claim it never made. The measured state was a
sibling in an abandoned conflicted merge with a whole task's files staged and none committed, and
`HEAD` sitting exactly on the pinned commit, so every reading the tool took was correct and the
answer was green.

⭐ **`tools/workspace/checkout.py`.** `uncommitted(directory, run)` returns one finding per state:

| what the tree carries | how it is found |
|---|---|
| an unfinished merge, rebase, cherry-pick or revert | the marker git itself leaves in the git directory — `MERGE_HEAD`, `rebase-merge`, `rebase-apply`, `CHERRY_PICK_HEAD`, `REVERT_HEAD` |
| a **conflicted** path | `git status --porcelain=v1 -z`, every code carrying `U`, plus `AA` and `DD` |
| a path **staged and not committed** | the same status, index column |
| a tracked path **modified and not staged** | the same status, work-tree column |
| a path **untracked and not ignored** | the same status, `--untracked-files=normal` passed rather than inherited |

⛔ **Each state is its own finding, never folded into one word**, because each is its own repair:
an unfinished merge is finished or aborted, a conflicted path resolved, a staged file committed or
reset, an untracked file added or ignored. ⭐ Every path finding carries the **count** as well as
up to three names, so the cap can never read as *"that is all there was"*.

⛔ **The exit-code contract is unchanged, and the register reads this gate every round.** This is
exit **1**, printed **beside** the pin findings and never instead of them — a checkout off its pin
*and* dirty reports both. ⭐ No new code was added; `0`, `1` and `2` still mean what
[`workspace.md`](../../conventions/workspace.md) says they mean. ⚠️ **What DID change is the
population of trees that read `1`**, which is the whole row.

## Decisions

- ⭐ **Untracked-but-not-ignored is dirt; ignored is not.** `.scratch/`, `__pycache__/` and the
  generated study artifacts are what an ignore file is *for*, and a checkout full of them is a
  working checkout. A module nobody added is the half of *"work on no ref"* that carries the most
  and that nothing else sees. ⛔ So the population is exactly what `git status` reports by default
  and the decision stays in each component's own ignore file, where it already lives — **a
  component that reds for editor noise is repaired by one line there**, never by widening this
  check. ⚠️ This is the register's own note for the row, taken rather than re-argued, and it is
  asserted in both directions (`test_a_sibling_with_an_untracked_file_is_named`,
  `test_an_ignored_file_is_not_dirt`).
- ⛔ **`studyforge`'s own row is exempt, and it is the same asymmetry ancestry already is.** The
  `self` row cannot be checked for **equality** because the file is inside the commit; it is not
  checked for **dirt** because it is the tree the reader is standing in and editing — `record`
  itself writes an uncommitted pin file, and the fixture the whole existing suite is built on says
  so in its own docstring. ⭐ Failing on that would make a check the register runs every round
  permanently red, which is a red nobody reads. ⚠️ **Asserted rather than only argued**, and both
  ways: `test_a_dirty_self_checkout_is_not_a_finding`, and
  `test_the_exemption_is_the_row_and_not_the_directory` refuses the exemption being written as
  *"skip the first row"* or *"skip whatever `--root` points at"*.
- ⭐ **A new module, not a bigger one.** [`module-structure.md`](../../conventions/module-structure.md)
  and R11: `tools/workspace/__init__.py` stood at 339 lines of a 400 ceiling, so the new logic is
  a sibling module and `__init__.py` gains the call and a comment.
- ⭐ **The git runner is a parameter, not an import.** `tools.workspace.git` lives in the package
  `__init__`, which imports this module, so importing it back would be a cycle. Handing it in
  keeps the dependency one-way — and it is what lets the porcelain parse be asserted directly,
  without five real repositories for five unfinished operations.
- ⭐ **`-z`, and the parse steps over a rename's source.** A path may hold a newline or a quote;
  the non-`-z` form escapes those into a shape that would have to be un-escaped here by hand. A
  rename writes its source as a second field, which is the same path under another name, so
  counting it would double every rename and name a path that no longer exists.
- ⭐ **The standing `pending` declaration is AMENDED, narrowly, not replaced.**
  [`workspace.md`](../../conventions/workspace.md) declares a known red — the ISO pin between an
  integration merge and the register's next round — and its pass condition was *exactly one
  component named*. ⛔ A working-tree finding is not a second **pin** disagreement, so the
  amendment says so in one paragraph and leaves the pin clause exactly as it was. ⚠️ The frozen
  measurement beneath it is left unedited (Ruling 106).

## For dependents

- ⛔ **`verify`'s exit codes are unchanged and its population is not.** If you run it in a round
  and it reds naming a component with a path count, the repair is in **that component's tree**,
  not in the pin: commit it, abort the operation, or ignore it. ⚠️ Advancing the pin will not
  clear it, and `record` does not touch a working tree.
- ⭐ **A component that reds for editor or build noise is repaired in its own ignore file.** That
  is the designed remedy, not a workaround, and it keeps the decision where the project already
  keeps it.
- ⛔ **`studyforge` itself is exempt**, so this tool will never tell you your own worktree is
  mid-merge. If that matters for a round, `git status` in your own checkout is the instrument; a
  trial merge is the other one.
- ⭐ **If you need one checkout's state without the pin machinery**, import
  `tools.workspace.checkout.uncommitted` and hand it `tools.workspace.git`. It takes a directory
  and a runner, returns a list of sentences, and knows nothing about `workspace.json`.
- ⭐ **`workspace_root` and `DEV_CONTAINER` were LEFT WHERE THEY ARE**, in
  `tools/workspace/__main__.py`. This row does not need either, so neither moved — the package
