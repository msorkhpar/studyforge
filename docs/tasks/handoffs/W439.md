## Decisions

1. ⭐ **The skill takes the recorded manifest as its own draft — the row's preferred option.**
   Argued: the manual path (copy the manifest, empty `not_material` of the generated globs,
   add the new ones, pass `existing=`) has two ways to go wrong that a function cannot: leave
   a generated glob in and promotion refuses it as a collision; take a person's glob out and
   it survives only because `existing=` happens to carry it. ⭐ **`recorded_draft` never has
   to know which glob a generator owns**: its `not_material` is ONLY what the caller adds,
   and everything the manifest already declares arrives through `existing=` — a person's glob
   byte for byte, a generated one re-derived. That reuses `W283`'s mechanism and adds none.
2. ⛔ **Not a re-survey.** `survey('.')` on an onboarded corpus reads the framework's own
   generated half as material (`W329`, the integration office's round-2 finding), so a draft
   from it is a string of refusals. The recorded manifest IS the settled draft.
3. ⭐ **`settle` — the guide's step 2 needed it, and the row did not name it.** Before this
   row, flipping `exercises` to `true` on an onboarded corpus had NO regenerate path:
   `recorded.moved` refused it however the draft said it, leaving hand-edit or uninstall.
   ⛔ `settle` names a top-level answer on purpose; `W329` still refuses every answer NOT
   named (tested). ⛔ `content` is refused as a `settle` key: its growing field has its own
   argument, and its others are the material's shape, which is a new onboarding.
4. ⭐ **The recorded pin and skills are the defaults.** `framework_commit=` re-pins; the pin,
   every stub and the reader document (`artifacts.READER_DOC`) then move in one write.
5. ⭐ **The guide's fence is run, not only bound.** `fence_faults` proves it binds; the new
   test proves it DOES what the prose says on a real onboarded corpus. The reasons in the
   fence were shortened to fit the 100-column bound ruff reads markdown fences at.

### Clause 3 — a moved pin with stale stubs

⭐ **It IS refused by the corpus-side check the skill already generates**:
`test_framework_pin.py::test_no_stub_has_drifted_from_the_pin` — the very test that was RED on
the ISO corpus at `ISO-M10/1`. Now pinned by a test here on a fixture (pin advanced by hand to
a real second commit, stubs left behind: the generated check raises), and `hand_edited` names
`.studyforge/pin.json` as well. ⛔ **What it cannot be is refused at COMMIT time**: that needs
a git hook. A hook lives under `.git/`, so it is never committed and never reaches a clone,
and version-control configuration is what `W278`'s `parse_edits` refuses even to let a
manifest declare as an edit (R3). ⭐ The check refuses at the corpus's
suite, which is where every other generated guarantee lives; the ISO drift sat undetected
because the suite was not run before the pin commit, not because nothing checks it.
