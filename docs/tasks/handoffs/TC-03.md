## What landed

- ⭐ **A prime is a directory a consumer supplies**, read by `prime/prime.py` and mounted read-only
  into the build as the named context `consumer-prime`: `gradle/` (its Gradle build files, its
  wrapper if it has one, `gradle/verification-metadata.xml`) and/or `maven/` (a trivial module whose
  `pom.xml` reaches the consumer's parent POM, copied verbatim, by `relativePath`). Nothing else may
  sit at its top, and a project whose tool is not declared is refused naming it.
- ⭐ **Two warmers, both carried into their own scripts.** `prime/warm-gradle.sh` builds the Gradle
  project into `/opt/code-server/prime/gradle-home` (through the prime's `gradlew` when it has one,
  otherwise the image's pinned `gradle`); the NEW `prime/warm-maven.sh` runs `mvn test` into
  `/opt/code-server/prime/maven-repo` with `-C` (Maven Central's own checksums enforced as each file
  arrives) and a placeholder User-Agent. Each has a `prove` mode the build runs with no network, and
  a `check` mode the host tests run on real-shaped logs.
- ⭐ **The sources must be real, and the build is what knows it.** Each warmer reads its own build
  log: every Gradle project that compiles at all must run a main compile task, a test compile task
  and `test`; every Maven module must compile sources and run a test. A `NO-SOURCE` or *No sources
  to compile* fails the build naming the project and why.
- ⭐ **The version guards read `pins.json` through `plan()`** and add no pin of their own. They cover
  a Gradle wrapper (version and `distributionSha256Sum`), a Maven wrapper, the Kotlin Gradle plugin
  (three spellings, including a version catalog), the Gradle Java toolchain and the Maven compiler
  release (including one reached through a POM property).
- ⭐ **The prime is a build input.** Its digest is folded into the editor's tag and passed as
  `PRIME_KEY` to the warm step, so a warm is cached per prime and never served to another
  (`W379`'s lesson). `prime/` is part of the editor's inputs digest.
- ⭐ **The entrypoint seeds each cache** into `$GRADLE_USER_HOME` (default `~/.gradle`) and
  `~/.m2/repository` only when that directory is empty, through a `.seed-partial` directory so a
  container killed mid-copy leaves it "still empty". The runtime user's `.m2` directory is created
  in the image owned by uid 1000, as the other mount points are.
- ⭐ **`W379/1`:** `build.py` builds the runner with the runner's own command. `W379` keyed the
  runner stage by its tag, so the `--no-cache-filter runner` rebuild is no longer buying anything.

## Decisions

- ⭐ **The prime arrives as a named build context, not a `COPY`.** `--build-context
  consumer-prime=DIR` keeps a consumer's project out of the image entirely: only what the warm
  produced is kept, and the prime is never a layer. Without `--prime` the context is an empty
  temporary directory and both switches are `no`, so the Dockerfile still has exactly one shape.
- ⭐ **The version guards run on the host, the source guards run in the build.** A version
  disagreement is a fact about files, so it is refused before Docker starts (exit 2, naming both
  versions). Whether a compile task actually ran is a fact only the build knows, so it is read from
  the build's own log. This is why the two acceptance clauses fail in two different places.
- ⭐ **A Gradle prime must carry `gradle/verification-metadata.xml`** with `verify-metadata` true and
  a sha256 for every artifact. Gradle checks no checksum by default, so without it the warm would
  fetch unpinned files (R15). Maven's `-C` gives the same property from Central's own checksums.
- ⭐ **The image proves its own guarantee.** The last prime step rebuilds a fresh copy of the prime
  with `--network=none` from a copy of each seed. A seed that would miss offline is never tagged, for
  every consumer's build, not only in our tests.
- ⭐ **The Maven warm runs the `test` phase.** That is what the Acceptance reads (`mvn -o test`), and
  it resolves every dependency every module DECLARES. A consumer that needs `package` or `verify`
  offline needs the contract widened; see `TC-03/3`.
- ⭐ **The fixture prime is a fixture**: `org.example.prime`, a trivial adder, one test per project,
  and a parent POM that declares a test dependency no test uses — the Java corpus's shape, none of
  its content.

## Surprises

- ⚠️ **A pure-Kotlin project's `compileJava` is `NO-SOURCE`, and that is correct.** A rule reading
  "every compile task must run" would fail the carried Gradle warmer on its own Kotlin project. The
  check is therefore per project: at least one main compile, one test compile, and `test`.
- ⚠️ **Every temp-root copy in the editor's tests had to carry `prime/`.** The Dockerfile now binds
  the warmers from the main context, so a planted copy without `prime/` fails at the mount rather
  than at the plant. Four test modules' copy helpers were updated.
- ⭐ **The prime adds about 0.36GB** to this fixture's image (2.8GB against 2.44GB) — the Kotlin
  plugin's classpath dominates it.
