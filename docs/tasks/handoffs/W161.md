## What landed

- **The subject vocabulary is declared** in
  [`board.md`](../../conventions/board.md#w161-the-in-flight-tables-subject-vocabulary-and-where-each-subject-is-argued).
  A `W` id is argued in `rows/<ID>.md`. An epic task (`NS-03`, `SF-19b`) is argued in its epic.
  Any other subject is read and printed, never refused.
- [`bijection.py`](../../../tools/quality/board/bijection.py): `EPIC_TASK`, `Subjects`,
  `subjects(text)` and `bijection_reading(root, text)`. `rows_on_disk` is now defined here.
- **`board-detail` also fires on an In-flight `W` id with no row file.** An epic task owes no
  row file. A `rows/<ID>.md` for one is `board-orphan`, and the message names the epic.
- [`notice.py`](../../../tools/quality/board/notice.py): `board_state` prints the
  `bijection (…) over W ids ONLY` line. That line names the epic tasks left outside and every
  subject in neither form.
- Tests: `tools/tests/quality/board/test_subject_vocabulary.py`.

## Decisions

- **The epic-task grammar is text, not a lookup in `docs/tasks/E*.md`.** The parser stays
  file-free. A token that continues past `/` is a finding id, not a task.
- **A subject in neither form is printed, not flagged.** Flagging it would be a build failure
  on a non-`W` subject, which is `NS-01/2`'s class.
- **`rows_on_disk` moved to the arm.** The notice needed this arm's reading, and the old import
  direction would have made a cycle. `notice.rows_on_disk` still resolves.

## Surprises

- Re-measured at `a2ae2c4`: an In-flight `W` id with no register row and no row file read clean.
  So *a `W` row with no detail file fails* held only for the register. Every In-flight `W` id in
  every board version that had a `rows/` directory had its file, so the new rule is not red on
  history.
