## What landed

⭐ **`TC-05/2`.** `E12` § `TC-05`'s Acceptance said `consuming.json`'s sufficiency is *"demonstrated
by SK-07 doing exactly that"*, and the sentence explaining why `consuming.json` exists at all said
`SK-07` for the same reason. `SK-07` generates the reading floor's artifacts and renders no compose
file; `SK-09` is the execution half that does, and it already depends on `TC-05`. Both now name
`SK-09`, the Acceptance points at it, and the old wording is recorded beside it rather than erased
(Ruling 106's habit).

⭐ **The other end of the same clause.** `SK-09`'s Acceptance now says that its rendering IS the
demonstration `TC-05` claims, so the obligation is written where it is owed and not only where it
is cited — ⛔ and it states the consequence: a key the renderer needs and the component's contract
does not carry is a finding against `TC-05`, never a hand-written value (R19).

⭐ **`TC-05/5`.** Spec §8.1's fourth compose ruling ended *"the backend creates it and the container
waits on the backend's health check"*, which describes a two-service project. A corpus served by
this framework has no backend service in the editor's own compose file, so the bullet now states
the general form — every bind source exists before the start; where another service creates one,
the editor is gated on that service's health check; where the project creates it itself, it is
created before the containers come up — and says that the per-mount and ordering keys carrying it
live in `code-server-toolchain`'s consuming contract, which `TC-05` owns.

## Decisions

- ⭐ **The correction is recorded, not swapped silently.** Both edits keep the superseded sentence
  in view with the finding id that measured it, because a reader who met the old wording elsewhere
  needs to see it was read and disposed of, rather than wonder which copy is current.
- ⭐ **The spec states the RULING, the contract states the SHAPE.** §8.1 is a design document, so
  it gains the general form and a pointer to where the machine-readable keys live; it does not
  gain `must_exist_before_start` or `healthcheck.ordering` by name, which would put a component's
  schema in the spec and give it a second place to drift from.
- ⭐ **The component is named in prose, never linked.** It is a sibling repository, not a path in
  this tree, and a link into it would not resolve for the floor's pointer walk.
- ⭐ **`SK-09`'s paragraph sits with its Acceptance, above the round-74 milestone note**, so the
  obligation reads as part of what the task must show rather than as scheduling history.
