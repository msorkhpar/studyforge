## Decisions

1. ⭐ **A folder per practice, not a lock naming every practice's main.** A union lock needs every
   practice of the corpus at write time. It makes practice B's source writable in practice A's
   window, and it keeps one shared file that every request rewrites, which is the race. A folder per
   practice makes criterion 1 structural: a practice's lock is a file no other practice writes. It
   also makes `hotExit`'s per-workspace restore state per practice, and W435's ignore file per
   directory.
2. ⭐ **The folder is DERIVED, because the record has no slot for it.** It is the deepest directory
   holding every file the practice names. ⚠️ **The build file counts on purpose.** Without it the
   pilot's practices open `…/practice-1/src`, and the Java tooling there sees two loose source trees
   and no project. Measured folders: `practice/bitmap`, `practice/mti`, `practice/fields`, and
   `practice/iso-fundamentals/prose/unit-15/practice-1` and `-2`.
3. ⛔ **The staging name is per write, in a DIRECTORY the ignore file names.** A glob in the ignore
   file would have broken W435's "names, never `*`" rule (asserted in `test_workbench_ignored.py`).
   The directory stays behind empty, so a concurrent writer never loses the directory it is about
   to stage into.
4. ⭐ **W429/W433 integrity is unchanged.** The lock is still `**/*` read-only with the practice's own
   main excluded back out. The test is never excluded. The lock is read against the practice's own
   folder, and nothing in the user scope changed.
5. ⚠️ **`runs.py` stands at exactly 400 lines**, the ceiling. The next change there owes a split.

## Surprises

- ⚠️ **The first workbench session in a freshly started editor did not take the first typed edit**
  (the pilot's practice-1 main read "disk unchanged" once). The same window URL was WRITABLE in every
  later session, including a whole second pass in the same order. This matches the known "cold start
  needs one reload" behaviour of a fresh editor and is not the lock. The settings file behind that
  window named that main editable at the time. Recorded so the next reader does not mistake it for
  one.
