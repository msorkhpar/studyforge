## What landed

- **`SF-20`'s Definition.** It now says that `execute` is the only package that
  runs a corpus's commands. It is also the only package permitted to start a
  process, **save two named sites**, each of which asks the local `git` a fixed
  question about a source checkout: `validate/source/enumeration.py` and
  `skills/onboarding/pin.py`. Any other package reaches a process only by
  handing a command to `execute`.
- **`SF-19a`'s Acceptance (`SF-22/6`).** The clause is now *no module of the
  package imports a process-spawning library*. It states that `serve` imports
  `execute` for Run and Submit, and only from the run routes. Both halves are
  already asserted by `tests/studyforge/serve/test_init.py`, which `SF-22`
  narrowed when it landed. This row edits only the prose.
- **The shared context.** *"The server may not start a process; only the runner
  may"* now says that a Run or Submit is a command the server hands to
  `execute`, never a process it starts itself.
- **The sweep**, [`tests/test_process_starts.py`](../../../tests/test_process_starts.py):
  see the clause → test table.

## Decisions

⭐ **The row offered two settlements: narrow the sentence, or keep it whole and
name the exceptions. I took both, and the second is the one that gets asserted.**

- ⛔ **Narrowing alone cannot be swept.** Whether an argv is *"a corpus's
  command"* is a semantic question, and an AST cannot answer it. A sentence that
  only said *"the only package that runs a corpus's commands"* would leave every
  other module in `src/` free to start any process, and no test could refuse
  one. The narrowed half stays because it is true and it is `SF-20`'s real job,
  and `execute/runner.py`'s docstring already uses it.
- ⭐ **Keeping the sentence whole with a closed list of named sites CAN be swept**,
  and the list stays closed in both directions. A new start outside the list is
  RED by module name. A named site that stops starting a process is RED too, so
  the list cannot keep an excuse for a site that no longer needs one.
- ⭐ **Why these two sites are acceptable exceptions and not defects.** Both hand
  `subprocess` an argv literal whose first element is the resolved `git`, and
  they run nothing a corpus supplies. The sweep asserts that shape, so a named
  site cannot start some other program under cover of its exception.
- **The unit of exception is a module, not a package.** A plant in a sibling
  module of a named site (`validate/source/`, `skills/onboarding/`) is refused.
- **`execute/` is excused as a whole package.** The runner's internal split
  (`mode`, `handle`, `runner`) is its own business.
- **The detector is imported, not retyped.** `spawns` comes from
  `tests/studyforge/serve/test_init.py`, whose plants cover every spelling it
  knows, so one instrument answers both the serve question and the tree
  question. There is precedent for importing from a test module (for example
  `tests/test_spec_corpus_table.py`). See `W361/2` for the cost.
- **Strings are not starts.** `skills/onboarding/nondestructive.py` and
  `pin.py` carry `"import subprocess"` inside the text of a script they WRITE.
  The detector reads the AST, so those strings are not counted, and that is
  correct because writing a script starts nothing.

## For dependents

- ⭐ **Adding a process start outside `execute/`.** Hand the command to
  `execute` instead. If it truly is a fixed local-tool question like the two
  `git` sites, add the module to `EXCEPTIONS` in the sweep **and** name it in
  `E05` `SF-20`'s Definition. The sweep fails if either one is missing.
- ⭐ **Retiring a named site.** Remove it from both places. The sweep fails
  while a named site no longer starts anything.
- ⭐ **`SF-44` / `SF-22`:** reaching the runner by importing `execute` is not a
  process start in the importing module, and the sweep does not flag it. Which
  `serve` modules may import `execute` is pinned by serve's own test, not by
  this one.
