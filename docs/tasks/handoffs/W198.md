## Decisions

- ⛔ **RULED: `Layout` is the type that owns archive geography, and no new type was minted.**
  The brief allowed *whichever type genuinely owns geography* and asked for it to be named.
  ⭐ Measured: `Layout` already answers the manifest, the archive root, each container's map,
  each variant directory, each unit directory, each document and the staging root, and
  `validate.source.membership` and `generate.media` both already ask it where a unit's own files
  are. ⚠️ `corpus.placement.tree` answers the **site**'s shape, not the archive's, and the
  archive is where an overlay is authored — so the address belongs here and nowhere else.
- ⛔ **RULED: the JOIN lives in `Layout`, the FILENAME stays in the contract, and the import
  runs one way only.** The brief's clauses 1 and 2 pull in opposite directions if read as *the
  address is one constant*: clause 1 puts it on the geography type, clause 2 puts it in
  `content_api`'s family. ⭐ They are met together by splitting the address into the two pieces
  that already have owners and giving the **join** one home. ⚠️ **The direction is forced, not
  chosen** — measured under the third plant, the reverse import is a circular import that fails
  at collection, because `skills.adapter.layout` already imports what `unit.content` would need.
- ⛔ **RULED: `CONTENT_FILENAME` is NOT re-exported onto `skills.adapter`'s surface**, although
  `ARCHIVE_DIR`, `RAW_DIR` and `UNITS_DIR` all are. ⚠️ Those exist because an adapter's whole
  vocabulary arrives through that package (R19) — and an adapter **never writes this file**.
  R21's producer column says **a person**. ⭐ So the package has no author to hand the name to;
  what it has is one caller, and a re-export would be a second place to read the contract's
  filename from for no consumer at all.
- ⛔ **RULED: the spec is NOT edited, and the brief's condition was measured rather than
  assumed.** §R21's register already carries the `authored overlay` row with its file, its
  version key and its producer; the row is complete under R21, which asks for three things and
  gets three. ⚠️ **An `Address` column would be a fourth thing asked of sixteen rows**, fifteen
  of which this office has not read and none of which it may speak for — and the register's
  agreement is required before a `docs/specs/` edit either way. ⭐ **Recorded as a question for
  the register rather than answered here** (`W198/2`): *should R21's register gain an address
  column, now that one contract has a computed address and the others do not?*
- ⛔ **RULED: `generate/units.py`'s docstring is IN surface, although the brief did not name
  it.** It carried the marker's other half in prose — *"nothing in `src/` declares where a unit's
  overlay sits inside an archive"* — which this diff makes **false**. ⚠️ A false sentence beside
  a true test is the failure the row exists to prevent, one register over. ⭐ The paragraph was
  **inverted, not deleted**: it now says which half closed, which did not, and why this module
  still declines to be the first caller.

## For dependents

- ⭐ **Ask `Layout.content(address, unit)` for a unit's authored overlay. Never join one.**
  `from studyforge.skills.adapter import Layout`; the address is `<archive>/<address>/units/
  unit-NN/content.json` and that spelling is now derivable rather than prose, so nothing should
  be reading it out of a document again.
- ⛔ **An address is not a feature. v1 applies no overlay.** A build reads a unit from its
  archive documents alone, and a unit that ships a `content.json` is served without it. ⚠️ The
  verb — reading the file, refusing its version (R9), composing its `sections` over the
  archive's blocks, and deciding what a conflict between them means — is **unowned**, and none
  of those four questions is answered anywhere in `src/`. ⭐ Whoever takes it starts from
  `unit.content.load` and this address, and has to answer all four.
- ⛔ **Two tests will fail the day an overlay IS applied, and that is intended.**
  `test_an_authored_overlay_is_still_not_applied_although_its_address_is_declared` in
  `test_declarations.py` and the prose tests naming `unowned`. ⚠️ They are **markers, not
  guarantees** — retiring them is part of the work that applies an overlay, and they are what
  makes that work impossible to land silently.
- ⚠️ **Nothing a build writes changed**, no generated artifact moved, and no corpus repository
  needs regenerating. The only new name is one method.
