## What landed

⭐ **What the software does now that it did not:** `python3 -m pytest -n auto` in the pinned
image gives the same outcome for every test id as the serial run, in about a third of the
wall-clock time (Measured, below). The merge gate takes its pinned-image suite that way, says which form each
suite gate took, and holds the shared container lock only while a container gate runs.

- **The pins.** `pytest-xdist==3.8.0` and its one missing requirement, `execnet==2.1.1`.
  Chosen by hand, not by a resolver run: the brief allowed no network except the image build.
  The build's own resolver confirmed them: it collected exactly the file's pins and nothing
  else, and `pip list` in the image reads `pytest-xdist 3.8.0`, `execnet 2.1.1`.
- **The plugins, per role.** Under xdist every worker is a pytest session and fires the root
  hooks. The tree check (`pytest_sessionstart`/`pytest_sessionfinish`) now returns early on
  a worker, so only the controller checks, and its window is the serial run's: it starts
  before any worker runs a test and finishes after the last. A worker's tree check would be a
  race (workers finish at different times) and its exit status never reaches the run. The
  *unreachable population* line needed nothing: the controller's tally carries every
  worker's skip reports, and the reasons arrive intact.
- **The visual harness line vanished under `-n`.** `tests/visual/conftest.py` is not an
  initial conftest, and an xdist controller never collects, so the hook that prints it never
  loaded there. The root conftest now forwards it on a controller whenever the run reached a
  test in `tests/visual/`, and stands down when that conftest is already registered. That
  happens when the run's argument lies inside the directory, and before the stand-down it
  printed the line twice. `report_line` reads only the environment, so the controller's
  reading is the one the serial run prints.
- **`SERIAL`.** `tests/visual/` and `tests/docker/` each run on one worker, beside the rest
  (`xdist_group`). A bare `-n` is promoted to `--dist loadgroup`, which schedules every
  unmarked test exactly as `load` does.
- **The gate.** `GATES` is the static declaration: floor and suite in the image (suite
  `-n auto`), suite on the host serial. `declared()` is what `stage_and_read` now takes by
  default. It asks the host's own `python3`, by a child process, whether `xdist` imports, and
  makes the host suite parallel only then. Each suite reading prints its form, e.g.
  `suite [host] (serial: pytest-xdist is not importable here)`.
- **Clause 6.** With `STUDYFORGE_CONTAINER_LOCK` naming a file, `stage_and_read` runs every
  image gate with an exclusive `fcntl.flock` on it held and every host gate with it released,
  and leaves it released when it returns, a red reading's early return included. Unset, no
  lock is taken. (The code also keeps it through consecutive image gates rather than
  releasing between them; no test asserts that part.)

## Decisions

- ⭐ **Mark serial by directory, not by fixing the harness.** `tests/visual/` holds one
  headless browser per session. Spread across workers that is one browser per worker, all
  capturing through the container's one shared-memory mount, which is the resource a capture
  once wedged the suite on. ⚠️ **Measured:** the first batch ran with the grouping broken
  (see Surprises), so `tests/visual/` WAS spread across workers, three times in a row, and
  every visual outcome matched the serial run. So spreading it is not measured unsafe; the
  group is kept because the wedge was a load-dependent hang, and one run of evidence does not
  cover that.
- ⭐ **`tests/docker/` is serial, unmeasured.** Opted in with `STUDYFORGE_DOCKER_TESTS=1`, its
  checks build and start images through one daemon under content-named tags. Neither gate
  environment reaches them (the image skips them by its recursion guard, a default host run by
  the opt-in), so their parallel safety could not be measured here, and they are not spread.
- ⭐ **No other test needed fixing or marking.** The id-by-id comparison found no difference
  outside the grouped directories, so nothing else is marked.
- ⭐ **The pinned image's bare `docker/dev/check` stays serial.** Only the gate's argv changed.
  The wrapper's default is the image's `CMD`, a checked copy (`test_dev_check_timeout.py`), and
  making it parallel is a change to the image's contract that no clause asked for.
- ⭐ **A split, not a trim (Ruling 261).** `tools/mergegate.py` stood at 389 lines when the
  row began and reached 410 with clause 6. The seam: `tools/gates.py` says which commands are
  the gates and how each is taken (its form, and under which lock); `mergegate` says what the
  merged tree read under them. `mergegate` re-exports `GATES`, `Gate`, `IMAGE`, `HOST`, so no
  caller moved. `gates.py` imports only the standard library, so `W310`'s property holds.
- ⭐ **The lock is taken around the RUN of the image gates, not around staging.** Staging,
  authorship and the abort are git work on the checkout and need no container.

## Surprises

- ⚠️ **xdist 3.8.0 workers re-parse the run's own argv.** Each worker derives `loadgroup` from
  that argv before any conftest configures, so a promotion on the controller alone never
  reached them. The first batch's grouping test was RED, and went GREEN with the fix below. ⭐ The
  controller now hands its mode to each worker through `workerinput`
  (`pytest_configure_node`, an optional hook, so a host without xdist is unaffected), and a
  worker promotes itself from it. The grouping test and its control (an undeclared directory
  does spread) are GREEN in the image.
- ⚠️ **The speed-up is about 3x, not 20x.** The image sees all 20 of the host's cores. Why it
  plateaus was not measured (no `--durations` reading was taken). The likely bound is the
  longest single tests, several of which run the quality floor or a child suite end to end.

## Findings

- `[structural]` **`W364/1`: the register must stop wrapping the merge gate in `flock`.**
  With clause 6, the gate takes the lock itself. The register invokes it as

  ```
  STUDYFORGE_CONTAINER_LOCK=<the shared lock file> python3 -m tools.mergegate <branch> --body <file>
  ```

  with no outer `flock`. ⛔ **An outer `flock` on the same file DEADLOCKS the gate:** the
  wrapper holds the lock, and the gate's own `flock` is a second open file description, so
  it waits for the wrapper forever. ⚠️ The lock path is supplied at invocation and written
  into no file.
- `[local]` **`W364/2`: the host suite gate stays serial on this host.** `xdist` does not
  import on this host, so the host gate reads `(serial: pytest-xdist is not importable
  here)`. Making it parallel is a host install, which is the user's call and not this row's.
- `[local]` **`W364/3`: no convention carries the lock.** The merge-gate invocation in
  [the board convention](../../conventions/board.md) names no lock, and a `grep` for `flock`
  there and in the review rubric finds nothing, so the outer `flock` is register practice
  that lives outside the tree. Both documents are outside this row's surface. The invocation
  in `W364/1` is the one to carry there.

## For dependents

- ⭐ Under `-n`, a test id in `tests/visual/` or `tests/docker/` carries xdist's group suffix
  (`…@tests-visual`, `…@tests-docker`) in pytest's output and in `--junitxml`. A tool that
  compares ids across the two forms must strip it. It names the worker group, not a
  different test.
- ⭐ A new directory that is unsafe to spread goes in `conftest.SERIAL` with its reason.
  `tests/test_parallel_suite.py` checks that every entry is an existing directory and carries
  a reason.
- ⭐ `tools.mergegate.stage_and_read(root, branch)` with no `gates` now asks the host whether
  `xdist` imports. Pass `gates` to pin the set.
