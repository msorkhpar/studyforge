## Decisions — and the ground, because a widening is argued, not defaulted into

### ⭐ Chosen: clause 1 + clause 2 — a non-expiring RECORD, and ONE client reload

⭐ **`Runs` keeps every editor origin the instance has ever discovered, and `origins()`
composes `frame-src` from that record.** ⛔ **The record never expires**; it is dropped
when the process ends, which is the one event that cannot leave a reader holding a
document composed under the wider policy.

⛔ **Why the TTL's ground does not transfer.** `EditorProbe`'s TTL answers *may I act on
this answer* — do not start a process against a container that may be gone. A `frame-src`
answers *may this document embed that origin*, and a stale entry's entire effect there is
that the policy names a loopback port where nothing is listening: the frame fails to load,
which is precisely what happens when there is no editor at all. ⭐ **No capability is
granted by a stale entry**, and a policy that oscillates between correct and `'none'`
every ten seconds is the worse failure — it is the one the reader actually had.

### ⛔ Refused: the wildcard loopback `frame-src` (`http://127.0.0.1:*`)

⚠️ It is cheaper: it removes the probe from the CSP path entirely and costs no reload.
⛔ **It lets a served page frame ANY local service, on any port, for ever, including ports
no editor ever ran on and services with no relation to this framework.** ⭐ The record is
strictly narrower — it names only ports an editor for THIS source root was actually
discovered on, and only after it was discovered. ⭐ **A second, independent reason to
refuse it:** `frame_origin`'s `FORBIDDEN` set contains `*` deliberately, so shipping the
wildcard would have meant weakening the one function whose job is to refuse a forged
source list. ⛔ That is a widening of the validator, not only of the policy.

### ⭐ The first page of a genuinely COLD instance — the row's clause 2, taken

⛔ **The serving process still may not ask earlier** (§8.3). A cold instance has
discovered nothing, so the first document a reader opens is served under `frame-src
'none'`; the panel then asks the practice-editor route, which is explicitly requested and
may fork, and that ask fills the record one document too late for the document it is on.

⭐ **So the remedy is the client's, and the browser is ASKED rather than guessed at.**
`practice.js` listens for `securitypolicyviolation`; an event naming `frame-src` whose
blocked URI is the editor's host is the browser STATING that the frame was refused, and
the page then reloads once into a document composed from the record the ask just filled.
⛔ **No violation, no reload** — nothing reloads on a hunch.

⛔ **Three guards, and each closes a real loop rather than tidying one:**

| guard | the loop it closes |
|---|---|
| the blocked URI's host is the editor's | an unrelated violation reloads the page |
| the editor's host is `location.hostname` | the `W427` host trap withholds that editor on PURPOSE, and no reload would ever change it — a reader on the other spelling would reload for ever |
| this navigation is not itself a reload | anything a reload cannot fix costs exactly one reload and never two |

⚠️ **A browser with no navigation timing is not reloaded at all.** ⭐ Failing closed is a
frame that does not load; failing open is a page that reloads for ever, and only one of
those two is recoverable by the reader.

⭐ **Nothing is written to browser storage, and that rule is kept rather than excepted.**
The whole state of the reload is the browser's own navigation type, which is why it needs
nowhere to remember — the alternative loop guards all wanted `sessionStorage` or a marker
in the URL the reader can see.

### ⚠️ A THIRD shape was looked for and there is not one

⭐ **A CSP is fixed for a document's lifetime**, so nothing a client learns after the
response headers were sent can widen the document it is on: rebuilding the iframe, asking
again, or re-rendering all fail for the same reason, and a reload is the only instrument.
⛔ **Warming at startup, or on the path of a page response, is the shape that WOULD remove
the reload, and it stays refused** — it is `W427`'s first hand-back, it had every page load
reach the Docker socket, and it passed three green pinned-image gates while doing it.
⛔ **Proxying the editor through the serving origin** would remove the CSP question
entirely and is far worse: it puts a full development environment with a shell behind an
unauthenticated loopback server that already reads the reader's disk.

## What landed

**`studyforge.serve.routes.runs`** — the record, and the reader the policy uses:

- `Runs._discovered` / `Runs._origins_lock` — every editor origin this instance has ever
  discovered, and its lock. ⚠️ A lock rather than bare `set.add`: `sorted()` over a set
  another request thread is adding to raises rather than returning a policy.
- `Runs._remember(where)` — records an editor's origin and hands the editor straight back,
  so every reader of a probe passes through it.
- `Runs.origins()` — reads the record, still asks nothing (§8.3), and no longer expires.
- `Runs.found()` and `Runs.practice_editor()` — each now records what it found. ⭐ So a
  reader who never loads the index still gets a policy that admits the editor the
  practice-editor route just handed their panel.

**`studyforge.render.assets.practice.js`** — `hostOf(url)` and `reloadWhenBlocked(url)`,
installed BEFORE the frame that raises the violation, and argued in the file's own head.

**Three docstrings corrected rather than left standing**, because each made a claim about
the policy that this row makes false:

- `execute/editor.py::EditorProbe.known()` said returning an expired reading *"would let a
  policy outlive the editor it was composed from"*. ⭐ It now says what a TTL is for and
  names the caller that keeps the lasting record.
- `serve/security.py` said *"the policy narrows again when an editor goes away"*. ⭐ That
  module composes whatever it is handed and decides nothing about when an origin stops
  being handed to it; it now says so, and names `Runs.origins()` as the decider.
- `serve/routes/runs.py` carries the whole argument, as the row requires.

## For dependents

- ⛔ **A frame policy is composed from `Runs.origins()`, which is a RECORD and not a
  reading.** Do not "fix" it by giving `EditorProbe.known()` a longer or softer TTL: the
  TTL's ground is *do not act on a stale answer*, and a row that softens it changes what
  every caller that RUNS something is allowed to act on.
- ⛔ **Nothing on the path of an ordinary response may fork, and that is unchanged.**
  `origins()` still reads `known()` and never `editor()`; the readers that may ask are
  still the run index and the practice-editor route, both explicitly requested by a
  reader's own client. ⚠️ **Measure it with
  [`tests/studyforge/cli/test_serve_process.py`](../../../tests/studyforge/cli/test_serve_process.py)
  ON THE HOST** — the pinned image cannot reach that arm.
- ⚠️ **A stub probe must be able to EXPIRE.** `StubEditor.expire()` and
  `StubEditors.expire()` exist for that; a new reading of the frame policy that does not
  cross the boundary is not a reading of it.
- ⭐ **The record is per-process and per-instance.** A test that wants a cold instance
  builds a new `Runs`; there is no `forget()` and adding one would be a row of its own,
  with an argument about what happens to a reader already holding a wide document.
- ⚠️ **`practice.js` may reload the page exactly once per fresh navigation.** A row that
  adds anything to that file which must survive a reload has to say where it survives —
  browser storage is refused there, and the reload's own state is deliberately nothing but
  the browser's navigation type.
