  `docs/tasks/handoffs/<ID>.md` to `docs/tasks/rows/<ID>.md` is not a finding while that file is

## Decisions

1. ⛔ **THE LINK ARM MOVED; THE BARE ARM DID NOT.** The row offered both. ⭐ **The other repair —
   making `handoffs.citing` blind to `docs/tasks/rows/` — was REFUSED**: it would make the bare
   name the only wording a handoff could use for the document it cites most, which is exactly
   Ruling 163's harm (`W150`: a bare basename is invisible to every instrument) and the hole
   Ruling 285(b) was minted to close. ⚠️ **It would also be the wider change of the two** — an
   exemption over a whole directory in every handoff, against one pointer per handoff here — and
   a reader of a handoff would lose the click, permanently, in every tree.
2. ⭐ **The relation is self-evidencing, so there is no list.** `docs/tasks/handoffs/<ID>.md` may
   link `docs/tasks/rows/<ID>.md`, and the `<ID>` is read off the citing document's own name.
   ⛔ The row's first *must not become* is a per-id allow-list; nothing here has an entry to add.
3. ⛔ **Clause 2 is CLOSED BY A COUNT, not by widening the walk.** The blind spot is
   `check_pointers`' population being git's INDEX — so an office's handoff is read once it is
   staged and not before. ⚠️ **Widening that walk to the disk was refused: it is `W148` exactly**,
   whose measurement was one untracked file giving two different denominators at one ref. ⭐ So
   the walk is unchanged and the notice now NAMES what it did not read, with the remedy in the
   sentence: `git add` it and re-run. An office reading `0` there knows the green covers its work.
4. ⭐ **The two directory spellings are written in `pointers.py` and their equality is ASSERTED**,
   because the seam runs one way: `handoffs` and `board.register` both import `pointers`, so
   importing either back would be a cycle. ⚠️ Same construction, same reason, as
   `citations.MAX_RANGE_SPAN` against `reach.REACH_WINDOW`.
5. ⚠️ **One bullet of the [agent protocol](../../conventions/agent-protocol.md) changed**, and only the one this decision makes false:
   *"where the target is absent on your ref, the backticked NAME is right"* is now qualified by
   its single exception, with the rule an office copies. ⛔ Nothing else in that document moved.

### 3. `[local]` Nothing binds a handoff's id to a row that exists

⛔ **Declared gap of the deferral** (Ruling 258, and it is in `pointers.py`'s docstring): a
handoff named for a row the register never mints keeps a deferred pointer forever, because
nothing in the tree walks from a handoff's id to a row. ⚠️ `handoffs/existence.py` walks the
other way, from a CLOSED register row to the handoff it owes. ⭐ **The exposure is one pointer per
handoff**, and the register's own bijection arms read those ids; closing it would need an arm this
row does not own.

### 4. `[local]` The other notices do not yet say what their walk missed
