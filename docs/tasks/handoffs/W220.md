## Decisions

⛔ **1. A NEW MODULE, at a seam named (Ruling 261), and the measurement is why.** The first
form put the class and the message inline in `record.py` and took it to **400 lines against a
ceiling of 400** — passing, since the check is `lines <= ceiling`, and leaving the next editor
nothing. ⭐ R11's remedy is a split at a named seam, never a trim, and the seam was already
argued: *"a refusal in this package tests the relationship between its arguments itself"* is
a statement about the package, not about `record`. It went where the argument lives.

⛔ **2. `ReconnaissanceRefused`, not `ReconnaissanceError`.** Follows the sibling skill's
`skills.onboarding.record.OnboardingRefused` rather than the framework packages'
`<Thing>Error`, because the two skills are the pair a reader compares. `ValueError` for the
base, following SF-01's split as `corpus.manifest` reads it: this is a value a caller passed,
not a document that could not be read.

⛔ **3. A PRE-CHECK, and never `raise … from`.** Catching `Path.relative_to`'s `ValueError`
and re-raising from it would put the leaking message in `__cause__` — the same leak with one
more frame in front of it, reproduced in every traceback the new refusal appears in. ⭐ The
test asserts `__cause__ is None`, so a later author cannot add the chain back quietly.

⛔ **4. BEFORE the read, not after it, which is a behaviour change on one edge.** An
*unreadable* path outside the root used to be a quiet `None` (the `OSError` arm) and is now
loud. It is a caller mistake in both cases and R6 wants it named. ⛔ **What a *successful*
read returns is untouched**, and a test pins that.

⛔ **5. Exported from the package (`__all__`), and the module table gains its row.** A
refusal a caller cannot name is a refusal a caller catches as bare `ValueError`. ⚠️ The
`__init__` docstring calls its table *what is in the package*, so a module added without a
row would have made that sentence false in the same commit.
