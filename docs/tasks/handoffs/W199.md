## Decisions

- ⛔ **RULED: the single minter is `corpus.placement`, not either site named in the row.** The row
  left the direction to the taker and required it out loud. The ground is measured, not aesthetic:
  - [`layout.py`](../../../src/studyforge/skills/adapter/layout.py)'s own contract forbids
    depending on `validate` — *"a writer that imported its own judge would be checking itself"* —
    and [`module-structure.md`](../../conventions/module-structure.md) makes a stated direction
    part of the package contract.
  - ⛔ **The other direction is a CYCLE, and this is the measurement that settles it:**
    `src/studyforge/validate/source/membership.py` already imports `studyforge.skills.adapter`
    for `Layout`. Minting in the skill and importing it from `validate` closes the loop
    `validate → skills.adapter → validate`.
  - ⭐ `corpus.placement` is where [`W241`](W241.md) put the archive root for the same reason,
    both packages already import it, and the edge it adds is **zero** — each import exists today.
- ⛔ **RULED (the row's rider): `ARCHIVE_DIR` and `RAW_DIR` STAY on `skills.adapter.__all__`, as
  bindings.** The row asks whether a second NAME for one value survives. It does, and the reason
  is R19: an adapter author imports one package, and every name they need arrives from it. ⚠️ What
  the row forbids is a re-export **leaving two definitions** — there is one definition, in
  placement, and two instruments hold it there (the literal scan, the behavioural walk). ⭐ The
  alternative — renaming the skill's exports to placement's spellings — would move a published
  surface and every adapter the scaffold has generated, for a rename. That is a ruling with a
  blast radius across repositories, and it is `W199/4` rather than a line in this diff.
- ⛔ **CLAUSE 3 OF THE ROW IS REPORTED, NOT REWRITTEN** (agent protocol, *an acceptance clause you
  cannot meet is reported*). It reads *"whatever survives is on `validate.__all__`"*, which
  presupposes the minter stays in `validate`. ⭐ **Nothing survives there to export**: `validate`
  is now a pure consumer of both segments, and re-exporting placement's names from `validate` would
  mint a second import path for one value — the shape the row's own *what it must not become*
  refuses. ⚠️ **The clause's PURPOSE — that surface having an instrument — is met in full**, by the
  two tests above, and the row's clause 4 is met as written.

## Surprises

- **Half the row was already discharged and its rider said so.** `archive` was settled by `W241`
  at PO round 76; the row's body still describes three spellings. ⭐ Re-measuring first was the
  difference between a one-line import change and a rewrite of a settled decision.
- **`validate` had no surface test at all.** `tests/studyforge/validate/test_init.py` was ten
  lines asserting the docstring. The package it mirrors is the one Ruling 101's own text cites as
  the deviation — so the rule's example had no instrument, which is exactly the row's complaint.
- ⛔ **A plant left a STALE COMPILED MODULE, and it read as a defect in the new arm.** After P5
  the full suite failed the sweep with *"no package takes anything from a validate module"* while
  the source on disk was correct, measured with `grep`. ⭐ **The cause is the plant procedure, not
  the test:** `PACKAGE`'s planted value (`studyforge.progress`) is the SAME LENGTH as the real one
  (`studyforge.validate`), and the restore landed within the same mtime second, so pytest's
  rewritten-module cache stayed valid by `(mtime, size)` and the run read the PLANTED constant.
  ⚠️ **`W143` says restore from a copy per file; it does not say clear the caches**, and a
  same-length plant is exactly when the copy alone is not enough — `W199/6`.
- **A stale claim in a test docstring.** `test_what_this_layout_writes_is_what_validate_reads`
  said both names are *"owned by `validate.corpus`, which puts neither on a package surface"* —
  false for `archive` since `W241`, and false for `raw` after this. Corrected in place, and the
  test's own argument is unchanged.
