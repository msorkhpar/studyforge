## ⭐ How `SK-02/1` closes without a person retyping anything

**Measured 2026-09-10, at `16eb984`, end to end in the pinned image.**

`SK-02/1` measured the hole: scaffolding into a clean corpus gave
`NOT valid: 8 finding(s), 1 unchecked claim(s)`, one `unclassified` per

report** — R19's *anything a second source would have to retype*.

The circle looked closed — an adapter's file set must be declared in the

collects the globs the generators hand back, and promotes again.

⛔ **That is not argued, it is pinned:**
`test_re_scaffolding_from_the_written_manifest_changes_nothing` re-scaffolds
from the *written* manifest and asserts the files are byte-identical. If the
second pass ever starts to matter, that test fails rather than the design
quietly becoming load-bearing.

⚠️ **The negative control is not decoration.** A walkthrough that only ever

## Decisions

- ⭐ **`promote` refuses to invent a reason, and names every unreasoned path at
  once.** A draft's `content.exclude` is a list of bare paths; a manifest's is
  a list of reasons. ⛔ An exclusion asserts *material was withheld from the
  reader*, so **a generated reason is an audit nobody performed** — the reasons
  arrive as a `reasons` mapping and a corpus that excludes nothing onboards
  unattended, which is the ordinary case.
- ⭐ **`corpus_api` is never below the draft's and never above what the data
  needs.** A manifest using `not_material` is `2`; one that does not stays
  where the draft put it. ⛔ *What a generator emits by default becomes the
  convention*, and R9 freezes a field's name from its first declaration.
- ⚠️ **The rule is "invent no key", not "drop the ones I dislike".** The first
  draft of this module had `media` on a `NEVER_EMITTED` list, which would have
  **discarded a block a person put in the draft**. It is on `OPTIONAL_KEYS`
  now: nothing is added, and an empty optional key is dropped.
- ⛔ **R9's membership test is `studyforge.version`'s, never a second copy.**
  `_api_for` had one for about an hour; `test_no_module_reads_a_contract_field_without_importing_the_guard`
  is what found it, which is `SF-33` working exactly as designed.
- ⭐ **`write(regenerate=True)` keeps an existing hand-written file rather than
  refusing on it** — the one place this differs from `Scaffold.write`, and
  deliberately. After step 4 of the procedure `ingest/read.py` always exists,
  so refusing on it would make *"regenerate rather than hand-edit"* advice
  nobody can follow (R19); overwriting it would destroy the one file that was
  a person's. It is neither written nor reported as written.
- ⭐ **The `not_material` coverage is asserted over the paths, not against a
  list.** `test_every_path_this_skill_writes_is_classified_by_a_glob_it_declares`
  walks `artifacts.paths()` and asks the *manifest's own* `classify`. ⛔ A
  seventh artifact added without a glob fails here rather than in somebody
  else's repository.
- ⚠️ **`corpus.json` is deliberately not declared `not_material`.** A manifest
  classifying itself is a statement about the document making it. Asserted
  positively (`test_the_manifest_is_not_declared_not_material_by_the_document_it_is`)
  so the omission is a decision rather than a gap.
