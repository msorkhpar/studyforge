⚠️ **This is worth more than the row.** It is the fourth instance this project has

before the ruling and never revisited; the section beneath it was written after.

read and the section is what people update.

that is asserted elsewhere in the same document. It carries a **pointer** to the
section, and the section carries the status. This is `version.py`'s answer from
round 16 — *the docstring pointed instead of enumerating, and the enumeration was
already wrong* — applied to the board. **PO owns the edit.**

# ⛔ Ruling 17 — the W1 ↔ SF-25 boundary. `validate` does not sanitise. Measured.

**The question: does `validate` sanitise what it forwards, or trust that upstream
refusals are clean?**

⭐ **Answer: it trusts, it does not sanitise — and the trust is verified by a test
`validate` owns, not assumed.** Three parts, and the middle one is the measurement.

## 17a. First, the premise. `validate` **is** an R7 emission site today.

Trial merge, pinned container, ten poison shapes driven end to end through
`validate(root)` with a container map whose address segment carries a fabricated
identifier, counting how many reproduce it in a report line:

| shape of the poisoned segment | reaches the report? | who refused it |
|---|---|---|
| POSIX home path | clean | personal-data gate |
| macOS home path | clean | personal-data gate |
| email address | clean | personal-data gate |
| URL with a userinfo part | clean | personal-data gate |
| **Windows user-profile path** | ⛔ **reproduced** | `require_slug` |
| **UNC share with a user share name** | ⛔ **reproduced** | `require_slug` |
| **relative path through a user directory** | ⛔ **reproduced** | `require_slug` |
| **hostname** | ⛔ **reproduced** | `require_slug` |
| **build path under a temp dir carrying a username** | ⛔ **reproduced** | `require_slug` |
| **a plain authored title carrying a person's name** | ⛔ **reproduced** | `require_slug` |

⛔ **Six of ten.** Measured 2026-09-09, `docker/dev/check python3 <probe>`, trial
merge of `feat/SF-25-validate` onto `release/m0-foundations` @ `9ad45a2`.

⭐ **And the reason is exactly the standing ruling, which is why this is worth the
round.** The four clean shapes are clean because the personal-data gate fires
*first*, and the gate is **a list of shapes**. A temp-build path carrying a
username is not "a home path". A hostname is not on the list. An authored title is
not on the list and never can be. ⛔ **The four clean results were the gate's list
being lucky, not `validate` being safe** — and a reviewer reading only the POSIX
case, which is the one everybody reaches for, would have concluded the opposite.

⚠️ **The escalation was right and its reasoning was one step short.** It named
`AddressError` reaching a `Finding` through `str(error)`. The measurement adds the
part that decides the ruling: **`require_slug`'s echo is guarded by a shape list,
and shape lists are the thing this project has ruled against four times.**

## 17b. The fix is upstream, and W1 alone closes all six.

I prototyped W1 in the trial-merge worktree — the two `{value!r}` removals in
`slug.py`, nothing else, **no change to `validate` at all** — and re-ran the same
ten shapes:

⭐ **Ten of ten clean.** The `(did you pass a title? slugify() it first…)`
diagnosis survives, because W1 removes the echo and not the sentence.

## 17c. So: the ruling.

⛔ **A refusal is clean where it is raised, and nowhere else.** Only the raiser
knows what the value *is* — a slug, a title, a path, an opaque source string.
`validate` receives a `str` and has no way to know. **The obligation is upstream,
at the raise site, and W1/W2 is where it discharges.**

⛔ **`validate` must not scrub what it forwards, and this is the load-bearing
half.** Three reasons, in increasing order of force:

1. The rubric already rules it. §1d: *the gate refuses rather than rewrites; a
   gate that scrubs silently produces a clean file and a false belief.*
2. A scrubbing forwarder is a **shape list at the boundary** — the same list, one
   layer further from the value, where even less is known about it. It would have
   caught four of the ten shapes above and been believed for all ten.
3. ⛔ **And it would remove the symptom that motivates the cure.** If `validate`
   scrubbed, all six leaks go quiet **in the one report anybody reads**, W1 stops
   looking urgent, and the echo stays in every traceback, every other caller and
   every future consumer of `studyforge.address`. ⭐ **The one place the leak is
   currently visible is the place it would be hidden.** That is decisive.

⭐ **But "trusts upstream" is not free, and trust enforced nowhere is what Ruling
13 condition 3 already refused.** So `validate` owns a **test**, not a scrub:

> ⛔ **`validate`'s own suite poisons an identifier-shaped value into each input
> shape it parses — manifest, container map, archive document — and asserts that
> no `Finding.line()` or `Unchecked.line()` reproduces it.**

⭐ **This is not a duplicate of W2, and the difference is the whole point.** W2
poisons **one function's parameters** and checks **that function's** refusal. This
poisons **a file on disk** and checks **the report**, across a composition of four
packages that no single function's test can see. ⚠️ It is §10b's vantage-point
argument for the third time: *the trial merge exists because neither branch sees
the merge; the base measurement because the merge does not see the base; and this,
because no raise-site test sees the path from bad input to printed line.*

⭐ **The probe above is that test, already written and already proven to bite** —
it caught six real sites on its first run and went to zero on the fix. It should
land in `tests/studyforge/validate/` as part of SF-25 rather than be thrown away.
⚠️ ⛔ **The poison values are fabricated and none of them is written into this
document**, for the reason the document is about.

## 17d. What each developer owes

- **Developer 1 (SF-25).** Does **not** scrub. Keeps `str(error)` — but see
  Findings 10 and 11, which are both in `corpus.py` and both in scope. Adds the

  written to pass against the leak, and the second is worse.

# ⛔ Ruling 18 — FND-07's freshness check reads a recorded commit, never a clock.

**The coordinator's finding is upheld, and I re-measured it — with a result that
makes the case stronger than the one reported.**

The coordinator measured the graph's mtime as **older** than the newest tracked
source and read it as stale. I measured the same two values 33 minutes later:

- graph mtime `20:18:35`, newest tracked source under `src`/`tools` `20:00:54` — by
  mtime, now **fresh**.
- the same content probe — `grep -c` for a symbol from `SF-09`'s package — **13
  hits**, unchanged.

⛔ **The verdict flipped from FAIL to PASS while the fact it reports did not
move.** That is not a check with a bug; it is a check measuring a quantity
unrelated to its question. Git rewrites mtimes on merge, checkout, rebase and
worktree creation — ⚠️ **`git worktree add` alone, which this team runs several
times a round and which the rubric now *requires* for every review, resets every
mtime in the tree.** ⛔ A freshness check on mtime would fail on every trial-merge
worktree the review gate creates. It would be muted within a day.

⭐ **And the mechanism already exists in the artifact.** `graphify-out/graph.json`
carries a top-level **`built_at_commit`**, which today reads `9ad45a2` — the
release tip, exactly. ⛔ **Nobody had read it.** The check does not need building,
only reading.

**Ruled — FND-07's Acceptance is replaced with this:**

| state | verdict |
|---|---|
| no `graph.json` | ⚠️ report, with the rebuild command, **exit 0** — unchanged, and still right for a fresh clone |
| `built_at_commit` present, and `git diff --quiet <it> HEAD -- src tools docs` exits 0 | ✅ **current** |
| `built_at_commit` present, that diff is non-empty | ⛔ **FAIL — stale**, naming how many indexed paths differ |
| `built_at_commit` absent, or unknown to this repository (shallow clone, or the commit was rebased away) | ⚠️ **report loudly, exit 0** — the check cannot answer, and says so |

⛔ **Not `built_at_commit != HEAD`.** That fails after every commit, including one
that touches nothing indexed — the same cry-wolf failure in a different costume.
**The comparison is over content in the indexed paths**, and git already
implements it exactly.

⚠️ **The check answers about committed state, and FND-07 says so in words.** An
uncommitted edit leaves the index behind the working tree and this will pass. That
is correct and deliberate: committed state is the state that travels, which is the
whole of FND-07's founding defect. ⛔ **Do not add dirty-tree handling** — it is a
list, and the honest sentence is cheaper than the list.

⭐ **And the rule is made unrepresentable rather than promised:** FND-07 ships a
test that touches every tracked file, or the graph, and asserts **the verdict does
not change.** ⛔ A freshness check that reads a clock cannot survive that test, so
it cannot be reintroduced by someone who has not read this ruling. *A rule a
machine can check should not be a rule a person checks* (Ruling 13).

⚠️ **Item 4 of FND-07 — the bridging census — is untouched by this** and remains
as written. It is a content measurement and was never a timestamp.

⭐ **What this cost, recorded because it is the evidence:** the coordinator was one
step from warning both developers that the index had lost `SF-09`'s package.
Checking content before sending is the only reason a false alarm did not go out.
⛔ **The timestamp was confidently wrong and nothing about it looked wrong.**

### 9. `[structural]` — `AddressError`'s docstring *requires* the echo W1 removes

`src/studyforge/address/errors.py`, the class docstring:

> ⛔ The message names the offending value with `!r` and says what was expected.

⛔ **The rule that produces the leak is written down as the package's contract**,
in the file that defines the exception, two modules from the two lines W1 changes.
⚠️ **W1 as scoped fixes `slug.py` and `ordinal.py` and leaves this standing** — so
the next function added to `address/` will be written to it, correctly, by an
author reading the contract. ⛔ **A fix that leaves its own cause documented as
policy is a fix with a timer on it.**

⭐ **Routed: ruled, and it is Developer 2's, in the W1 commit.** The docstring is
rewritten to say what `describe` will do — name the **type**, or the character
class and position that failed — and **never the value**. ⚠️ The `!r` sentence's
*intent* is right and must survive: a refusal that says only "invalid" costs more
to diagnose than to fix. It is the mechanism that is wrong, not the goal.

**Measured:** `grep -rn "class AddressError" -A6 src/studyforge/address/errors.py`,
2026-09-09, `release/m0-foundations` @ `9ad45a2`.

`Finding`'s docstring, on `feat/SF-25-validate`:

### 11. `[structural]` — `except (ContainerError, ValueError)` is a category-sized catch

`corpus.py:159`. ⛔ **`ValueError` is not a type this package's contract names; it
is every bad-input exception in the framework and the standard library.**
`AddressError` today — which is how Ruling 17's six shapes arrive — and
`json.JSONDecodeError`, and an `int()` that met a string, tomorrow. Each one's
message was written by an author who did not know it would be printed to an
integrator.

⭐ **It is the same shape as Ruling 13 condition 3 and Ruling 12**: `except` is a
list, and this one is written wide enough to be a category. ⛔ **R17 — every
package states its contract.** If `parse_container` can raise `AddressError`, that
belongs in `corpus.container`'s stated contract and is caught **by name**. If it
cannot, the clause should not be there. ⚠️ Either way the answer is a named type;
the one answer that is wrong is the one in the tree.

⭐ **Routed: ruled, Developer 1's, in SF-25.** Narrow to named types. ⚠️ If
narrowing surfaces an undocumented raise in `corpus.container`, that is a
**finding against SF-05**, not scope for SF-25 — file it, do not fix it.

**Measured:** `git show cf6be28:src/studyforge/validate/structure.py`, and the
probe, which reaches the report through precisely this clause.

### 12. `[structural]` — `structure.py` branches on a placement profile name, and SF-03's own test says no

⛔ **A real test failure in the trial merge, and it is not housekeeping:**

```
AssertionError: a consumer branches on a profile name: structure.py:109
```

`structure.py:109` is `if walk.manifest.placement != "sibling":`.
`tests/studyforge/corpus/placement/test_profile.py` walks every `*.py` under
`src/` with `ast` and forbids exactly this outside the three placement modules.

⚠️ **This is §10b, exactly and for the third time**: the constraint lives in
**another package's** test, so neither the author of `validate` nor a reviewer
reading the `validate` diff would ever see it. ⭐ **Only the trial merge finds it**
— which is C5's ruling paying for itself inside one round of the milestone it was
made for.

⛔ **It is not an R1 REJECT.** `sibling` is *framework* vocabulary, not a source's
— the framework has not been taught about a corpus. It is SF-03's extensibility
guard: a fourth profile must not require editing every consumer.

⭐ **Routed: ruled, Developer 1's, in SF-25 — and the answer is the standing
ruling again.** Do not compare the name; **ask the profile**. `Profile` already
carries `name` and `describes`; it gains the capability this check actually needs
— *does this profile generate beside the material?* — and `structure.py` reads it.
⚠️ **That is a change to `corpus/placement/`, which is SF-03's module and outside
SF-25's Owns.** ⛔ So it is a **two-line contract request to SF-03's owner, routed
by me here**, not a reach across the boundary — the last cross-package hotfix is
what produced the seam we spent two rounds closing (Ruling 14). ⚠️ Until it lands,
`validate` is blocked on this one check and the honest interim is an `Unchecked`,
which is the package's own vocabulary for precisely this.

**Measured:** `docker/dev/check python3 -m pytest -q -rs` in the trial merge,
2026-09-09 — 5 failed, and this is one of them. Re-confirmed against tip
`cf6be28`.
