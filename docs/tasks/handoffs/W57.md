## Decisions

### ⛔ The closed set was not relaxed. It was SPLIT, because it had two kinds in it

⭐ **`("http://", "https://", "mailto:", "#", "/", "./", "../")` is seven
entries and only three of them are schemes.** ⚠️ **That is the whole defect, and
it is a `module-structure.md` failure rather than a link-handling one:** the
conventions say to close the set you are defining, and this closed *one* set over
*two* domains. Crowding four relative-reference forms into a tuple named
`SAFE_SCHEMES` made it read as complete — and a reader auditing it counts
schemes, sees `javascript:` absent, and stops.

⛔ **So `SAFE_SCHEMES` now holds schemes and only schemes, and the relative form
is a GRAMMAR rather than a prefix list.** ⭐ **A grammar is what makes the set
finishable:** *"no scheme, and not outside the site"* is a rule a reviewer can
restate, where *"…and `./`, and `../`, and `#`, and…"* is a list you can always
add one more entry to — which `module-structure.md` names as the tell that you
are writing the wrong kind of set.

⛔ **A denylist was never on the table** and the row said so; nothing here refuses
by enumeration. **Both halves stay closed:** the scheme set is closed, the
character set is closed, and the relative form is closed by a production.

### ⛔ Deciding "does this have a scheme?" is RFC 3986's rule, not `":" in href`

⭐ `_SCHEME` is `^[A-Za-z][A-Za-z0-9+.-]*:`, anchored, and `/` is deliberately
not a scheme character. ⚠️ **The three traps that costs nothing and a `":" in`
test gets wrong in both directions:**

- `notes:draft.html` **has** a scheme (`notes`) and is refused. A browser agrees.
- `path/to:x` and `page.html#a:b` have **no** scheme, because a `/` or `#`
  precedes the colon, and are admitted as relative. A browser agrees.
- `%6Aavascript:x` has no scheme — `%` is not a scheme character and no browser
  percent-decodes before parsing one — so it is a relative path, and admitting it
  navigates to a missing local file rather than running anything.

### ⛔ `/` LEAVES the permitted set, and that narrowing is deliberate

⚠️ **This is the one place the row narrows rather than widens, and it is the
brief's own list that demands it:** *absolute paths that escape the site root,
anything carrying a home path*. ⛔ **Neither was refused before.**
`safe_href("/home/<someone>/notes.html")` returned it, because `/` was a
permitted prefix.

**Three independent reasons, and no reason to keep it:**

- ⛔ **R8.** Opened over `file://` a rooted href resolves to the *filesystem*
  root, not the site root. It is broken at the floor this project ships on.
- ⛔ **R7.** `/home/<name>/notes.html` is a rooted href, so admitting the form
  admits a personal path straight onto a page.
- ⭐ **`placement.relative_href` already refuses to EMIT one**, in a docstring
  that gives exactly reason one: *"never rooted, never absolute. A rooted href
  would work under a server and break the moment the page was opened from a
  file."* ⛔ **So the emitter and the gate disagreed, and the gate was the lax
  one.**

⭐ **Measured blast radius before taking it:** `grep -rn '](/' tests/ src/` and
`grep -rn 'href="/' src/ tests/` are **both empty**, and the only assertion that
depended on it was `test_a_permitted_scheme_survives_verbatim`'s own `/a` row.
Nothing in this repository emits or consumes a rooted href.

### ⛔ The character set is what keeps a refused scheme refused

⚠️ **This is the trap the row's own brief names: every scheme you admit is one
you can no longer refuse — and widening to relative references admits a great
deal at once.** ⛔ **A browser NORMALISES a URL before it parses one.** It strips
tab, newline and carriage return, and it rewrites `\` to `/`. So:

| candidate | naive reader sees | browser sees |
|---|---|---|
| `java<TAB>script:alert(1)` | no scheme → a relative path | ⛔ `javascript:` |
| `/\evil.example/x` | a rooted path | ⛔ `//evil.example/x` |
| `\\evil.example\share` | a relative path | ⛔ `//evil.example/share` |

⛔ **The old prefix set blocked all three BY ACCIDENT** — it admitted nothing that
did not start with one of seven literals, so a mangled `javascript:` fell through
the same hole a legitimate `page.html` did. ⭐ **Widening to relative references
would have opened every one of them**, which is why `_HREF_CHARACTERS` is part of
the same commit and not a follow-up. **`M2` in the sweep is that claim, run
negatively: remove the character check and eight refusals turn green.**

### ⛔ `example.com/x` is now a link, and the trade is stated rather than hidden

⚠️ **The module's own docstring used to argue for refusing it** — *"treating it
as relative is wrong and treating it as `http` is inventing intent"*. ⛔ **The
first half of that is no longer available.** `example.com/x` and
`unit-02-fields-and-constructors.unit.html` are both one path segment containing
dots; **nothing about their shape separates them.** Refusing one and admitting
the other needs a *"looks like a hostname"* heuristic — an open set, and the row
forbids answering with an exception.

⭐ **So it is admitted, and it renders as a relative link to a local file that
does not exist.** ⛔ **The cost is bounded and named: one dead link, no network
request, nothing leaves the origin** — because a relative reference cannot name a
host, which is exactly what refusing `//` buys and what
`test_a_permitted_relative_reference_can_never_name_a_host` asserts over the
whole permitted population. ⚠️ **The alternative cost 46 % of the bar on every
`sibling` corpus, silently.**

### ⭐ `SF-13`'s pinning test was inverted, not deleted

⛔ **Its author wrote it to be inverted:** *"the behaviour is pinned by a test in
my own tree that names this finding, so the day somebody widens the set the test
says so."* ⚠️ **`tests/studyforge/contents/test_acceptance.py` is outside this
row's `Owns`**, and touching it is unavoidable — the fix makes its assertions
false. ⭐ **So the assertions are flipped in place, the comment now reads as
history, and the finding it names is still findable from it.** `W57/3` records
the boundary crossing.

### ⛔ Anyone touching `safe_href` — the rule, in one paragraph

⭐ **Absolute → the scheme must be in `SAFE_SCHEMES`. No scheme → it is a
relative reference, and it must not begin `/`. Either way, every character must
be in `_HREF_CHARACTERS`.** ⚠️ **All three parts are load-bearing and each is
proved by a sweep row that removes it.** ⛔ **Do not add a prefix to
`SAFE_SCHEMES` — it takes scheme NAMES now** (`test_the_scheme_set_holds_schemes_and_not_prefixes`
fails on a `:` or a `/`), and **do not relax `_HREF_CHARACTERS` to admit a
"harmless" character without checking whether a browser normalises it**, which is
what `M2` measures.
