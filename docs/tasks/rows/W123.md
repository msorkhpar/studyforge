### ⛔ THE DEFECT IT BOUNDS, AND THE HALF IT IS NOT

⭐ **`RECEIVED` as `W36/2`, CONFIRMED by the CTO by reading the code:** `call()` sets `deadline = time.monotonic() + CALL_TIMEOUT` and loops `while time.monotonic() < deadline`, but the loop body is `self._receive()`, which blocks in `os.read` on a live pipe with no deadline. ⛔ **So `BrowserError(f"{method}: no answer in {CALL_TIMEOUT:.0f}s")` is unreachable for a browser that is UP AND SILENT; it fires only if the pipe CLOSES.**

⛔ **THIS ROW IS THE OUTER BOUND AND NOT THE DEADLINED READ.** ⭐ **The deadlined read is a change to the harness's TRANSPORT and stays with `QA-03`'s successor, for the reason Ruling 235(a) gives and it is better than ownership: `select`-ing on the fd is a different I/O path, so fixing it inside the harness changes what every one of the 57 first readings was taken against.** ⚠️ **An outer `timeout` changes nothing any reading is taken against, which is the whole of why it is separable.**
