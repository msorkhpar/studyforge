⚠️ **It is not that the overlay is unimplemented — it is that the LOCATION is unsaid.** ⛔ **A build that wants to honour an authored overlay has nowhere to look and no name to look for, and every consumer that invents one invents a different one.**

⭐ **THE OFFICE MARKED IT RATHER THAN GUESSING: a premise test that FAILS the day `Layout` grows the field.** ⛔ **That is the right shape and it is why this is a row and not a bug — the marker will fire, and when it does somebody needs a decision already taken.**

### ⛔ WHAT SETTLES IT

1. ⛔ **`Layout` — or whichever type owns archive geography — CARRIES THE OVERLAY'S ADDRESS**, named once, so no consumer derives it.
2. ⛔ **THE ADDRESS IS A CONTRACT AND GOES WHERE CONTRACTS GO** (spec §R21's register of located contracts, `content_api`'s family), ⚠️ **not into a build's private constant.** ⭐ **CORRECTED IN PO ROUND 104 (`W198/1`): this clause said §R9 and `corpus_api`, and both halves were wrong — measured by the office that took the address half, and re-measured by the register against the spec and against `unit/content.py`, which mints `CONTENT_FILENAME` beside `content_api`.**
3. ⭐ **THE PREMISE TEST STAYS AND INVERTS**: ⛔ **today it asserts the field is ABSENT; when the field lands the same test asserts the address, so the marker is never quietly deleted.**
4. ⚠️ **WHETHER AN OVERLAY EXISTS AT ALL IS A SEPARATE QUESTION AND IS NOT ANSWERED HERE** — ⛔ **if the honest answer is that v1 has none, this row closes by SAYING SO in the contract, not by deleting the marker.**
