### ⛔ THE READING — the same bytes, twice, and the exit code moves

⛔ **The cause, read rather than guessed: that gate's subject is `tracked_files(FORMAT_POPULATION)`, so an untracked file is not in its population at all.** ⚠️ **The green run printed `PYTEST_EXIT=0`, which is the most convincing possible way to be wrong.**

⭐ **AND THE DEFECT IT HID WAS REAL:** ruff 0.16.6 formats a multi-exception `except` without parentheses under PEP 758, which is the form five existing modules in `src/` already use, and the new module had the parenthesised one.

### ⛔ WHAT THIS ROW IS NOT, and the reviewer ruled it in advance

⛔ **NOT *widen the gate to the disk*.** ⭐ **`W142` REMOVED exactly that — two floor checks reaching their verdict through `ruff check .`, which walks the disk, so an untracked file reddened a correct tree — and Ruling 80 forbids a floor check's verdict depending on untracked state.** ⚠️ **Reading tracked files is the RIGHT subject for a repository gate, and it is the same property that makes the whole floor stable.**

### ⛔ WHAT SETTLES IT — the question is whether the WORKING-TREE SIGNAL REACHES AUTHORS

1. ⛔ **THE REMEDY IS PROCEDURAL, AND A PROCEDURE WITH NO ARTIFACT IS THE THING THIS PROJECT KEEPS RE-LEARNING.** ⭐ **The rule is *commit the new file, THEN take the reading*, and today it exists in exactly one place: a closed row's handoff.**
2. ⚠️ **ITS HOME IS A CONVENTION DOCUMENT, NOT A CHECK.** ⛔ **`agent-protocol.md` says how a task is worked and `review-rubric.md` §9 is where acceptance output is pasted — ⭐ and the clause binds the moment an office takes a reading over a diff that adds a file, which is a MOMENT no instrument reads.**
3. ⛔ **THE DISJOINTNESS FRAMING IS THE GENERAL FORM AND IS WORTH CARRYING WITH IT:** ⚠️ **DISJOINT IS ASSERTED OF THE POPULATION AN INSTRUMENT READS, NOT ONLY OF THE FILES A BRANCH TOUCHES.** ⭐ **Here the file set the branch touched and the file set the gate read were disjoint for exactly one commit, and nothing in the green run said so.**
4. ⚠️ **A NOTICE IS ADMISSIBLE AND IS THE TAKER'S CALL.** ⛔ **A floor NOTICE naming untracked files inside `FORMAT_POPULATION`'s directories would carry no verdict and so would not violate Ruling 80** — ⭐ **but `NS-05/4` already records that a notice reading the working tree is `W142`'s enumerated design, so the taker must read that enumeration before adding one rather than re-deriving it.**

### ⚠️ WHAT IT MUST NOT BECOME

⛔ **A CHECK THAT FAILS ON AN UNTRACKED FILE.** ⭐ **That is Ruling 80 inverted and `W142` undone, and it would redden every correct tree with a scratch file in it.** ⛔ **AND NOT A RULE THAT EVERY READING IS TAKEN TWICE** — ⚠️ **the cost falls only on a diff that ADDS a file, and a clause priced at every reading is one offices will drop.**
